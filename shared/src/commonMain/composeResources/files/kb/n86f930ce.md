# R8, ProGuard, обфускация

При сборке **release** APK/AAB код проходит обработку: удаление мусора, уменьшение и обфускация. Сегодня этим занимается **R8** (заменил ProGuard).

## Что делает R8 (4 функции)

| Функция | Что делает | Зачем |
| --- | --- | --- |
| **Shrinking** (tree shaking) | удаляет неиспользуемые классы/методы/поля | меньше размер, меньше методов (важно для лимита DEX) |
| **Optimization** | инлайнинг, упрощение кода, удаление мёртвых веток | быстрее/компактнее |
| **Obfuscation** | переименовывает классы/методы в `a`, `b`, `c` | защита + меньше размер строк |
| **Desugaring** | бэкпорт новых Java API/синтаксиса на старые API | поддержка старых устройств |

> [!info] R8 vs ProGuard
> **ProGuard** — старый инструмент (shrink + obfuscate отдельным шагом). **R8** — встроен в Android Gradle Plugin, делает **всё за один проход** и оптимизирует агрессивнее, при этом **использует тот же формат правил** (`proguard-rules.pro`). Сегодня ProGuard в Android фактически не используют — дефолт R8.

```kotlin
buildTypes {
    release {
        isMinifyEnabled = true       // включить R8 (shrink + obfuscate)
        isShrinkResources = true     // удалить неиспользуемые ресурсы
        proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
    }
}
```

## Keep-правила — главная боль

> [!warning] Что ломается и почему нужны `-keep`
> R8 не видит обращений через **рефлексию/имена строк**, поэтому может удалить/переименовать то, что нужно:
> • классы для **сериализации** (Gson по именам полей — особенно опасно; kotlinx.serialization безопаснее), модели API;
> • классы, используемые из **JNI/нативного кода**, имена в **манифесте**;
> • то, к чему обращаются по имени класса.
> Решение — правила в `proguard-rules.pro`:
> ```text
> -keep class com.app.model.** { *; }
> -keepclassmembers class … { @com.google.gson.annotations.SerializedName <fields>; }
> ```
> Хорошие библиотеки **поставляют свои keep-правила** (consumer rules в `.aar`), поэтому Retrofit/Coil/Room обычно работают из коробки.

> [!important] Обфускация ломает стектрейсы → mapping.txt
> После обфускby крэш-логи приходят в виде `a.b.c()` — нечитаемы. R8 генерирует **`mapping.txt`** (соответствие исходных имён обфусцированным). Его нужно **загрузить в Play Console / Crashlytics**, чтобы деобфусцировать стектрейсы. Каждая сборка — свой mapping; потерял его → не разберёшь краши этой версии.

> [!note] Обфускация — не настоящая защита
> Переименование усложняет реверс, но **не шифрует** код — APK всё равно декомпилируется. Секреты (ключи, токены) в коде небезопасны даже с R8 — это тема [[Безопасность в Android]] (Keystore, серверная проверка, NDK как слабая мера).

> [!tip] На собесе
> «`minifyEnabled` включает R8: он делает shrink (tree shaking), optimization, obfuscation и desugaring за один проход. Правила `-keep` нужны для классов, к которым обращаются по рефлексии/имени (модели сериализации, JNI). Обфускация требует хранить `mapping.txt` для деобфускации крашей.»
