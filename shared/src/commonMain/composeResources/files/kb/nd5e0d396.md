
==**В Kotlin нет примитивных типов данных в привычном смысле (как в Java), но они представлены как классы (например, Int, Double, Char).== Эти классы являются обёртками, которые Kotlin автоматически оптимизирует для повышения производительности, используя примитивы JVM под капотом.**

**1. Примитивные типы данных (простые типы)**
Примитивные типы в Kotlin представлены как классы, но компилируются в соответствующие примитивы JVM для повышения производительности

**2. Ссылочные типы**
К этим типам относятся все объекты, которые не являются примитивными. Например:

• String — строковый тип данных.
• Any — базовый класс для всех типов в Kotlin (аналог Object в Java).
• Unit — тип, используемый для функций, которые ничего не возвращают (аналог void в Java).
• Nothing — тип, который обозначает, что функция никогда не завершает выполнение (например, выбрасывает исключение).

### VAL VS CONST VAL

**В Kotlin val и const val используются для объявления неизменяемых переменных, но у них есть важные отличия в поведении и области применения:**

1. **val**
• **Что это:** val используется для объявления переменных, которые можно установить только один раз, но их значение может быть вычислено ==во время выполнения==.

• **Инициализация:** Значение переменной может быть вычислено ==в момент выполнения программы==.
• **Использование:** Может использовать ==любые выражения==, в том числе сложные вычисления, вызовы функций и т.д.

• **Контекст:** Может использоваться в любых местах, включая локальные переменные, свойства класса и т.д.

```kotlin
val currentTime = System.currentTimeMillis() // Значение вычисляется во время выполнения
val myList = listOf(1, 2, 3) // Используется вызов функции
```

2. **const val**

• **Что это:** const val используется для объявления ==компиляторных констант (compile-time constants)==.
• **Инициализация:** Значение должно быть известно ==на этапе компиляции==.
• **Использование:** Только для ==примитивных типов== (Int, Double, String, Boolean и т.д.) и строк.
• ==Нет пользовательского геттера==
• **Контекст:** ==Можно использовать только на уровне top-level (вне классов) или в companion object.== Нельзя использовать внутри функций.

```kotlin
const val MAX_USERS = 100 // Константа известна на этапе компиляции
const val APP_NAME = "MyApp"
```

**Когда использовать:**

• const val — когда значение известно на этапе компиляции и требуется оптимизация производительности (например, для константных конфигураций).
• val — для значений, которые вычисляются динамически или зависят от выполнения программы.

**Ключевые различия между val и const val**

| Характеристика              | val                                                            | const val                             |
| --------------------------- | -------------------------------------------------------------- | ------------------------------------- |
| Известность значения        | Во время выполнения                                            | На этапе компиляции                   |
| Типы данных                 | Любой тип данных                                               | Только примитивы                      |
| Использование в функциях    | Можно использовать внутри функций                              | Нельзя использовать                   |
| Контекст применения         | Локальные переменные, свойства классов и глобальные переменные | Только top-level или companion object |
| Выражение для инициализации | Любое выражение                                                | Только литералы                       |

**✅ 1. Compile Time (Время компиляции)**

Это этап, когда код **Kotlin/Java** преобразуется в байт-код DEX (Dalvik Executable) для Android.

• Проверка **синтаксиса кода**
• Проверка **типов данных**
• Компиляция Kotlin/Java → Bytecode → DEX (Dalvik Executable)
• Генерация .apk или .aab

**✅ 2. Run Time (Время выполнения)**

Это этап, когда приложение уже запущено на устройстве.
• Выполняется код (DEX → ART/Dalvik VM)
• Работают **корутины, потоки, обработчики событий**
• Загружаются **ресурсы** (**xml**, **assets**)
• Выполняются **анимации и API-запросы**
## Где хранятся примитивы и ссылочные типы?

**1. Примитивные типы**
  
В Kotlin примитивные типы (Int, Double, Char, Boolean и т.д.) могут обрабатываться по-разному в зависимости от контекста:

• **В стеке:**
• Когда примитив используется в локальной переменной функции, он хранится в стеке, так как стек — это место для временных данных.

• Пример:

```kotlin
fun sum(a: Int, b: Int): Int {
    val result = a + b
    return result
} //Здесь a, b и result будут храниться в стеке.
``` 

• **В куче:**
• Если примитив становится частью объекта (например, свойства класса), он хранится в куче вместе с объектом.

• Пример:
```kotlin
class MyClass(val number: Int)
val obj = MyClass(42) // Число 42 хранится в куче как часть объекта obj
```

**2. Ссылочные типы**

Ссылочные типы всегда хранятся в куче, так как они представляют собой объекты. Однако ссылка на объект (адрес в памяти) хранится в стеке.

• **Ссылки в стеке:**
• Ссылки на объекты находятся в стеке, если переменная локальная.
• Пример:

```kotlin
fun example() {
    val str = "Hello" // Ссылка на объект "Hello" хранится в стеке
}
```

• **Объекты в куче:**
• Сами данные ссылочного типа (например, строки, списки, пользовательские классы) всегда размещаются в куче.

• Пример:

```kotlin
val str = "Hello" // Строка "Hello" хранится в куче
```

**3. Автобоксинг (Boxing) и разворачивание (Unboxing)**

Kotlin использует механизм автобоксинга при работе с примитивами и ссылочными типами.

• **Когда примитив “упаковывается” (boxing):**
• Примитив становится объектом (например, Int преобразуется в Integer).
• Это происходит, например, при использовании коллекций:

```kotlin
val numbers: List<Int> = listOf(1, 2, 3) // Примитивы упаковываются в объекты
```


## ЗАДАЧА НА ПОНИМАНИЕ BOXING и UNBOXING

```kotlin
fun main() {
    var first: Int? = 0
    var second: Int? = 0

    first = 10
    second = 10
    println(first === second)   // true

    first = 10000
    second = 10000
    println(first === second)   // false
}
```

### Разбор

`Int?` (nullable) — это **боксированный** тип (`java.lang.Integer`), поэтому `===` сравнивает **ссылки**.

- `10` попадает в диапазон кэша `Integer` (**−128…127**) → обе переменные ссылаются на один кэшированный объект → `true`.
- `10000` вне кэша → создаются **два разных** объекта `Integer` → `false`.

> [!tip]
> Если бы тип был `Int` (не nullable), оба сравнения дали бы `true` — там нет боксинга, сравниваются примитивы по значению. Мораль: `===` на боксированных числах зависит от Integer-кэша; для сравнения значений используй `==`.


**Итог**

• **Примитивные типы:**
• Локальные переменные хранятся в стеке.
• Если примитив становится частью объекта, он хранится в куче.
• **Ссылочные типы:**
• Сами объекты (данные) хранятся в куче.
• Ссылки на объекты (адреса в памяти) хранятся в стеке.

>**В Kotlin нет примитивных типов данных в привычном смысле (как в Java), но они представлены как классы (например, Int, Double, Char). Эти классы являются обёртками, которые Kotlin автоматически оптимизирует для повышения производительности, используя примитивы JVM под капотом.**

**Как работает это в Kotlin**

1. **На уровне языка:**

• Все типы данных (включая числа, символы и логические значения) представлены как классы. Например:

• Int — это класс, который обеспечивает дополнительные методы и функциональность.
• Boolean, Char, Float и другие работают аналогично.
• Kotlin предлагает удобство работы с типами, как если бы все они были объектами.

2. **На уровне JVM:**

• Когда Kotlin-компилятор генерирует байт-код для JVM, он оптимизирует использование этих типов.
• Для переменных, свойств и параметров используется соответствующий примитивный тип JVM (int, double, boolean и т.д.), если это возможно.
• Автоматический **автобоксинг** и **разупаковка** происходят при необходимости (например, при использовании коллекций, работающих с объектами).

```kotlin
val x: Int = 42 // `Int` в Kotlin — это класс
val y: Int = x + 1 // Операции выполняются как с объектами
```

```kotlin
int x = 42; // `Int` преобразуется в примитивный тип `int` для оптимизации
int y = x + 1;
```

**Когда используются примитивы и обёртки**

**1. Примитивы:**

• Используются при выполнении арифметических операций.
• Хранятся как примитивные типы (int, double, и т.д.) в стеке для повышения производительности.

**2. Обёртки:**

• Используются, если типы данных необходимо хранить в коллекциях (например, ``List<Int>``).

• Kotlin автоматически упаковывает (boxing) и распаковывает (unboxing) значения при необходимости.

**В Kotlin обёртки используются для упрощения работы с кодом, улучшения читаемости и добавления функциональности без изменения исходного объекта или класса. Они применяются в разных контекстах и могут быть реализованы разными способами. Вот основные случаи, где обёртки полезны и часто применяются:**

**1. Обёртки для коллекций**

Kotlin предоставляет обёртки для работы с коллекциями, чтобы делать их неизменяемыми или синхронизированными.
Пример

```kotlin
val mutableList = mutableListOf(1, 2, 3)
val readOnlyList: List<Int> = mutableList // Обёртка, предотвращающая модификацию
mutableList.add(4) // Сама коллекция может быть изменена
println(readOnlyList) // [1, 2, 3, 4]
```

**Зачем это нужно:**

• Контроль доступа к данным (например, предоставление только для чтения).

**2. Обёртки для делегирования**

В Kotlin есть делегирование свойств с использованием ключевого слова by. Это упрощает создание обёрток для изменения поведения существующих объектов.

**Преимущества использования обёрток:**

1. **Инкапсуляция**: Скрытие деталей реализации.
2. **Расширение функциональности**: Добавление новых возможностей без изменения исходного кода.
3. **Повторное использование**: Обёртки легко применять в разных частях приложения.
4. **Безопасность**: Обёртки могут ограничивать или модифицировать доступ к данным.


## Чему равне Int в 32 битной системе

В **32-битной системе**, максимальное значение для типа int **(целое число со знаком)** определяется следующим образом:

**✅ Диапазон 32-битного int**

• **Минимальное значение**: -2,147,483,648 (-2³¹)
• **Максимальное значение**: 2,147,483,647 (2³¹ - 1)

**✅ Диапазон 32-битного double**
 **Java/Kotlin**, тип double всегда занимает **64 бита (8 байт)**, **независимо от разрядности системы (32-бит или 64-бит)**.

# Базовые примитивные типы

Базовые примитивные типы в языке Kotlin и их особенности:

1. **Byte:**
    - Размер: 8 бит.
    - Диапазон значений: от -128 до 127.
    - Лучше всего подходит для экономии памяти, когда требуется хранить небольшие целочисленные значения.

2. **Short:**
    - Размер: 16 бит.
    - Диапазон значений: от -32768 до 32767.
    - Обычно используется, когда требуется больше значений, чем может предложить тип Byte, но при этом не нужно использовать тип Int.

3. **Int:**
    - Размер: 32 бита.
    - Диапазон значений: от -2^31 до 2^31-1.
    - Это наиболее распространенный целочисленный тип и обычно используется для хранения целых чисел.

4. **Long:**
    - Размер: 64 бита.
    - Диапазон значений: от -2^63 до 2^63-1.
    - Используется, когда требуется хранить очень большие целочисленные значения.

5. **Float:**
    - Размер: 32 бита.
    - Представляет число с плавающей запятой одинарной точности.
    - Часто используется в вычислениях, где точность не является критической.

6. **Double:**
    - Размер: 64 бита.
    - Представляет число с плавающей запятой двойной точности.
    - Часто используется в вычислениях, где требуется высокая точность.

7. **Boolean:**
    - Размер: не определен (зависит от реализации).
    - Используется для хранения логических значений: true или false.

8. **Char:**
    - Размер: 16 бит.
    - Представляет символ Unicode.
    - Используется для хранения отдельных символов.

### В каких случаях лучше применять тот или иной тип:

- **Byte и Short:** Используйте их, когда вам нужно экономить память и диапазон значений не выходит за их пределы.
    
- **Int:** Это стандартный тип для целых чисел. Используйте его, когда вам нужно хранить целые числа и нет необходимости в огромных значениях.
    
- **Long:** Используйте его, когда вам нужно хранить очень большие целочисленные значения.
    
- **Float и Double:** Используйте Float, если вам необходимо хранить числа с плавающей точкой одинарной точности, и Double для повышенной точности.
    
- **Boolean:** Используйте Boolean для хранения логических значений true/false.
    
- **Char:** Используйте Char для хранения отдельных символов.
    

При выборе типа следует учитывать требования к памяти, диапазон значений и требуемую точность. Использование наименее подходящего типа может привести к ненужным затратам памяти или потере точности данных.
