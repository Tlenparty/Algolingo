# 02 Spring: контроллер и роутинг

Контроллер — класс, который принимает HTTP-запрос, достаёт из него параметры, зовёт сервис и отдаёт ответ. В Spring Boot это обычный Kotlin-класс с аннотациями. Термины — в [[01 Словарь Spring]], методы и статусы HTTP — в [[02 HTTP]].

Урок: `bk3.1` на вкладке Backend.

## Минимальный контроллер

```kotlin
@RestController
@RequestMapping("/users")
class UserController(private val users: UserService) {

    // GET /users/7
    @GetMapping("/{id}")
    fun byId(@PathVariable id: Long): UserDto =
        users.byId(id)
}
```

- `@RestController` говорит Spring: это бин, он принимает HTTP, результат метода уходит в тело ответа как JSON.
- `@RequestMapping("/users")` — общий префикс. Все методы ниже живут под `/users`.
- Зависимость `UserService` приходит через конструктор: Spring сам найдёт бин по типу.
- `@GetMapping("/{id}")` — метод GET на `/users/{id}`. Фигурные скобки — переменная пути.
- `@PathVariable id: Long` — Spring берёт кусок пути и превращает в `Long`. Имя параметра должно совпадать с именем в `{id}`.
- Возвращённый `UserDto` Jackson превращает в JSON, статус по умолчанию 200.

## Откуда берётся параметр

| Где лежит | Пример запроса | Аннотация | Если нет |
| --- | --- | --- | --- |
| в пути | `GET /users/7` | `@PathVariable id: Long` | маршрут не совпадёт — 404 |
| в строке запроса | `GET /users?limit=20` | `@RequestParam limit: Int` | 400, если нет `defaultValue` или `required = false` |
| в теле | `POST /users` + JSON | `@RequestBody body: CreateUser` | 400 `Required request body is missing` |
| в заголовке | `Authorization: Bearer …` | `@RequestHeader("Authorization") auth: String` | 400 |

> [!question]- Почему `@RequestParam` для `/users/7` не сработает?
> `7` — часть пути, а не строки запроса. Spring будет искать `?id=7`, не найдёт и ответит 400 `Required request parameter 'id' is not present`.

> [!question]- Почему `defaultValue = "20"`, а не `20`?
> Значения аннотаций — строки, Spring сам конвертирует в тип параметра. `defaultValue = 20` не скомпилируется.

## Список с параметром

```kotlin
// GET /users?limit=20
@GetMapping
fun list(
    @RequestParam(defaultValue = "20") limit: Int
): List<UserDto> = users.list(limit)
```

`@GetMapping` без пути — это сам `/users`. `defaultValue` делает параметр необязательным: `GET /users` даст 20 записей.

## Создание и статус

```kotlin
// POST /users + JSON в теле
@PostMapping
@ResponseStatus(HttpStatus.CREATED)
fun create(@RequestBody body: CreateUser): UserDto =
    users.create(body)
```

- Создание — `POST`. `GET` тело не несёт: клиент, который пошлёт `POST /users` на `@GetMapping`, получит 405 Method Not Allowed.
- По умолчанию контроллер отвечает 200. Для созданного ресурса принято 201 Created: либо `@ResponseStatus(HttpStatus.CREATED)`, либо `ResponseEntity.status(201).body(dto)`.
- 202 Accepted значит «принял, сделаю позже». Для синхронного создания это неправда.

## Когда нужен ResponseEntity

Если статус зависит от результата, метод возвращает `ResponseEntity`:

```kotlin
@GetMapping("/{id}")
fun byId(@PathVariable id: Long): ResponseEntity<UserDto> =
    users.find(id)?.let { ResponseEntity.ok(it) }
        ?: ResponseEntity.notFound().build()
```

Чаще же сервис бросает `NotFoundException`, а `@ControllerAdvice` превращает её в 404 для всех контроллеров сразу. Это урок `bk3.4`.

## ⚠️ Грабли

- `@Controller` без `@ResponseBody`: Spring ищет HTML-шаблон с именем возвращённого значения, а не отдаёт JSON. Для API — только `@RestController`.
- `@GetMapping` на классе не скомпилируется: это аннотация метода. На класс — `@RequestMapping`.
- `@RequestParam` обязателен по умолчанию: забыл `defaultValue` — клиенты без параметра получают 400.
- Имя в `{id}` и имя параметра разошлись (`{userId}` и `id`) — Spring не найдёт переменную и ответит 500.
- `@PostMapping` без `@RequestBody`: тело запроса игнорируется, в объекте будут значения по умолчанию или ошибка создания.
- Контроллер ходит в репозиторий напрямую: логика расползается по ручкам. Между ними сервис — урок `bk3.2`.
