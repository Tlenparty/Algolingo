# Как перехватить все исключения в runtime

## 1. Локально — try-catch

Если нужно обработать исключение в конкретном месте:

```kotlin
try {
    val result = 10 / 0 // ArithmeticException
} catch (e: RuntimeException) {
    println("Перехвачено исключение: $e")
}
```

## 2. Глобально во всём процессе — setDefaultUncaughtExceptionHandler

Чтобы поймать **все** необработанные исключения в любом потоке, ставится глобальный обработчик:

```kotlin
fun main() {
    Thread.setDefaultUncaughtExceptionHandler { thread, e ->
        println("Глобальный перехват в потоке ${thread.name}: $e")
    }

    throw RuntimeException("Ошибка в главном потоке!")
}
```

## 3. Для конкретного потока — setUncaughtExceptionHandler

Если нужно обработать исключения отдельного потока:

```kotlin
fun main() {
    val thread = Thread {
        throw RuntimeException("Ошибка в потоке!")
    }

    thread.setUncaughtExceptionHandler { t, e ->
        println("Исключение в потоке ${t.name}: $e")
    }

    thread.start()
}
```

> [!note] Порядок поиска обработчика
> При необработанном исключении JVM ищет обработчик так: сначала `Thread.uncaughtExceptionHandler` конкретного потока, затем обработчик его `ThreadGroup`, и в конце — `Thread.defaultUncaughtExceptionHandler`.

## В Android — глобальный обработчик в Application

Ставить лучше в `Application.onCreate()`, а не в Activity:

```kotlin
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()

        Thread.setDefaultUncaughtExceptionHandler { _, throwable ->
            Log.e("GLOBAL_EXCEPTION", "Необработанное исключение", throwable)
            // можно отправить на сервер перед завершением
            restartApp()
        }
    }

    private fun restartApp() {
        val intent = Intent(applicationContext, MainActivity::class.java).apply {
            addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK)
        }
        startActivity(intent)
        Runtime.getRuntime().exit(1) // завершаем процесс
    }
}
```

> [!warning] Важно
> - `setDefaultUncaughtExceptionHandler` **не предотвращает краш** — он позволяет залогировать ошибку и выполнить действия перед завершением приложения.
> - Если подключён **Firebase Crashlytics**, он ставит свой обработчик. Чтобы не сломать ему сбор крашей, сохраните предыдущий обработчик и вызовите его в конце своего:
>   ```kotlin
>   val previous = Thread.getDefaultUncaughtExceptionHandler()
>   Thread.setDefaultUncaughtExceptionHandler { thread, throwable ->
>       Log.e("GLOBAL_EXCEPTION", "Необработанное исключение", throwable)
>       previous?.uncaughtException(thread, throwable) // отдаём дальше в Crashlytics
>   }
>   ```

> [!tip] А что с корутинами?
> Исключения внутри корутин до глобального хендлера могут не дойти — там работает `CoroutineExceptionHandler` (см. [[Coroutines]]). А `CancellationException` — это «штатная» отмена, её не считают ошибкой и обычно не логируют.
