# Коллекции: основные виды

Обзор коллекций, которые чаще всего встречаются в Android-разработке. Сгруппированы по базовому интерфейсу: `List`, `Set`, `Map`, `Queue`, `Stack`.

> **На собес одной фразой:** `List` — упорядоченный, допускает дубликаты; `Set` — уникальные элементы; `Map` — пары ключ→значение; `Queue`/`Stack` — линейные структуры с разным порядком доступа (FIFO/LIFO).

---

## 1. List (список)
Упорядоченная коллекция с доступом по индексу, допускает дубликаты.

- **`ArrayList`** — динамический массив. Быстрый произвольный доступ по индексу (`O(1)`), но вставка/удаление в середине — `O(n)` (сдвиг элементов). Дефолтный выбор для большинства задач.
- **`LinkedList`** — двусвязный список. Быстрые вставка/удаление на концах (`O(1)`), но доступ по индексу — `O(n)`. См. [[LinkedList]].

## 2. Set (множество)
Хранит только уникальные элементы, дубликаты игнорируются.

- **`HashSet`** — на основе хеш-таблицы. Быстрые `add`/`contains`/`remove` (`O(1)` в среднем), **порядок не гарантирован**. См. [[HashSet]].
- **`LinkedHashSet`** — как `HashSet`, но **сохраняет порядок вставки**.
- **`TreeSet`** — отсортированное множество на красно-чёрном дереве, операции за `O(log n)`. Полезен для диапазонов и упорядоченного обхода. См. [[TreeSet]].

## 3. Map (словарь, отображение)
Хранит пары «ключ → значение», ключи уникальны.

- **`HashMap`** — хеш-таблица. Быстрый доступ по ключу (`O(1)` в среднем), **порядок не гарантирован**. См. [[HashMap]], [[Как работает HashMap]].
- **`LinkedHashMap`** — сохраняет порядок вставки **или** порядок доступа (access-order) — база для LRU-кеша.
- **`TreeMap`** — на красно-чёрном дереве, сортирует по ключам, операции за `O(log n)`.

## 4. Queue (очередь)
- **`ArrayDeque`** — двусторонняя очередь (deque) на массиве. Добавление/удаление с обоих концов за `O(1)`. Современная замена `Stack` и `LinkedList` для ролей стека и очереди.
- **`PriorityQueue`** — очередь с приоритетами (на куче/heap). Элементы извлекаются по естественному порядку или по `Comparator`; `peek` — `O(1)`, `offer`/`poll` — `O(log n)`.

## 5. Stack (стек)
- **`Stack`** — классический стек на основе `Vector` (синхронизирован, устаревший). Чаще рекомендуют **`ArrayDeque`** как более быструю и современную альтернативу.

## Шпаргалка по сложности (Big-O)

| Коллекция | Доступ по индексу | Поиск / `contains` | Вставка/удаление | Порядок |
|---|---|---|---|---|
| `ArrayList` | `O(1)` | `O(n)` | конец `O(1)`*, середина `O(n)` | вставки |
| `LinkedList` | `O(n)` | `O(n)` | концы `O(1)`, середина `O(n)` | вставки |
| `HashSet` / `HashMap` | — | `O(1)` ср. / `O(log n)` худш. | `O(1)` ср. | нет |
| `LinkedHashSet` / `LinkedHashMap` | — | `O(1)` ср. | `O(1)` ср. | вставки / доступа |
| `TreeSet` / `TreeMap` | — | `O(log n)` | `O(log n)` | сортировка |
| `ArrayDeque` | — | `O(n)` | концы `O(1)` | вставки |
| `PriorityQueue` | — | `O(n)` | `offer`/`poll` `O(log n)` | по приоритету |

\* амортизированно: при переполнении массив пересоздаётся (`O(n)`), но в среднем — `O(1)`.

## Queue vs Stack

Обе — линейные структуры, но с разным порядком работы с элементами.

| Характеристика | Queue (очередь) | Stack (стек) |
|---|---|---|
| Принцип работы | **FIFO** — первый вошёл, первый вышел | **LIFO** — последний вошёл, первый вышел |
| Добавление | в конец (`enqueue` / `offer`) | наверх (`push`) |
| Удаление | с начала (`dequeue` / `poll`) | сверху (`pop`) |
| Аналогия | очередь в супермаркете | стопка тарелок |

**Когда что использовать:**

- **Queue** — обработка в порядке поступления (очередь задач, события), обход графа в ширину (**BFS**).
- **Stack** — обработка в обратном порядке (undo/отмена действий, стек вызовов), обход графа в глубину (**DFS**).

```kotlin
// Стек и очередь на ArrayDeque
val stack = ArrayDeque<Int>()
stack.addLast(1); stack.addLast(2)
stack.removeLast()   // 2 — LIFO

val queue = ArrayDeque<Int>()
queue.addLast(1); queue.addLast(2)
queue.removeFirst()  // 1 — FIFO
```
