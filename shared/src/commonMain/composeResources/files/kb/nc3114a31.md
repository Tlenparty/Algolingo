composed {} — это **аналог** remember {} **для** Modifier.

🔹 **Без** composed {}

Обычные Modifier **не пересоздаются** при recomposition (перерисовке UI).

🔹 **С** composed {}

Если нужно **создать** Modifier**, который может изменяться при recomposition**, используем composed {}.

> [!danger] Что чинить в этом коде (типичный набор проблем перформанса Compose)
> 1. **`remember { CoroutineScope(Dispatchers.Main) }`** — самодельный scope **не отменяется** вместе с композицией → утечка корутин. Нужно **`rememberCoroutineScope()`**: он привязан к жизненному циклу composable и отменяется автоматически.
> 2. **`sortedMessage.forEach { item { … } }`** — антипаттерн. Надо использовать DSL **`items(list, key = { it.id })`**. Без `forEach`-обёртки и, главное, **с `key`**: без ключей LazyColumn не может корректно диффить при вставке/перестановке → лишние рекомпозиции и потеря состояния элементов.
> 3. **`messages.sorted()` в композиции** — сортировка не место в UI-слое; делать её выше (в VM/UseCase) и передавать готовый список. `remember(messages)` лишь кэширует между рекомпозициями, но первая всё равно сортирует на каждом новом списке.
> 4. **`Message` нестабилен → `LocalDateTime`.** Compose считает класс stable, только если стабильны все поля. `java.time.LocalDateTime` компилятору неизвестен как stable → весь `Message` **unstable** → `Message()` не пропускается (skippable) даже при тех же данных. Решение — раскомментировать **`@Immutable`** (обещание неизменяемости) или хранить дату как примитив/обёртку.

> [!warning] `Modifier.composed {}` — устаревший и «тяжёлый» способ
> Формулировка «`composed` = `remember` для Modifier» неточна и вредна для перфоманса. `composed {}` **не мемоизируется и пересоздаётся на каждой рекомпозиции**, ломает skipping и пропуск рекомпозиции — поэтому Google его **не рекомендует**. Современный путь — `Modifier.Node` API (`Modifier.element { … }`) или обычная фабрика-extension без `composed`. Голые `Modifier` действительно не «оживают» при рекомпозиции — но это и хорошо.

> [!note] Затенение имени `Message`
> `@Composable fun Message(message: Message, …)` — composable-функция и `data class` называются одинаково. Компилируется, но читается плохо; на ревью стоит переименовать (например, `MessageItem`).
