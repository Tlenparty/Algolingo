В Jetpack Compose есть три специальных эффекта: **LaunchedEffect**, **DisposableEffect** и **SideEffect**. Они управляют побочными эффектами и помогают правильно работать с асинхронными задачами, подписками и изменениями состояния
### LaunchedEffect

**LaunchedEffect** — это Composable-функция для **запуска корутин в безопасном контексте Compose**. Помогает выполнять асинхронные операции: загрузку данных, задержки `delay()`, анимации, сетевые запросы.

**🔹 Как работает LaunchedEffect?**

- Запускает **новую корутину** в скоупе, привязанном к жизненному циклу композиции (на диспетчере применяющего потока — обычно `Main`).
- Если ключ (`key`) изменяется — старая корутина **отменяется**, запускается новая.
- Если Composable **удаляется** из композиции — корутина **отменяется**.

📌 **Простая схема работы:**
1. Компонент входит в композицию → LaunchedEffect запускает корутину.
2. Если ключ изменился → старая корутина отменяется, новая запускается.
3. Если Composable удален → корутина автоматически завершается.

```kotlin
LaunchedEffect(key1, key2, ...) {
    // Здесь выполняем асинхронную операцию
}
```

• key1, key2, ... — зависимости, при изменении которых корутина перезапускается.
• **Если ключ не указывать (**LaunchedEffect(Unit)**)**, корутина запускается только один раз.

**🔹 Примеры использования**
**✅ 1. Запуск асинхронной задачи при старте**

```kotlin
@Composable
fun TimerScreen() {
    LaunchedEffect(Unit) {
        delay(3000)
        println("Таймер сработал через 3 секунды")
    }
}
// Unit → гарантирует, что корутина запустится **только один раз**.
```

  **✅ 2. Перезапуск корутины при изменении параметра**
Если count изменится, то старая корутина **отменится**, и запустится новая.
```kotlin
@Composable
fun Counter(count: Int) {
    LaunchedEffect(count) {
        println("Новое значение: $count")
    }
}
// • Если count = 1, затем count = 2 → **предыдущий эффект отменяется**, новый запускается.
```

**✅ 3. Запрос в сеть (имитация)**

Асинхронная загрузка данных при первом появлении UI.
```kotlin
@Composable
fun LoadDataScreen() {
    var data by remember { mutableStateOf("Загрузка...") }

    LaunchedEffect(Unit) {
        data = fetchData() // Запрос данных (имитация)
    }

    Text(text = data)
}

// Имитация сетевого запроса
suspend fun fetchData(): String {
    delay(2000) // Задержка 2 сек
    return "Данные загружены!"
}
```

**✅ 4. Анимация с LaunchedEffect**

Можно использовать LaunchedEffect для управления анимацией.

```kotlin
@Composable
fun AnimatedProgress(targetValue: Float) {
    var progress by remember { mutableStateOf(0f) }

    LaunchedEffect(targetValue) {
        while (progress < targetValue) {
            delay(100)
            progress += 0.1f
        }
    }

    LinearProgressIndicator(progress = progress)
}
//Здесь прогресс будет **плавно увеличиваться** до targetValue.
```

**❌ Когда не использовать LaunchedEffect?**

🔴 **Для управления ресурсами (подписки, слушатели, BroadcastReceiver)**
➡ Используйте DisposableEffect, так как он **гарантирует очистку ресурсов**.

🔴 **Для обновления внешних состояний (например,** ViewModel **из Composable)**
➡ Используйте SideEffect, так как он выполняется при каждой перерисовке.

### **2. DisposableEffect: Подписки и освобождение ресурсов**

Он полезен для управления **ресурсами, подписками, слушателями и таймерами**.

**Как работает:**
**🔹 Как работает DisposableEffect?**

1. **Запускается** при появлении **Composable**.
2. **Выполняет код в** onDispose перед удалением Composable.
3. **Перезапускается**, если изменяется его **ключ (**key**)**.
4. **Гарантированно очищает ресурсы** при выходе из композиции.

Синтаксис 
```kotlin
DisposableEffect(key1, key2, ...) {
    // Код выполняется при входе в композицию

    onDispose {
        // Код выполняется при выходе из композиции (очистка)
    }
}
/**• **Если** key **изменится**, onDispose вызовется перед запуском нового эффекта.

• Если ключ **не указывать**, эффект выполняется **один раз** и очищается при удалении Composable.
**/
```

**Пример:**

```kotlin
@Composable
fun SensorListener(sensor: Sensor) {
    DisposableEffect(sensor) {
        sensor.registerListener()
        onDispose {
            sensor.unregisterListener()
        }
    }
}
//**Когда использовать?**

✅ Подключение и отключение слушателей.

✅ Регистрация и очистка ресурсов.
```

**🔹 Когда использовать DisposableEffect?**

✅ **Для подписки на ресурсы** (например, BroadcastReceiver, GPS, сенсоры)
✅ **Для регистрации и удаления слушателей**
✅ **Для управления ресурсами (например, WebSocket, таймеры, камеры)**
✅ **Для выполнения кода при входе и выходе из композиции**

**🔹 Примеры использования**

**✅ 1. Регистрация слушателя при входе в композицию и его удаление при выходе**
```kotlin
@Composable
fun SensorListener(sensor: Sensor) {
    DisposableEffect(sensor) {
        sensor.registerListener() // Подписка

        onDispose {
            sensor.unregisterListener() // Отписка
        }
    }
}
//📌 **Как работает?**
//• **При входе в композицию** регистрируем слушатель.
//• **При удалении Composable** отписываемся, чтобы избежать утечек памяти.
```

**✅ 3. Запуск и остановка таймера**
```kotlin
@Composable
fun Timer(onTick: () -> Unit) {
    DisposableEffect(Unit) {
        val timer = Timer()
        timer.scheduleAtFixedRate(object : TimerTask() {
            override fun run() {
                onTick()
            }
        }, 0, 1000)

        onDispose {
            timer.cancel() // Остановка таймера при удалении Composable
        }
    }
}
// 📌 **Без** onDispose**, таймер продолжал бы работать даже после удаления UI**, что могло бы вызвать утечки памяти.
```

**✅ 4. Работа с MediaPlayer**
```kotlin
@Composable
fun MusicPlayer(context: Context, musicResId: Int) {
    DisposableEffect(musicResId) {
        val mediaPlayer = MediaPlayer.create(context, musicResId)
        mediaPlayer.start()

        onDispose {
            mediaPlayer.release() // Освобождаем ресурсы при выходе из композиции
        }
    }
}
// 📌 **Если не освободить** MediaPlayer**, он может продолжать играть после выхода из экрана!**
```

> DisposableEffect - вызывает onDispose , когда вот вот изменится, и вызвается onDispose перед.
> А если он без ключей, то при смерти Compose функции

### **3. SideEffect: Для небезопасных изменений состояния**

**📌 SideEffect — это эффект в Jetpack Compose, который используется для выполнения кода, изменяющего внешнее состояние (то есть состояние вне Compose).**

**Используется для:** обновления состояния, которое не влияет на композицию, но не должно теряться при перерисовках.

**🔹 Как работает SideEffect?**

1. **Выполняется при каждой перерисовке (recomposition).**
2. **Гарантирует, что код выполняется только в одном потоке UI.**
3. **Используется для обновления состояний, которые не зависят от композиции.**

> SideEffect **никогда не отменяется** и **не перезапускается** в отличие от LaunchedEffect.

> SideEffect при каждой рекомпозиции. Вцелом так же можно использовать как и обычную функцию в рамках Composable функции, но сама функция может вызывать не только после рекомпозиции


**🔹 Когда использовать SideEffect?**

✅ **Для обновления внешнего состояния (например,** ViewModel**,** LiveData**)**
✅ **Для логирования или аналитики**
✅ **Для взаимодействия с кодом вне Compose** (например, Toast, Snackbar, SharedPreferences)
✅ **Для отправки событий во ViewModel**

❌ **Не использовать для корутин** → Вместо этого использовать LaunchedEffect.
❌ **Не использовать для подписок** → Использовать DisposableEffect.

```kotlin
SideEffect {
    // Код, который должен выполняться при каждой перерисовке
}
```

```kotlin
@Composable
fun LogScreen(state: String) {
    SideEffect {
        println("State updated: $state") // Логирование состояния
    }
}
```

**Примеры использования**

**✅ 1. Обновление состояния во ViewModel**

```kotlin
@Composable
fun MyScreen(viewModel: MyViewModel, count: Int) {
    SideEffect {
        viewModel.updateCount(count) // Отправляем обновленные данные во ViewModel
    }
}
```

## **🔥 produceState и derivedStateOf в Jetpack Compose**

**🔹 Что делает?**

• Позволяет **производить состояние** ``(State<T>)`` **асинхронно** (например, загружая данные).
• Использует **корутины** внутри.
• **Перезапускается** при изменении входных параметров.

**🔹 Как работает?**
1. **Создает** State и автоматически обновляет его в produceState { }.
2. Если **ключи изменяются**, старая корутина отменяется и запускается новая.
3. Под капотом использует remember **+** LaunchedEffect.

**✅ Пример 1: загрузка данных с API**

```kotlin
@Composable
fun UserProfileScreen(userId: String): State<User?> {
    val userState = produceState<User?>(initialValue = null, userId) {
        value = fetchUser(userId) // Асинхронная загрузка
    }
    return userState
}
```

• produceState создаёт ``State<User?>``.
• fetchUser(userId) вызывается **асинхронно** при первом запуске.
• Если userId изменится, **старый запрос отменится**, и начнется новый.

**✅ Пример 2: обратный отсчет (таймер)**

```kotlin
@Composable
fun CountdownTimer(seconds: Int): State<Int> {
    return produceState(initialValue = seconds) {
        for (time in seconds downTo 0) {
            delay(1000)
            value = time
        }
    }
}
// 📌 **Каждую секунду состояние** value **обновляется, уменьшаясь на 1**.
```

**🔍 Как produceState работает под капотом?**
```kotlin
@Composable
fun <T> produceState(
    initialValue: T,
    vararg keys: Any?,
    producer: suspend ProduceStateScope<T>.() -> Unit
): State<T> {
    val state = remember { mutableStateOf(initialValue) }
    LaunchedEffect(*keys) { // Автоматически перезапускает корутину при изменении ключей
        producer(ProduceStateScope(state))
    }
    return state
}
```

📌 **Под капотом**:

• Использует remember { mutableStateOf(initialValue) } для хранения состояния.
• Запускает **корутину внутри** LaunchedEffect для обновления состояния.
• При изменении ключей (**keys**) старая корутина отменяется и запускается новая.

Когда использовать?? 
✅ Когда нужна **перезапускаемая корутина** внутри Composable. 

### **📌 2. derivedStateOf — вычисляемое состояние**

• Позволяет **создавать зависимое (вычисляемое) состояние** на основе другого State.
• **Оптимизирует recomposition** → вычисляет новое значение **только при изменении зависимых данных**.
• Работает **сразу**, без suspend.

**✅ Пример 1: отфильтрованный список**

```kotlin
@Composable
fun FilteredList(searchQuery: String, items: List<String>): List<String> {
    val filteredItems by remember(searchQuery, items) {
        derivedStateOf { 
            items.filter { it.contains(searchQuery, ignoreCase = true) }
        }
    }
    return filteredItems
}
```

📌 **Как работает?**
• filteredItems обновляется **только при изменении** searchQuery **или** items.
• Если searchQuery не изменяется → **не будет лишних перерисовок!** 🚀

**🔍 Как derivedStateOf работает под капотом?**

```kotlin
fun <T> derivedStateOf(calculation: () -> T): State<T> {
    return object : State<T> {
        private var lastValue: T = calculation()
        override val value: T
            get() {
                val newValue = calculation()
                if (newValue != lastValue) {
                    lastValue = newValue
                }
                return lastValue
            }
    }
}
```

📌 **Оптимизация:**
• **Кэширует последнее значение.**
• Вычисляет новое значение **только если входные данные изменились**.
• Используется внутри remember { derivedStateOf { ... } }, чтобы сохранить ссылку.
**✅ Когда использовать derivedStateOf?**
✅ **Когда нужно пересчитывать значение только при изменении входных данных.**
✅ **Для производительности**, чтобы избежать лишних recomposition.
✅ **Для мемоизации сложных вычислений** (например, фильтрация списка).

### Пример со скроллом и derivedStateOf

Типичный кейс: показать кнопку «вверх», когда список прокручен. Без `derivedStateOf` чтение `firstVisibleItemIndex` будет триггерить рекомпозицию на **каждый пиксель** скролла. С `derivedStateOf` значение пересчитывается на каждый скролл, но **новое состояние эмитится только когда меняется результат лямбды** (`false → true`):

```kotlin
val showButton by remember {
    derivedStateOf { listState.firstVisibleItemIndex > 0 }
}
```

То есть рекомпозиция произойдёт только в момент пересечения порога, а не на каждый «чих» скролла.

> [!tip] Все эффекты на одном экране — что выбрать
> | Хочу...                                              | Эффект                                  |
> | --------------------------------------------------- | --------------------------------------- |
> | запустить suspend-работу при входе / смене ключа    | **LaunchedEffect**                      |
> | подписаться и обязательно отписаться (listener, GPS)| **DisposableEffect** (`onDispose`)      |
> | синхронизировать состояние Compose с не-Compose     | **SideEffect** (каждая рекомпозиция)    |
> | запустить корутину по событию (клик)                | **rememberCoroutineScope** + `scope.launch` |
> | произвести `State<T>` асинхронно                    | **produceState**                        |
> | вычислить производное состояние без лишних рекомпозиций | **derivedStateOf**                  |
> | использовать «свежее» значение в долгой корутине без её перезапуска | **rememberUpdatedState**  |
>
> Ключевое отличие **LaunchedEffect vs rememberCoroutineScope**: первый запускается сам при входе в композицию (реакция на состояние), второй — для запуска корутин из колбэков (реакция на событие пользователя).
