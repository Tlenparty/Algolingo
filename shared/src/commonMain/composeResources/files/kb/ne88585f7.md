# Как работает HashMap

`HashMap` — структура данных на основе **массива бакетов** (корзин) и **цепочек** (связных списков / деревьев) для разрешения коллизий. Базовые свойства и примеры — в [[HashMap]]; здесь разбираем механику изнутри.

> **На собес одной фразой:** ключ → `hashCode()` → перемешивание бита → индекс бакета через `(n-1) & hash` → в бакете поиск по `equals()`; при 8+ коллизиях и таблице ≥64 список превращается в красно-чёрное дерево.

---

## Принцип работы

1. **Хеширование.** Ключ проходит через `hashCode()` → int. Из него вычисляется индекс во внутреннем массиве.
2. **Хеш-таблица.** Пары ключ-значение лежат в массиве; индекс соответствует (нормализованному) хешу ключа.
3. **Решение коллизий.** Если разные ключи дают один индекс, они кладутся в один бакет: связным списком, а при большом числе — красно-чёрным деревом (Java 8+).
4. **Вставка:** вычислить хеш → выбрать бакет → проверить коллизии → добавить в список/дерево.
5. **Поиск:** вычислить хеш → выбрать бакет → искать по списку/дереву через `equals()`.
6. **Удаление:** по тому же принципу — хеш → бакет → поиск → удаление.

---

## Шаги вычисления бакета

### 1. Хеш-код ключа
Вызывается `hashCode()` ключа — возвращает int (может быть отрицательным).

### 2. Дополнительное перемешивание хеша
Чтобы ключи равномернее распределялись по бакетам, `HashMap` домешивает старшие биты к младшим (в Java 8 — сдвиг + XOR). Это снижает число коллизий на маленьких таблицах.

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

### 3. Индекс бакета
Индекс = `(размер_массива - 1) & hash`. Так как размер массива — степень двойки, `AND` эквивалентен остатку от деления, но быстрее.

```kotlin
val bucketIndex = (table.size - 1) and hash   // table.size — степень двойки (16, 32, 64...)
```

Эквивалент через остаток от деления (для наглядности):

```kotlin
val bucketIndex = (hashCode % numberOfBuckets + numberOfBuckets) % numberOfBuckets
```

### Пример
```kotlin
val key = "apple"
val hashCode = key.hashCode()          // напр. 93029210
val bucketIndex = (16 - 1) and hashCode // (15) and 93029210 -> напр. 10
```
`bucketIndex` (0..15 при массиве 16) указывает на корзину, куда попадёт элемент.

### Почему `AND`, а не `%`
`(n - 1) & hash` работает только когда `n` — степень двойки, и в этом случае даёт тот же результат, что `% n`, но быстрее (побитовая операция дешевле деления). Отсюда же требование, чтобы ёмкость `HashMap` всегда была степенью двойки.

## Обработка коллизий

Коллизия — когда два разных ключа указывают на один бакет (совпал хеш или совпал индекс после `AND`). Механизмы:

1. **Связные списки** — ранние версии (до Java 8).
2. **Красно-чёрные деревья** — с Java 8.
3. **Перехеширование (rehashing / resize)** — при заполнении таблицы сверх `load factor` (по умолчанию 0.75) массив увеличивается вдвое, и элементы перераспределяются.

### 1. Связные списки (до Java 8)
Ключи из одного бакета связываются в список: бакет хранит ссылку на первый узел, каждый узел — `ключ + значение + ссылку на следующий`.

**Проблема:** при многих коллизиях длина списка растёт, поиск/вставка деградируют до `O(n)`.

### 2. Красно-чёрные деревья (с Java 8)
Если в одном бакете накопилось много элементов, список превращается в сбалансированное дерево — поиск/вставка/удаление ускоряются до `O(log n)`.

**Пороги (гистерезис не даёт структуре «дёргаться» на границе):**
1. Список → дерево (**treeify**): в бакете `≥ 8` элементов **И** размер таблицы `≥ 64`. Если корзин меньше 64 — сначала делается `resize()` (это часто само разносит коллизии).
2. Дерево → список (**untreeify**): при удалении, когда в бакете становится `≤ 6` элементов.

| Структура бакета | Поиск / вставка |
|---|---|
| Связный список | `O(n)` |
| Красно-чёрное дерево | `O(log n)` |
