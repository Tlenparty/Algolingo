**1️⃣ Деструктурируемые классы с operator fun componentN()**

Любой **обычный класс** может поддерживать деструктурирование, если вручную определить методы componentN():

```kotlin
class Person(val name: String, val age: Int) {
    operator fun component1() = name
    operator fun component2() = age
}

fun main() {
    val person = Person("Alice", 25)
    val (name, age) = person // Деструктурирование
    println("$name, $age") // Alice, 25
}
```

**2️⃣ Pair и Triple**

Kotlin из коробки поддерживает деструктурирование Pair и Triple, потому что у них уже есть componentN():
```kotlin
fun main() {
    val pair = "Hello" to 42
    val (word, number) = pair
    println("$word, $number") // Hello, 42

    val triple = Triple("A", "B", "C")
    val (first, second, third) = triple
    println("$first, $second, $third") // A, B, C
}
//✅ Pair **(component1, component2)** и Triple **(component1, component2, component3)** работают сразу.
```

**3️⃣ Деструктурирование коллекций (List, Map)**

**✅ Списки (List)**

List поддерживает деструктурирование **первых пяти элементов** через componentN():
```kotlin
fun main() {
    val list = listOf("Kotlin", "Java", "C++")
    val (first, second, third) = list
    println("$first, $second, $third") // Kotlin, Java, C++
}
```

✅ В List есть component1(), component2(), component3(), …, component5(). Больше 5 элементов деструктурировать нельзя без get().

**✅ Map.Entry**

Для Map можно деструктурировать ключ и значение:
```kotlin
fun main() {
    val map = mapOf("Alice" to 25, "Bob" to 30)

    for ((name, age) in map) {
        println("$name: $age")
    }
}
```
✅ Map.Entry имеет component1() (ключ) и component2() (значение).

**🚀 Итог:**

✅ **Поддерживают** componentN() **и деструктурирование**:

1. data class (по умолчанию).
2. **Обычные классы**, если вручную добавить operator fun componentN().
3. Pair **и** Triple (из коробки).
4. **Списки (**List**)** (до 5 элементов).
5. Map.Entry (ключ и значение).

> [!warning] Деструктуризация позиционна, а не по имени
> При `val (name, age) = person` Kotlin сопоставляет переменные с `component1()`, `component2()` **по порядку**, а не по именам. То есть `val (age, name) = person` молча присвоит `age = person.name`! Имена переменных значения не имеют — важен только порядок объявления свойств в первичном конструкторе.
>
> Поэтому деструктуризацию `data class` с однотипными полями (`val (x, y) = point`) используют осторожно: добавление/перестановка полей тихо ломает места деструктуризации. Ненужные компоненты можно пропустить через `_`: `val (_, age) = person`.
