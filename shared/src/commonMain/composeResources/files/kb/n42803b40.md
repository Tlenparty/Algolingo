**1️⃣ BuildType (Тип сборки)**

Определяет, **как** будет собираться приложение (например, с дебажными логами или с оптимизацией).

**📌 Обычные BuildType в Android:**
```groovy
android {
    buildTypes {
        debug {
            applicationIdSuffix ".debug" // Уникальный ID для Debug
            debuggable true // Включает отладку
        }
        release {
            minifyEnabled true // Включает ProGuard для уменьшения размера APK
            shrinkResources true // Удаляет неиспользуемые ресурсы
            signingConfig signingConfigs.release // Подписывает APK
        }
    }
}
```

🔹 debug → используется во время разработки, поддерживает отладку.
🔹 release → оптимизированная версия для продакшена, включает ProGuard и обфускацию.

💡 **Можно создать дополнительные типы сборок (например, “staging”)**:
```groovy
buildTypes {
    staging {
        applicationIdSuffix ".staging"
        initWith(buildTypes.debug) // Наследует настройки debug
        matchingFallbacks = ['debug'] // Если staging нет, используется debug
    }
}
```

**2️⃣ BuildFlavor (Варианты сборки)**

Определяет **разные версии одного и того же приложения**.

**📌 Примеры использования:**

1. Бесплатная и платная версия приложения (free vs paid).
2. Разные серверные окружения (dev vs prod).
3. Разные клиенты (google vs huawei).

```groovy
android {
    flavorDimensions "version"

    productFlavors {
        free {
            dimension "version"
            applicationIdSuffix ".free"
            versionNameSuffix "-free"
        }
        paid {
            dimension "version"
            applicationIdSuffix ".paid"
            versionNameSuffix "-paid"
        }
    }
}
```

```groovy
src/
 ├── main/ (общие файлы)
 ├── free/ (уникальные файлы для free)
 ├── paid/ (уникальные файлы для paid)
```

**3️⃣ BuildVariant (Вариант сборки)**

BuildVariant = BuildType + BuildFlavor

👉 Он формируется автоматически, комбинируя BuildType и BuildFlavor.

**🔹 Как переключаться между BuildVariant?**

• В **Android Studio** → Build → Select Build Variant

• В **Gradle CLI**:
```groovy
./gradlew assembleFreeDebug   # Соберёт freeDebug APK
./gradlew assemblePaidRelease # Соберёт paidRelease APK
```


### **📌 Как в Android сделать две сборки для разных устройств?**

Если нужно создать **разные версии приложения** (например, для **телефонов и планшетов** или **разных брендов устройств**), лучше всего использовать **Build Types** или **Product Flavors** в Gradle.

### **🔹 1. Build Types – для отладки и релиза**

📌 **Когда использовать?**

• Если **различия только в настройках сборки** (например, debug и release).
• Если **нет сильных различий в коде и ресурсах**.

**Пример build.gradle.kts с разными API URL для debug и release**

```kotlin
android {
    buildTypes {
        debug {
            applicationIdSuffix ".debug"
            buildConfigField("String", "API_URL", "\"https://dev.api.com\"")
        }
        release {
            minifyEnabled true
            buildConfigField("String", "API_URL", "\"https://prod.api.com\"")
        }
    }
}
```

📌 **Как использовать в коде?**

```kotlin
val apiUrl = BuildConfig.API_URL // В зависимости от типа сборки подставится нужный URL
```

### **🔹 2. Product Flavors – для разных устройств или версий**

📌 **Когда использовать?**

• Если **различается код или ресурсы** (например, одна версия для **телефонов**, другая для **планшетов**).

• Если приложение **бесплатное и платное** (free и pro).

**Пример build.gradle.kts с разными версиями для телефонов и планшетов**

```kotlin
android {
    flavorDimensions += "device"

    productFlavors {
        create("phone") {
            dimension = "device"
            applicationIdSuffix = ".phone"
            resValue("string", "app_name", "MyApp Phone")
        }
        create("tablet") {
            dimension = "device"
            applicationIdSuffix = ".tablet"
            resValue("string", "app_name", "MyApp Tablet")
        }
    }
}
```

📌 **Как использовать в коде?**

```kotlin
val deviceType = BuildConfig.FLAVOR // Вернет "phone" или "tablet"
```

**📌 Разные ресурсы (res/values) для phone и tablet**

📂 src/phone/res/values/strings.xml

```xml
<resources>
    <string name="app_name">MyApp Phone</string>
</resources>
```

📂 src/tablet/res/values/strings.xml
```xml
<resources>
    <string name="app_name">MyApp Tablet</string>
</resources>
```

✅ **Когда использовать Product Flavors?**

• Если надо **изменять код, ресурсы или ID приложения**.
• Если надо делать **разные версии приложения (free/pro, phone/tablet, Huawei/Google Play)**.

❌ **Минусы:**

• Увеличивает сложность сборки.

> [!tip] Нюансы на собесе
> - **BuildVariant = BuildType × Flavor** (декартово произведение). При 2 типах и 2 флейворах — 4 варианта (`freeDebug`, `freePaid`, `paidDebug`, `paidRelease`).
> - **`buildConfigField` и `BuildConfig`** в новом AGP (8.0+) требуют включить `buildFeatures { buildConfig = true }` — по умолчанию генерация `BuildConfig` отключена.
> - **`flavorDimensions`** обязателен, если флейворов больше одного измерения (например, `device` × `environment`).
> - **Где переопределять:** код/ресурсы кладут в `src/<flavor>/` и `src/<buildType>/` — Gradle мёржит их поверх `src/main/`.
> - `minifyEnabled`/`shrinkResources` (R8) обычно только в `release`; для отладки выключены ради скорости сборки.
