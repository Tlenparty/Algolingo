# Главный поток (UI Thread / Main Thread)

**Главный поток** — единственный поток в Android, из которого можно трогать UI (создавать/менять `View`, вызывать composable-обновления). Его также называют **UI thread** или **Main thread**. Через него же проходит цикл событий (`Looper`), обрабатывающий ввод, отрисовку и колбэки.

> **На собес одной фразой:** UI можно менять только с главного потока; тяжёлую работу уводим в фон, а результат возвращаем на главный. Долгая работа на главном потоке = фриз UI и ANR.

## Почему UI только с главного потока

Android UI-тулкит **не потокобезопасен**: если несколько потоков будут менять `View` одновременно — [[Гонка данных|гонки данных]] и несогласованное состояние экрана. Поэтому доступ к UI ограничен одним потоком (thread confinement). Обращение к `View` из фонового потока → `CalledFromWrongThreadException`.

## Правило двух пунктов

1. **Не блокировать** главный поток — никаких сети, БД, тяжёлых вычислений на нём. Кадр должен рендериться за ~16 мс (60 fps); долгая работа → пропуск кадров (jank), а блокировка на 5+ секунд → **ANR** (Application Not Responding).
2. **Не трогать UI из фона** — обновление интерфейса только на главном потоке.

Типичный паттерн: «тяжёлое — в фон, результат — на главный».

```kotlin
// Корутины (современный способ)
viewModelScope.launch {
    val data = withContext(Dispatchers.IO) {   // фоновый поток: сеть/БД
        repository.load()
    }
    // снова на главном потоке (Dispatchers.Main по умолчанию в viewModelScope)
    _uiState.value = data                       // безопасно обновляем состояние UI
}
```

Как «вернуться» на главный поток разными способами:
```kotlin
withContext(Dispatchers.Main) { /* обновить UI */ }   // корутины
Handler(Looper.getMainLooper()).post { /* ... */ }     // классика на Handler
view.post { /* ... */ }                                 // из самого View
runOnUiThread { /* ... */ }                             // из Activity
```
