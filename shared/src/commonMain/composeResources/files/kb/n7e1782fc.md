### Как работает remember в Compose под капотом ?

 **Jetpack Compose** remember — это вспомогательная функция, которая используется для хранения состояния внутри композиции. Она сохраняет значение на время жизни **composition** и пересоздаёт его только в случае рекомпозиции, если входные параметры изменились.
```kotlin
@Composable
fun <T> remember(calculation: () -> T): T {
    val composition = currentComposition() // Получаем текущее `Composition`
    return composition.remember(calculation) // Сохраняем значение в Composition Storage
}
```

• currentComposition() — это **текущее дерево Compose**.
• composition.remember(calculation) — сохраняет значение в специальном хранилище.
### **Что происходит во время рекомпозиции?**

1. **При первой композиции**

• remember {} выполняется и **сохраняет значение** в специальном хранилище.
• Хранилище связано с Composition.

2. **При рекомпозиции**

• remember {} **не выполняет лямбду заново**.
• Возвращается **ранее сохранённое значение**.

3. **Если** remember {} **вызывается в новом** Composable **(например,** if **убрал компонент)**

• Хранилище **очищается**, и при следующей композиции значение **будет создано заново**.

**🔍 Как работает remember под капотом?**

1. **Запоминает значение на время жизни composition**

• remember {} использует механизм ==**Composition Local Storage**== внутри **Compose runtime**. (внутренний механизм хранения данных во время композиции). [[Compose. Composition Local]]

2. **Переживает рекомпозицию (recomposition)**

• Если **composition** остаётся активной (например, изменились не связанные с этим значением параметры UI), то remember просто возвращает сохранённое значение.

• Это предотвращает повторные вычисления и улучшает производительность.

3. **Сбрасывается при уничтожении composition**

• Если composable выходит из UI-дерева (например, из-за смены экрана или удаления компонента), то хранимое значение теряется.
• При повторном появлении в UI remember снова создаёт значение с нуля.

**🔹 Внутренний механизм работы remember**

• Внутри remember использует Composition.saveable() для сохранения состояния внутри композиции.

• При рекомпозиции Jetpack Compose пытается использовать **ранее сохранённые объекты**.

• Если объект не может быть восстановлен (например, composable был удалён и снова добавлен), он пересоздаётся.

```kotlin
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) } // count сохраняется при рекомпозиции
    Button(onClick = { count++ }) {
        Text("Clicked $count times")
    }
}
```


**🔧 Под капотом: Код remember**

Если посмотреть в исходный код Compose, то remember реализован примерно так:
```kotlin
@Composable
fun <T> remember(vararg keys: Any?, calculation: () -> T): T {
    val scope = currentComposer
    return scope.cache(false, keys, calculation)
}
```

- `keys` — если они изменятся, состояние пересоздастся.
- `calculation` — функция, результат которой запоминается.
- `currentComposer.cache(...)` — механизм хранения данных внутри **Composer**.
### **Отличие remember от rememberSaveable**

rememberSaveable — это расширенная версия remember, которая не только сохраняет значение при рекомпозиции, но и переживает **смену конфигурации (например, поворот экрана)** или даже **убийство процесса**.

**🔹 Как rememberSaveable работает под капотом?**

• Использует Bundle (стандартный механизм Android) для сохранения данных при изменении конфигурации.
• Использует Saver, если значение **не поддерживается Bundle**.
• При восстановлении проверяет, можно ли загрузить данные из SavedStateHandle или ViewModel.

**✅ Простой пример использования**

```kotlin
@Composable
fun Counter() {
    var count by rememberSaveable { mutableStateOf(0) } // Значение сохранится при повороте экрана
    Button(onClick = { count++ }) {
        Text("Clicked $count times")
    }
}
```

**🔎 Что здесь происходит?**

1. `rememberSaveable` сохраняет `mutableStateOf(0)`.
2. При изменении конфигурации (например, поворот экрана) Compose восстанавливает сохранённое значение.
3. Если бы использовали просто `remember`, `count` сбрасывался бы при пересоздании Activity.

 **Как rememberSaveable сохраняет данные?**

Если значение **может быть сохранено в** Bundle (например, Int, String, Boolean), то rememberSaveable использует Bundle напрямую.

Если значение **сложное** (например, кастомные классы или объекты), используется Saver.


**1️⃣ Использование rememberSaveable с объектами, поддерживаемыми Bundle**
```kotlin
var text by rememberSaveable { mutableStateOf("Hello") } // String автоматически сохраняется
```

**2️⃣ Использование Saver для кастомных объектов**

Если у вас сложный объект (например, data class), он не может быть автоматически сохранён. Нужно использовать Saver.
```kotlin

data class User(val name: String, val age: Int)

val UserSaver = listSaver<User, Any>(
    save = { listOf(it.name, it.age) }, // Преобразуем в список простых значений
    restore = { User(it[0] as String, it[1] as Int) } // Восстанавливаем объект
)

@Composable
fun UserProfile() {
    var user by rememberSaveable(stateSaver = UserSaver) {
        mutableStateOf(User("Alice", 25))
    }
    Text(text = "User: ${user.name}, Age: ${user.age}")
}
```

**🔧 Код rememberSaveable под капотом**

Если посмотреть в исходный код Compose, rememberSaveable реализован так:

```kotlin
@Composable
fun <T> rememberSaveable(
    vararg keys: Any?,
    saver: Saver<T, out Any> = autoSaver(),
    init: () -> T
): T {
    return rememberSaveableStateHolder().rememberSaveable(*keys, saver = saver, init = init)
}
```

• autoSaver() – автоматически выбирает Bundle или Saver.

• **Использует** rememberSaveableStateHolder() – это механизм хранения состояния внутри SavedStateRegistry.

> [!tip] remember vs rememberSaveable — на собесе
> - `remember` живёт, пока composable в дереве; **сбрасывается при повороте экрана** (пересоздание Activity).
> - `rememberSaveable` переживает смену конфигурации и смерть процесса (через `Bundle`/`Saver`), но хранить можно только сериализуемое.
> - Частая ошибка — **ключи**: `remember(key) { ... }` пересоздаёт значение при изменении `key`. Если забыть ключ, значение «залипнет» на старом параметре (например, грузим данные не для того id).
> - Где хранить состояние: эфемерное UI-состояние (раскрыт ли элемент) — `remember`/`rememberSaveable`; бизнес-состояние экрана — в `ViewModel`.
