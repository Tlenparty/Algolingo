# Задача от Яндекс со станциями

## Условие

Дан **отсортированный** массив координат заправок `gasStations`. Машина стоит
у заправки с индексом `carIndex`. Нужно вернуть `k` **ближайших** к машине
заправок (по расстоянию вдоль прямой).

Это классика — «k ближайших элементов» (LeetCode 658, *Find K Closest Elements*),
завёрнутая в историю про заправки.

Пример:
```
gasStations = [1, 3, 6, 8, 9, 11]
carIndex    = 2   → машина в точке 6
k           = 3
```

Расстояния от точки 6: `1→5, 3→3, 8→2, 9→3, 11→5`.
Три ближайших: `8` (2), `3` (3), `9` (3) → ожидаемый ответ `[8, 3, 9]`.

---

## Исходный вариант (с багом)

```kotlin
fun main() {
     val gasStations = arrayOf(1, 3, 6, 8, 9, 11)
    //                              v
    val carIndex = 2
    val k = 3
    var currentCursorIndex = carIndex
    val nearestGasStations = mutableListOf<Int>()

    repeat(k) {
        if (gasStations[currentCursorIndex] - gasStations[currentCursorIndex - 1] < gasStations[currentCursorIndex + 1] - gasStations[currentCursorIndex]) {
            nearestGasStations.add(gasStations[currentCursorIndex - 1])
            currentCursorIndex--
        } else {
            nearestGasStations.add(gasStations[currentCursorIndex + 1])
            currentCursorIndex++
        }
    }

    println(nearestGasStations)
}
```

### Почему он неверный

Идея правильная — двигаться от машины к краям, выбирая более близкого соседа.
Но используется **один бегающий курсор**, и сравнение идёт относительно *текущего
положения курсора*, а не относительно машины.

Прогон:

| Шаг | курсор | сравнение `лев < прав`   | взяли          | nearest      |
|-----|--------|--------------------------|----------------|--------------|
| 1   | 2 (6)  | (6-3)=3 < (8-6)=2? нет    | `8`, курсор→3  | [8]          |
| 2   | 3 (8)  | (8-6)=2 < (9-8)=1? нет    | `9`, курсор→4  | [8, 9]       |
| 3   | 4 (9)  | (9-8)=1 < (11-9)=2? да    | `8`, курсор→3  | [8, 9, **8**]|

Результат: `[8, 9, 8]` — дубликат `8`, станцию `3` не рассмотрели.

Две принципиальные ошибки:
1. **Точка отсчёта «уезжает».** После шага курсор стоит на `8`, и расстояния
   меряются от `8`, а не от машины (`6`) → курсор разворачивается и берёт уже
   посещённую станцию.
2. **Нет проверки границ.** Как только курсор дойдёт до края
   (`currentCursorIndex - 1 < 0` или `+ 1 > lastIndex`) — `IndexOutOfBoundsException`.

## Правильное решение — два указателя

Ключ: **зафиксировать точку машины** и держать **два независимых указателя**
`left` и `right`, которые расходятся только наружу.

### Алгоритм по шагам
1. Запоминаем позицию машины `carPos = gasStations[carIndex]`.
2. Ставим `left = carIndex - 1`, `right = carIndex + 1` (соседи машины).
3. Повторяем `k` раз:
   - если `left` вышел за левый край → берём `right`, `right++`;
   - иначе если `right` вышел за правый край → берём `left`, `left--`;
   - иначе сравниваем расстояния `carPos - gasStations[left]` и
     `gasStations[right] - carPos`:
     - правый **строго ближе** → берём `right`, `right++`;
     - иначе (левый ближе или равны) → берём `left`, `left--`.
4. Возвращаем накопленный список.

```kotlin
fun nearestGasStations(gasStations: IntArray, carIndex: Int, k: Int): List<Int> {
    val carPos = gasStations[carIndex]
    var left = carIndex - 1
    var right = carIndex + 1
    val result = mutableListOf<Int>()

    repeat(k) {
        val takeRight = when {
            left < 0 -> true                          // слева больше нет станций
            right > gasStations.lastIndex -> false    // справа больше нет станций
            // правый строго ближе → берём правый; при равенстве предпочитаем левый
            else -> gasStations[right] - carPos < carPos - gasStations[left]
        }
        if (takeRight) {
            result.add(gasStations[right]); right++
        } else {
            result.add(gasStations[left]); left--
        }
    }
    return result
}

fun main() {
    val gasStations = intArrayOf(1, 3, 6, 8, 9, 11)
    println(nearestGasStations(gasStations, carIndex = 2, k = 3)) // [8, 3, 9]
}
```

### Прогон на примере
```
carPos = 6, left = 1 (3), right = 3 (8)
шаг 1: |8-6|=2 < |6-3|=3 → правый ближе → 8,  right→4
шаг 2: left 3 (d3), right 9 (d3) → равны → предпочитаем левый → 3, left→0
шаг 3: left 1 (d5), right 9 (d3) → правый ближе → 9, right→5
→ [8, 3, 9]
```

### Сложность
- **Время:** `O(k)` — ровно `k` шагов, на каждом константная работа
  (массив уже отсортирован).
- **Память:** `O(k)` на результат.

## Сигналы / шпаргалка к собесу

- **Почему два указателя, а не сортировка по расстоянию?** Массив отсортирован
  по координате → ближайшие к машине лежат «вокруг» неё, расходимся за `O(k)`
  вместо `O(n log n)`.
- **Сигнал к двум указателям:** *отсортированный массив* + *«ближайшие / пара /
  окно вокруг точки»*. См. `Задача на 2 указателя.md`, `01 Ключи и сигналы.md`.
- **Крайние случаи:** машина у самого края массива; `k` больше числа станций по
  одну сторону; `k = 0`; дубликаты координат.
- **Альтернатива при произвольной точке (не индексе):** сначала `binarySearch`
  за `O(log n)` находим место машины, затем те же два указателя → `O(log n + k)`.
