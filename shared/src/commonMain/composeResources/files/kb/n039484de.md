**📌 Реализация автоматического запроса данных при восстановлении сети в Android**

💡 **Задача:**

1. **Если пропала связь**, запомнить, что нужно обновить данные.
2. **Как только сеть восстановилась**, автоматически сделать запрос на сервер.

### **🔹 1. Используем BroadcastReceiver для отслеживания сети**


📌 **Android предоставляет ConnectivityManager, который позволяет получать события о подключении.**

• ==Когда интернет **пропадает**, **запоминаем**, что надо обновить данные.==
• ==Когда интернет **появляется**, **автоматически делаем запрос**.==

**🔹 Реализация через BroadcastReceiver (API < 29)**
```kotlin
class NetworkChangeReceiver : BroadcastReceiver() {

    override fun onReceive(context: Context, intent: Intent?) {
        if (isNetworkAvailable(context)) {
            println("📶 Интернет восстановлен! Запрашиваем свежие данные...")
            fetchDataFromServer() // Запрос на сервер при восстановлении сети
        }
    }

    private fun isNetworkAvailable(context: Context): Boolean {
        val connectivityManager = context.getSystemService(Context.CONNECTIVITY_SERVICE) as ConnectivityManager
        val activeNetwork = connectivityManager.activeNetworkInfo
        return activeNetwork != null && activeNetwork.isConnected
    }

    private fun fetchDataFromServer() {
        // Здесь отправляем запрос на сервер
        println("🔄 Запрашиваем актуальные данные...")
    }
}
```

📌 **Как зарегистрировать BroadcastReceiver в AndroidManifest.xml:**
```xml
<receiver android:name=".NetworkChangeReceiver">
    <intent-filter>
        <action android:name="android.net.conn.CONNECTIVITY_CHANGE"/>
    </intent-filter>
</receiver>
```

✅ **Когда использовать?**

• Для приложений **до Android 10 (API 29)**.

❌ **Минусы:**

• В **Android 10+** CONNECTIVITY_CHANGE **работает только в Foreground**.

### **🔹 2. Используем ConnectivityManager (Android 10+, API 29)**


📌 **Для Android 10+ нужно использовать registerDefaultNetworkCallback().**

```kotlin
class NetworkCallbackListener(private val onNetworkAvailable: () -> Unit) {

    private lateinit var connectivityManager: ConnectivityManager

    fun register(context: Context) {
        connectivityManager = context.getSystemService(Context.CONNECTIVITY_SERVICE) as ConnectivityManager
        connectivityManager.registerDefaultNetworkCallback(object : ConnectivityManager.NetworkCallback() {
            override fun onAvailable(network: Network) {
                println("📶 Интернет появился! Загружаем свежие данные...")
                onNetworkAvailable.invoke() // Вызываем коллбек
            }
        })
    }

    fun unregister() {
        connectivityManager.unregisterNetworkCallback(ConnectivityManager.NetworkCallback())
    }
}

// Использование в `Activity` или `ViewModel`
val networkCallbackListener = NetworkCallbackListener {
    fetchDataFromServer() // Авто-запрос данных при восстановлении сети
}

override fun onResume() {
    super.onResume()
    networkCallbackListener.register(this)
}

override fun onPause() {
    super.onPause()
    networkCallbackListener.unregister()
}

fun fetchDataFromServer() {
    println("🔄 Запрашиваем актуальные данные с сервера...")
}
```

✅ **Когда использовать?**

• **Для Android 10+ (API 29+).**

❌ **Минусы:**

• Работает **только, пока приложение активно**.

### **🔹 3. WorkManager + LiveData (Фоновая проверка)**


📌 **Если нужно гарантированно выполнить запрос при появлении сети, даже если приложение закрыто.**

```kotlin
class NetworkWorker(context: Context, workerParams: WorkerParameters) : Worker(context, workerParams) {

    override fun doWork(): Result {
        if (isNetworkAvailable()) {
            println("📶 Интернет появился! Загружаем свежие данные...")
            fetchDataFromServer()
            return Result.success()
        }
        return Result.retry() // Повторяем, если сети нет
    }

    private fun isNetworkAvailable(): Boolean {
        val connectivityManager = applicationContext.getSystemService(Context.CONNECTIVITY_SERVICE) as ConnectivityManager
        val activeNetwork = connectivityManager.activeNetworkInfo
        return activeNetwork != null && activeNetwork.isConnected
    }

    private fun fetchDataFromServer() {
        println("🔄 Запрашиваем актуальные данные с сервера...")
    }
}

// Запускаем WorkManager
val constraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.CONNECTED) // Запуск при появлении сети
    .build()

val workRequest = OneTimeWorkRequestBuilder<NetworkWorker>()
    .setConstraints(constraints)
    .build()

WorkManager.getInstance(context).enqueue(workRequest)
```

✅ **Когда использовать?**

• Если **нужно обновить данные даже после перезапуска телефона**.

❌ **Минусы:**

• **Запрос не моментальный**, WorkManager может запустить его с задержкой.


## **📊 Сравнительная таблица подходов**


| **Метод**                          | **Когда использовать?**                                     | **Плюсы**             | **Минусы**                   |
| ---------------------------------- | ----------------------------------------------------------- | --------------------- | ---------------------------- |
| **BroadcastReceiver**              | Android < 10, когда приложение активно                      | Простая реализация    | Не работает в Android 10+    |
| **ConnectivityManager (Callback)** | Android 10+, когда приложение открыто                       | Мгновенное обновление | Работает только в Foreground |
| **WorkManager**                    | Когда важно обновлять данные даже после закрытия приложения | Выполнится 100%       | Запускается с задержкой      |
**🚀 Итог**

• **Если приложение активно → ConnectivityManager (самый быстрый способ).**
• **Если приложение закрыто → WorkManager (гарантированное выполнение при появлении сети).**
• **Если приложение поддерживает Android 6-9 → BroadcastReceiver (но устарел для 10+).**

**🔥 Лучший вариант – комбинировать ConnectivityManager (для быстрого обновления) и WorkManager (для фоновой синхронизации).**
