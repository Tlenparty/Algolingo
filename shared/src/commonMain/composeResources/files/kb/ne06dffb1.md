В Android жизненные циклы **Activity** и **Fragment** схожи, но есть важные различия, связанные с тем, что **Fragment** является частью **Activity** и должен взаимодействовать с ее жизненным циклом. Чтобы понять эти различия, давайте рассмотрим подробное объяснение жизненных циклов обоих компонентов.

### **Жизненный цикл Activity**:

**Activity** — это один из важнейших компонентов Android-приложения, который представляет собой экран с интерфейсом для взаимодействия с пользователем. Каждый раз, когда пользователь запускает приложение, система создает объект Activity и запускает его жизненный цикл.

**Основные стадии жизненного цикла Activity:**

1. **onCreate()** — вызывается при создании Activity.В `onCreate()` вы должны вызвать метод [setContentView()](https://developer.android.com/reference/android/app/Activity.html#setContentView%28int%29).

• Здесь обычно инициализируются компоненты UI, устанавливаются обработчики событий, а также можно восстановить состояние Activity, если оно было сохранено.

2. **onStart()** — Activity становится видимой пользователю, но еще не доступна для взаимодействия с ним.

3. **onResume()** — Activity становится активной, и пользователь может взаимодействовать с ней. Это состояние Activity, когда оно активно и на переднем плане.

4. **onPause()** — вызывается, когда система начинает переключаться на другую Activity или когда текущая Activity теряет фокус, но еще не уничтожена.

5. **onStop()** — Activity больше не видна пользователю, например, когда пользователь переходит на другой экран или приложение уходит на задний план.

6. **onRestart()** — вызывается, когда Activity снова становится видимой после того, как она была остановлена.

7. **onDestroy()** — вызывается перед тем, как Activity будет уничтожена. Это финальный этап жизненного цикла, и в нем освобождаются ресурсы. Этот метод может и не вызываться. Например, когда мы прекращаем работу активити непосредственно в onCreate(), не стоит полагаться на него.

 ## Несколько примеров:  

1. Пользователь жмет Home. В этом случае активити больше не видна, поэтому вызываются `onPause()`, `onStop()`. Пользователь открывает приложение снова - `onStart()`, `onResume()`.  

2. Пользователь переходит на другую активити внутри приложения (реализуется вызовом `startActivity()`) – `onPause()`, `onStop()`. Пользователь возвращается на предыдущую активити – `onStart()`, `onResume()`.
  
3. Вызов `finish()` – `onPause()`, `onStop()`, `onDestroy()`. Когда пользователь перейдет на эту активити снова, она будет создана с нуля без сохранения состояния.  
  
4. Пользователь поворачивает телефон и ориентация активити меняется. Активити пересоздается и вызываются коллбеки `onPause()`, `onStop()`, `onDestroy()`, `onCreate()`, `onStart()`, `onResume()` с сохранением состояния.  
  
Это базовые методы активити. Более подробно они описаны в [документации](https://developer.android.com/guide/components/activities/activity-lifecycle).  
  
В полный жизненный цикл также входят `onRestart()`, `onSaveInstanceState()`, `onRestoreInstanceState()`, `onNewIntent()` и другие методы, которые разберем в будущем.


### **Жизненный цикл Fragment**:

**Fragment** — это часть пользовательского интерфейса, который может быть встроен в Activity и повторно использован в разных активностях. Жизненный цикл фрагмента тесно связан с жизненным циклом Activity, к которой он прикреплен, но фрагмент имеет свои собственные методы жизненного цикла.


**Основные стадии жизненного цикла Fragment:** (Только если есть константа ЖЦ)

1. **onAttach()** — вызывается, когда фрагмент прикрепляется к Activity. (Если фрагмент в XML)

• В этом методе фрагмент может получить ссылку на Activity и его контекст.

2. **onCreate()** — вызывается при создании фрагмента. Здесь можно инициализировать данные, не связанные с UI.

3. **onCreateView()** — вызывается для создания пользовательского интерфейса фрагмента (например, создание и привязка макета).

4. **onActivityCreated()** — вызывается, когда Activity и все ее фрагменты полностью созданы.

5. **onStart()** — вызывается, когда фрагмент становится видимым пользователю (когда его пользовательский интерфейс будет отображен).

6. **onResume()** — вызывается, когда фрагмент становится активным и готов к взаимодействию с пользователем.

7. **onPause()** — вызывается, когда фрагмент больше не находится в фокусе, но еще не уничтожен.

8. **onStop()** — вызывается, когда фрагмент больше не виден пользователю.

9. **onDestroyView()** — вызывается, когда пользовательский интерфейс фрагмента уничтожается. Этот метод полезен для освобождения ресурсов, которые были связаны с UI фрагмента (например, если использовался RecyclerView, следует отменить его адаптер).

10. **onDestroy()** — вызывается, когда фрагмент полностью уничтожен. Этот метод вызывается перед тем, как фрагмент будет освобожден из памяти.

11. **onDetach()** — вызывается, когда фрагмент отсоединяется от Activity.


### Может ли быть у фрагмента приватный конструктор ?? Какие проблемы? 


Технически, **фрагмент может иметь приватный конструктор**, но это может привести к нескольким **проблемам** при использовании фрагментов в приложении Android.

>*Да, но когда у тебя будет смена конфигурации у тебя будет крэш, так как при восстановлении используется дефолтный конструктор, но вроде как можно у FragmentManager переопределить FragmentFactory и тогда можно будет это пофиксить*

Фрагменты должны быть **созданы через** FragmentManager или **метод** FragmentTransaction для корректного добавления и управления ими в жизненном цикле приложения. Для этого фрагмент должен быть доступен для создания через конструктор.

### **Проблемы с приватным конструктором у фрагмента**

1. FragmentManager **не сможет создать фрагмент**:
Если конструктор фрагмента приватный, FragmentManager не сможет создать экземпляр фрагмента, поскольку он не сможет вызвать приватный конструктор. Это нарушает нормальное функционирование фрагмента.
2. **Не будет возможности программно создавать фрагмент**:
Без публичного конструктора невозможно будет создать фрагмент вручную в коде, например, из активити или другого фрагмента. Это ограничит гибкость и повторное использование фрагмента.
3. **Проблемы с поддержкой жизненного цикла**:
Android управляет жизненным циклом фрагментов, и они должны быть созданы через стандартный механизм фреймворка. Приватный конструктор может нарушить этот процесс, так как фрагмент не будет создан должным образом.
4. **Передача данных в фрагмент**:
В Android передача данных во фрагменты часто осуществляется через Bundle и методы, такие как setArguments(). Но даже в этом случае фрагмент должен быть доступен для создания через конструктор, и использование приватного конструктора может сделать это сложным.

### **Какие методы жизненного цикла вызываются при повороте экрана в Android?**

При повороте экрана (смене конфигурации) система **уничтожает текущую активность и пересоздаёт её**. Это связано с тем, что при изменении ориентации экрана могут измениться ресурсы (например, layout-land/), и Android создаёт новую активность с новой конфигурацией.

**Методы жизненного цикла, которые вызываются при повороте экрана:**

23. onPause() – Активность теряет фокус, но ещё видима.
24. onStop() – Активность становится невидимой.
25. onDestroy() – Активность уничтожается.
26. onCreate() – Создаётся новая активность.
27. onStart() – Активность становится видимой.
28. onResume() – Активность снова получает фокус

### **В каком методе лучше освобождать ресурсы?**


💡 **Лучше всего освобождать ресурсы в** onDestroy() **или** onStop()**, в зависимости от ситуации.**
  
**Когда использовать onDestroy()?**

Если ресурс **больше не нужен при любом сценарии уничтожения активности**, освобождайте его здесь.

Примеры:

• **Закрытие потоков (I/O, файлы, сокеты)**.
• **Отмена** BroadcastReceiver**,** EventBus **и** LiveData.
• **Закрытие базы данных, если она больше не используется**.
• **Отмена подписок на GPS, сенсоры и т. д.**.

```kotlin
override fun onDestroy() {
    super.onDestroy()
    mediaPlayer.release() // Освобождаем аудио/видео плеер
    unregisterReceiver(myReceiver) // Отписываемся от BroadcastReceiver
}
```

**Когда использовать onStop()?**

Если ресурс **может снова понадобиться при возвращении к активности**, лучше освободить его в onStop().

Примеры:

• **Остановка анимаций и воспроизведения видео**.
• **Отключение обновлений местоположения (GPS)**.
• **Остановка сетевых запросов, если они не критичны**.

```kotlin
override fun onStop() {
    super.onStop()
    locationManager.removeUpdates(locationListener) // Отключаем GPS
    videoView.pause() // Ставим видео на паузу
}
```

### **Как finish() влияет на жизненный цикл?**

Если вы вызываете finish(), жизненный цикл активности проходит следующие стадии:
```kotlin
onPause() → onStop() → onDestroy()
```

**Что важно знать про finish()?**

29. **Если активность последняя в стеке**, после finish() приложение может завершиться.

30. **Если активность была запущена** startActivityForResult(), после finish() вызывается onActivityResult() в предыдущей активности.

31. **Если вызвано** finishAffinity(), **закроются все активности** в текущем таске (например, если у вас была A → B → C, то finishAffinity() в C закроет все три активности).

32. **Если у активности** FLAG_ACTIVITY_NO_HISTORY, она **всегда уничтожается после выхода**, даже если finish() не вызывался.

Флаги активности в Android используются для управления её поведением при запуске и навигации между экранами. Они указываются в Intent при вызове startActivity().

# В каком случае onDestroy вызовется без onPause и onStop?

Такое может произойти в единственном случае, когда метод `finish()` использован в коллбэке активити `onCreate()`.  
  
Всё дело в том, что `onStop` и `onPause` – коллбэки завершающих фаз для `onStart` и `onResume` соответственно. На момент вызова `onCreate()` эти фазы еще не случились. Подробнее про жизненный цикл активити читайте в [ранней публикации](https://itsobes.com/ru/android/opishite-zhiznennyi-tsikl-fragmenta).  
  
Согласно [документации](https://developer.android.com/reference/android/app/Activity.html), в любой другой нормальной ситуации вызов этих коллбэков гарантирован.

### **🔹 Основные флаги активности**


Вот основные флаги и их назначение:
  
**1️⃣ FLAG_ACTIVITY_NEW_TASK**

🔹 **Создаёт новую задачу (task) для активности.**

📌 Если активность уже есть в другом таске, она переместится туда и откроется поверх всех остальных.
  
**Пример использования:**
```kotlin
val intent = Intent(this, SecondActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
startActivity(intent)
```

📌 **Часто используется при запуске активностей из сервисов или** BroadcastReceiver**.**

**2️⃣ FLAG_ACTIVITY_SINGLE_TOP**

🔹 **Если активность уже на вершине стека (**task**), создаётся не новая активность, а используется существующая.**

📌 Если активность **не на вершине**, создаётся новая.

**Пример:**
```kotlin
val intent = Intent(this, MainActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_SINGLE_TOP)
startActivity(intent)
```

✅ **Полезно для обработки кликов на уведомления (чтобы не создавать дубликаты).**

**3️⃣ FLAG_ACTIVITY_CLEAR_TOP**

🔹 **Закрывает все активности, которые находятся выше уже существующей активности в стеке.**

📌 Если активность уже есть в стеке, все активности поверх неё удаляются, а она пересоздаётся (onNewIntent() вызывается вместо onCreate()).

**Пример:**
```kotlin
val intent = Intent(this, MainActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP)
startActivity(intent)
```

✅ **Используется при возврате в** MainActivity**, чтобы очистить стек.**

**4️⃣ FLAG_ACTIVITY_NO_HISTORY**

🔹 **Активность не сохраняется в истории (не остаётся в стеке).**

📌 После выхода из неё или запуска другой активности она уничтожается (onDestroy()).

**Пример:**
```kotlin
val intent = Intent(this, LoginActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_NO_HISTORY)
startActivity(intent)
```

✅ **Полезно для** SplashActivity**,** LoginActivity**,** PaymentActivity **и других экранов, которые не должны сохраняться.**

**5️⃣ FLAG_ACTIVITY_REORDER_TO_FRONT**


🔹 **Если активность уже есть в стеке, она просто перемещается наверх, без создания новой.**

📌 Не уничтожает другие активности.

**Пример:**

```kotlin
val intent = Intent(this, MainActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_REORDER_TO_FRONT)
startActivity(intent)
```

✅ **Удобно для работы с множеством экранов, чтобы не создавать дубликаты.**


**6️⃣ FLAG_ACTIVITY_CLEAR_TASK**

🔹 **Очищает весь стек и делает новую активность корневой (**root**).**

📌 Часто используется с FLAG_ACTIVITY_NEW_TASK, чтобы полностью перезапустить приложение.


**Пример:**
```kotlin
val intent = Intent(this, LoginActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK)
startActivity(intent)
```

✅ **Полезно при разлогине (**Logout**), чтобы очистить весь стек.**

**7️⃣ FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS**

🔹 **Активность не появится в списке недавних приложений.**

**Пример:**
```kotlin
val intent = Intent(this, HiddenActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS)
startActivity(intent)
```
✅ **Полезно для скрытых экранов (например, “секретных” настроек).**


**🔹 Сочетания флагов**

Флаги можно комбинировать через or (|):
```kotlin
val intent = Intent(this, LoginActivity::class.java)
intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK)
startActivity(intent)
```

📌 **Этот код очищает весь стек и делает** LoginActivity **новой корневой (**root**) активностью.**

| Флаг                               | Описание                                                           |
| ---------------------------------- | ------------------------------------------------------------------ |
| FLAG_ACTIVITY_NEW_TASK             | Создаёт новую задачу (task).                                       |
| FLAG_ACTIVITY_SINGLE_TOP           | Использует существующую активность, если она уже на вершине стека. |
| FLAG_ACTIVITY_CLEAR_TOP            | Закрывает все активности выше нужной.                              |
| FLAG_ACTIVITY_NO_HISTORY           | Активность не сохраняется в истории.                               |
| FLAG_ACTIVITY_REORDER_TO_FRONT     | Перемещает существующую активность наверх, не создавая новую.      |
| FLAG_ACTIVITY_CLEAR_TASK           | Очищает весь стек и делает новую активность корневой.              |
| FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS | Активность не будет видна в списке последних приложений.           |

### Когда может не вызваться onDestroy ?

**🔹 1. Система убила процесс (Kill by System)**

**Если Android убивает процесс из-за нехватки памяти (**OOM**),** onDestroy() **не вызовется!**

📌 Это происходит, если:

• Другое приложение требует **много памяти**.
• Активность ушла в onStop(), и система **решила её выгрузить**.
• Ваше приложение долго не использовалось, и система очистила его.


**Пример:**

Вы открыли Activity A, затем свернули приложение и открыли тяжёлое приложение (Chrome, YouTube). Android может убить ваш процесс, но при этом onDestroy() **не вызовется**.

  **🔹 2. Используется finishAffinity()**


Метод ==finishAffinity() **закрывает ВСЕ активности в таске** без вызова onDestroy()== для каждой.

**🔹 3. Включён dontKeepActivities в Developer Options**

Если в настройках разработчика включён **“Не сохранять активности” (**Don't Keep Activities**)**, система уничтожает активность сразу после выхода из неё.


📌 Это влияет только на тестирование, в реальном сценарии активности сохраняются.

**🔹 4. FLAG_ACTIVITY_NO_HISTORY**

Если активность запущена с **флагом** FLAG_ACTIVITY_NO_HISTORY, она уничтожается сразу после выхода из неё **без** onDestroy().

**🔹 5. Приложение завершено принудительно (Force Stop)**


Если пользователь вручную закрыл приложение через **“Принудительно остановить” (**Force Stop**)** или смахнул из списка недавних приложений, onDestroy() **не вызовется**.


📌 Это происходит, потому что **Android сразу убивает процесс**, а не проходит через стандартный жизненный цикл.



✅ **Как проверить?**

1. Открыть настройки **→ Приложения → [Ваше приложение] → Принудительная остановка**.

2. Убедиться, что onDestroy() не вызвался.

> [!important] Актуальность лайфцикла Fragment
> - **`onActivityCreated()` устарел** (deprecated с Fragment 1.3). Вместо него: код, зависящий от view, — в **`onViewCreated()`**; не зависящий от view — в `onCreate()`.
> - У фрагмента **два жизненных цикла**: цикл самого фрагмента и цикл его **View** (`onCreateView`…`onDestroyView`). View может пересоздаваться, пока фрагмент жив (например, при возврате из бэкстека). Поэтому для подписок на UI используют **`viewLifecycleOwner`**, а не `this`, — иначе утечка/двойные подписки.
> - `onAttach()` вызывается **всегда** при присоединении к Activity (не только «если фрагмент в XML»).

> [!warning] Неточность про finishAffinity
> `finishAffinity()` **финиширует** активности таска — а финиш проходит штатно через `onPause → onStop → onDestroy`. То есть `onDestroy` там как раз **вызывается**. В список «когда onDestroy НЕ вызовется» корректно относить: **убийство процесса системой/Force Stop** (там жизненный цикл не доигрывается) и `finish()` прямо в `onCreate` (тогда нет `onPause`/`onStop`).

> [!tip] Activity vs Fragment — главное
> - **Activity** — экран/точка входа, регистрируется в манифесте, имеет свой `Context`. **Fragment** — переиспользуемая часть UI внутри Activity, своего `Context` не имеет (берёт у хоста).
