## A. Универсальный каркас (7 шагов, проговаривай вслух)

> **U-E-P-B-O-C-S**: Understand → Examples → Pattern → Brute → Optimize → Code → Sanity.

1. **Understand** — повтори условие, уточни вход/выход и ограничения (n? диапазон? дубликаты? пустой вход?).
2. **Examples** — разбери 1–2 примера руками + крайние случаи.
3. **Pattern** — назови сигналы и выбери метод ([[01 Ключи и сигналы]]).
4. **Brute force** — самое тупое решение + его Big O. Это страховка.
5. **Optimize** — какой приём убирает лишнюю работу?
6. **Code** — маленькими шагами, проговаривая инвариант.
7. **Sanity check** — прогон на примерах, проверка индексов, финальная сложность.

## B. Код-заготовки (скелеты, которые надо помнить наизусть)

### Два указателя навстречу
```kotlin
var l = 0; var r = n - 1
while (l < r) {
    // оцениваем условие на (l, r)
    when {
        условиеПодходит -> { /* ответ или l++; r-- */ }
        нужноБольше     -> l++
        else            -> r--
    }
}
```

### Скользящее окно (Sliding Window)

**Что это.** «Окно» — это непрерывный кусок массива/строки `[left .. right]`. Мы не перебираем все возможные куски заново (это было бы O(n²)), а двигаем границы одного окна по массиву: правую — чтобы окно росло, левую — чтобы оно сжималось, когда нарушилось условие.

**Зачем нужно.** Когда в задаче просят что-то про **непрерывный подотрезок** («подстрока без повторов», «подмассив с суммой ≥ K», «максимальная длина при условии»). Окно превращает O(n²) в **O(n)**: каждый элемент входит в окно один раз (через `right`) и выходит максимум один раз (через `left`).

**Аналогия.** Представь рамку, которую двигаешь по строке слева направо: правый край захватывает новые символы, а левый «отпускает» старые, как только внутри рамки стало «плохо» (например, появился повтор).

```kotlin
var left = 0                          // левая граница окна
var best = 0                          // лучший ответ (например, макс. длина)
for (right in 0 until n) {            // right — правая граница, расширяем окно
    добавитьВОкно(arr[right])         // включили новый элемент справа

    while (окноНарушаетУсловие()) {   // пока окно «плохое» —
        убратьИзОкна(arr[left])       // выкидываем элемент слева
        left++                        // и сдвигаем левую границу вправо
    }

    // здесь окно [left .. right] корректное → обновляем ответ
    best = maxOf(best, right - left + 1)  // длина окна = right - left + 1
}
```

> Ключевая идея: `right` идёт только вперёд, `left` тоже только вперёд → суммарно ≤ 2n шагов → **O(n)**.

### Бинарный поиск

**Что это.** Ищем элемент в **отсортированном** массиве, каждый раз отбрасывая половину диапазона. Поддерживаем диапазон поиска `[low .. high]` — границы, между которыми ещё может находиться ответ.

- `low` (low index) — **левая граница** диапазона поиска (самый левый индекс, где ещё может быть ответ).
- `high` (high index) — **правая граница** диапазона поиска (самый правый возможный индекс).
- `middle` — середина текущего диапазона, элемент, который мы проверяем на этом шаге.

На каждом шаге сравниваем `arr[middle]` с целью и сдвигаем одну из границ, отрезая ту половину, где цели точно нет.

```kotlin
var low = 0                                  // левая граница (начало массива)
var high = n - 1                             // правая граница (конец массива)

while (low <= high) {                        // пока диапазон не пуст
    val middle = low + (high - low) / 2      // середина (так безопаснее от переполнения, чем (low + high) / 2)
    when {
        arr[middle] == target -> return middle      // нашли
        arr[middle] < target  -> low = middle + 1   // цель больше → ищем в ПРАВОЙ половине
        else                  -> high = middle - 1  // цель меньше → ищем в ЛЕВОЙ половине
    }
}
return -1                                    // диапазон опустел → элемента нет
```

> Инвариант: искомый элемент, если он есть, всегда лежит внутри `[low .. high]`. Мы двигаем границы так, чтобы никогда не отрезать сам ответ.

### BFS
```kotlin
val queue = ArrayDeque<Node>()
val visited = HashSet<Node>()
queue.add(start); visited.add(start)
var steps = 0
while (queue.isNotEmpty()) {
    repeat(queue.size) {                  // обработать целый слой
        val node = queue.removeFirst()
        for (next in neighbors(node)) if (next !in visited) {
            visited.add(next); queue.add(next)
        }
    }
    steps++
}
```

### DFS / backtracking
```kotlin
fun dfs(state) {
    if (готово) { записатьОтвет(); return }
    for (выбор in варианты(state)) {
        применить(выбор)
        dfs(новоеСостояние)
        откатить(выбор)        // важная строка backtracking
    }
}
```

## C. Worked example — задача на два указателя «от и до»

**Задача.** Дан **отсортированный** массив `nums` и число `target`.
Верни индексы двух чисел, дающих в сумме `target` (гарантированно существует ровно одна пара).

### Шаг 1. Understand
- Вход: отсортированный массив + target. Выход: пара индексов.
- Ограничения уточняю: массив отсортирован по возрастанию, ответ единственный.

### Шаг 2. Examples
```
nums = [1, 2, 3, 4, 6, 8, 9], target = 10
ожидаем (1, 5): nums[1] + nums[5] = 2 + 8 = 10
```
Крайние случаи: 2 элемента; пара на самых краях; target меньше/больше всех сумм.

### Шаг 3. Pattern (распознаём)
Сигналы из [[01 Ключи и сигналы]]:
- «**отсортированный массив**» + «**пара чисел с суммой**» → ❗ **два указателя**.
- Вслух: «Раз массив отсортирован, мне не нужен вложенный цикл. Двигаю указатели по краям».

### Шаг 4. Brute force (страховка)
Два вложенных цикла — перебрать все пары. Сложность **O(n²)**, память O(1).
Работает, но не использует то, что массив отсортирован → можно лучше.

### Шаг 5. Optimize — ключевая идея
Ставим `left` в начало, `right` в конец и смотрим сумму:
- сумма == target → нашли;
- сумма **меньше** target → текущая сумма мала, увеличить можно только сдвинув `left++` (вправо — там числа больше);
- сумма **больше** target → уменьшить можно только `right--`.

Каждый шаг сдвигает один указатель → всего ≤ n шагов → **O(n)**, память **O(1)**.
**Инвариант:** искомая пара всегда лежит внутри `[left, right]` — мы отбрасываем только заведомо невозможные варианты.

### Шаг 6. Code
```kotlin
fun twoSumSorted(nums: IntArray, target: Int): Pair<Int, Int>? {
    var left = 0
    var right = nums.size - 1

    while (left < right) {
        val sum = nums[left] + nums[right]
        when {
            sum == target -> return left to right
            sum < target  -> left++   // нужно больше → двигаем левый вправо
            else          -> right--  // нужно меньше → двигаем правый влево
        }
    }
    return null
}
```

### Шаг 7. Sanity check
- `[1,2,3,4,6,8,9], target=10`: (0,6)=10? 1+9=10 → вернёт (0,6). ✅ (тоже валидная пара)
- Проверка границ: `left < right` не даёт указателям пересечься и не берёт один элемент дважды.
- Пустой/один элемент → цикл не выполнится, вернём null. ✅
- **Сложность: время O(n), память O(1).**

> 📌 Почему это «узнаётся мгновенно»: связка **«отсортировано» + «пара/сумма»** → два указателя.
> Запомни её как рефлекс, и шаги 3–5 займут 10 секунд.

## D. Мини-тренажёр распознавания

Закрой ответы и для каждой задачи назови метод **за 10 секунд** (ответы — в конце строки).

1. «Найти, есть ли в массиве два одинаковых элемента» → `Hash Set`
2. «Самая длинная подстрока без повторов» → `Скользящее окно`
3. «Корректность скобок ()[]{}» → `Стек`
4. «Минимальное число пересадок между станциями метро» → `BFS`
5. «Сколько есть способов разменять сумму монетами» → `DP`
6. «K самых частых слов» → `Hash Map + Heap`
7. «Найти элемент в отсортированном массиве за log n» → `Бинарный поиск`
8. «Все подмножества множества» → `DFS / backtracking`
9. «Сумма элементов на отрезке [i..j], много запросов» → `Префиксные суммы`
10. «Пара чисел с суммой target в отсортированном массиве» → `Два указателя`
