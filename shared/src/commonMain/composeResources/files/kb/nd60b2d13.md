# KMP. Библиотеки экосистемы

Карта «чем заменить привычные Android-библиотеки» в общем коде. Зрелость экосистемы — частый вопрос на собесе.

| Задача | Android-привычка | KMP-решение |
| --- | --- | --- |
| Корутины/конкурентность | kotlinx.coroutines | **kotlinx.coroutines** (мультиплатформенный) |
| Сеть / HTTP | Retrofit + OkHttp | **Ktor Client** |
| JSON | Gson / Moshi | **kotlinx.serialization** |
| База данных | Room | **SQLDelight** (или Room KMP — в новых версиях) |
| DI | Dagger / Hilt | **Koin** (или Kodein) |
| Дата/время | java.time | **kotlinx-datetime** |
| Key-value (Prefs) | SharedPreferences / DataStore | **multiplatform-settings** (или DataStore KMP) |
| Логи | Timber | **Napier** / Kermit |
| Image loading | Coil / Glide | **Coil 3** (KMP) — для Compose Multiplatform |
| Навигация (при шаринге UI) | Navigation Compose | **Decompose**, Voyager |

## Ключевые

> [!info] Ktor Client вместо Retrofit
> Сетевой клиент Ktor пишется в `commonMain`, а реальный движок подставляется per-target: **OkHttp/CIO** на Android, **Darwin** (NSURLSession) на iOS, **JS** на web.
> ```kotlin
> // commonMain
> val client = HttpClient {
>     install(ContentNegotiation) { json() }
> }
> suspend fun loadUser(): User = client.get("https://api/user").body()
> ```
> Сериализация цепляется через `kotlinx.serialization` (`@Serializable`).

> [!info] SQLDelight вместо Room
> SQLDelight идёт «от SQL»: вы пишете `.sq`-файлы со схемой и запросами, плагин генерирует типобезопасный Kotlin API. Драйвер — платформенный (`AndroidSqliteDriver`, `NativeSqliteDriver`), подключается через DI. Альтернатива — **Room с поддержкой KMP** (появилась в Room 2.7), если команда уже знает Room.

> [!tip] DI: почему Koin, а не Hilt
> **Hilt/Dagger завязаны на JVM/кодогенерацию под Android** и в `commonMain` не работают. В KMP берут **Koin** (рантайм-DI, чистый Kotlin) — он мультиплатформенный. Это перекликается с [[DI VS SERVICE LOCATOR]]: Koin ближе к Service Locator, но для KMP это осознанный компромисс ради переносимости.

> [!warning] Не всё, что есть на JVM, есть в commonMain
> Частая ошибка — тянуть в общий код чисто-JVM-библиотеку (Retrofit, Gson, Hilt, java.time до kotlinx-datetime). Они скомпилируются под Android, но **сломают iOS-сборку**. Правило: в `commonMain` — только мультиплатформенные артефакты; платформенно-специфичное — за интерфейсом или в `androidMain`/`iosMain`.

> [!note] Touchlab и инструменты
> Многое в экосистеме двигает **Touchlab**: **SKIE** (улучшает Swift-интероп — см. [[KMP. iOS interop и корутины]]), **Kermit** (логирование), стартер **KaMPKit**. Полезно упомянуть на собесе как признак зрелости экосистемы.
