# KMP. iOS interop и корутины

Самая «нетривиальная» часть KMP — как Kotlin-код потребляется из Swift/Objective-C и что происходит с корутинами и `Flow` на границе.

## Что такое interop вообще

**Интероп здесь** — это способность Swift напрямую, в одном процессе, вызывать Kotlin-код из общего модуля так, будто это родной ObjC/Swift-класс: `UserRepository()`, `repo.loadUser()` — без сети и сериализации, просто вызов скомпилированной функции. Возможным это делает мост, который Kotlin/Native встраивает в `.framework` через сгенерированные Objective-C-заголовки, переводя Kotlin-представление типов и памяти в понятное рантайму ObjC — и вся «нетривиальность» KMP как раз в том, что этот перевод неидеален (`suspend`, `Flow`, `sealed` теряют часть смысла на границе).

У Kotlin четыре интеропа — по одному на бэкенд:

| Пара | Механизм | Качество |
| --- | --- | --- |
| Kotlin/JVM ↔ Java | один и тот же байткод, моста нет | бесшовный, двусторонний |
| Kotlin/Native ↔ ObjC/Swift | компилятор генерирует **ObjC-заголовки** для API | с «огрублениями» (эта заметка) |
| Kotlin/Native ↔ C | `cinterop`: биндинги по `.def` + C-заголовкам | хороший, односторонний (Kotlin → C) |
| Kotlin/JS ↔ JavaScript | `external`-декларации, `@JsExport` | ручной |

> [!important] Мост на iOS идёт через Objective-C, а не Swift
> Kotlin/Native разговаривает с **рантаймом ObjC** (у Swift не было стабильного публичного ABI для этого). API протаскивается через самый узкий общий знаменатель — ObjC не знает про дженерики Kotlin, sealed-иерархии и suspend — отсюда все «огрубления» ниже. Обратное направление тоже ограничено: Kotlin видит Swift-код, только если тот помечен `@objc` (или через [[KMP. expect-actual|expect/actual]]-прослойку). SKIE/KMP-NativeCoroutines — «надстройки над мостом»: генерируют Swift-обёртки поверх ObjC-заголовков и возвращают потерянное.

## Как Kotlin виден из Swift

Kotlin/Native компилирует общий модуль в **`.framework`**, экспортируя API через **Objective-C-заголовки**. Swift видит их как обычный ObjC-фреймворк:

```swift
import shared            // имя framework

let repo = UserRepository()
let name = repo.platform.name      // обычный вызов Kotlin-кода
```

> [!warning] Маппинг типов не один-к-одному
> Через ObjC-мост многое «огрубляется»:
> • `Int`/`Long` → `KotlinInt`/`KotlinLong` (боксятся), дженерики часто теряются;
> • **`sealed class`** превращается в обычные классы — Swift **не видит исчерпывающность**, `switch` без `default` не сделать;
> • перегрузки и default-параметры разворачиваются в длинные имена;
> • Kotlin-`enum` маппится, но не идеально.
> Именно эти шероховатости и чинит SKIE (ниже).

## Suspend-функции и Flow на границе

> [!important] Главный вопрос интеропа: что станет с suspend
> ObjC не знает про корутины, поэтому **`suspend`-функция экспортируется как функция с completion-handler**, а в Swift автоматически становится **`async`**:
> ```kotlin
> // Kotlin (commonMain)
> suspend fun loadUser(): User
> ```
> ```swift
> // Swift — вызывается как async
> let user = try await repo.loadUser()
> ```
> Но из коробки есть ограничения: **`Flow` теряет тип** (`SkieSwiftFlow`/обёртки нет — голый `Flow<Foo>` приходит как `Flow` без дженерика), отмену пробрасывать неудобно.

> [!tip] SKIE / KMP-NativeCoroutines — стандарт де-факто
> Чтобы интероп был приятным, подключают:
> • **SKIE** (Touchlab) — `Flow` → нативная **`AsyncSequence`**, `suspend` → `async` с поддержкой отмены, `sealed` → Swift **`enum`** с исчерпывающим `switch`. Работает прозрачно, без обёрток в Kotlin-коде.
> • **KMP-NativeCoroutines** — альтернатива, требует аннотаций, но даёт явный контроль над отменой и Combine-интеграцию.
> На собесе по KMP знание про «suspend → async, а Flow надо причёсывать через SKIE» — сильный сигнал.

## Как SKIE устроен

**SKIE** (Swift Kotlin Interface Enhancer, от Touchlab) — это **Kotlin-compiler-plugin + генератор Swift-кода**, встроенный в тот же Gradle-билд. Он не трогает ObjC-мост, а **надстраивается над ним**: Kotlin/Native по-прежнему генерирует «огрублённые» заголовки, а SKIE поверх них выпускает тонкий слой Swift-обёрток, возвращающий потерянный смысл. Твой код в `commonMain` остаётся чистым — никаких аннотаций (в отличие от [[Coroutines|KMP-NativeCoroutines]]).

Порядок в билде:

```text
Kotlin/Native компилирует commonMain
        ↓
генерируются ObjC-заголовки (.framework)   ← «огрублённый» API
        ↓
SKIE читает заголовки + инфу компилятора
        ↓
генерирует Swift-обёртки (.swift)          ← «причёсанный» API
        ↓
Xcode собирает всё в iOS-приложение
```

Тот же Kotlin-код на Swift-стороне становится нативным:

```kotlin
// commonMain — пишем как обычно, без обёрток
class UserRepository {
    suspend fun loadUser(): User
    fun observeUsers(): Flow<List<User>>
}
sealed class LoadState {
    object Loading : LoadState()
    data class Success(val user: User) : LoadState()
    data class Error(val message: String) : LoadState()
}
```

```swift
// Flow → AsyncSequence, тип List<User> сохранён
for await users in repo.observeUsers() { render(users) }

// suspend → async, отмена Swift-Task пробрасывается в корутину
let user = try await repo.loadUser()

// sealed → Swift enum с исчерпывающим switch (default не нужен)
switch state {
case .loading:            showSpinner()
case .success(let s):     show(s.user)
case .error(let e):       show(e.message)
}
```

> [!note] Три уровня, снизу вверх
> **Kotlin/Native** (компилирует Kotlin + делает ObjC-мост, обязателен) → **ObjC-заголовки** (узкий общий знаменатель, где теряется семантика) → **SKIE** (опциональная надстройка, возвращает потерянное на Swift-уровне, не меняя общий код).

## Память и потоки

> [!info] Новый memory manager убрал главную боль
> До Kotlin 1.7.20 Kotlin/Native имел **двухуровневую модель с заморозкой** (`freeze()`): объект, разделяемый между потоками, нужно было «заморозить», иначе `InvalidMutabilityException`. Это ломало привычные паттерны с корутинами. Сейчас действует **новый memory manager** без freezing — многопоточность и `Dispatchers.Default/Main` работают как на JVM. Старую модель упоминают только как «как было раньше».

> [!note] GC на Native — другой
> На JVM/Android — свой GC (см. [[GC, Виды ссылок, GC roots]]); Kotlin/Native использует собственный трассирующий GC (исторически на основе подсчёта ссылок + цикл-коллектор). Для интеропа важно: Kotlin-объекты, переданные в Swift, удерживаются ARC-ссылкой Swift, и наоборот — утечки возможны при циклах Kotlin↔Swift, как и в обычном ObjC.

## Что обычно держат на нативной стороне

UI (SwiftUI/UIKit), системные разрешения, специфичные Apple-фреймворки (HealthKit, push через APNs) — это пишут на Swift и при необходимости отдают в общий код через [[KMP. expect-actual|expect/actual]] или интерфейсы.
