**Аллокация (allocation)** — это **выделение памяти** в **куче (heap)** для создания нового объекта в Java/Kotlin.

Когда мы создаем новый объект через new (Java) или val obj = SomeClass() (Kotlin), JVM **выделяет память (аллокация)** в куче (Heap).

Позже, **Garbage Collector (GC) удаляет объекты**, которые больше не используются (не имеют ссылок).

 **Как происходит аллокация памяти в JVM?**

1️⃣ **Создание объекта**

• val user = User("Alex") → JVM выделяет место в куче (heap).

2️⃣ **Запись объекта в память**

• JVM **ищет свободный участок памяти**, записывает объект и возвращает ссылку.

3️⃣ **GC удаляет неиспользуемые объекты**

• Если `user = null` (и других ссылок нет), объект становится **«мусором»**, и GC его очищает.

> [!tip] Что добавить на собесе
> - Аллокация в куче не бесплатна. JVM ускоряет её через **TLAB (Thread-Local Allocation Buffer)** — у каждого потока свой кусок Eden, куда он кладёт объекты без блокировок (bump-the-pointer).
> - **Escape analysis**: если JIT видит, что объект не «убегает» за пределы метода, он может вообще не аллоцировать его в куче (scalar replacement) — объект «разбирается» на локальные переменные в стеке.
> - Новые объекты создаются в **Eden** (молодое поколение); пережившие несколько сборок переезжают в Old. Дешёвые короткоживущие объекты — это норма для JVM.
> - В Kotlin лишние аллокации создают: автобоксинг (`Int?`, дженерики), лямбды с захватом, промежуточные коллекции (`map{}.filter{}` без `asSequence`).
