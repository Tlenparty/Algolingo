# Почему hashCode не уникален и почему возможны коллизии

`hashCode` — это `Int`, то есть всего **2³² ≈ 4,3 млрд** возможных значений. А различных объектов может быть сколько угодно — бесконечно много. По принципу Дирихле («голубей больше, чем клеток») невозможно раздать бесконечному множеству объектов уникальные значения из конечного набора. Поэтому коллизии — не баг, а математическая неизбежность.

> **На собес одной фразой:** `hashCode` возвращает `Int` — значений всего 2³², а объектов бесконечно много, поэтому разным объектам неизбежно достаются одинаковые хеши. Хеш и не обязан быть уникальным: его контракт — «равные объекты дают равный хеш», а не наоборот.

## Почему так — по пунктам

1. **Конечный диапазон.** И в Java, и в Kotlin `hashCode(): Int` — 32 бита. Уже `Long` (2⁶⁴ значений) физически не влезает: разных `Long` в 4 млрд раз больше, чем разных `Int`.
2. **Бесконечное множество входов.** Строк, списков, дата-классов — неограниченно много. Отобразить большее множество в меньшее без совпадений нельзя.
3. **Контракт этого и не требует.** Контракт `hashCode` гарантирует только: `a.equals(b)` → `a.hashCode() == b.hashCode()`. Обратное **не обязано** выполняться: одинаковый хеш ≠ равные объекты.
4. **Хеш — это про скорость, а не про идентичность.** Задача хеша — быстро (O(1)) отправить объект в нужный бакет `HashMap`/`HashSet`. Точную проверку «тот ли это объект» всё равно делает `equals()` — см. [[Как сравниваются ключи в HashMap при одинаковом hashCode]].

## Наглядные примеры коллизий

```kotlin
// Long: 2⁶⁴ значений сжимаются в 2³² — коллизии заложены в саму формулу
// hashCode() = (value xor (value ushr 32)).toInt()
println(1L.hashCode())          // 1
println(4294967296L.hashCode()) // 1 — другой Long, тот же хеш!

// String: знаменитая пара с одинаковым хешем
println("Aa".hashCode())        // 2112
println("BB".hashCode())        // 2112 — коллизия
```

```text
Почему "Aa" и "BB" совпали: hash строки = s[0]*31 + s[1]
'A'*31 + 'a' = 65*31 + 97 = 2112
'B'*31 + 'B' = 66*31 + 66 = 2112
```

## А в Kotlin что-то иначе?

Нет. Kotlin на JVM использует те же `hashCode`/`equals` из `java.lang.Object`, `data class` просто генерирует их автоматически по полям. Диапазон тот же — `Int`, коллизии так же возможны.

## Что с этим делают хеш-структуры

Раз коллизии неизбежны, `HashMap` умеет с ними жить: элементы с одинаковым хешем складываются в один бакет (список, с Java 8 — дерево при разрастании), а различает их `equals()`. Подробнее — [[Как выглядит Bucket при ключах с одинаковым hashCode в HashMap]] и [[Как работает HashMap]].

> ⚠️ Хороший `hashCode` не «уникальный», а **равномерный**: чем реже совпадения на реальных данных, тем ближе `HashMap` к O(1). Плохой хеш (например, константа) законен по контракту, но превращает поиск в O(n)/O(log n).
