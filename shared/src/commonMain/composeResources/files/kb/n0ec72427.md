# KMP. Вопросы с собеса

Шпаргалка «вопрос → короткий сильный ответ». Развёрнутые объяснения — по ссылкам.

> [!question] Чем KMP отличается от Flutter / React Native?
> KMP по умолчанию **не несёт свой UI и рантайм** — делится только Kotlin-логика, а UI остаётся нативным (Compose/SwiftUI). Flutter рисует свой UI движком (Skia/Impeller) и тащит рантайм Dart; RN — JS-мост к нативным компонентам. KMP даёт нативный UX и постепенное внедрение. (UI можно шарить опционально через [[KMP. Compose Multiplatform]].)

> [!question] Что компилируется во что?
> `commonMain` собирается несколькими бэкендами: **Kotlin/JVM** (Android, байткод), **Kotlin/Native** (iOS — LLVM → `.framework`), **Kotlin/JS** и **Kotlin/Wasm** (web). Детали — [[KMP]].

> [!question] Как работает expect/actual и когда его НЕ использовать?
> `expect` в `commonMain` — контракт без тела, `actual` в каждом таргете — реализация; нет `actual` → ошибка компиляции (статическая гарантия полноты). **Не использовать**, когда есть несколько реализаций или нужна подмена в тестах — там чище обычный интерфейс + DI. См. [[KMP. expect-actual]].

> [!question] Почему в commonMain нельзя Retrofit/Hilt/java.time?
> Это **чисто-JVM**-библиотеки — под iOS (Kotlin/Native) их нет, сборка упадёт. Мультиплатформенные замены: **Ktor, Koin, kotlinx-datetime, kotlinx.serialization, SQLDelight**. См. [[KMP. Библиотеки экосистемы]].

> [!question] Что происходит с suspend-функцией и Flow в Swift?
> `suspend` экспортируется через completion-handler и в Swift становится **`async`**. `Flow` из коробки теряет дженерик и неудобен — причёсывается через **SKIE** (`Flow`→`AsyncSequence`, `sealed`→`enum`) или **KMP-NativeCoroutines**. См. [[KMP. iOS interop и корутины]].

> [!question] Что за «заморозка объектов» в Kotlin/Native?
> Легаси старого memory model: объекты, разделяемые между потоками, требовалось `freeze()`. С **Kotlin 1.7.20** действует новый memory manager **без freezing** — корутины и многопоточность работают как на JVM. Сейчас это вопрос «на знание истории».

> [!question] KMP — это стабильно? Можно в прод?
> Да: **KMP стабилен с Kotlin 1.9.20 (ноябрь 2023)**. В проде у McDonald's, Netflix, Forbes, 9GAG, Philips и др. **Compose Multiplatform**: Android/Desktop — Stable, **iOS — Stable с 2025**, Web (Wasm) — Alpha/Beta. См. [[KMP. Compose Multiplatform]].

> [!question] Как устроен типовой проект и как делят работу?
> `shared/` (KMP-модуль с логикой) + `androidApp/` (Android Studio) + `iosApp/` (Xcode, подключает framework из shared). Android-команда пишет Kotlin и логику, iOS-команда — Swift UI и интероп. Source sets — [[KMP. Source sets и Gradle]].

> [!question] Что шарить, а что нет?
> **Шарят:** сеть, парсинг, БД, бизнес-логику, репозитории, use-case'ы, часто ViewModel/презентеры на корутинах. **Оставляют нативным:** UI (если без CMP), системные разрешения, платформенные SDK (HealthKit, push). Перекликается с [[Чистая архитектура]] — общий слой это domain + data, платформенный — presentation/UI.

> [!question] За счёт чего собирается iOS-приложение, можно ли из Android Studio?
> Общий Kotlin-код компилируется **Kotlin/Native через LLVM** в нативный `.framework`; **Xcode** линкует его со Swift-кодом в `.app`, `codesign` подписывает сертификатом + provisioning-профилем, доставка — Xcode/TestFlight/App Store. Android Studio с KMP-плагином запускает всё одной кнопкой, **но только на macOS** (внутри зовёт `xcodebuild` и Apple-toolchain). Подробно — [[KMP. Сборка и доставка iOS-приложения]].

> [!tip] Как показать глубину
> Упомяните: default hierarchy template (Gradle сам строит иерархию source sets), XCFramework для объединения iOS-таргетов, SKIE для интеропа, новый memory manager, и честно назовите минусы CMP на iOS (accessibility, размер бинаря, UX-нюансы). Это отличает «слышал про KMP» от «работал с KMP».
