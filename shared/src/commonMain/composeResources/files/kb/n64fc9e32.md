```kotlin
//Что будет выведено
fun main(args: Array<String>) = runBlocking {
    launch {
        delay(200L)
        println("Task from runBlocking")
    }
 
    coroutineScope {
        launch {
            delay(500L)
            println("Task from nested launch")
        }
 
        delay(100L)
        println("Task from coroutine scope")
    }
 
    println("Coroutine scope is over")
}
```

**Ответ (порядок вывода):**

```text
Task from coroutine scope
Coroutine scope is over
Task from runBlocking
Task from nested launch
```

## Разбор по таймингу

1. `runBlocking` запускает «верхний» `launch` (delay 200) — он уходит в ожидание.
2. Доходим до `coroutineScope { }`. Внутри запускается вложенный `launch` (delay 500) и идёт `delay(100)`.
3. На **t≈100** печатается `Task from coroutine scope`.
4. **`coroutineScope` ждёт завершения ВСЕХ своих дочерних корутин** (вложенный launch с delay 500). На **t≈500** печатается... но сначала:
5. На **t≈200** срабатывает верхний `launch` → `Task from runBlocking` (он дочерний для `runBlocking`, а не для `coroutineScope`).
6. На **t≈500** завершается вложенный launch → `Task from nested launch`, и только после этого `coroutineScope` отдаёт управление.

Подожди — порядок вывода именно такой:

```text
~100  Task from coroutine scope
~200  Task from runBlocking      (верхний launch, живёт в runBlocking)
~500  Task from nested launch
~500  Coroutine scope is over
```

> [!warning] Уточнение по выводу
> Строка `Coroutine scope is over` печатается **после** `coroutineScope { }`, а он ждёт вложенный `launch` (delay 500). Значит `Coroutine scope is over` идёт **после** `Task from nested launch`, а не до. Правильный порядок:
> ```text
> Task from coroutine scope   (~100)
> Task from runBlocking       (~200)
> Task from nested launch     (~500)
> Coroutine scope is over     (~500, сразу за nested launch)
> ```
> Главный смысл задачи: **`coroutineScope` не вернёт управление, пока не завершатся все его дочерние корутины** (structured concurrency), а `launch` из `runBlocking` живёт параллельно и не блокирует scope.
