
Composer — это один из центральных компонентов в Jetpack Compose, который управляет **составлением** (composition) вашего UI. В рамках Compose, **composition** — это процесс создания UI на основе данных и состояния, и Composer играет ключевую роль в этом процессе.

Простыми словами, Composer отвечает за:

• **Регистрацию** и **выполнение** всех ваших @Composable функций.
• **Отслеживание состояния UI** и зависимостей между состоянием и элементами UI.
• **Управление рекомпозицией**: он решает, какие части UI необходимо обновить при изменении состояния.

**🎯 Основные функции Composer**

**🔹 1. Регистрация и выполнение @Composable функций**

Когда вы вызываете функцию с аннотацией @Composable, Composer запускает её, создавая элементы UI и добавляя их в **композицию**.

Пример:
```kotlin
@Composable
fun Greeting(name: String) {
    Text("Hello, $name!")
}
```

• Composer создает этот Text элемент и **сохраняет его в структуре композиции**.
• Он **связывает** Text с состоянием или параметром, чтобы при изменении данных UI обновился.

**🔹 2. Отслеживание изменений состояния**

Composer отслеживает **зависимости** между элементами UI и состоянием (например, remember или mutableStateOf).

Когда **состояние изменяется**, Composer решает, какие части композиции нуждаются в обновлении.

Пример:

```kotlin
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) }

    Button(onClick = { count++ }) {
        Text("Clicked $count times")
    }
}
```

• Composer отслеживает, что Text зависит от состояния count.
• Когда count изменяется, Composer помечает Text как “устаревший” и инициирует рекомпозицию только этого элемента.
**Под капотом** MutableState в этом примере **делает три вещи:**

1. **Обновляет хранимое значение.**

• MutableState внутри содержит StateRecord, который хранит текущее значение count.
• count.value = 1 изменяет его.

2. **Вызывает** Snapshot.notifyObjectsChanged()

• MutableState реализует механизм SnapshotMutableState, который **регистрирует изменение состояния в** Snapshot.

• Snapshot теперь знает, что какое-то состояние изменилось.

1. **Уведомляет** Composer **через** SnapshotObserver

• SnapshotObserver следит за изменениями и говорит Composer:

❗ **“Этот** @Composable **использует изменённое состояние, нужно перерисовать UI!”**

• Composer проверяет, какие @Composable зависят от count, и **перерисовывает только** Text("Clicked $count times"), а не весь экран.

**🔹 3. Управление рекомпозицией**

Когда состояние меняется, Composer управляет рекомпозицией, чтобы **обновить только изменённые элементы** UI, а не пересоздавать весь экран.

• Он использует Slot Table для отслеживания зависимости между состоянием и @Composable элементами.

• Composer эффективно решает, какие части UI нужно пересоздать, и только они будут обновлены при рекомпозиции.

### **🔥 Как работает Composer под капотом?**


**✅ 1. Связывание состояния с UI**


Когда вы создаёте состояние с помощью remember или mutableStateOf, Composer связывает это состояние с соответствующими UI элементами, чтобы при изменении состояния UI обновлялся.

```kotlin
val count = remember { mutableStateOf(0) }
```

• Composer создает запись в композиции, которая хранит ссылку на count.
• Если count изменяется, Composer отслеживает это изменение и инициирует обновление UI.

**✅ 2. Пометка устаревших элементов**

Когда состояние изменяется, Composer помечает элементы, зависящие от этого состояния, как **устаревшие**.

• Он анализирует, какие элементы зависят от count, и только их будет рекомпозировать.


**✅ 3. Рекомпозиция**

Composer решает, какой части композиции нужно быть обновленной, основываясь на информации, собранной в Slot Table и Snapshot. Он инициирует обновление только тех элементов, которые действительно зависят от изменённого состояния.


## Composer and Snapshot 

### ** 1. Что делает Composer?**

Composer — это центральный механизм, который управляет **композицией** UI. Он ответственен за:

• **Запуск и выполнение** ``@Composable`` **функций**.
• **Регистрацию зависимостей между состоянием и UI**.
• **Управление рекомпозицией**.


### **🧩 Основные задачи Composer:**

2. **Создание UI**: Composer запускает @Composable функции, создавая UI элементы. Это можно сравнить с процессом, когда компоненты создаются и добавляются в структуру композиции.
3. **Отслеживание зависимостей**: Он отслеживает, какие элементы UI зависят от каких состояний. Когда состояние изменяется, Composer **помечает устаревшие** элементы UI как **неактуальные**, и инициирует их **рекомпозицию**.
4. **Рекомпозиция**: Он обновляет UI, вызывая перерисовку только тех элементов, которые зависят от изменённого состояния, минимизируя производительность.

### **2. Что делает Snapshot?**
  
Snapshot — это механизм управления состоянием в Jetpack Compose. Его основная задача — отслеживать **изменения состояния** и **обеспечивать синхронизацию с UI**. Он управляет тем, какие значения и когда обновляются в UI.


**🧩 Основные задачи Snapshot:**

5. **Отслеживание изменений состояния**: Когда мы изменяем состояние (например, через mutableStateOf), Snapshot отслеживает, что произошло изменение, и уведомляет Composer, чтобы обновить UI.

6. **Группировка изменений**: Он позволяет **группировать изменения** состояния, чтобы избежать лишних обновлений UI.

7. **Отложенные обновления**: При необходимости можно использовать snapshot {}, чтобы изменения состояния не запускали немедленную рекомпозицию, а произошло обновление UI только один раз после завершения всех изменений.

8. **Откат изменений**: С помощью Snapshot.takeSnapshot() можно **сохранить снимок состояния** и при необходимости **откатить изменения** (например, в случае ошибки).

### **Какая разница между Composer и Snapshot?**

9. **Функция**:

• Composer управляет **композицией UI**. Он регистрирует и выполняет @Composable функции, отслеживает зависимости и инициирует рекомпозицию.

• Snapshot отслеживает **изменения состояния** и управляет их синхронизацией с UI. Он уведомляет Composer об изменениях в состоянии, но сам не обновляет UI.

10. **Уровень взаимодействия**:

• Composer работает на уровне **UI** и управления композиционными функциями.

• Snapshot работает на уровне **состояния**, отслеживая изменения и обеспечивая **эффективное обновление UI**.

11. **Процесс обновления UI**:

• Composer инициирует перерисовку только тех UI элементов, которые зависят от изменённого состояния.

• Snapshot обеспечивает, чтобы все изменения состояния были правильно синхронизированы и оптимизированы перед тем, как Composer перерисует UI.

12. **Группировка и откат изменений**:

• Snapshot позволяет **группировать изменения** состояния для минимизации обновлений UI и **откатывать изменения** в случае ошибки.

• Composer не управляет группировкой или откатом изменений, его задача — обновить UI по мере изменений.

> [!tip] Одной фразой
> **Snapshot** = «что изменилось» (слой состояния, отслеживает чтения/записи `mutableStateOf`). **Composer** = «что с этим делать в UI» (слой композиции, помечает узлы устаревшими и запускает рекомпозицию). Snapshot уведомляет — Composer перерисовывает.
