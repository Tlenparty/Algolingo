Выбор зависит от **типа и объема данных**, которые нужно хранить.


| Критерий                 | SQL (ROOM)                                   | SharedPreferences                        |
| ------------------------ | -------------------------------------------- | ---------------------------------------- |
| **Тип данных**           | Структурированные, сложные (объекты, списки) | Простые (String, Int, Boolean) JSON тоже |
| **Объем данных**         | Большие (1000+ записей)                      | Маленькие (настройки, 10-100 записей)    |
| **Многопоточная работа** | Да (поддержка Coroutines, Flow)              | Нет (нужны apply() или commit())         |
| **Кэширование данных**   | Можно (например, для API)                    | Нет                                      |
| **Связи между данными**  | Поддерживает (@Relation, JOIN)               | Нет                                      |

> [!important] SharedPreferences устарел → DataStore
> Google рекомендует вместо `SharedPreferences` использовать **Jetpack DataStore**:
> - **Preferences DataStore** — аналог SharedPreferences (ключ-значение), но **асинхронный** (Flow + корутины), без блокирующего `commit()` и без проблем с UI-тредом.
> - **Proto DataStore** — типобезопасное хранилище со схемой (protobuf).
>
> Проблемы старого `SharedPreferences`: `commit()` блокирует поток; `apply()` асинхронный, но может терять данные при краше; нет реактивности.

> [!tip] Как выбрать (коротко)
> - Пара простых настроек (тема, флаги, токен) → **DataStore** (или SharedPreferences в legacy).
> - Структурированные данные, списки, запросы, связи, кэш API → **Room**.
> - Большие файлы/медиа → файловое хранилище, не БД.
