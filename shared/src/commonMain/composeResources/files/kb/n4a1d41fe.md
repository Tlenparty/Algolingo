**Основные особенности:**

1. **Хэш-код — это целое число**:

• Метод hashCode() возвращает значение типа int.
• Это значение вычисляется на основе содержимого объекта, чтобы обеспечить уникальность для различных объектов (хотя коллизии возможны).

**Почему вообще надо переопределять hashCode() ??**
Переопределение метода hashCode важно в контексте коллекций, использующих хеширование, таких как HashMap, HashSet и других. Хотя метод equals определяет, как сравнивать объекты на эквивалентность, hashCode используется для улучшения производительности при поиске и хранении объектов в хеш-таблицах.

>Потому что он не зависит от содержимого объекта (Базовый)
>Eсли ты создашь два одинаковых с точки зрения контента объекта, то у них будут разные хэшкоды

**Устранение избыточных коллизий**

Когда hashCode() не переопределён, используется реализация из класса Object, которая возвращает значение, основанное на адресе объекта в памяти. Это приводит к уникальным хэш-кодам для каждого объекта, но такие хэш-коды бесполезны, если два объекта логически равны (по equals()), но находятся в разных местах памяти.

Метод equals() в Java и Kotlin используется для сравнения двух объектов **по значению**, а не по ссылке.
**По умолчанию,** equals() **сравнивает ссылки, но его можно переопределить для сравнения содержимого.**

```kotlin
val str1 = "Hello"
val str2 = "Hello"
println(str1 == str2)  // true (вызывает str1.equals(str2))
```

**Эквивалентный код в Java:**

```java
String str1 = "Hello";
String str2 = "Hello";
System.out.println(str1.equals(str2)); // true
```

Если один из объектов null, то == не вызовет NullPointerException, а просто вернёт false:
```kotlin
val s1: String? = "Hello"
val s2: String? = null
println(s1 == s2) // false (без NPE!)
```

**2. Как работает === в Kotlin? (Сравнение ссылок)**

```kotlin
val obj1 = Any()
val obj2 = Any()
val obj3 = obj1

println(obj1 === obj2) // false (разные объекты в памяти)
println(obj1 === obj3) // true (указывают на один объект)
```

**3. Переопределение equals() в Kotlin**

В Kotlin можно переопределить метод equals(), если нужно сравнивать объекты по содержимому:
```kotlin
data class Person(val name: String, val age: Int)
```

Такой data class **автоматически переопределяет** equals() и hashCode():

```kotlin
val p1 = Person("Alice", 25)
val p2 = Person("Alice", 25)

println(p1 == p2)  // true (так как `equals()` сравнивает поля)
println(p1 === p2) // false (разные объекты в памяти)
```

**🔹 Правила связи equals() и hashCode()**
>==1. **Если два объекта равны по** equals()**, то их** hashCode() **должен быть одинаковым.**==
==2. **Если** hashCode() **у двух объектов разный, то** equals() **точно вернёт** false**.**==
==3. **Если** hashCode() **у двух объектов одинаковый,** equals() **может вернуть** true **или** false. Это называется **коллизией** (разные объекты с одинаковым hashCode())==.

### **Почему сравнение по hashCode() быстрее, чем по equals()?**

Сравнение объектов с помощью hashCode() **быстрее**, чем с помощью equals(), потому что:

> 1. `hashCode()` возвращает **целое число (`int`)** — сравнить два числа очень дёшево; а `equals()` ==сравнивает объекты поле за полем==, что дороже.

2. **В коллекциях (**HashMap**,** HashSet**) сначала сравнивают** hashCode()**, и только если он совпадает — вызывают** equals(). Поэтому в среднем коллекция почти не вызывает дорогой `equals`.

### Сравнение по ссылке в java и Kotlin

В **Java** и **Kotlin** объекты можно сравнивать **по ссылке** (т.е. проверять, указывают ли они на один и тот же объект в памяти) и **по значению** (т.е. сравнивать содержимое объектов).

**📌 1. Сравнение по ссылке в Java**
**✅ Используем оператор == (сравнивает ссылки на объекты, а не их значения)**

```java
String s1 = new String("Hello");
String s2 = new String("Hello");

System.out.println(s1 == s2); // ❌ false (разные объекты в памяти)
```

🔹 **Почему** false**?**
• new String("Hello") создает **новый объект в памяти**.
• Поэтому s1 и s2 указывают на **разные экземпляры строк**.)

**✅ Но если строка создается без new, Java использует String Pool:**

```java
String s3 = "Hello";
String s4 = "Hello";

System.out.println(s3 == s4); // ✅ true (указывают на один объект в String Pool)
```

🔹 **Почему** true**?**
• **Строки, созданные без** new, кешируются в **String Pool**.
• s3 и s4 указывают на один и тот же объект в памяти.

**✅ Для сравнения по значению используем equals()**

```java
System.out.println(s1.equals(s2)); // ✅ true (сравнение по содержимому)
```

**📌 2. Сравнение по ссылке в Kotlin**
**✅ Используем оператор === (аналог == в Java)**

```kotlin
val s1 = String("Hello".toCharArray())
val s2 = String("Hello".toCharArray())

println(s1 === s2) // ❌ false (разные объекты в памяти)
```

🔹 **Почему** false**?**

• String("Hello".toCharArray()) создаёт **новые объекты в памяти**.

**✅ Для сравнения по значению используем == (аналог equals() в Java)**

```kotlin
println(s1 == s2) // ✅ true (сравнение по значению)
// 🔹 **В Kotlin** == **автоматически вызывает** equals().
```

**🔥 Что будет при сравнении Integer a == Integer b в Java?**

```java
Integer a = 100;
Integer b = 100;
System.out.println(a == b); // Что выведет?
```

**📌 Почему true?**
Java использует **кеширование значений** Integer в диапазоне **от -128 до 127**.

При присвоении Integer a = 100; и Integer b = 100; **оба переменных ссылаются на один и тот же объект из кеша**.

```java
Integer x = 127;
Integer y = 127;
System.out.println(x == y); // ✅ true (оба из кеша)

Integer m = 128;
Integer n = 128;
System.out.println(m == n); // ❌ false (разные объекты)
```

> [!important] Контракт equals / hashCode
> 1. Если `a.equals(b)` → то `a.hashCode() == b.hashCode()` (**обязательно**).
> 2. Обратное **неверно**: равные хэши не гарантируют равенства объектов (коллизия).
> 3. `equals` должен быть рефлексивным, симметричным, транзитивным и консистентным.
>
> **Нарушение №1 — классический баг:** переопределили `equals`, но забыли `hashCode` → объект «теряется» в `HashMap`/`HashSet` (кладём по одному хэшу, ищем по другому). `data class` генерирует оба согласованно — поэтому в Kotlin это редкая проблема.

> [!tip] Про String Pool и Integer cache на собесе
> - `String s = "Hello"` берётся из **String Pool** (литералы интернируются), а `new String("Hello")` всегда новый объект → `==` даст `false`. Сравнивать строки нужно через `equals` (в Kotlin — `==`).
> - `Integer` кэширует значения **−128…127**, поэтому `Integer a = 100; Integer b = 100; a == b` → `true`, а для `128` → `false`. В Kotlin аналогично для боксинга `Int?`.
