# Синхронные и асинхронные операции

**Синхронные** и **асинхронные** операции — это два подхода к выполнению задач. Они определяют, как программа ведёт себя с операциями, которые могут занять время (запрос к серверу, работа с файлами, БД и т. д.).

## 1. Синхронные операции

Выполняются последовательно: каждая операция блокирует выполнение программы, пока не завершится. Пока текущая не закончилась, следующая не начнётся.

**Характеристики:**

- **Блокировка.** Поток ждёт завершения операции и в это время не делает ничего другого.
- **Простой поток исполнения.** Задачи идут одна за другой.
- **Пример.** Синхронное чтение файла или HTTP-запрос: пока ответ не получен, программа не продолжит.

```kotlin
fun fetchData(): String {
    Thread.sleep(2000) // имитация долгой операции
    return "Data fetched"
}

fun main() {
    println("Fetching data...")
    val result = fetchData() // ждём завершения, поток заблокирован
    println(result)
}
```

## 2. Асинхронные операции

Выполняются, не блокируя вызывающий поток. Когда программа запускает асинхронную операцию, она продолжает делать другие задачи, а результат получит позже.

**Характеристики:**

- **Неблокирующие.** Поток не простаивает в ожидании.
- **Колбэки / Future / корутины.** Результат приходит через колбэк, `Future`/`Promise` или suspend-функцию.
- **Многозадачность.** Особенно важно для UI: длинные операции (сеть, БД) не должны блокировать главный поток.

```kotlin
import kotlinx.coroutines.*

suspend fun fetchDataAsync(): String {
    delay(2000) // приостанавливает корутину, НЕ блокируя поток
    return "Data fetched"
}

fun main() = runBlocking {
    println("Fetching data...")
    val result = async { fetchDataAsync() } // запускаем не блокируя
    // здесь можно делать другую работу...
    println(result.await())                  // получаем результат, когда готов
}
```

Здесь используются **корутины** — механизм асинхронного программирования в Kotlin. `delay()` приостанавливает корутину, освобождая поток для другой работы, а `await()` дожидается результата.

> [!warning] Не используйте `GlobalScope`
> Часто в примерах пишут `GlobalScope.async { ... }` — это **антипаттерн**: такая корутина живёт вне дерева задач, её никто не отменит вместе с экраном → утечки. Запускайте корутины в привязанном скоупе (`viewModelScope`, `lifecycleScope`, `coroutineScope`). См. [[Structured Concurrency]].

## 3. Асинхронность ≠ параллельность

Это разные понятия, которые часто путают.

### Параллельность (parallelism)

Выполнение нескольких операций **физически одновременно** на нескольких ядрах/процессорах.

- **Идея.** Задача делится на подзадачи, которые считаются одновременно на разных ядрах.
- **Когда нужна.** Ускорение вычислений: обработка больших данных, тяжёлые расчёты.
- Требует несколько ядер; есть затраты на синхронизацию и управление потоками.

### Асинхронность (asynchrony)

Выполнение операции **независимо** от вызывающего потока — работа не блокирует другие задачи.

- **Идея.** Ожидание результата происходит не в текущем потоке (другой поток, событие, suspend).
- **Когда нужна.** Операции ввода/вывода (сеть, файлы): важно не блокировать главный поток.
- Может работать даже на **одном** потоке (например, один поток обслуживает много неблокирующих I/O-операций).

### Сравнение

| Аспект            | Параллельность                                             | Асинхронность                                                       |
| ----------------- | --------------------------------------------------------- | ------------------------------------------------------------------ |
| Суть              | Несколько задач считаются **одновременно**                | Задача выполняется **не блокируя** вызывающий поток                 |
| Ресурсы           | Нужно несколько ядер/процессоров                          | Достаточно одного потока или небольшого пула                        |
| Блокировка потока | Потоки заняты вычислениями                                 | Поток свободен, продолжает другую работу                           |
| Типичный кейс     | CPU-bound: расчёты, обработка изображений                  | I/O-bound: сеть, диск, БД                                          |

> [!tip] Формулировка для собеса
> «**Конкурентность** (concurrency) — про *структуру*: умение работать с несколькими задачами одновременно (переключаясь между ними). **Параллельность** — про *выполнение*: задачи реально идут в один момент на разных ядрах. Можно быть конкурентным без параллелизма (один поток, корутины переключаются), и наоборот». Корутины дают конкурентность; параллельность добавляется через диспетчеры с пулом потоков (`Dispatchers.Default`).
