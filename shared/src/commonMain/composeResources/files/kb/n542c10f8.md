# DataStore

**Jetpack DataStore** — современная замена **SharedPreferences** для хранения небольших данных (настройки, флаги, токены). Решает фундаментальные проблемы `SharedPreferences`.

## Два вида

| Вид | Что хранит | Типобезопасность |
| --- | --- | --- |
| **Preferences DataStore** | пары ключ-значение (как SharedPreferences) | нет (ключи) |
| **Proto DataStore** | типизированный объект по схеме `.proto` | да, со схемой |

## Почему не SharedPreferences

> [!danger] Проблемы SharedPreferences, которые чинит DataStore
> 1. **`apply()` пишет асинхронно, но `commit()` — синхронно на диск**, и оба можно случайно вызвать на main → ANR/блокировки. SharedPreferences вообще **блокирует main** при первом чтении (загрузка всего файла).
> 2. **Нет обработки ошибок** — при повреждении файла молча теряются данные.
> 3. **Не реактивен** — только `OnSharedPreferenceChangeListener` (костыль), нельзя удобно наблюдать.
> 4. **Не транзакционен** — нет атомарного обновления нескольких значений.
> DataStore: **полностью асинхронный** (корутины + Flow), безопасно работает с main, отдаёт данные как **`Flow`**, обновление — `suspend`-транзакция, ошибки чтения ловятся.

## Использование (Preferences)

```kotlin
val Context.dataStore by preferencesDataStore(name = "settings")
val THEME = stringPreferencesKey("theme")

// чтение — реактивно
val themeFlow: Flow<String> = context.dataStore.data
    .map { prefs -> prefs[THEME] ?: "system" }

// запись — suspend, транзакционно
suspend fun setTheme(value: String) {
    context.dataStore.edit { it[THEME] = value }
}
```

> [!info] Под капотом
> DataStore сериализует данные в файл (Preferences — свой формат, Proto — protobuf), все операции идут через **один экземпляр** на файл, обёрнутый в корутины с гарантией консистентности. `data` — холодный `Flow`, эмитит при каждом изменении.

> [!warning] Частые грабли
> • **Один экземпляр на файл** — создавать `dataStore` через делегат на уровне `Context` (как выше), не плодить новые экземпляры на тот же файл (иначе `IllegalStateException`).
> • DataStore — **не БД**: для больших/структурированных/запрашиваемых данных это [[Room]], а не DataStore.
> • Чтение токена «прямо сейчас» синхронно нельзя — только через Flow/`first()`. Иногда это меняет архитектуру (репозиторий отдаёт Flow).

> [!tip] На собесе в одну фразу
> «SharedPreferences синхронен, блокирует main и не реактивен; DataStore — асинхронный на корутинах, отдаёт данные как Flow, транзакционные записи и обработка ошибок. Для пар ключ-значение — Preferences DataStore, для типизированных объектов — Proto.» В KMP key-value делают через **multiplatform-settings** или DataStore (см. [[KMP. Библиотеки экосистемы]]).
