Передача точной геолокации с определённым интервалом на Android требует использования API для определения местоположения, такого как **Fused Location Provider API**, который является частью Google Play Services. Этот подход обеспечивает баланс между точностью, энергопотреблением и частотой обновления.

**Шаги для реализации передачи геолокации**

**1. Добавьте необходимые разрешения**

В файле AndroidManifest.xml добавьте разрешения для получения местоположения:

```xml
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```

Если хотите получать данные в фоновом режиме, вам также потребуется использовать **foreground service**.

**2. Убедитесь, что разрешения запрашиваются во время выполнения**

Для Android 6.0+ (API 23 и выше), необходимо запросить разрешение у пользователя во время выполнения:

```kotlin
if (ContextCompat.checkSelfPermission(this, Manifest.permission.ACCESS_FINE_LOCATION) != PackageManager.PERMISSION_GRANTED) {
    ActivityCompat.requestPermissions(this, arrayOf(Manifest.permission.ACCESS_FINE_LOCATION), LOCATION_PERMISSION_REQUEST_CODE)
}
```

**3. Настройте FusedLocationProviderClient**

Класс FusedLocationProviderClient используется для получения местоположения.

Пример кода:

```kotlin
import android.Manifest
import android.annotation.SuppressLint
import android.content.pm.PackageManager
import android.location.Location
import android.os.Bundle
import android.os.Looper
import androidx.appcompat.app.AppCompatActivity
import androidx.core.app.ActivityCompat
import com.google.android.gms.location.*

class MainActivity : AppCompatActivity() {
    private lateinit var fusedLocationClient: FusedLocationProviderClient
    private lateinit var locationRequest: LocationRequest
    private lateinit var locationCallback: LocationCallback

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        fusedLocationClient = LocationServices.getFusedLocationProviderClient(this)

        // Настройка запросов на получение геолокации
        locationRequest = LocationRequest.create().apply {
            interval = 5000 // Интервал в миллисекундах (5 секунд)
            fastestInterval = 2000 // Минимальный интервал
            priority = LocationRequest.PRIORITY_HIGH_ACCURACY // Высокая точность
        }

        // Обработчик обновлений местоположения
        locationCallback = object : LocationCallback() {
            override fun onLocationResult(locationResult: LocationResult) {
                for (location in locationResult.locations) {
                    // Отправка или обработка полученного местоположения
                    sendLocationToServer(location)
                }
            }
        }

        startLocationUpdates()
    }

    @SuppressLint("MissingPermission") // Предполагается, что разрешения уже запрошены
    private fun startLocationUpdates() {
        if (ActivityCompat.checkSelfPermission(this, Manifest.permission.ACCESS_FINE_LOCATION) == PackageManager.PERMISSION_GRANTED) {
            fusedLocationClient.requestLocationUpdates(locationRequest, locationCallback, Looper.getMainLooper())
        }
    }

    private fun stopLocationUpdates() {
        fusedLocationClient.removeLocationUpdates(locationCallback)
    }

    private fun sendLocationToServer(location: Location) {
        // Здесь вы можете отправить местоположение на сервер через API
        println("Широта: ${location.latitude}, Долгота: ${location.longitude}")
    }

    override fun onDestroy() {
        super.onDestroy()
        stopLocationUpdates()
    }
}
```

**Объяснение работы кода**

1. **Настройка** LocationRequest**:**

• Устанавливаем интервал обновлений (interval и fastestInterval).
• Указываем приоритет (в данном случае PRIORITY_HIGH_ACCURACY для высокой точности).

2. **Создание** LocationCallback**:**

• В этом объекте обрабатываются обновления местоположения.
• В методе onLocationResult вы получаете список объектов Location, содержащих координаты.

3. **Включение и отключение обновлений местоположения:**

• fusedLocationClient.requestLocationUpdates() запускает получение геолокации.
• fusedLocationClient.removeLocationUpdates() останавливает обновления.

4. **Передача данных на сервер:**

• В методе sendLocationToServer можно отправить координаты на сервер через REST API, используя Retrofit, OkHttp или другие библиотеки.

> [!warning] `LocationRequest.create()` и `PRIORITY_*` устарели
> Старый API (`LocationRequest.create().apply { interval = ...; priority = LocationRequest.PRIORITY_HIGH_ACCURACY }`) **deprecated**. Современный вариант — builder:
> ```kotlin
> val locationRequest = LocationRequest.Builder(
>     Priority.PRIORITY_HIGH_ACCURACY,
>     5000L // intervalMillis
> ).setMinUpdateIntervalMillis(2000L).build()
> ```
> Константы приоритета переехали в класс **`Priority`** (`Priority.PRIORITY_HIGH_ACCURACY`, `Priority.PRIORITY_BALANCED_POWER_ACCURACY` и т.д.).

> [!important] Утечка при обновлениях локации в Activity
> `requestLocationUpdates` запущен в `onCreate`, а `removeLocationUpdates` — в `onDestroy`. Это работает, но при `HIGH_ACCURACY` GPS молотит **даже когда экран в фоне** (Activity не уничтожена, но не видна). Корректнее привязывать старт/стоп к **`onResume`/`onPause`**, а для фона использовать **Foreground Service**, а не Activity. См. [[Способы передачи геолокации в фоновом режиме]].

> [!tip] Callback на главном потоке
> `Looper.getMainLooper()` доставляет `onLocationResult` в UI-поток — удобно для обновления UI, но тяжёлую обработку/отправку на сервер оттуда запускать нельзя. В Service лучше отдать callback на отдельный `HandlerThread`.
