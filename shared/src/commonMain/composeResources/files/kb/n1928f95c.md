Android — это операционная система на основе ядра Linux, предназначенная для мобильных устройств, таких как смартфоны, планшеты, умные часы и телевизоры. Она включает несколько уровней, которые обеспечивают работу приложений, управление устройством и взаимодействие пользователя с системой.

**Основные уровни архитектуры Android**

1. **Ядро Linux (Linux Kernel)**:

• Основа операционной системы Android.
• Обеспечивает низкоуровневые функции, такие как управление памятью, планирование процессов, сеть и драйверы оборудования.
• Драйверы включают поддержку дисплеев, камер, аудиоустройств, Bluetooth и других компонентов.

2. **Библиотеки (Libraries)**:

• Набор библиотек на языке C/C++, обеспечивающих работу функций системы:
• **Bionic libc**: стандартная библиотека C для Android.
• **OpenGL ES**: для рендеринга 2D/3D-графики.
• **SQLite**: для работы с базами данных.
• **WebKit**: для отображения веб-контента.
• **Media Framework**: для воспроизведения аудио и видео.

3. **Android Runtime (ART)**:

• Среда выполнения приложений.
• Заменяет Dalvik (с версии Android 5.0).
• Выполняет приложения на основе скомпилированного байт-кода, конвертированного в машинный код с помощью AOT (Ahead-of-Time) или JIT (Just-in-Time) компиляции.

4. **Фреймворк приложений (Application Framework)**:

• Предоставляет API для взаимодействия с системными функциями и сервисами:
• **Activity Manager**: управление жизненным циклом приложений.
• **Window Manager**: управление окнами.
• **Content Providers**: доступ к данным между приложениями.
• **Location Manager**: доступ к геолокации.
• **Notification Manager**: управление уведомлениями.

5. **Приложения (Applications)**:

• Это программы, написанные на Java/Kotlin, которые пользователь запускает на устройстве.
• Они работают в изолированных процессах, что обеспечивает безопасность и стабильность системы.

**Компиляция и сборка Android-приложения**

Процесс сборки Android-приложения состоит из нескольких этапов, которые превращают исходный код и ресурсы в финальный APK-файл (Android Package). Этот процесс управляется инструментами, такими как Gradle и Android Studio.

**1. Исходный код**

• Основной код приложения пишется на **Java** или **Kotlin**.
• Интерфейсы описываются в **XML**.

**2. Процесс сборки**

Сборка приложения происходит в несколько шагов:

**2.1 Компиляция исходного кода (Java/Kotlin → байт-код)**

• **Код на Java/Kotlin** компилируется с помощью **Kotlin Compiler** или **Java Compiler**.
• Результатом компиляции являются файлы .class, содержащие байт-код Java.

**2.2 Конвертация в байт-код DEX (Dalvik Executable)**

• Файлы .class преобразуются в **.dex** (Dalvik Executable) с помощью инструмента **D8/R8**.
• Формат .dex оптимизирован для выполнения в среде Android Runtime (ART/Dalvik).

**2.3 Обработка ресурсов**

• XML-файлы интерфейсов, строки, изображения и другие ресурсы обрабатываются инструментом **AAPT (Android Asset Packaging Tool)**:
• Генерируется файл R.java (или R.kt), содержащий ссылки на ресурсы.
• Все ресурсы упаковываются в сжатом виде.

**2.4 Минификация и обфускация (опционально)**

• С помощью инструмента **R8/ProGuard**:
• Удаляется неиспользуемый код.
• Применяется обфускация для уменьшения размера и повышения сложности анализа кода.


**2.5 Сборка APK**

• Все компоненты (байт-код .dex, ресурсы, метаданные) объединяются в единый файл APK.
• Инструмент сборки Gradle использует apkbuilder для создания APK.


**2.6 Подпись APK**

• APK подписывается ключом разработчика с помощью инструмента **apksigner**.
• Подпись гарантирует, что APK не был изменён после сборки.

**2.7 Выравнивание (Zipalign)**

• APK проходит оптимизацию с помощью инструмента **zipalign**, чтобы ресурсы могли загружаться быстрее.

**3. Установка и выполнение приложения**

1. **Установка APK:**

• Установленный APK распаковывается в системе, а его байт-код DEX загружается в память.
• Ресурсы и файлы манифеста используются для настройки приложения.

2. **Запуск:**

• ART выполняет компиляцию JIT или использует AOT-компиляцию, чтобы ускорить запуск приложения.
• Приложение работает в собственном процессе с виртуальной машиной ART.

> [!tip] Что добавить на собесе
> - **APK vs AAB:** в Google Play публикуют **Android App Bundle (.aab)** — Play сам генерирует оптимизированные APK под конкретное устройство (только нужная плотность/архитектура/язык), уменьшая размер скачивания.
> - **Между ядром и библиотеками есть HAL** (Hardware Abstraction Layer) — абстракция над драйверами для камеры, сенсоров и т.д.
> - **ART:** при установке делает AOT-компиляцию (`dex2oat`) горячих участков в нативный код, остальное — JIT в рантайме + профилирование. Раньше был **Dalvik** (только JIT). Каждое приложение порождается из процесса **Zygote** (общие классы фреймворка, copy-on-write).
> - **D8** — дексер (`.class` → `.dex`), **R8** — дексер + минификатор/обфускатор (замена ProGuard).
