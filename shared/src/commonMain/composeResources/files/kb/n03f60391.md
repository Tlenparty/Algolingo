Объектно-Ориентированное Программирование (**ООП**) базируется на **четырёх принципах**:

1️⃣ **Абстракция (Abstraction)**
2️⃣ **Инкапсуляция (Encapsulation)**
3️⃣ **Наследование (Inheritance)**
4️⃣ **Полиморфизм (Polymorphism)**

## **1. Инкапсуляция**

Инкапсуляция — это принцип объединения данных (полей) и методов (функций), работающих с этими данными, в один объект. Она позволяет скрывать внутреннюю реализацию объекта от внешнего мира, предоставляя доступ только через определённые интерфейсы (методы).

**Цель:**
• Скрыть детали реализации (инкапсуляция данных).
• Обеспечить контроль над доступом к данным.

**Пример:**

```kotlin
class Person(private var name: String, private var age: Int) {

    fun getName(): String {
        return name
    }

    fun setName(newName: String) {
        name = newName
    }
}
```

```kotlin
class BankAccount(private var balance: Double) { // Поле private
    fun deposit(amount: Double) {
        if (amount > 0) {
            balance += amount
            println("Баланс пополнен: $balance")
        } else {
            println("Неверная сумма!")
        }
    }

    fun getBalance(): Double {
        return balance
    }
}

fun main() {
    val account = BankAccount(100.0)
    account.deposit(50.0) // Баланс пополнен: 150.0
    println(account.getBalance()) // 150.0
}
```

## **2. Наследование**

Наследование — это возможность ==создавать новые классы на основе существующих. ==Новый класс (наследник) перенимает свойства и методы базового класса, но может их изменять (переопределять) или добавлять новые.

**Цель:**

• Повторное использование кода.
• Организация иерархий классов.

**Пример:**

```kotlin
open class Animal {
    open fun sound() {
        println("Some generic animal sound")
    }
}

class Dog : Animal() {
    override fun sound() {
        println("Bark")
    }
}
```

## **3. Полиморфизм**

Полиморфизм — это способность объектов разного типа обрабатывать одно и то же сообщение (вызов метода) по-разному. Это может быть достигнуто за счёт переопределения методов в наследниках или реализации интерфейсов.

**Цель:**
• Универсальность кода, возможность работы с разными объектами через единый интерфейс.

**Пример:**

```kotlin
open class Shape {
    open fun draw() {
        println("Drawing a shape")
    }
}

class Circle : Shape() {
    override fun draw() {
        println("Drawing a circle")
    }
}

class Square : Shape() {
    override fun draw() {
        println("Drawing a square")
    }
}

fun drawShape(shape: Shape) {
    shape.draw()
}

drawShape(Circle()) // Output: Drawing a circle
drawShape(Square()) // Output: Drawing a square
```

## **4. Абстракция**

Абстрактный класс в программировании используется для ==создания общего шаблона== или базовой структуры, ==на основе которой могут быть построены конкретные классы==. Он служит основой для проектирования и организации классов в иерархии. Абстрактные классы сами по себе не могут быть созданы как экземпляры, а предназначены только для наследования.

### **Зачем нужен абстрактный класс?**

1. **Создание общего интерфейса для подклассов.**

Абстрактный класс определяет базовую функциональность, которую должны реализовать все его подклассы. Это гарантирует, что все подклассы будут иметь одинаковый набор обязательных методов.

2. **Частичная реализация.**

Абстрактный класс может содержать как абстрактные методы (без реализации), так и методы с реализацией. Это позволяет делиться общей логикой между подклассами, исключая дублирование кода.

3. **Организация структуры кода.**

Абстрактный класс помогает задать архитектурные рамки проекта, предоставляя основу для других классов и способствуя соблюдению принципа “от общего к частному”.

4. **Повышение читаемости и понимания кода.**

Он позволяет выразить намерение, что класс не предназначен для создания экземпляров, а только для использования в наследниках.

**Пример:**

```kotlin
abstract class Vehicle {
    abstract fun move()
}

class Car : Vehicle() {
    override fun move() {
        println("Car is driving")
    }
}

class Airplane : Vehicle() {
    override fun move() {
        println("Airplane is flying")
    }
}
```

Здесь Vehicle — абстрактный класс, который определяет интерфейс move, а конкретные классы (Car и Airplane) реализуют его по-своему.

## Противоречие ООП с SOLID ?

 **SOLID не противоречит ООП, а дополняет его**!

🔹 **ООП** (Объектно-Ориентированное Программирование) — это **парадигма** (общий подход к проектированию кода), включающая **инкапсуляцию, наследование, полиморфизм и абстракцию**.

🔹 **SOLID** — это набор **пяти принципов** проектирования **чистого и гибкого кода** в рамках ООП. Эти принципы помогают писать **поддерживаемый, расширяемый и переиспользуемый** код. См. [[SOLID]].

> [!tip] Инкапсуляция по-котлиновски
> В примере выше `getName()`/`setName()` — это **Java-стиль**. В Kotlin геттеры/сеттеры писать вручную не нужно — есть **свойства**:
> ```kotlin
> class Person(name: String) {
>     var name: String = name
>         private set            // читать можно снаружи, менять — только внутри
> }
> ```
> Инкапсуляция в Kotlin достигается модификаторами видимости свойств и `private set`, а не парами get/set-методов.

> [!note] Абстракция vs инкапсуляция (часто путают)
> - **Инкапсуляция** — *сокрытие реализации* (как сделано): прячем поля за модификаторами.
> - **Абстракция** — *выделение сути* (что делает, а не как): интерфейс/абстрактный класс описывает «что умеет» объект, скрывая детали.
> Их легко перепутать на собесе — держи это различие наготове.
