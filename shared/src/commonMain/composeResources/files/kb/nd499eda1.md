Делегаты в Kotlin — это механизм, позволяющий передавать ответственность за выполнение определённой задачи другому объекту. Делегаты позволяют использовать определённую логику без необходимости писать её вручную, что помогает делать код более чистым и удобным.

## **Как работают делегаты в Kotlin:**

1. **Делегирование свойств**:

В Kotlin есть механизм делегирования свойств, который позволяет передавать логику управления свойствами (полями класса) другому объекту. Вместо того чтобы каждый раз писать код для чтения или записи значения, можно передать это управление делегату.

2. **Ключевое слово** by:

В Kotlin делегирование свойств осуществляется через ключевое слово by. При этом объект, которому делегировано свойство, должен реализовывать соответствующий интерфейс, например, ReadOnlyProperty или ReadWriteProperty.
```kotlin
import kotlin.properties.ReadOnlyProperty
import kotlin.reflect.KProperty

class ReadOnlyDelegate : ReadOnlyProperty<Any?, String> {
    override fun getValue(thisRef: Any?, property: KProperty<*>): String {
        return "Value from ReadOnlyDelegate for property '${property.name}'"
    }
}

class Example {
    val readOnlyProperty by ReadOnlyDelegate()
}

fun main() {
    val example = Example()
    println(example.readOnlyProperty) 
    // Выведет: Value from ReadOnlyDelegate for property 'readOnlyProperty'
}
```

или
```kotlin
import kotlin.properties.ReadWriteProperty
import kotlin.reflect.KProperty

class ReadWriteDelegate : ReadWriteProperty<Any?, String> {
    private var storedValue: String = "Initial Value"

    override fun getValue(thisRef: Any?, property: KProperty<*>): String {
        return storedValue
    }

    override fun setValue(thisRef: Any?, property: KProperty<*>, value: String) {
        println("New value '${value}' is assigned to '${property.name}'")
        storedValue = value
    }
}

class Example {
    var readWriteProperty by ReadWriteDelegate()
}

fun main() {
    val example = Example()
    println(example.readWriteProperty) // Выведет: Initial Value
    example.readWriteProperty = "New Value" // Вывод: New value 'New Value' is assigned to 'readWriteProperty'
    println(example.readWriteProperty) // Выведет: New Value
}
```

**Пример делегирования:**

1. **Пример с делегированием для чтения (read-only)**:

Например, мы можем делегировать доступ к свойству объекта, который будет хранить его значение.

```kotlin
class Example {
    val myProperty: String by lazy {
        println("Initializing property")
        "Hello, World!" // Значение инициализируется при первом доступе
    }
}

fun main() {
    val example = Example()
    println(example.myProperty)  // Инициализация происходит только здесь
    println(example.myProperty)  // Далее свойство используется без повторной инициализации
}
```

**Что происходит:**

• В этом примере свойство myProperty делегировано объекту lazy, который откладывает инициализацию до первого обращения. Это полезно, когда нужно инициализировать свойство только при его использовании (поздняя инициализация).

2. **Пример с делегированием для записи и чтения (read-write)**:

В Kotlin можно также делегировать не только чтение, но и запись в свойство. Для этого можно использовать интерфейс ReadWriteProperty.

```kotlin
import kotlin.properties.Delegates

class Example {
    var myProperty: Int by Delegates.observable(0) { prop, old, new ->
        println("Property ${prop.name} changed from $old to $new")
    }
}

fun main() {
    val example = Example()
    example.myProperty = 10  // Выведет: Property myProperty changed from 0 to 10
    example.myProperty = 20  // Выведет: Property myProperty changed from 10 to 20
}
```

**Что происходит:**

• В данном примере используется делегат observable, который позволяет отслеживать изменения значения свойства myProperty. При каждом изменении выводится информация о старом и новом значении.

• Делегат observable требует указания начального значения и функции, которая будет вызываться при изменении значения.

**Примеры встроенных делегатов:**

1. lazy: Делегат для ленивой инициализации.

	• Инициализация переменной происходит только при первом доступе к ней.

2. observable: Делегат для отслеживания изменений значения.

	• Позволяет следить за тем, когда и как меняется значение переменной.

3. vetoable: Делегат, позволяющий контролировать изменения свойства.

	• Возвращает true, если значение изменено, или false, если значение не может быть изменено.

**Преимущества делегатов:**

• **Чистота кода**: Делегирование позволяет избежать дублирования кода для обработки свойств и логики их изменения.
• **Повторное использование**: С помощью делегатов можно повторно использовать логику (например, логику проверки или отслеживания изменений) без написания её каждый раз.
• **Отделение логики от данных**: Делегаты позволяют отделить бизнес-логику от данных, улучшая организацию и читаемость кода.

## Lateinit and lazy

lateinit и lazy — это два механизма в Kotlin для инициализации переменных, но они используются в разных ситуациях и имеют различные особенности.

### **1. lateinit**

lateinit используется для **отложенной инициализации** переменной, которая ==будет проинициализирована позже== (до первого использования).

• **Когда использовать?**

> Используется для переменных, которые не могут быть инициализированы в момент объявления, но гарантируется, что они будут инициализированы до первого использования.

• **Особенности:**
• Работает ==только с **var**== (переменные должны быть изменяемыми).
• Используется для ==**непримитивных типов**== данных (==например, классов, объектов==), так как для примитивов такой механизм не работает.
• Если попытаться обратиться к переменной до её инициализации, произойдёт исключение ==UninitializedPropertyAccessException==.

```kotlin
class Example {
    lateinit var myProperty: String

    fun initialize() {
        myProperty = "Hello, Kotlin"
    }
}

fun main() {
    val example = Example()
    example.initialize() // Инициализация переменной
    println(example.myProperty) // Использование переменной
}
```
• **Важное замечание**: lateinit не работает с типами данных, которые могут быть null, например, String?.

### **2. lazy**

lazy — это делегат для **ленивой инициализации**. Переменная, помеченная как lazy, будет инициализирована ==только при первом обращении к ней==.

• **Когда использовать?**

Используется, когда переменная ==должна быть инициализирована только один раз==, и её значение должно быть вычислено только при первом доступе к ней.

• **Особенности:**

• ==Работает с **val**== (неизменяемыми переменными), то есть переменная, инициализированная через lazy, должна быть **неизменяемой**.

• lazy позволяет более эффективно управлять памятью и ускорять запуск приложения, так как инициализация происходит только по мере необходимости.

• Под капотом используется механизм синхронизации (по умолчанию), чтобы ==гарантировать безопасность потоков при многозадачности.==

• **Пример:**

```kotlin
val myLazyProperty: String by lazy {
    println("Initializing property")
    "Hello, Kotlin"
}

fun main() {
    println("Before accessing lazy property")
    println(myLazyProperty)  // Инициализация произойдёт только при первом доступе
    println(myLazyProperty)  // Второй раз инициализация не произойдёт
}
```

• **Вывод:**

• "Before accessing lazy property"
• "Initializing property"
• "Hello, Kotlin"
• "Hello, Kotlin"

**Основные различия между lateinit и lazy:**

1. **`lateinit` vs `lazy`**:
    
    - `lateinit`: Переменная с модификатором `lateinit` должна быть инициализирована до ее первого использования. Использование переменной до инициализации вызовет исключение `UninitializedPropertyAccessException`.
    - `lazy`: Переменная с использованием `lazy` инициализируется при первом обращении к ней. Это ленивая инициализация, и значение переменной будет вычислено только при первом использовании, а затем кэшируется.

2. **Параметры для `lazy`**: Функция `lazy` принимает лямбда-выражение в качестве аргумента, которое возвращает значение, которое должно быть вычислено при первом обращении к переменной. Кроме того, `lazy` принимает параметр `LazyThreadSafetyMode`, который определяет режим безопасности потоков для доступа к значению переменной. Возможные значения:
    
    - `SYNCHRONIZED`: Гарантирует, что значение переменной будет вычислено только один раз, и предоставляет безопасный доступ к этому значению из нескольких потоков.
    - `PUBLICATION`: Также гарантирует, что значение переменной будет вычислено только один раз, но не предоставляет безопасного доступа к этому значению из нескольких потоков.
    - `NONE`: Не предоставляет никакой защиты от нескольких потоков при доступе к значению переменной.

| Аспект                               | lateinit                                                                          | lazy                                                                                   |
| ------------------------------------ | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Тип переменной                       | Только var                                                                        | Только val                                                                             |
| Тип данных                           | ==Только **непримитивные** типы (например, классы)==                              | Работает с любыми типами, в том числе с примитивами                                    |
| **Когда инициализируется?**          | Инициализация происходит вручную, после создания объекта                          | Инициализация происходит при первом доступе к переменно                                |
| **Использование**                    | При необходимости отложенной инициализации переменной                             | Когда нужно отложить инициализацию для вычисления значения один раз                    |
| **Работа с** null                    | ==Не работает с переменными, которые могут быть null==                            | Работает с любыми типами, в том числе с типами, которые могут быть null                |
| **Проверка на инициализацию**        | Приводит к исключению, если переменная не инициализирована (можно проверить через `::prop.isInitialized`) | Всегда инициализируется при первом доступе, не может быть «неинициализированной»        |
| **Использование с многозадачностью** | Не поддерживает синхронизацию по умолчанию                                        | Поддерживает синхронизацию, если используется по умолчанию в многозадачных приложениях |


## Почему lateinit часто считают «злом»

Исторически `lateinit` появился под нужды DI (Dagger) и инъекции в Android-компоненты. Допустимые применения — поля, внедряемые Dagger'ом, или ссылки на View/binding. Но у него есть минусы:

1. **`lateinit` требует `var`** — переменную можно перезаписать в любой момент (теряется неизменность).
2. **Обращение до инициализации → краш** (`UninitializedPropertyAccessException`).
3. **Во фрагментах `lateinit var binding` — частый источник утечек/крашей.** View живёт меньше фрагмента (`onCreateView`…`onDestroyView`), и обращение к `binding` после `onDestroyView` падает. Правильно — обнулять binding в `onDestroyView` или использовать паттерн `viewBinding` через делегат жизненного цикла.

> [!tip] lateinit vs lazy на собесе
> - **`lateinit var`** — значение **присваивается снаружи** позже (DI, `onCreate`); только не-nullable ссылочные типы; можно проверить `::x.isInitialized`.
> - **`val by lazy`** — значение **вычисляется само** при первом обращении и кэшируется; потокобезопасно по умолчанию (`SYNCHRONIZED`).
> - Альтернатива обоим — обычное nullable-поле `var x: T? = null` с явной проверкой; безопаснее `lateinit`, но многословнее.
