**📌 Что такое Snapshot в Jetpack Compose?**

Snapshot — это **основной механизм управления состоянием в Jetpack Compose**, который позволяет:

• **Отслеживать изменения состояния (**mutableStateOf**)**
• **Группировать изменения и откатывать их при ошибках**
• **Оптимизировать рекомпозицию и избегать лишних обновлений UI**

📌 Snapshot — это аналог транзакционной системы, где Compose отслеживает **“что изменилось” и “кто зависит от этих изменений”**, а затем **оптимально обновляет UI**.

**🎯 Как работает Snapshot под капотом?**

**🔹 1. SnapshotState отслеживает изменения**

Когда мы создаём mutableStateOf, он использует SnapshotState:
```kotlin
val count = mutableStateOf(0)
```

🔍 Внутри mutableStateOf(0) делает две вещи:

1. Создаёт объект StateRecord, который хранит текущее значение (count = 0).
2. Добавляет этот StateRecord в глобальный Snapshot, который следит за изменениями.

> **Важно:** SnapshotState — это **не просто переменная**, а объект, который уведомляет систему о каждом изменении!

**🔹 2. Snapshot отслеживает, какие @Composable используют состояние**

Когда в @Composable вызывается count.value:
```kotlin
Text("Clicked ${count.value} times")
```

**Compose запоминает, что этот** Text **зависит от** count.value**!**

Это делается с помощью Snapshot Observer, который создаёт связь между состоянием и UI.

**🔹 3. При изменении count.value вызывается Snapshot.notifyObjectsChanged()**
```kotlin
count.value++ // Уведомляет Compose об изменении состояния
```

Когда count.value изменяется:

• Snapshot **помечает** Text **как устаревший (invalidated)**
• Запускается **рекомпозиция только для** Text, а не для всего UI!

📌 **Таким образом, Compose обновляет только изменённые элементы UI, а не весь экран!**

**🔥 Как Snapshot оптимизирует состояние?**

  

**✅ 1. Группировка изменений с `Snapshot.withMutableSnapshot {}`**

Если мы изменяем несколько `mutableStateOf` внутри одного снапшота, наблюдатели увидят изменения **атомарно** — за одну рекомпозицию:

```kotlin
Snapshot.withMutableSnapshot {
    count1.value++
    count2.value++
} // ✅ изменения применяются вместе
```

**✅ 2. Откат изменений с snapshot.takeSnapshot()**

Можно **создать снимок состояния** и откатить изменения, если что-то пошло не так:
```kotlin
val snapshot = Snapshot.takeSnapshot()
try {
    count.value++ 
    name.value = "New Name"
    // Что-то пошло не так? Откатываем!
    snapshot.restore() 
} finally {
    snapshot.dispose()
}
```

📌 Это как **“undo” для состояния**, полезно при изменениях с возможностью отмены.


**✅ 3. Отложенные обновления через mutable snapshot + apply()**

Можно изменить состояние в изолированном снапшоте и применить изменения разом вызовом `apply()`:

```kotlin
val snapshot = Snapshot.takeMutableSnapshot()
snapshot.enter {
    count.value++
    name.value = "Updated"
}
snapshot.apply()   // ✅ изменения становятся видимыми атомарно
snapshot.dispose()
```

**🏆 Вывод**

• Snapshot **управляет состоянием в Compose и отслеживает зависимости.**
• **При изменении** mutableStateOf**,** Snapshot **помечает затронутые** @Composable **и запускает рекомпозицию только для них.**
• **Позволяет откатывать, группировать и оптимизировать изменения.**
• **Делает обновление UI быстрым и эффективным! 🚀**


 ### **Как работают Snapshot и Slot Table вместе?**
Snapshot и Slot Table работают в связке, чтобы обеспечивать эффективную **рекомпозицию UI** при изменении состояния.


**🔹 1. Структура Slot Table**


Slot Table можно представить как таблицу или список слотов, где каждый слот:

• Содержит информацию о @Composable **функции**.
• Хранит **состояние** (например, значение, возвращаемое mutableStateOf).
• Следит за **зависимостями** — то есть, какие состояния влияют на данный элемент UI.

Когда Compose вызывает @Composable функцию, например:
```kotlin
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) }
    Button(onClick = { count++ }) {
        Text("Clicked $count times")
    }
}
```

• В Slot Table будет записано, что:
• Button зависит от состояния count.
• Text зависит от count.

📌 **Задача** Slot Table **— следить за состоянием и зависимостями между элементами UI.**



**🔹 2. Структура Snapshot и отслеживание изменений**

Snapshot — это основа механизма отслеживания изменений состояния в Compose. Когда мы создаём mutableStateOf, например:
```kotlin
val count = remember { mutableStateOf(0) }
```

Он **отслеживает** состояние и **вызывает обновления** в UI, когда это состояние изменяется.
Когда мы изменяем count.value, например:
count.value++
Snapshot отслеживает, что значение count.value изменилось и **уведомляет** Slot Table, что Text (который использует count) нужно обновить.

**🔹 3. Взаимодействие Snapshot и Slot Table**

1. **Состояние и его изменения**

Когда значение состояния изменяется, например, при вызове count.value++, Snapshot уведомляет о том, что состояние изменилось.

2. **Обновление зависимых** @Composable

Slot Table хранит информацию о том, какие @Composable функции зависят от этого состояния. В случае с Counter(), Text("Clicked $count times") зависит от count.

1. **Рекомпозиция**

Когда Snapshot обнаруживает изменение, он помечает зависимые элементы UI в Slot Table как **устаревшие**. Затем происходит **рекомпозиция только этих элементов**, а не всего UI.


📌 **Таким образом,** Snapshot **отслеживает изменения в состоянии, а** Slot Table **управляет зависимостями и рекомпозицией UI.**

> [!tip] Аналогия для собеса
> Snapshot State — это **MVCC-подобная (как в БД) система версий состояния**. Каждый поток/корутина видит свой консистентный «снимок» состояния; изменения применяются атомарно через `apply()`. Отсюда два следствия:
> - **Чтение** `State` внутри `@Composable` регистрирует подписку → при изменении будет рекомпозиция.
> - **Запись** можно делать из любого потока — Snapshot обеспечит согласованность.
>
> Это и есть ответ на вопрос «почему `mutableStateOf` потокобезопасен, а обычный `var` — нет».
