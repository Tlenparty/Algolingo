# Atomic — принцип работы

`Atomic*`-классы (`AtomicInteger`, `AtomicLong`, `AtomicBoolean`, `AtomicReference`) предоставляют потокобезопасные операции над одной переменной **без блокировок**. В основе — аппаратная инструкция **CAS** (compare-and-swap) плюс `volatile` для видимости.

> **На собес одной фразой:** атомики работают на CAS — «сравни-и-обменяй»: атомарно проверяют, что значение не изменилось, и только тогда пишут новое; `volatile` гарантирует, что изменение увидят все потоки. Это lock-free: без блокировки потока, в цикле повторных попыток.

## Ключевые принципы

1. **Атомарные операции.** Методы `getAndIncrement()`, `compareAndSet()`, `getAndSet()`, `updateAndGet()` выполняются неделимо — переключение контекста в середине операции невозможно.
2. **Compare-and-Swap (CAS).** Базовый механизм: сравнить текущее значение с ожидаемым и, если совпало, записать новое. Выполняется атомарно; при неудаче — повторяется в цикле.
3. **Видимость через `volatile`.** Внутреннее поле — `volatile`, поэтому запись одним потоком сразу видна остальным (мимо кешей). См. [[Volatile]]. CAS решает атомарность, `volatile` — видимость: вместе они дают корректность.
4. **Lock-free.** Нет ожидания блокировок → выше пропускная способность при высокой конкуренции и нет риска deadlock.
5. **Платформозависимость.** На большинстве архитектур CAS ложится на одну процессорную инструкцию; конкретная реализация зависит от JVM/CPU.

## CAS-цикл (retry loop)

`incrementAndGet` и подобные внутри — это цикл: прочитать текущее, вычислить новое, попытаться записать через CAS; если другой поток опередил — повторить.

```kotlin
// Псевдо-реализация incrementAndGet поверх CAS
fun incrementAndGet(): Int {
    while (true) {
        val current = get()                  // читаем текущее (volatile-чтение)
        val next = current + 1               // вычисляем новое
        if (compareAndSet(current, next)) {  // пишем, только если значение не изменилось
            return next                      // успех
        }
        // иначе кто-то опередил — крутим цикл заново
    }
}
```

## Пример: инкремент и декремент из двух потоков

```kotlin
import java.util.concurrent.atomic.AtomicInteger

fun main() {
    val counter = AtomicInteger(0)

    val thread1 = Thread { repeat(1000) { counter.incrementAndGet() } } // атомарный ++
    val thread2 = Thread { repeat(1000) { counter.decrementAndGet() } } // атомарный --

    thread1.start(); thread2.start()
    thread1.join();  thread2.join()

    println("Counter value: ${counter.get()}")   // 0 — гонок данных нет
}
```
Каждая операция инкремента/декремента выполняется целиком до того, как другой поток вклинится, поэтому итог детерминирован (`0`). Обычный `Int` тут дал бы случайный результат — см. [[Гонка данных]].

## Lock-free vs блокировки

| | `Atomic` (CAS) | `synchronized` / `Mutex` |
|---|---|---|
| Механизм | неблокирующий CAS-цикл | блокировка (поток засыпает) |
| Область | **одна** переменная | произвольный блок кода |
| Накладные расходы | низкие при слабой конкуренции | выше (парковка/пробуждение) |
| Риск | много ретраев при жёсткой конкуренции | deadlock при неверной работе с локами |

## Когда чего хватает

- **Атомик** — меняешь **одну** переменную (счётчик, флаг, ссылка).
- **`Mutex`/`synchronized`** — надо атомарно изменить **несколько** переменных или защитить составную операцию.
