**🔹 1. Что такое атомарная операция?**

**Атомарность (Atomicity)** означает, что операция выполняется **целиком или не выполняется вообще**.

📌 **Ключевые особенности атомарных операций:**

✔ Не может быть **прервана**
✔ Работает с **одним объектом/переменной**
✔ Не требует явного **фиксации (commit)** или **отката (rollback)**

✅ **Пример атомарной операции в AtomicInteger:**
```kotlin
val counter = AtomicInteger(0)

// Атомарно увеличиваем значение
counter.incrementAndGet()  // Это выполняется за ОДИН шаг
```

🔹 **Здесь операция атомарна, потому что выполняется без промежуточных состояний.**

**🔹 2. Что такое транзакция?**

**Транзакция** – это группа операций, которая должна быть выполнена **как единое целое** (либо все, либо ничего).

📌 **Ключевые особенности транзакции:**

✔ Может включать **много операций**
✔ Поддерживает **откат (rollback)** при ошибке
✔ Часто используется в **базах данных**

✅ **Пример транзакции в SQL:**
```sql
BEGIN TRANSACTION;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;  -- Подтверждаем изменения
```

**🔥 Основные отличия**

| **Фактор**                        | **Атомарная операция**                     | **Транзакция**                             |
| --------------------------------- | ------------------------------------------ | ------------------------------------------ |
| **Что затрагивает?**              | Одну переменную или объект                 | Несколько операций                         |
| **Можно ли откатить (rollback)?** | ❌ Нет                                      | ✅ Да                                       |
| **Как выполняется?**              | За один шаг (без промежуточных состояний)  | Несколько шагов (но либо все, либо ничего) |
| **Где применяется?**              | AtomicInteger, AtomicLong, AtomicReference | Базы данных, файловые системы              |
| **Пример**                        | counter.incrementAndGet()                  | BEGIN TRANSACTION; COMMIT;                 |

> [!info] Как `AtomicInteger` достигает атомарности — CAS
> Под капотом atomic-классы используют **CAS (Compare-And-Swap)** — аппаратную инструкцию процессора: «если значение по адресу всё ещё `X`, замени на `Y`, иначе повтори». Это **lock-free**: нет блокировки потока, при конфликте операция просто повторяется в цикле. Поэтому `incrementAndGet()` атомарен без `synchronized`.

> [!warning] Атомарность отдельных операций ≠ атомарность их комбинации
> Даже из атомарных операций легко собрать гонку (**check-then-act**):
> ```kotlin
> if (atomic.get() == 0) atomic.set(1) // НЕ атомарно как целое!
> ```
> Между `get` и `set` другой поток может вклиниться. Для «прочитать-проверить-записать» одним шагом есть `compareAndSet(expect, update)` или `updateAndGet { … }`.

> [!note] Слово «атомарность» в БД — часть ACID
> В транзакциях атомарность («всё или ничего») — лишь буква **A** из **ACID**: **A**tomicity, **C**onsistency, **I**solation, **D**urability. Это шире, чем атомарная CPU-операция: транзакция координирует **много** изменений и умеет откатываться. На Android транзакции БД — это `@Transaction` / `runInTransaction {}` в [[Room]]; внутри корутин критическую секцию защищают `Mutex.withLock`.
