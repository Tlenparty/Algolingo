Snapshot в Jetpack Compose — это механизм, который управляет состоянием и обеспечивает реактивность. Он отслеживает изменения в MutableState и контролирует, как они применяются в UI.

**1. Основные принципы Snapshot**

В Compose Snapshot работает по **Copy-on-Write** принципу. Это означает, что:

• Есть **глобальный снапшот**, который содержит текущее состояние.
• При изменении состояния создается **локальная копия снапшота** (private snapshot).
• Когда изменения завершены, снапшот **сливается** с глобальным.

**Зачем это нужно?**

• Позволяет безопасно изменять состояние в многопоточной среде.
• Обеспечивает согласованность данных при обновлениях UI.
• Позволяет делать **оптимизированные перерисовки**, не изменяя всю композицию.

**2. Ключевые классы в Snapshot**

Compose использует несколько ключевых классов для управления состоянием: 

| Класс                 | Описание                                        |
| --------------------- | ----------------------------------------------- |
| Snapshot              | Представляет моментальный снимок состояния      |
| ``MutableState<T>``   | Оборачивает значение и делает его отслеживаемым |
| SnapshotStateObserver | Позволяет следить за изменениями состояния      |
| SnapshotTransaction   | Группа изменений, которые применяются атомарно  |

**3. Механизм работы**

**(1) Чтение состояния**

Когда Compose читает MutableState, он автоматически подписывается на его изменения. Например:
```kotlin
val count = remember { mutableStateOf(0) }

Text("Count: ${count.value}") // Compose подписывается на count
```

Теперь, если `count.value` изменится, этот `Text` будет перерисован.

**(2) Изменение состояния (Write)**

При изменении состояния создается **локальная копия снапшота**:
```kotlin
count.value += 1
```

• Compose сначала создает **локальный снапшот** (Copy-on-Write).
• После завершения изменения локальный снапшот **сливается** с глобальным.

**(3) Слияние снапшотов**

При завершении изменения Snapshot.apply() объединяет локальные изменения с глобальным:
```kotlin
Snapshot.withMutableSnapshot {
    count.value += 1
}
```

• withMutableSnapshot создает изолированную область изменений.
• После завершения изменений снапшот сливается с глобальным.
• **UI получает обновления**, и перерисовываются только затронутые Composables.

**4. Как Snapshot помогает с многопоточностью?**


Compose **гарантирует безопасность потоков**:

• Каждый поток может изменять состояние **в своем снапшоте**.
• Одновременно несколько потоков могут изменять MutableState, но их изменения **не видны другим потокам** до момента слияния.
• Если два потока изменяют одно и то же состояние, применяется стратегия **Last Write Wins** (LWW).


Пример использования Snapshot в нескольких потоках:
```kotlin

CoroutineScope(Dispatchers.Default).launch {
    Snapshot.withMutableSnapshot {
        count.value += 1
    }
}
```

**5. Оптимизации с SnapshotStateObserver**

Compose **отложенно применяет обновления**, если они не нужны.

Если состояние изменилось, но **никто не подписан** на его обновления, UI **не перерисовывается**.

```kotlin
val observer = SnapshotStateObserver {}
observer.observeReads({}) {
    println(count.value) // подписка на count
}
```

Когда `count.value` изменится, `observeReads` отловит это и вызовет перерисовку.

**6. Итог**

• Snapshot **позволяет отслеживать состояние** MutableState **и обновлять UI.**
• **Изменения происходят в локальном снапшоте и сливаются с глобальным.**
• **Работает по принципу Copy-on-Write, что повышает производительность.**
• **Безопасен для многопоточного окружения.**
