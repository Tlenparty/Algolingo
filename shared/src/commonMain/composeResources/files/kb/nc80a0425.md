**Standby Bucket** — это механизм в **Android** (начиная с **Android 9 Pie, API 28**), который определяет, **когда и как часто приложение может выполнять фоновые задачи** в зависимости от его использования.

📌 **Цель**: Оптимизировать расход **батареи** и **ресурсов** системы, ограничивая активность редко используемых приложений.

**🚀 Как работает Standby Bucket?**

Android автоматически помещает каждое приложение в одну из **5 категорий** (buckets), в зависимости от частоты его использования:

| **Bucket** **(Категория)**     | **Описание**                                              | **Ограничения**                    |
| ------------------------------ | --------------------------------------------------------- | ---------------------------------- |
| **Active**                     | Приложение запущено или недавно использовалось            | ❌ Нет ограничений                  |
| **Working Set**                | Приложение используется **регулярно**, но не прямо сейчас | ⏳ Ограниченный доступ к ресурсам   |
| **Frequent**                   | Приложение **редко** используется                         | ⏳ Ещё больше ограничений           |
| **Rare**                       | Приложение **почти не используется**                      | ⏳ Сильно ограничены фоновые задачи |
| **Restricted** _(Android 12+)_ | Пользователь **ограничил** активность приложения          | ⛔ Очень жёсткие лимиты             |

**🔥 Какие ограничения накладываются?**

**Чем ниже категория, тем реже Android позволяет:**

• Запускать **фоновые задачи** (например, WorkManager, JobScheduler).
• Получать **события от системы** (например, Alarms, Broadcasts).
• Использовать **сетевые запросы** в фоне.

📌 **Пример:**

• **Active:** Нет ограничений, можно выполнять любые фоновые задачи.
• **Rare:** Фоновые задачи выполняются **раз в несколько часов**.
• **Restricted:** Почти все фоновые задачи **блокируют**

**🛠 Как узнать Standby Bucket приложения?**

Можно получить текущую категорию с помощью **UsageStatsManager**:
```kotlin
val usageStatsManager = getSystemService(UsageStatsManager::class.java)
val bucket = usageStatsManager?.appStandbyBucket

when (bucket) {
    UsageStatsManager.STANDBY_BUCKET_ACTIVE -> println("Active")
    UsageStatsManager.STANDBY_BUCKET_WORKING_SET -> println("Working Set")
    UsageStatsManager.STANDBY_BUCKET_FREQUENT -> println("Frequent")
    UsageStatsManager.STANDBY_BUCKET_RARE -> println("Rare")
    UsageStatsManager.STANDBY_BUCKET_RESTRICTED -> println("Restricted")
    else -> println("Unknown")
}
```

**🎯 Вывод**

• **Standby Bucket** автоматически ограничивает активность приложений в фоне, **экономя батарею**.
• **Категория зависит от частоты использования приложения.**
• **Чем реже используется приложение, тем жёстче лимиты.**

## **🚀 Что такое Doze Mode в Android?**

**📌 Определение**

**Doze Mode** — это режим энергосбережения в Android, который **ограничивает фоновые процессы** и **сетевую активность** устройства, когда оно не используется.


📌 **Впервые появился в Android 6.0 (API 23, Marshmallow).**
📌 **Цель:** Уменьшить расход **батареи**, когда устройство **неактивно**.

**🔥 Как работает Doze Mode?**

1. 📵 **Телефон неактивен** (лежит без движения, экран выключен, не заряжается).
2. 💤 Android **включает Doze Mode** через некоторое время.
3. ❌ **Ограничиваются фоновые задачи**:

• Запрещается выполнение фоновых сервисов.
• Останавливаются **WakeLock**.
• Ограничивается доступ к **сети**.
• **Отключаются AlarmManager и WorkManager**, кроме GCM/Firebase сообщений с высоким приоритетом.

4. ⏳ **Периодические “окна активности”** (Maintenance Windows), когда система **разрешает** выполнение отложенных задач.

### **🏆 Этапы Doze Mode**

| Этап                        | Описание                       | Доступ к сети | Запуск фоновых задач | Alarm Manager                        |
| --------------------------- | ------------------------------ | ------------- | -------------------- | ------------------------------------ |
| **Light Doze** (Android 7+) | Лёгкий режим                   | ❌ Ограничен   | ✅ Разрешены          | ⏳ Только setAndAllowWhileIdle()      |
| **Deep Doze**               | Глубокий сон                   | ❌ Отключен    | ❌ Запрещены          | ⏳ Только setExactAndAllowWhileIdle() |
| **Maintenance Window**      | Короткие промежутки активности | ✅ Разрешен    | ✅ Разрешены          | ✅ Разрешены                          |
**🎯 Когда Doze Mode включается?**

✅ **Телефон лежит неподвижно, экран выключен, не заряжается**.

❌ **Doze Mode не включается, если:**

• Телефон **заряжается**.
• Идёт **активное движение** (например, в кармане или машине).
• Подключён к **Wi-Fi с высоким приоритетом** (например, звонки по Wi-Fi).

**🛠 Как обойти Doze Mode для важного функционала?**

1. **Foreground Service** (если активность нужна пользователю).
2. **Firebase Cloud Messaging (FCM)** — сообщения с **высоким приоритетом**.
3. **AlarmManager с** setExactAndAllowWhileIdle().
4. **Включить Whitelist в настройках (для критичных приложений, например, мессенджеров).**

```kotlin
val pm = getSystemService(PowerManager::class.java)
if (pm.isIgnoringBatteryOptimizations(packageName)) {
    println("Приложение в белом списке")
}
```

> [!tip] Главное для собеса
> **Doze** и **App Standby Buckets** — две части системы экономии батареи. Doze срабатывает, когда **устройство** неактивно (лежит, экран выключен); Standby Bucket — про конкретное **приложение** по частоте использования. Оба откладывают фоновую работу до «окон обслуживания».
>
> Практический вывод: для надёжной фоновой работы используй **WorkManager** (он сам учитывает Doze/ограничения и выполнит задачу в подходящее окно), для срочной доставки — **FCM high-priority**, для пользовательской длительной работы — **foreground service**. Прямой `Thread`/`AlarmManager` в Doze не сработает как ожидается. ⚠️ GCM устарел — сейчас только **FCM**.
