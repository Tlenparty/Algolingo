![[ia30bd705.png]]

- В активити мы получаем ссылку на ViewModel, используя
``  ViewModelProvider(this).get(ViewModel::class.java);``
- `ViewModelProvider` создаёт вью-модель и сохраняет её во `ViewModelStore`.
- Параметр, который мы передаём как `this` при получении `ViewModelProvider` имеет тип `ViewModelStoreOwner`, который как раз и хранит `ViewModelStore`. Если отследить, какие классы наследует наша активити, то видно, что она наследуется от [ComponentActivity](https://android.googlesource.com/platform/frameworks/support/+/8514bc0f4d930b5470435aa365719b2a6a3ad2f3/activity/src/main/java/androidx/activity/ComponentActivity.java "`ComponentActivity`"), которая реализует интерфейс `ViewModelStoreOwner`.
- Когда активити пересоздаётся, она сохраняет текущий `ViewModelStore`, используя свои методы ==`onRetainNonConfigurationInstance()`== и ==`getLastCustomNonConfigurationInstance()`==, а также статический класс `NonConfigurationInstances`.
- Также активити имеет `LifecycleEventObserver`, который слушает изменения жизненного цикла и, при уничтожении активити, вызывает `getViewModelStore().clear()`.

```kotlin
import androidx.lifecycle.ViewModel

class MainViewModel : ViewModel() {
    var counter: Int = 0

    fun increment() {
        counter++
    }

    override fun onCleared() {
        super.onCleared()
        println("MainViewModel уничтожена!") // логируем очистку
    }
}
```

📌 Класс `ViewModel` содержит счётчик, который должен сохраняться при повороте экрана.

**✅ 2. MainActivity.kt (Использование ViewModel в Activity)**
```kotlin

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.lifecycle.ViewModelProvider
import kotlinx.android.synthetic.main.activity_main.*

class MainActivity : ComponentActivity() {

    private lateinit var viewModel: MainViewModel

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // Получаем ViewModel через ViewModelProvider
        viewModel = ViewModelProvider(this).get(MainViewModel::class.java)

        setContentView(R.layout.activity_main)

        // Отображаем значение счётчика
        textView.text = "Counter: ${viewModel.counter}"

        button.setOnClickListener {
            viewModel.increment()
            textView.text = "Counter: ${viewModel.counter}"
        }
    }
}
```
📌 **Ключевые моменты:**

• ViewModelProvider(this).get(MainViewModel::class.java) получает ViewModel, который хранится в ViewModelStore.
• Даже если Activity пересоздаётся (например, при повороте экрана), ViewModel остаётся той же.
• Только при полном уничтожении Activity (например, когда пользователь закрывает приложение), ViewModel будет очищена (onCleared()).

**🔹 Как это работает под капотом?**
1. ViewModelProvider(this) использует ViewModelStoreOwner, который есть в Activity.
2. Activity (через ComponentActivity) переопределяет onRetainNonConfigurationInstance(), чтобы сохранить ViewModelStore.
3. Если Activity пересоздаётся (configuration change), она получает **тот же** ViewModelStore, а значит, и тот же ViewModel.
4. Когда Activity **уничтожается окончательно**, вызывается getViewModelStore().clear(), и ViewModel очищается (onCleared()).

## SavedStateRegistry

SavedStateRegistry — это компонент в Android, который управляет сохранением и восстановлением состояния компонентов в приложении, таких как Activity, Fragment, или ViewModel. Он используется для того, чтобы **сохранить данные**, которые могут быть утеряны при уничтожении компонента, например, при изменении конфигурации (поворот экрана) или завершении приложения системой из-за нехватки памяти.

SavedStateRegistry помогает **сохранить и восстановить состояние** компонента (например, Activity или Fragment), при этом делая этот процесс более универсальным и удобным, чем использование старого подхода с методом onSaveInstanceState().

**✅ 1. Как работает SavedStateRegistry?**

SavedStateRegistry предоставляет методы для:

1. **Регистрации состояния** (с помощью провайдера, который будет хранить данные).
2. **Восстановления состояния** (после пересоздания компонента).

Когда система уничтожает компонент, SavedStateRegistry сохраняет данные в объект Bundle, который может быть восстановлен при пересоздании компонента.

**✅ 2. Основные методы SavedStateRegistry:**

>• registerSavedStateProvider(key: String, provider: SavedStateProvider)

Метод, который позволяет зарегистрировать провайдер состояния для компонента с ключом key. Провайдер — это лямбда-функция, которая возвращает Bundle, в котором хранится состояние.

>• consumeRestoredStateForKey(key: String)

Этот метод используется для **восстановления сохранённого состояния**. Он возвращает Bundle, которое содержит данные, сохранённые под ключом key.

Предположим, что мы хотим сохранить счётчик в Activity:
```kotlin
class MainActivity : AppCompatActivity(), SavedStateRegistryOwner {

    private val savedStateRegistry = getSavedStateRegistry()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        // Сохраняем состояние
        savedStateRegistry.registerSavedStateProvider("countKey") {
            Bundle().apply {
                putInt("count", 5) // Сохраняем счётчик
            }
        }

        // Восстанавливаем состояние
        val restoredState = savedStateRegistry.consumeRestoredStateForKey("countKey")
        val count = restoredState?.getInt("count", 0) ?: 0

        val textView = findViewById<TextView>(R.id.textView)
        textView.text = "Count: $count"
    }
}
```
  
1. **Регистрация состояния**: С помощью метода registerSavedStateProvider() мы сохраняем состояние счётчика в Bundle под ключом "countKey".

2. **Восстановление состояния**: После уничтожения Activity и её пересоздания, мы восстанавливаем состояние с помощью метода consumeRestoredStateForKey().

**✅ 3. Для чего нужен SavedStateRegistry?**

**🔹 1. Для сохранения состояния при изменении конфигурации**

Когда, например, происходит поворот экрана, Activity или Fragment пересоздаются, и без сохранения состояния приложение теряет все данные. SavedStateRegistry позволяет сохранить данные и восстановить их после пересоздания.

**🔹 2. Для удобной работы с ViewModel и SavedStateHandle**

SavedStateRegistry позволяет интегрировать сохранение состояния с ViewModel и SavedStateHandle. Это позволяет сохранить и восстановить данные в ViewModel при уничтожении Activity или Fragment.

**🔹 3. Для работы с динамически изменяемыми данными**

Если ваше приложение обрабатывает данные, которые нужно сохранить (например, состояние формы или списка), SavedStateRegistry предоставляет механизм для автоматического сохранения этих данных.

**✅ 4. Как SavedStateRegistry интегрируется с другими компонентами?**

**🔹 Интеграция с ViewModel через SavedStateHandle**

Когда вы создаёте ViewModel с помощью SavedStateViewModelFactory, она получает доступ к SavedStateRegistryOwner, что позволяет использовать SavedStateHandle для автоматического сохранения и восстановления состояния внутри ViewModel.


Пример:
```kotlin
val viewModel: MyViewModel by viewModels { 
    SavedStateViewModelFactory(application, this)
}
```

• В этом примере SavedStateViewModelFactory создаёт ViewModel с поддержкой сохранения состояния.

• ViewModel может использовать SavedStateHandle, чтобы управлять сохранением состояния.

**✅ 5. Когда использовать SavedStateRegistry?**

• **Поворот экрана**: Если ваше приложение должно сохранять состояние при изменении конфигурации, например, при повороте экрана.
• **Процесс уничтожен системой**: Если система завершила процесс, например, для освобождения памяти, а вам нужно восстановить состояние после пересоздания.
• **Интеграция с** ViewModel: Когда вы хотите сохранить состояние в ViewModel или при работе с динамическими данными, которые должны быть восстановлены после уничтожения компонента.

**🚀 Вывод:**

• SavedStateRegistry — это механизм для сохранения и восстановления состояния компонента, например, Activity или Fragment.

• Он помогает управлять состоянием при **изменениях конфигурации**, **уничтожении** и **пересоздании** компонента.

• Он интегрируется с ViewModel и SavedStateHandle, что позволяет легко управлять сохранением состояния внутри вашего приложения.

🔥 **Используйте** SavedStateRegistry**, чтобы ваше приложение становилось устойчивым и не теряло данные при изменении конфигурации или уничтожении компонентов!** 🚀
## **SaveStateHandle в Android – что это и как работает?**

**📌 SavedStateHandle – это механизм сохранения состояния ViewModel при изменении конфигурации (например, поворот экрана) или в случае восстановления приложения после уничтожения системой.**

Ранее использовался onSaveInstanceState(), но SavedStateHandle интегрирован с **ViewModel** и управляется автоматически.

**✅ 1. Как работает SavedStateHandle?**

**🔹 Основные принципы:**

• Позволяет **сохранять и восстанавливать данные** в ViewModel.
• Автоматически управляется **Jetpack ViewModel**.
• Сохраняет данные **между уничтожением и пересозданием** Activity **или** Fragment.

**Как работает SavedStateHandle в связке с onSaveInstanceState()?**

**🔹 Основной механизм работы:**

1. **При создании** ViewModel **с** SavedStateHandle → система загружает данные из Bundle, переданного в onSaveInstanceState().

2. **При изменении значений в** SavedStateHandle **(**``state[key] = value``**)** → данные **автоматически записываются в** Bundle, привязанный к onSaveInstanceState().

3. **Когда** Activity **уничтожается (**onSaveInstanceState() **вызывается)** → SavedStateHandle **сохраняет данные в** Bundle.

4. **При пересоздании** Activity → SavedStateHandle получает Bundle и восстанавливает данные.

📌 **Таким образом,** SavedStateHandle **выступает как прослойка между** ViewModel **и** onSaveInstanceState()**, автоматически сохраняя данные.**

```kotlin

import androidx.lifecycle.SavedStateHandle
import androidx.lifecycle.ViewModel

class MyViewModel(private val state: SavedStateHandle) : ViewModel() {

    companion object {
        private const val KEY_COUNT = "count"
    }

    // LiveData с автоматическим сохранением
    val count = state.getLiveData(KEY_COUNT, 0)

    // Функция увеличения счётчика
    fun increment() {
        state[KEY_COUNT] = (state[KEY_COUNT] ?: 0) + 1
    }
}
```

🔹 **Как это работает?**

• SavedStateHandle создаётся автоматически и получает Bundle, если он есть.
• getLiveData(KEY, defaultValue) загружает сохранённое значение **или** берёт 0 по умолчанию.
• ``state[KEY] = value`` сохраняет новые данные в SavedStateHandle, а он уже передаёт их в onSaveInstanceState().

```kotlin

import android.os.Bundle
import androidx.activity.viewModels
import androidx.appcompat.app.AppCompatActivity
import androidx.lifecycle.Observer
import android.widget.Button
import android.widget.TextView

class MainActivity : AppCompatActivity() {
    private val viewModel: MyViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        val textView = findViewById<TextView>(R.id.textView)
        val button = findViewById<Button>(R.id.button)

        // Подписываемся на LiveData
        viewModel.count.observe(this, Observer { count ->
            textView.text = "Count: $count"
        })

        // Кнопка увеличивает счётчик
        button.setOnClickListener {
            viewModel.increment()
        }
    }
}
```

**🚀 Вывод**

✅ SavedStateHandle – это **прослойка между** ViewModel **и** onSaveInstanceState(), которая:

• **Автоматически сохраняет данные в** Bundle при уничтожении Activity.
• **Автоматически загружает данные при пересоздании** Activity**.**
• **Работает в связке с** SavedStateRegistry, встроенным в AndroidX.

🔥 **Теперь вам не нужно вручную писать** onSaveInstanceState() **–** SavedStateHandle **сделает всё за вас!** 🚀

## **SavedStateRegistryOwner**

SavedStateRegistryOwner — это интерфейс, который предоставляет доступ к механизму **сохранения и восстановления состояния** в **Android**. Он является частью **Jetpack** библиотеки, а точнее — SavedStateRegistry.

**✅ 1. Что такое SavedStateRegistryOwner?**

SavedStateRegistryOwner — это интерфейс, который реализуют компоненты, ответственные за управление **сохранением состояния**. К примеру, это могут быть:

• Activity
• Fragment

Этот интерфейс предоставляет доступ к объекту SavedStateRegistry, который управляет сохранением и восстановлением состояния.

**✅ 2. Как работает SavedStateRegistryOwner?**

```kotlin
interface SavedStateRegistryOwner {
    fun getSavedStateRegistry(): SavedStateRegistry
}
```

SavedStateRegistryOwner предоставляет доступ к методу getSavedStateRegistry(), который позволяет взаимодействовать с SavedStateRegistry для регистрации и восстановления состояния.

**🔹 Пример использования**

Например, Activity или Fragment реализуют этот интерфейс и предоставляют доступ к SavedStateRegistry, который управляет данными между пересозданиями:

```kotlin

class MyActivity : AppCompatActivity(), SavedStateRegistryOwner {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // Работа с SavedStateRegistry
        val stateRegistry = getSavedStateRegistry()

        // Регистрация состояния для ViewModel
        stateRegistry.registerSavedStateProvider("key") {
            Bundle().apply {
                putString("some_key", "some_value")
            }
        }
    }
}
```

🔹 **Что происходит здесь?**

• SavedStateRegistry отвечает за сохранение состояния в Bundle для ключа "key".
• Этот объект сохраняет данные, например, при изменении конфигурации или уничтожении компонента.

**✅ 3. Взаимодействие с SavedStateRegistry**

SavedStateRegistry позволяет:

• **Сохранять состояние** с помощью метода registerSavedStateProvider(), который регистрирует провайдер состояния для заданного ключа.
• **Восстанавливать состояние** с помощью метода consumeRestoredStateForKey(), который извлекает данные для заданного ключа.

Пример:
```kotlin
// Регистрация сохранённого состояния
savedStateRegistry.registerSavedStateProvider("myKey") {
    Bundle().apply {
        putString("username", "JohnDoe")
    }
}

// Восстановление состояния
val restoredState = savedStateRegistry.consumeRestoredStateForKey("myKey")
val username = restoredState?.getString("username")
```

**🔹 Как это работает:**

1. **Регистрация состояния** происходит с помощью registerSavedStateProvider().
2. **Восстановление состояния** осуществляется при пересоздании компонента (например, Activity) с помощью consumeRestoredStateForKey().

**✅ 4. Когда используется SavedStateRegistryOwner?**

SavedStateRegistryOwner используется:

1. **В** Activity **и** Fragment для управления сохранением состояния в SavedStateRegistry.

2. Для интеграции с SavedStateHandle, что позволяет сохранять и восстанавливать состояние **в** ViewModel.


**📌 Пример использования с ViewModel:**

Когда Activity или Fragment является SavedStateRegistryOwner, вы можете передать SavedStateRegistry в SavedStateViewModelFactory, чтобы передавать состояние в ViewModel.
```kotlin
val viewModel: MyViewModel by viewModels { 
    SavedStateViewModelFactory(application, this)
}
```


### Какая разница между SavedStateHandle и SavedStateRegistry ?? 

SavedStateHandle и SavedStateRegistry — оба механизма для сохранения состояния в Android, но они используются в разных контекстах. Давай разберёмся в их различиях.

**🔹 1. SavedStateHandle (Jetpack ViewModel)**

✅ **Где используется?**

Используется внутри ViewModel для хранения и восстановления состояния после уничтожения Activity/Fragment.

✅ **Как работает?**

• Работает как MutableLiveData, позволяя сохранять и восстанавливать данные.
• Поддерживает **переживание поворота экрана** и других конфигурационных изменений.
• Используется с ViewModel, интегрирован с ViewModelProvider.


✅ **Пример использования**

**Создаём ViewModel с SavedStateHandle**

```kotlin
class MyViewModel(private val savedStateHandle: SavedStateHandle) : ViewModel() {

    fun saveData(value: String) {
        savedStateHandle["key"] = value
    }

    fun getData(): String? {
        return savedStateHandle["key"]
    }
}
```

**Используем в Activity или Fragment**
```kotlin
class MainActivity : AppCompatActivity() {

    private lateinit var viewModel: MyViewModel

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        viewModel = ViewModelProvider(this, 
            SavedStateViewModelFactory(application, this))
            .get(MyViewModel::class.java)

        viewModel.saveData("Привет!")
        Log.d("MainActivity", viewModel.getData() ?: "Нет данных")
    }
}
```

✅ **Когда использовать** SavedStateHandle**?**

• Когда данные нужно хранить в ViewModel и **переживать конфигурационные изменения**
• Когда **не нужно** сохранять данные при закрытии приложения.


**🔹 2. SavedStateRegistry (Activity / Fragment API)**

✅ **Где используется?**

Применяется в Activity и Fragment напрямую, **не зависит от ViewModel**.


✅ **Как работает?**

• Позволяет вручную сохранять данные перед уничтожением Activity/Fragment.
• Не использует LiveData, нужно явно получать данные.
• Требует регистрации через SavedStateRegistryOwner.


✅ **Пример использования**

**Сохранение данных в Activity**

```kotlin
class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        val savedStateRegistry = savedStateRegistry

        if (savedStateRegistry.consumeRestoredStateForKey("my_key") != null) {
            val savedValue = savedStateRegistry
                .consumeRestoredStateForKey("my_key")
                ?.getString("key")
            Log.d("MainActivity", "Восстановленные данные: $savedValue")
        }

        savedStateRegistry.registerSavedStateProvider("my_key") {
            bundleOf("key" to "Привет от SavedStateRegistry!")
        }
    }
}
```

✅ **Когда использовать** SavedStateRegistry**?**

• Если работаешь напрямую с Activity или Fragment, без ViewModel.
• Если нужно вручную управлять процессом сохранения.
• Если используешь SavedStateRegistryOwner (например, для **кастомных компонентов**).

**📌 Основные отличия**


|                               | **SavedStateHandle**                                | **SavedStateRegistry**                           |
| ----------------------------- | --------------------------------------------------- | ------------------------------------------------ |
| 📍 Где используется?          | Внутри ViewModel                                    | В Activity и Fragment                            |
| 🔄 Поддерживает LiveData?     | ✅ Да, работает как LiveData                         | ❌ Нет, нужно запрашивать данные вручную          |
| 🔄 Переживает поворот экрана? | ✅ Да                                                | ✅ Да                                             |
| 💾 Переживает Process Death?  | ✅ Да, если есть ViewModelProvider                   | ✅ Да, но нужно вручную сохранять                 |
| 🛠 Интеграция с Jetpack?      | ✅ Да (ViewModel)                                    | ✅ Да (LifecycleOwner)                            |
| 📝 Как сохраняет данные?      | Автоматически через SavedStateHandle["key"] = value | Нужно вручную через registerSavedStateProvider() |


**🔥 Что выбрать?**

• **Если используешь** ViewModel **→** SavedStateHandle (автоматически работает с ViewModel).
• **Если работаешь напрямую с** Activity**/**Fragment **→** SavedStateRegistry (даёт больше контроля).

🚀 **Лучший вариант** — использовать SavedStateHandle вместе с ViewModel, так как это удобнее и безопаснее.

> [!important] Актуальность примеров
> - **`kotlinx.android.synthetic` удалён** (с Kotlin 1.8) — `import ...synthetic...` и обращение к `textView` по id больше не работают. Используйте **ViewBinding** (`binding.textView`) или Compose.
> - **Явный `SavedStateViewModelFactory(application, this)` обычно не нужен.** Современный `by viewModels()` сам предоставляет `SavedStateHandle`, если конструктор ViewModel его принимает:
>   ```kotlin
>   class MyViewModel(private val state: SavedStateHandle) : ViewModel() { ... }
>
>   // в Activity/Fragment — фабрику писать не надо:
>   private val viewModel: MyViewModel by viewModels()
>   ```
>   А с Hilt — `@HiltViewModel` + `@Inject constructor(savedStateHandle: SavedStateHandle)`.

> [!tip] Главное на собесе — три уровня
> - **ViewModel** переживает поворот (через `ViewModelStore` + `onRetainNonConfigurationInstance`), но **НЕ** смерть процесса.
> - **SavedStateHandle** = ViewModel + переживание смерти процесса (под капотом — `SavedStateRegistry` → `Bundle`). Это «лучшее из двух».
> - **`onSaveInstanceState`/`SavedStateRegistry`** — низкоуровневый механизм, на котором SavedStateHandle и построен.
