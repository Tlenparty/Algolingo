# Как сравниваются ключи в HashMap при одинаковом hashCode

Даже когда у ключей **совпал `hashCode`** (и они попали в один бакет), `HashMap` всё равно различает их точно — через `equals()`.

> **На собес одной фразой:** `hashCode` отвечает «в какой бакет», `equals` — «тот ли это ключ». Одинаковый хеш → один бакет, но внутри бакета решает `equals`.

## Как это работает

1. **Группировка по бакету.** Ключи с одинаковым `hashCode` попадают в одно «ведро» (bucket).
2. **Точное сравнение через `equals`.** Внутри бакета `HashMap` вызывает `equals()`, чтобы понять, эквивалентны ли ключи (найти нужный / отсеять дубликат).
3. **Список или дерево в бакете:**
   - **До Java 8** — бакет это связный список; поиск нужного ключа идёт по списку через `equals()` (`O(n)`).
   - **Java 8+** — при превышении порога (`≥ 8` элементов и таблица `≥ 64`) список превращается в красно-чёрное дерево (`TreeNode`), поиск ускоряется до `O(log n)`, но финальное «тот ли ключ» по-прежнему определяет `equals()`.

## Пример

```kotlin
class MyKey(val id: Int) {
    override fun hashCode() = 42                    // намеренно одинаковый хеш
    override fun equals(other: Any?) = other is MyKey && other.id == id
}

val map = HashMap<MyKey, String>()
val key1 = MyKey(1)   // hashCode = 42
val key2 = MyKey(2)   // hashCode = 42 — тот же бакет!

map[key1] = "Value1"
map[key2] = "Value2"  // тот же бакет, но equals(key1, key2) == false -> оба хранятся

println(map.size)     // 2 — коллизия по хешу, но ключи разные по equals
```

> ⚠️ Если бы `equals` вернул `true` для `key1` и `key2`, второй `put` **перезаписал** бы значение первого, и `size` был бы `1`. Именно поэтому `equals` и `hashCode` переопределяют **вместе**.
