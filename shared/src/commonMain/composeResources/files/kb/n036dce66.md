**Backing field** (вспомогательное поле) в Kotlin — это скрытое поле, которое используется для хранения значения свойства класса. Оно необходимо в тех случаях, когда вам нужно реализовать кастомный геттер или сеттер и при этом сохранить или изменить текущее значение свойства.


**🔍 Когда используется field?**
  
field — это специальное ключевое слово, доступное только внутри кастомных get и set методов. Оно автоматически ссылается на само хранимое значение свойства (то есть на **backing field**).


**📌 Пример использования backing field:**
```kotlin
class User {
    var name: String = "Unknown"
        get() {
            println("Геттер вызван")
            return field // Использование backing field
        }
        set(value) {
            println("Сеттер вызван")
            field = value // Присваивание через backing field
        }
}

fun main() {
    val user = User()
    println(user.name) // Геттер вызван, Unknown
    user.name = "Alice" // Сеттер вызван
    println(user.name) // Геттер вызван, Alice
}
```

**⚠️ Когда backing field обязателен?**

Если в сеттере или геттере используется свойство напрямую (например, name = value), это приведет к рекурсивному вызову метода и вызовет StackOverflowError. Использование field предотвращает эту проблему:
```kotlin
var name: String = "Unknown"
    set(value) {
        field = value // ✅ Правильно
        // name = value ❌ Ошибка! Рекурсивный вызов сеттера
    }
```

**🔄 Backing property (вспомогательное свойство)**

Если backing field не подходит, можно создать **backing property**:
```kotlin
private var _age: Int = 0

var age: Int
    get() = _age
    set(value) {
        if (value >= 0) _age = value
    }
```

> [!tip] Backing property — главный паттерн на собесе
> Самое частое применение backing property — **скрыть mutable-тип, наружу отдать read-only**. Так делают со `StateFlow` во ViewModel:
> ```kotlin
> private val _state = MutableStateFlow(UiState())
> val state: StateFlow<UiState> = _state.asStateFlow() // наружу только чтение
> ```
> Снаружи нельзя сделать `state.value = ...`, менять состояние может только сам ViewModel. То же — с `LiveData`/`MutableLiveData` и `List`/`MutableList`.
>
> Также помни: `field` доступен **только** внутри `get`/`set`. Если свойство не имеет backing field (например, `val full get() = "$first $last"`), Kotlin его и не генерирует.
