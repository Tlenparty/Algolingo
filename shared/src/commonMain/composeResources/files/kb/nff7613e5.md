**Что такое Generic в Kotlin и для чего они нужны?**

**Generic** (или обобщённые типы) в Kotlin — это механизм, позволяющий создавать классы, функции и интерфейсы, которые могут работать с любыми типами данных, но с сохранением строгой типовой безопасности. Это позволяет писать более универсальный и повторно используемый код, не теряя при этом информации о типах.

Вместо того чтобы создавать несколько версий классов и функций для разных типов, **Generic** позволяет создавать один универсальный класс или функцию, которые могут работать с любым типом данных, но будут типобезопасны.

**Пример использования Generic:**

```kotlin
// Обобщённый класс, который работает с любым типом
class Box<T>(val value: T)  // T — это параметр типа

fun main() {
    val intBox = Box(5)  // T будет заменён на Int
    val stringBox = Box("Hello")  // T будет заменён на String
    
    println(intBox.value)  // 5
    println(stringBox.value)  // Hello
}
```

Здесь ``Box<T>`` — это обобщённый класс, который может работать с любым типом, будь то Int, String или любой другой тип. Тип T определяется во время создания объекта класса.

**Почему используются Generic?**

1. **Параметризация типов:** Generic позволяют создавать универсальные типы, которые могут работать с разными типами данных.

Например, если вам нужно хранить в коллекции элементы разных типов, вам не нужно создавать разные коллекции для каждого типа данных.

2. **Повторное использование кода:** Generic помогают избежать дублирования кода, позволяя использовать один и тот же класс или функцию с разными типами.
3. **Типовая безопасность:** Несмотря на то, что вы работаете с обобщёнными типами, компилятор Kotlin обеспечит типовую безопасность, то есть предотвратит ошибки на уровне типов.

**Что значит in и out в контексте Generic в Kotlin?**
in и out — это **модификаторы типа**, которые используются в Kotlin для указания **ограничений по ковариантности** (для вывода данных) и **контравариантности** (для ввода данных) в обобщённых типах.

**1. out — ковариантность (вывод):**

Модификатор out указывает, что тип может быть только **выведен** (чтение данных) из этого обобщённого типа, но не может быть записан в него. Это означает, что класс с этим типом можно безопасно использовать только для **чтения**.

• Например, если у вас есть тип `Box<out T>`, вы можете получать (читать) объекты типа T, но не можете вносить туда объекты типа T.

• out используется, когда вы хотите гарантировать, что тип T может быть только возвращён, но не принят.

**Пример с out:**

```kotlin
// Ковариантный тип, который можно только читать
class Box<out T>(val value: T)

fun main() {
    // Создаем Box для типа Int
    val intBox: Box<Int> = Box(5)
    
    // Поскольку Box<Int> является подтипом Box<Any>, мы можем присвоить его Box<Any>
    val anyBox: Box<Any> = intBox
    
    // Теперь можем читать данные из anyBox
    println(anyBox.value)  // 5

    // Невозможно записать данные в anyBox, так как мы можем только читать
    // anyBox.value = "Hello"  // Ошибка компиляции
}
```
• **Что происходит здесь?**

• Класс `Box<out T>` использует out, что означает, что мы можем только **читать** данные из этого контейнера, но не записывать в него.

• Мы можем присвоить `Box<Int>` переменной типа`Box<Any>`, потому что `Box<Int>` является подтипом `Box<Any>`. Это возможно благодаря ковариантности (с использованием out).
  
**2. in — контравариантность (ввод):**

Модификатор in указывает, что тип может быть только **введён** (записан) в обобщённый тип, но не может быть извлечён из него. То есть тип T может быть только передан в функцию, но не возвращён из неё.

• Например, если у вас есть тип `Box<in T>`, вы можете передавать туда объекты типа T, но не можете извлекать (читать) объекты типа T.

**Пример с in:**

```kotlin
// Контравариантный тип, который можно только записывать
class Box<in T> {
    fun add(value: T) {
        println("Adding: $value")
    }
}

fun main() {
    // Создаем Box для типа Any
    val anyBox: Box<Any> = Box()
    
    // Мы можем передавать объекты типа String в Box<Any>
    anyBox.add("Hello")  // Adding: Hello

    // Мы также можем передавать объекты типа Int в Box<Any>
    anyBox.add(42)  // Adding: 42

    // Невозможно извлечь данные из Box<Any>, так как это контравариантный тип
    // val value: Any = anyBox.add("Hello")  // Ошибка компиляции
}
```

**Что происходит здесь?**

• Класс `Box<in T>` использует in, что означает, что данные могут быть только записаны в контейнер, но не извлечены из него.

• Мы можем передавать значения типа String и Int в `Box<Any>`, потому что `Box<Any>` может принимать String и Int как подтипы Any.

### Еще примеры с in out

**🔥 Ковариантность (out) и Контравариантность (in) в Kotlin Generics – простыми словами!**

**🚀 Представьте, что у вас есть коробки с фруктами 🍏🍊**

• **Ковариантность (**out**)** – коробка **может отдавать** фрукты, но **нельзя класть** новые.
• **Контравариантность (**in**)** – в коробку **можно класть** фрукты, но **нельзя забирать**.


**✅ 1. Ковариантность (out) – можно только брать (get)**

🔹 **Пример:** у вас есть **коробка с яблоками (**``Box<Apple>``**)**, и вам нужно передать её **методу, который работает с любыми фруктами (**``Box<Fruit>``**)**.

```kotlin
open class Fruit
class Apple : Fruit()
class Orange : Fruit()

class Box<out T>(private val item: T) { // Ковариантность (out)
    fun getItem(): T = item  // Можно брать (get)
    // fun putItem(item: T) { } // ❌ Ошибка: нельзя добавлять (set)
}

fun takeFruit(box: Box<Fruit>) {
    println("Взяли фрукт: ${box.getItem()}")
}

fun main() {
    val appleBox: Box<Apple> = Box(Apple())
    takeFruit(appleBox) // ✅ Работает, потому что Box<Apple> можно использовать как Box<Fruit>
}
```
✔ **Почему работает?**

• ``Box<out T>`` **позволяет использовать подтипы** (``Box<Apple> → Box<Fruit>``).
• **Можно** get()**, но нельзя** set(), потому что неизвестно, что в коробке.

**✅ 2. Контравариантность (in) – можно только добавлять (set)**

🔹 **Пример:** у вас есть метод, который **кладёт фрукты в коробку**.

```kotlin

class Box<in T> { // Контравариантность (in)
    fun putItem(item: T) { println("Положили в коробку: $item") }
    // fun getItem(): T { } // ❌ Ошибка: нельзя брать (get)
}

fun addFruit(box: Box<Apple>) {
    box.putItem(Apple()) // ✅ Можно класть яблоки
}

fun main() {
    val fruitBox: Box<Fruit> = Box<Fruit>()
    val appleBox: Box<Apple> = fruitBox // ✅ Контравариантность: Box<Fruit> можно использовать как Box<Apple>
}
```

✔ **Почему работает?**
• ``Box<in T>`` **позволяет использовать суперклассы** (``Box<Fruit> → Box<Apple>``).
• **Можно** set()**, но нельзя** get(), потому что неизвестно, что в коробке.


**PECS** – это правило, которое помогает понять, когда использовать **ковариантность**
(**out**) и контравариантность (**in**) в **Java/Kotlin Generics**.

📌 **PECS расшифровывается как:**

• **Producer → Extends** (out) – если **только читаем (producer)**, используем ? extends T.
• **Consumer → Super** (in) – если **только записываем (consumer)**, используем ? super T.


**🚀 Как работает PECS в Kotlin?**

**✅ 1. Producer → Extends (out) – Ковариантность**

• **Если объект только производит (**get**), используем** out
• **Пример:** ``List<out T>`` – можно читать, но нельзя добавлять

```kotlin
fun copyProducer(source: List<out Number>) { 
    for (item in source) { // ✅ Можно читать (Producer)
        println(item)
    }
    // source.add(42) ❌ Ошибка: нельзя `set()`
}

fun main() {
    val numbers: List<Int> = listOf(1, 2, 3)
    copyProducer(numbers) // ✅ Работает, потому что Int — это Number
}
```

✔ **Почему** out**?**

• ``List<out Number>`` означает, что **можно передавать** ``List<Int>``,``List<Double>``, но **нельзя менять (**set()**).

**✅ 2. Consumer → Super (in) – Контравариантность**

• **Если объект только потребляет (**set**), используем** in
• **Пример:** ``Comparator<in T>`` – можно передавать суперклассы

```kotlin
fun addToList(destination: MutableList<in Int>) { 
    destination.add(42) // ✅ Можно `set()` (Consumer)
    // println(destination[0]) ❌ Ошибка: нельзя `get()`
}

fun main() {
    val anyNumbers: MutableList<Number> = mutableListOf()
    addToList(anyNumbers) // ✅ Работает, потому что Number — супертип Int
}
```

✔ **Почему** in**?**

• ``MutableList<in Int>`` означает, что **можно передавать** ``MutableList<Number>``, но **нельзя читать (**get()**)**.

> [!tip] Шпаргалка по вариантности
> - **`out T` (ковариантность)** — тип только **производит/отдаёт** (`Producer`). `List<out T>`. `List<Int>` можно передать как `List<Any>`.
> - **`in T` (контравариантность)** — тип только **потребляет/принимает** (`Consumer`). `Comparator<in T>`. `Comparator<Any>` можно передать как `Comparator<Int>`.
> - **PECS:** **P**roducer-**E**xtends (`out`), **C**onsumer-**S**uper (`in`).
> - **Declaration-site (Kotlin)** — вариантность задаётся в объявлении класса (`class Box<out T>`); **use-site (Java/Kotlin)** — в месте использования (`List<out T>`, в Java `? extends T`).
> - **`*` (star-projection)** — `List<*>` ≈ «список чего-то неизвестного»: читать можно как `Any?`, добавлять нельзя.
> - **`reified`** позволяет узнать тип в рантайме, обходя стирание типов (см. [[Inline, Noinline, cross inline, reified]]).
