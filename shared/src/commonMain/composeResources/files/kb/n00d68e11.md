Декоратор (**Decorator Pattern**) — это **структурный паттерн проектирования**, который позволяет динамически добавлять поведение объектам без изменения их кода.

В **Android** он полезен, когда нужно **расширить функциональность класса без наследования**, например:

• Добавить **логирование** в репозиторий данных
• Расширить **View** (например, кастомный TextView)
• Расширить работу с **SharedPreferences**
• Декорировать **Adapter** в RecyclerView

Декоратор отлично подходит для кэширования данных, особенно в **репозиториях** (Repository).

📌 Представим, что у нас есть UserRepository, который получает данные из **API**. Вместо того, чтобы каждый раз делать запрос в сеть, мы добавим **кэш** через LruCache.
```kotlin
interface UserRepository {
    suspend fun getUser(id: String): User
}

class NetworkUserRepository(private val api: UserApi) : UserRepository {
    override suspend fun getUser(id: String): User {
        return api.getUser(id) // Запрос в сеть
    }
}
```

📌 **Проблема:** **Каждый вызов** getUser(id) **делает запрос в сеть** ❌

**🔥 Декоратор с Кэшем (CachedUserRepository)**

Добавим LruCache для хранения пользователей в памяти.
```kotlin
import android.util.LruCache

class CachedUserRepository(
    private val decorated: UserRepository, // Оригинальный репозиторий
    cacheSize: Int = 10 // Количество пользователей в кэше
) : UserRepository {

    private val cache = LruCache<String, User>(cacheSize) // Кэш в памяти

    override suspend fun getUser(id: String): User {
        // 1️⃣ Проверяем кэш
        cache.get(id)?.let {
            Log.d("CachedUserRepository", "User loaded from cache: $id")
            return it
        }

        // 2️⃣ Если нет в кэше, запрашиваем из сети
        val user = decorated.getUser(id)

        // 3️⃣ Добавляем в кэш
        cache.put(id, user)
        Log.d("CachedUserRepository", "User fetched from API and cached: $id")

        return user
    }
}
```

📌 **Теперь сначала проверяется кэш, а запрос в API делается только при необходимости!** 🚀

**✅ Использование Декоратора**
```kotlin
val api = RetrofitInstance.create(UserApi::class.java) // API-интерфейс
val networkRepository = NetworkUserRepository(api) // Оригинальный репозиторий
val cachedRepository = CachedUserRepository(networkRepository) // Декоратор с кэшем

// Теперь работаем с репозиторием с кэшем
val user = cachedRepository.getUser("123")
```

> [!tip] Декоратор vs наследование
> Декоратор добавляет поведение **во время выполнения**, оборачивая объект, а наследование — статически, на этапе компиляции. Преимущества обёртки:
> - можно **комбинировать** несколько декораторов (`Logging(Cache(Network(...)))`), не порождая комбинаторный взрыв подклассов;
> - соблюдается **OCP**: исходный `NetworkUserRepository` не меняется;
> - легко включить/выключить функциональность (просто не оборачивать).
>
> Декоратор реализует тот же интерфейс, что и оборачиваемый объект, — поэтому клиент не замечает разницы. В Android по этому принципу устроен `ContextWrapper`.
