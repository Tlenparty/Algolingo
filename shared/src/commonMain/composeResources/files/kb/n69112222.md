В **Jetpack ViewModel** есть два типа классов:

1️⃣ ViewModel – стандартная ViewModel, не имеющая прямого доступа к Application.
2️⃣ AndroidViewModel – наследуется от ViewModel, но получает Application в конструкторе.

**1️⃣ ViewModel (Обычная ViewModel)**

🔹 Используется для хранения и управления UI-данными, переживающими поворот экрана.
🔹 Не имеет прямого доступа к Context или Application.

**Пример:**
```kotlin
class MyViewModel : ViewModel() {
    val someData = MutableLiveData<String>()

    fun updateData(newValue: String) {
        someData.value = newValue
    }
}
```

✅ **Когда использовать?**

✔ Когда вам **не нужен доступ к** Application **или** Context.
✔ Когда данные чистые и не зависят от Android API.

**2️⃣ AndroidViewModel (ViewModel с доступом к Application)**

🔹 Наследуется от AndroidViewModel и получает Application в конструкторе.
🔹 Позволяет работать с Context через application.applicationContext.


**Пример:**
```kotlin
class MyAndroidViewModel(application: Application) : AndroidViewModel(application) {
    private val appContext = getApplication<Application>().applicationContext
    val someData = MutableLiveData<String>()

    fun getStringResource(): String {
        return appContext.getString(R.string.app_name)
    }
}
```

✅ **Когда использовать?**

✔ Когда нужен доступ к Application, например:
• Работа с БД через Room
• Чтение ресурсов getString(R.string.some_text)
• Работа с SharedPreferences

**🔹 Когда использовать AndroidViewModel?**

1️⃣ **Если нужен** Context **(например, для** SharedPreferences**, ресурсов или Room)**
2️⃣ **Когда данные привязаны к** Application **и живут столько же, сколько приложение**
3️⃣ **Когда не хочется передавать** Context **через конструктор или использовать DI**

## Варианты как сделать общую ViewModel для добавления товаров в корзину


> [!warning] Осторожно: «Singleton-ViewModel в Application» — антипаттерн
> Способ ниже (хранить экземпляр `CartViewModel` в `Application` и отдавать его всем) **противоречит контракту ViewModel**: такой объект **никогда не получит `onCleared()`**, живёт всё время процесса и легко превращается в утечку (особенно если внутри есть подписки/Context). Правильнее:
> - **Шарить между фрагментами одной Activity** — `by activityViewModels()` (ViewModel живёт в скоупе Activity, корректно очищается).
> - **Глобальное состояние корзины** — выносить в **репозиторий-синглтон** (через DI: Hilt `@Singleton`), а ViewModl лишь читает его через `Flow`. ViewModel **не должен** быть глобальным синглтоном.
>
> Пример ниже оставлен как иллюстрация «как делают, но не надо».

**1️⃣ Вариант: общий ViewModel через фабрику в Application (антипаттерн — см. предупреждение)**

Идея — глобальная корзина, доступная везде:

✅ Корзина доступна во всём приложении
✅ LiveData обновляет UI при изменении
❌ ViewModel не очищается (`onCleared` не вызовется) → риск утечки

**📌 Шаг 1: Создаем CartViewModel**

Используем MutableLiveData для хранения списка товаров:
```kotlin
class CartViewModel : ViewModel() {
    private val _cartItems = MutableLiveData<List<Product>>(emptyList())
    val cartItems: LiveData<List<Product>> get() = _cartItems

    fun addToCart(product: Product) {
        val updatedList = _cartItems.value.orEmpty().toMutableList()
        updatedList.add(product)
        _cartItems.value = updatedList
    }

    fun removeFromCart(product: Product) {
        val updatedList = _cartItems.value.orEmpty().toMutableList()
        updatedList.remove(product)
        _cartItems.value = updatedList
    }

    fun clearCart() {
        _cartItems.value = emptyList()
    }
}
```

**📌 Шаг 2: Используем CartViewModel в Application**
Создадим **Singleton**, чтобы CartViewModel был доступен везде:
```kotlin
class CartViewModelFactory : ViewModelProvider.Factory {
    private val cartViewModel = CartViewModel()

    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        return cartViewModel as T
    }
}

class MyApp : Application() {
    val cartViewModelFactory = CartViewModelFactory()
}
```

**📌 Шаг 3: Доступ к корзине в любом Activity или Fragment**

Теперь можно использовать **один и тот же** ViewModel **во всем приложении**:
```kotlin
class ProductListFragment : Fragment() {
    private lateinit var cartViewModel: CartViewModel

    override fun onCreateView(
        inflater: LayoutInflater, container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View? {
        val view = inflater.inflate(R.layout.fragment_product_list, container, false)

        // Получаем ViewModel из Application
        cartViewModel = ViewModelProvider(requireActivity(), (requireActivity().application as MyApp).cartViewModelFactory)
            .get(CartViewModel::class.java)

        cartViewModel.cartItems.observe(viewLifecycleOwner) { cart ->
            Log.d("Cart", "Товаров в корзине: ${cart.size}")
        }

        return view
    }

    fun addToCart(product: Product) {
        cartViewModel.addToCart(product)
    }
}
```

**4️⃣ (Опционально) Сохранение корзины при перезапуске приложения**

Если нужно сохранять корзину после закрытия приложения, используем SharedPreferences или Room.

**✅ Используем AndroidViewModel + SharedPreferences**

```kotlin
class CartViewModel(application: Application) : AndroidViewModel(application) {
    private val prefs = application.getSharedPreferences("cart_prefs", Context.MODE_PRIVATE)

    private val _cartItems = MutableLiveData<List<Product>>(loadCart())
    val cartItems: LiveData<List<Product>> get() = _cartItems

    fun addToCart(product: Product) {
        val updatedList = _cartItems.value.orEmpty().toMutableList()
        updatedList.add(product)
        _cartItems.value = updatedList
        saveCart(updatedList)
    }

    private fun saveCart(cart: List<Product>) {
        prefs.edit().putString("cart", Gson().toJson(cart)).apply()
    }

    private fun loadCart(): List<Product> {
        val json = prefs.getString("cart", "[]") ?: "[]"
        return Gson().fromJson(json, object : TypeToken<List<Product>>() {}.type)
    }
}
```

> [!tip] ViewModel vs AndroidViewModel — на собесе
> - **`ViewModel`** — по умолчанию; не должна знать про `Context`/`Application` (упрощает тесты).
> - **`AndroidViewModel`** — даёт **`Application` context** (живёт столько же, сколько процесс, поэтому **не течёт**, в отличие от Activity-контекста). Но даже так передавать `Context` в VM считается не лучшей практикой.
> - **Современный подход:** не тянуть `Context` в ViewModel вообще — нужные ресурсы/`SharedPreferences`/`Room` прятать за репозиторием и **внедрять через DI** (Hilt). Тогда обычной `ViewModel` достаточно.
> - **Шаринг между фрагментами** — `by activityViewModels()`; **состояние, переживающее смерть процесса** — `SavedStateHandle` (см. [[ViewModel, SaveStateHandle, SavedStateRegistryOwner]]).
