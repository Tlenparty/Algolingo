**1. Встроенные классы (Inline classes)**
**Inline class** (встроенный класс) — это специальный тип класса, который оборачивает одно значение, но компилятор “инлайнивает” (встраивает) это значение в места использования этого класса, что позволяет избежать накладных расходов, связанных с созданием объектов. Это значит, что объекты таких классов на самом деле не создаются, а значение, которое они хранят, используется напрямую.

**Пример Inline класса:**

```kotlin
inline class Name(val value: String)

fun printName(name: Name) {
    println(name.value)
}

fun main() {
    val name = Name("Alice")
    printName(name)
}
```

В этом примере Name — это inline-класс, который инкапсулирует строку. При использовании такого класса, компилятор **не создает объект** типа Name, а использует значение типа String напрямую.

**Особенности Inline классов:**

• **Не создают дополнительных объектов**: Они представляют собой эффективное оборачивание значений, при этом не вызывают дополнительного выделения памяти для объектов.
• **Инлайнинг**: Компилятор заменяет использование inline класса на его значение во время компиляции.
• **Ограничения**:
• Inline класс должен содержать **только одно свойство**.
• В Kotlin 1.5+ поддержка inline классов была заменена на **value class**.
• Inline классы не могут иметь состояния (например, нельзя хранить несколько свойств).
• Не могут наследовать другие классы и быть наследуемыми.
• Не могут быть типами-параметрами в дженериках.

 ### **Могут ли inline функции быть synchronized в Android?**
 
> Нет, inline **функции не могут быть** synchronized, потому что они **не имеют реального тела метода** на уровне байт-кода.


**2. Value class (Классы-значения)**

С введением Kotlin 1.5 концепция **value class** пришла на смену **inline class**. **Value class** представляет собой улучшенную и более гибкую версию inline класса с дополнительными возможностями, такими как поддержка дженериков и совместимость с многими другими аспектами языка.
```kotlin
@JvmInline
value class Name(val value: String)

fun printName(name: Name) {
    println(name.value)
}

fun main() {
    val name = Name("Bob")
    printName(name)
}
```

Как и inline классы, value классы инкапсулируют одно значение, но теперь ==они могут быть использованы с **дженериками**==, и есть дополнительные возможности для их расширения.

**Основные характеристики value class:**
• **Инлайнинг**: Подобно inline классу, ==value class позволяет компилятору “встраивать” значение типа в код, избегая создания объектов==.
• **Поддержка дженериков**: В отличие от inline классов, value классы могут использоваться с дженериками, что делает их более гибкими.

Пример с дженериками:
```kotlin
@JvmInline
value class Box<T>(val value: T)

fun <T> printBox(box: Box<T>) {
    println(box.value)
}

fun main() {
    val box = Box(42)
    printBox(box)
}
```

**Почему используется value class?**
Value class используется для оптимизации памяти и повышения производительности, когда необходимо работать с небольшими значениями (например, числами, строками или другими простыми типами), но без создания дополнительных объектов. Это может быть полезно в таких случаях, как:

• ==Работа с маленькими объектами, которые инкапсулируют одно значение==, например, идентификаторы, валюты, координаты.
• Улучшение производительности, поскольку объекты не создаются, и значения инлайнются в код.
• В сочетании с дженериками для более гибкой работы с данными.

**Пример использования value class:**

```kotlin
@JvmInline
value class Email(val value: String)

fun isValidEmail(email: Email): Boolean {
    return email.value.contains("@")
}

fun main() {
    val email = Email("test@example.com")
    println(isValidEmail(email))  // true
}
```
Здесь Email является **value class**, который инкапсулирует строку и используется для проверки валидности электронной почты. Этот подход позволяет избежать создания объектов и улучшает производительность, если такие классы часто используются.

**Заключение**

• **Inline class** — это устаревшая концепция, предназначенная для оптимизации работы с одиночными значениями путем инлайнинга, но она имеет некоторые ограничения.

• **Value class** — это улучшенная версия inline класса, которая поддерживает дженерики и может быть использована с большими возможностями, включая дополнительные методы и сложные конструкции.

typealias в Kotlin — это механизм для создания **псевдонимов типов**, который позволяет давать типам более ==удобные или осмысленные имена==. Он не создает новый тип, а лишь создает альтернативное имя для существующего типа. Это полезно, когда тип может быть громоздким или сложным для восприятия, или когда необходимо использовать более семантически значимые имена для типов, особенно при работе с типами-обобщениями (generic types).

==`typealias NewName = ExistingType`==

Где:
• NewName — это новый псевдоним для типа.
• ExistingType — это существующий тип, для которого создается псевдоним.

**Пример использования typealias**

1. **Псевдоним для сложного типа функции**:
Предположим, у нас есть функция, принимающая параметр типа Function<Int, String>, то есть функцию, которая принимает Int и возвращает String. Этот тип можно заменить на более читаемое имя с помощью typealias.

```kotlin
typealias IntToString = (Int) -> String

fun processIntToString(func: IntToString) {
    println(func(42))
}

fun main() {
    val toStringFunc: IntToString = { it.toString() }
    processIntToString(toStringFunc)  // 42
}
```

В этом примере IntToString — это псевдоним для типа `(Int) -> String`. Вместо того чтобы каждый раз писать `Function<Int, String>`, мы используем более короткое и понятное имя.
2. **Псевдоним для обобщенных типов (generic types)**:
Для дженериков, например, тип `Map<String, List<Int>>` может быть довольно громоздким. С typealias можно упростить его использование.

```kotlin
typealias StringListMap = Map<String, List<Int>>

fun printMap(map: StringListMap) {
    map.forEach { (key, value) ->
        println("$key: $value")
    }
}

fun main() {
    val myMap: StringListMap = mapOf(
        "One" to listOf(1, 2, 3),
        "Two" to listOf(4, 5, 6)
    )
    printMap(myMap)
}
```

В данном примере StringListMap — это псевдоним для типа `Map<String, List<Int>>`. Это улучшает читаемость и упрощает работу с такими типами.
3. **Псевдоним для типа с типом-аргументом**:
typealias также можно использовать для упрощения типов с параметрами, например:
```kotlin
typealias ListOfStrings = List<String>

fun processStrings(list: ListOfStrings) {
    list.forEach { println(it) }
}

fun main() {
    val strings: ListOfStrings = listOf("a", "b", "c")
    processStrings(strings)
}
```


**Заключение**

• typealias **в Kotlin** позволяет создавать удобные псевдонимы для типов, улучшая читаемость и упрощая работу с типами, особенно когда они сложные или используются многократно.
• **Преимущества**: сокращение громоздких типов, улучшение читаемости и понятности кода.
• **Ограничения**: не создает новый тип и не изменяет поведение существующих типов.


Ключевое слово ==**infix**== в Kotlin используется для создания **инфиксных функций**. Это ==позволяет вызывать методы без использования обычных скобок==, а вместо этого использовать более естественный и читаемый синтаксис.

**Что такое инфиксный вызов?**

**Инфиксный вызов** — это способ вызова функции, при котором она может быть вызвана как бинарный оператор между двумя объектами, без использования скобок.

С помощью infix можно вызвать функцию, передавая аргумент непосредственно после оператора, что делает код более чистым и читаемым. В Kotlin это аналогично тому, как работает использование операторов (например, +, -, *, и т. д.) в математике.

**Условия для использования infix:**

1. Функция должна быть членом класса (методом).
2. Функция должна принимать ==**только один параметр**==.
3. Функция должна быть ==**не** private==, то есть доступной для вызова извне.
4. Функция должна быть ==**членом** какого-то объекта, а не расширением== (если это не функция расширения).

**Пример использования infix:**

Допустим, у нас есть класс Person, и мы хотим создать инфиксную функцию для сравнения возрастов двух объектов этого класса.

```kotlin
data class Person(val name: String, val age: Int)

// Инфиксная функция для сравнения возрастов
infix fun Person.isOlderThan(other: Person): Boolean {
    return this.age > other.age
}

fun main() {
    val person1 = Person("Alice", 30)
    val person2 = Person("Bob", 25)

    // Вызов инфиксной функции
    val result = person1 isOlderThan person2 // читается как "person1 is older than person2"
    println(result) // true
}
```

**Пояснение:**

• infix в функции isOlderThan позволяет вызывать её в инфиксной форме как оператор, между двумя объектами.
• Вместо person1.isOlderThan(person2) можно использовать более читаемую форму: person1 isOlderThan person2.

**Пример с использованием инфиксных операторов:**

В Kotlin можно создать свои операторы. Вот пример с инфиксным оператором для сложения чисел:
```kotlin
infix fun Int.add(other: Int): Int {
    return this + other
}

fun main() {
    val result = 5 add 3 // читается как 5 add 3
    println(result) // 8
}
```
**Основные моменты:**

• Инфиксный вызов помогает улучшить читаемость кода, особенно при работе с операциями, которые логически выглядят как “операторы”.

• Хотя инфиксные функции выглядят как операторы, их можно использовать только для функций с одним параметром и при соблюдении определенных условий.


```kotlin
// inline-функция избавляет от создания объекта лямбды;
// inline не сочетается с synchronized-блоком внутри (нет реального тела метода)
inline suspend fun <T> List<T>.forEvery(itemAction: suspend (T) -> Unit) {
    reversed().forEach { itemAction(it) }
}
```

> [!warning] value class не всегда «бесплатен»
> Компилятор инлайнит значение (без обёртки) только в простых случаях. Объект **боксируется** (создаётся реальная обёртка), когда value class:
> - используется как **nullable** (`Email?`);
> - подставляется туда, где ожидается **супертип/интерфейс** (`Any`, реализуемый интерфейс);
> - кладётся в **дженерик** (`List<Email>`) или в коллекцию.
> В этих местах выигрыш по памяти теряется — учитывай это, прежде чем оборачивать всё подряд.

> [!tip] Зачем нужны (на собесе)
> - **value class** — типобезопасные «обёртки» для примитивов без оверхеда: `UserId(Long)` нельзя случайно перепутать с `OrderId(Long)`, хотя оба — `Long`. В Compose так сделаны `Dp`, `Color`, `TextUnit`.
> - **typealias** — лишь **псевдоним**, новый тип НЕ создаёт (`UserId` через typealias не защитит от путаницы с другим `Long`). Только для читаемости громоздких типов.
> - Разница value class vs typealias — частый вопрос: **value class = новый тип (type-safety), typealias = то же самое имя другим словом.**
