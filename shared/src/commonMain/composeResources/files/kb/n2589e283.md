# Что означает число, которое возвращает hashCode

Сама цифра **не означает ничего** — это не адрес в памяти, не ID, не порядковый номер. Это детерминированный «отпечаток» (fingerprint, digest) содержимого объекта: содержимое прогнали через формулу — получили число. У значения `2112` для строки `"Aa"` нет смысла, который можно «прочитать» или расшифровать обратно.

> **На собес одной фразой:** хеш — это отпечаток содержимого, у самой цифры смысла нет. Важны только её свойства: детерминированность (то же содержимое → та же цифра) и равномерность (биты размазаны по диапазону). Используется она ровно одним способом — из неё маской вырезают индекс бакета.

## Смысл не в цифре, а в её свойствах

1. **Детерминированность.** Одно и то же содержимое → всегда одна и та же цифра (в рамках одного запуска — обязательно; у `String` формула вообще зафиксирована навсегда). Без этого `HashMap` не нашёл бы то, что сам положил.
2. **Равномерность.** Хорошая формула «размазывает» значения по всем 2³² вариантам, чтобы разные объекты редко совпадали. Поэтому в формулах участвуют простые числа (31 у `String`) и битовые сдвиги.
3. **Дешевизна.** Считается за O(длины содержимого) один раз, у `String` ещё и кешируется в поле `hash`.

Цифра — просто носитель этих свойств. Сравнивать хеши по величине (`hash1 < hash2`) или искать в них закономерность бессмысленно.

## Откуда цифра берётся — примеры формул

```text
String:  s[0]·31ⁿ⁻¹ + s[1]·31ⁿ⁻² + … + s[n-1]      // полином от символов
         "Aa" → 65·31 + 97 = 2112

Int:     сам себе хеш → (42).hashCode() == 42        // уже число, ничего считать не надо

Long:    (value xor (value ushr 32)).toInt()         // 64 бита сворачиваются в 32

data class: 31-полином от hashCode всех полей — генерируется компилятором
```

А дефолтный `Object.hashCode()` (когда ничего не переопределено) — это **identity hash**: случайное число, которое JVM генерирует при первом запросе и запоминает в заголовке объекта. Исторически это был адрес в памяти, но давно нет: GC двигает объекты, а хеш меняться не должен. То есть даже у «сырого» хеша смысл — не адрес, а «уникальный-в-этом-запуске ярлык личности объекта».

## Единственное применение цифры

`HashMap` использует хеш ровно одним способом — вырезает из него младшие биты под размер таблицы:

```kotlin
// внутри HashMap (упрощённо):
val h = key.hashCode()
val hash = h xor (h ushr 16)          // «домешивание»: старшие биты влияют на младшие
val index = hash and (table.size - 1) // маска вместо % — размер таблицы всегда степень двойки
```

Строка `xor (h ushr 16)` существует как раз потому, что у цифры нет смысла, а у **битов** есть роль: маска берёт только младшие биты, и если объекты различаются лишь старшими — все попали бы в один бакет. Домешивание переносит информацию из старших битов в младшие.

## Аналогия

Хеш — как первая буква фамилии в бумажной картотеке: сама буква «К» ничего не говорит о человеке, но мгновенно указывает нужный ящик. Точную карточку в ящике ищут уже полным сравнением — это [[Зачем нужен hashCode если equals даёт точное сравнение|equals]].
