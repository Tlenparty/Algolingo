```kotlin
withContext(Dispatchers.Main) {
        val flow = flowOf(1, 2, 3)

        val singleValue = flow
            .map {
                it.toString()
                // 1  Какой диспатчер IO
            }
            .flowOn(Dispatchers.IO)
            .filter {
                it == "2" // 2 В каком диспатчере? DEFAULT
            }
            .flowOn(Dispatchers.Default)
            .single() // 3 А тут? MAIN
    }
}
```

## Разбор

Ключевое правило: **`flowOn` меняет контекст для операторов ВЫШЕ себя (upstream)**, до следующего `flowOn`.

- `map { }` → над ним стоит `.flowOn(Dispatchers.IO)` → выполняется на **IO**.
- `filter { }` → над ним (после IO-блока) стоит `.flowOn(Dispatchers.Default)` → выполняется на **Default**.
- `single()` — **терминальный** оператор. Он всегда выполняется в контексте **коллектора**, то есть `withContext(Dispatchers.Main)` → **Main**.

> [!tip]
> `flowOn` влияет только на upstream и не «протекает» вниз. Терминальная операция (`collect`, `single`, `toList`) всегда идёт в том контексте, где вызван сбор. Поэтому `flowOn` ставят, чтобы увести тяжёлую работу (`map`/сеть) с главного потока, а собирают результат на Main.
