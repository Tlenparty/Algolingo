# Sealed class vs enum

В Kotlin и `enum`, и `sealed`-классы работают с ограниченными наборами значений или типов, но предназначены для разного.

> `sealed class` компилируется в `abstract class`. Все его наследники известны на этапе компиляции, и нельзя создать инстанс самого sealed-класса.

## 1. Определение и назначение

| Характеристика | Enum                                                  | Sealed                                                          |
| -------------- | ----------------------------------------------------- | -------------------------------------------------------------- |
| Что это?       | Перечисление фиксированных констант                   | Базовый класс с ограниченным набором наследников               |
| Применение     | Фиксированный набор значений/состояний                | Иерархия типов с ограниченным количеством подклассов           |
| Компиляция     | Один класс с предопределёнными экземплярами           | Абстрактный класс + отдельные подклассы                        |

## 2. Особенности enum

- Используется для работы с фиксированными значениями.
- Каждое значение — объект типа enum.
- Может содержать методы, свойства, переопределять поведение для каждого значения.
- Встроенные функции: `values()` / `entries`, `valueOf()`, свойства `name`, `ordinal`.

**Плюсы:** простота; подходит для неизменных наборов (дни недели, направления).
**Минусы:** все значения одного типа — это ограничивает гибкость (нельзя нести разные данные в разных константах).

## 3. Особенности sealed-классов

- Позволяют создавать иерархию типов с ограниченным числом подклассов.
- Все подклассы должны быть объявлены **в том же модуле и пакете** (см. ниже), что и базовый класс.
- Поддерживают полиморфизм.
- Удобны с `when`: компилятор проверяет **исчерпывающность** (exhaustive) — можно не писать `else`.

**Плюсы:** гибче enum; разные типы и данные для каждого подкласса; идеальны для состояний/событий/результатов.
**Минусы:** подклассы ограничены модулем/пакетом — не получится расширить иерархию из другого модуля.

## Ключевые различия

| Критерий            | enum                                  | sealed                                                |
| ------------------- | ------------------------------------- | ----------------------------------------------------- |
| Количество значений | Фиксированное, **неизменное**         | Фиксированное, но подклассы могут быть **разных типов**|
| Полиморфизм         | Не поддерживает                       | Поддерживает                                          |
| Типы значений       | Все одного типа                       | Каждый подкласс — свой тип со своими данными          |
| Гибкость            | Меньше                                | Больше (свои методы и поля в подклассах)              |
| `when`              | Удобно, но один тип                   | Исчерпывающее сопоставление с разными типами          |

## Когда что использовать

**Enum** — когда нужен фиксированный список значений **одного типа**, статичных и без своих данных:

```kotlin
enum class Direction { NORTH, EAST, SOUTH, WEST }
```

**Sealed** — когда у вариантов общая база, но разное поведение/данные (состояния, события, результаты):

```kotlin
sealed interface UiState {
    data object Loading : UiState
    data class Success(val data: List<Item>) : UiState
    data class Error(val message: String) : UiState
}
```

## Где можно объявлять наследников sealed

> [!important] Важное уточнение (актуальная версия Kotlin)
> Часто говорят «наследники sealed-класса можно объявлять только в том же файле» — это устарело. **С Kotlin 1.5** наследники могут быть **в любом файле того же модуля и пакета**, не только в одном файле с базовым классом. Главное ограничение остаётся: нельзя добавить наследника из **другого модуля** — поэтому компилятор и знает их все на этапе компиляции (за это и `when` без `else`).

```kotlin
// Файл Result.kt
sealed class Result

// Файл Success.kt (тот же модуль и пакет) — ОК
class Success : Result()

// Другой модуль — ошибка компиляции
// class AnotherResult : Result()
```

## Sealed class vs sealed interface

| Особенность                             | sealed class                  | sealed interface                          |
| --------------------------------------- | ----------------------------- | ----------------------------------------- |
| Хранит состояние (поля `val`/`var`)     | ✅ Да                         | ❌ Нет (только абстрактные/default свойства)|
| Логика (методы с реализацией)           | ✅ Да                         | ⚠️ Только default-методы                  |
| Где можно наследоваться                 | Тот же модуль и пакет         | Тот же модуль и пакет                     |
| Множественное наследование              | ❌ Нет (один родитель)        | ✅ Да (можно реализовать несколько)        |
| Когда использовать                      | Нужны логика + состояние      | Нужен только контракт / гибкая иерархия   |

> [!tip] Что отвечать
> - **enum** — конечный набор **однотипных** констант (статусы без данных).
> - **sealed** — конечный набор **разнотипных** вариантов, каждый со своими данными (UI-state: `Loading`/`Success(data)`/`Error(msg)`).
> - Главная польза обоих — **исчерпывающий `when`**: добавил вариант → компилятор заставит обработать его везде.
> - **`sealed interface`** часто предпочтительнее `sealed class`: можно реализовать несколько интерфейсов и нет конструктора.
