В Kotlin есть два вида вложенных классов:

1️⃣ **Nested class** (статический вложенный класс)
2️⃣ **Inner class** (вложенный класс с доступом к outer классу)

**🔹 1. Nested Class (статический вложенный класс)**

• Это **обычный вложенный класс**, ==**НЕ** имеющий доступа к outer (внешнему) классу==.
• В Kotlin **по умолчанию** вложенные классы являются static (как в Java static class).

**✅ Пример Nested Class**
```kotlin
class Outer {
    val outerValue = "I'm Outer"
    
    class Nested {
        fun show() = "I'm Nested"
    }
}

fun main() {
    val nested = Outer.Nested()  // Создаём без Outer()
    println(nested.show())       // Вывод: "I'm Nested"
}
```

📌 **Особенности Nested Class:**

✔ Можно создать без создания объекта Outer.
✔ Не имеет доступа к свойствам Outer.

⛔ **Ошибка при попытке доступа к** outerValue:
```kotlin
class Nested {
    fun show() = outerValue  // ❌ Ошибка: нет доступа к Outer
}
```

**🔹 2. Inner Class (вложенный с доступом к внешнему классу)**

**⚡ Определение:**

• inner class **имеет доступ к членам внешнего класса** (this@Outer).
• Требует модификатора inner.

**✅ Пример Inner Class**
```kotlin
class Outer {
    val outerValue = "I'm Outer"
    
    inner class Inner {
        fun show() = "I'm Inner, outer value: $outerValue"
    }
}

fun main() {
    val outer = Outer()
    val inner = outer.Inner()  // Создаём через Outer()
    println(inner.show())  // Вывод: "I'm Inner, outer value: I'm Outer"
}
```

📌 **Особенности Inner Class:**

✔ **Доступ к** outer **свойствам** ``(this@Outer.outerValue)``.
✔ **Создаётся через объект** Outer.

**🔥 Nested Class vs Inner Class: Отличия**

| **Фактор**                    | **Nested Class**    | **Inner Class**     |
| ----------------------------- | ------------------- | ------------------- |
| **Модификатор**               | class Nested        | inner class Inner   |
| **Доступ к** Outer            | ❌ Нет               | ✅ Есть (this@Outer) |
| **Создание объекта**          | Outer.Nested()      | Outer().Inner()     |
| **Статический (**static**)?** | ✅ Да (по умолчанию) | ❌ Нет               |
**🔥 Когда использовать?**

✔ **Используйте** Nested Class, если **не нужен доступ** к Outer.
✔ **Используйте** Inner Class, если **нужно использовать свойства** Outer.

**🔥 Может ли Nested class быть не static в Kotlin?**
**❌ Нет, в Kotlin** Nested class **всегда** static (по умолчанию). Чтобы дать доступ к внешнему классу, добавляют `inner`.

> [!warning] Inner class и утечки памяти
> `inner class` хранит **неявную ссылку на внешний объект** (`this@Outer`). Это противоположность Java, где вложенный класс по умолчанию `inner` — в Kotlin наоборот, по умолчанию `static`-nested (без ссылки), и это сделано **намеренно ради безопасности**.
>
> Если `inner`-класс (или анонимный объект/нестатический хэндлер) живёт дольше внешнего (Activity), он держит её и не даёт собрать GC → **утечка памяти**. Классика — `Handler`/`Runnable` как inner-класс внутри Activity. Решение: делать вложенный класс обычным (nested) и передавать нужное через `WeakReference`/параметры.

> [!tip] Аналогия с Java
> - Kotlin `class Nested` ⟷ Java `static class Nested`.
> - Kotlin `inner class Inner` ⟷ Java `class Inner` (нестатический).
> На собесе часто спрашивают именно это различие «по умолчанию»: в Java вложенный класс по умолчанию держит outer, в Kotlin — нет.
