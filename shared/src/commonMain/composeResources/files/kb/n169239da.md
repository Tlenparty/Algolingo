# Hilt

**Hilt** — официальная DI-библиотека Google поверх **Dagger 2** (см. [[Dagger 2]]). Убирает бойлерплейт ручного Dagger и даёт **готовые компоненты, привязанные к жизненному циклу Android**.

## Hilt = Dagger + Android-интеграция

> [!info] Что Hilt делает за тебя
> Чистый Dagger требует руками описывать компоненты, их иерархию, scope и связывать с жизненным циклом. Hilt **генерирует стандартный набор компонентов** и сам встраивает граф в Android-классы. Достаточно аннотаций — компоненты, их связи и время жизни уже определены.

```kotlin
@HiltAndroidApp
class App : Application()

@AndroidEntryPoint
class FeedActivity : AppCompatActivity() {
    @Inject lateinit var analytics: Analytics   // инъекция «из коробки»
}

@HiltViewModel
class FeedViewModel @Inject constructor(
    private val repo: FeedRepository
) : ViewModel()
```

## Компоненты и их scope

| Компонент | Scope-аннотация | Живёт пока жив… |
| --- | --- | --- |
| `SingletonComponent` | `@Singleton` | Application |
| `ActivityRetainedComponent` | `@ActivityRetainedScoped` | переживает поворот (как ViewModel) |
| `ViewModelComponent` | `@ViewModelScoped` | ViewModel |
| `ActivityComponent` | `@ActivityScoped` | Activity |
| `FragmentComponent` | `@FragmentScoped` | Fragment |

## Модули и привязки

```kotlin
@Module
@InstallIn(SingletonComponent::class)
object NetworkModule {
    @Provides @Singleton
    fun api(): Api = Retrofit.Builder()…create()
}

@Module @InstallIn(SingletonComponent::class)
abstract class RepoModule {
    @Binds abstract fun repo(impl: FeedRepositoryImpl): FeedRepository  // интерфейс → реализация
}
```

> [!tip] `@Provides` vs `@Binds`
> • **`@Provides`** — когда объект нужно **сконструировать** (внешний класс, билдер, конфиг).
> • **`@Binds`** — когда просто **связать интерфейс с реализацией** (реализация уже `@Inject`-конструируема). `@Binds` дешевле — не генерирует тело метода. Это перекликается с [[DI VS SERVICE LOCATOR]] (внедрение зависимостей через конструктор).

> [!important] Compile-time — главное преимущество
> Как и Dagger, Hilt проверяет граф **на этапе компиляции**: пропущенная зависимость = ошибка сборки, а не краш в рантайме. Нулевой рантайм-оверхед на рефлексии. Это ключевое отличие от **Koin** (рантайм, ошибки в рантайме) — Koin берут в KMP, потому что Hilt/Dagger завязаны на JVM/Android (см. [[KMP. Библиотеки экосистемы]]).

> [!warning] Частые грабли
> • Забыть `@HiltAndroidApp` / `@AndroidEntryPoint` → рантайм-ошибка.
> • Воркеры — через **`@HiltWorker`** + `HiltWorkerFactory` (см. [[WorkManager]]).
> • Доступ к графу вне Android-классов — через `@EntryPoint`.
> • Hilt — это **JVM/Android only**: для общего KMP-кода не подходит.
