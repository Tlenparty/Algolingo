HTTP (**Hypertext Transfer Protocol**) — это протокол прикладного уровня, используемый для передачи данных в Интернете. Он работает по модели “клиент-сервер”, где клиент (например, браузер) отправляет запрос серверу, а сервер отвечает. Это основной протокол для работы с веб-страницами и API.

**Основные принципы работы HTTP**

1. **Клиент-серверная модель:**

• **Клиент** (например, браузер, мобильное приложение) отправляет запрос на сервер.
• **Сервер** (например, веб-сервер или REST API) обрабатывает запрос и возвращает ответ.

**Основные этапы работы HTTP**

1. **Установка соединения:**

• HTTP работает поверх протокола **TCP/IP**, который отвечает за передачу данных по сети.
• Клиент инициирует соединение с сервером, устанавливая TCP-соединение (обычно через порт 80 для HTTP или 443 для HTTPS).

2. **Формирование HTTP-запроса:**

• Клиент формирует запрос, который содержит:
• **Метод** HTTP: указывает действие (GET, POST, PUT, DELETE и т.д.).
• **URL**: адрес ресурса, к которому обращается клиент.
• **Заголовки**: дополнительная информация (например, тип клиента, поддерживаемые форматы).
• **Тело запроса** (необязательно): данные для передачи, например, JSON при POST.

3. **Обработка запроса сервером:**

• Сервер принимает запрос, обрабатывает его (например, читает из базы данных) и готовит ответ.

4. **Формирование HTTP-ответа:**

• Сервер формирует ответ, который содержит:
• **Код состояния**: указывает результат операции (200, 404, 500 и т.д.).
• **Заголовки**: дополнительная информация (например, тип контента, длина данных).
• **Тело ответа**: данные, например, HTML, JSON или файл.

5. **Закрытие соединения:**

• После отправки ответа сервер может закрыть соединение (в HTTP/1.1 соединение по умолчанию остаётся открытым для повторного использования).

**Пример HTTP-запроса и ответа**

**Запрос:**
```kotlin
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html
```

• **Метод:** GET
• **URL:** /index.html
• **Заголовки:**
• Host: указывает домен.
• User-Agent: информация о клиенте.
• Accept: поддерживаемые форматы ответа.

```html
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 137

<html>
  <body>
    <h1>Welcome to Example.com</h1>
  </body>
</html>
```

• **Код состояния:** 200 OK (успешный запрос).
• **Заголовки:**
• Content-Type: тип данных (HTML).
• Content-Length: длина тела ответа.
• **Тело ответа:** HTML-код страницы.

**Методы HTTP**

1. **GET**: Запрашивает данные с сервера. Тело запроса отсутствует.
2. **POST**: Отправляет данные на сервер для создания ресурса.
3. **PUT**: Полное обновление ресурса.
4. **PATCH**: Частичное обновление ресурса.
5. **DELETE**: Удаляет ресурс.
6. **HEAD**: Запрашивает только заголовки ответа.
7. **OPTIONS**: Запрашивает поддерживаемые сервером методы для ресурса.

**Коды состояния HTTP**

• **1xx (Информационные):** Указывают, что запрос обрабатывается.
• 100 Continue: Сервер принял начальную часть запроса.
• **2xx (Успешные):** Указывают, что запрос выполнен успешно.
• 200 OK: Успешный запрос.
• 201 Created: Ресурс успешно создан.
• **3xx (Перенаправления):** Требуется дополнительное действие от клиента.
• 301 Moved Permanently: Ресурс перемещён.
• 302 Found: Временное перенаправление.
• **4xx (Ошибки клиента):** Указывает на ошибку клиента.
• 400 Bad Request: Неправильный запрос.
• 401 Unauthorized: Неавторизованный доступ.
• 404 Not Found: Ресурс не найден.
• **5xx (Ошибки сервера):** Указывает на проблему на сервере.
• 500 Internal Server Error: Общая ошибка сервера.
• 503 Service Unavailable: Сервер временно недоступен.


**Базовая реализация HTTP-запроса на Android с HttpURLConnection**
**1. Добавьте разрешения в AndroidManifest.xml**

Приложению потребуется разрешение на доступ к интернету:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

**2. Пример базового HTTP-запроса (GET)**

```kotlin
import android.os.Bundle
import android.os.StrictMode
import android.widget.TextView
import androidx.appcompat.app.AppCompatActivity
import java.io.BufferedReader
import java.io.InputStreamReader
import java.net.HttpURLConnection
import java.net.URL

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        // Разрешение сетевых операций в основном потоке (НЕ рекомендуется в реальных приложениях)
        val policy = StrictMode.ThreadPolicy.Builder().permitAll().build()
        StrictMode.setThreadPolicy(policy)

        // URL для запроса
        val urlString = "https://jsonplaceholder.typicode.com/posts/1"

        // Выполнение запроса
        val result = httpGet(urlString)

        // Отображение результата
        findViewById<TextView>(R.id.textView).text = result
    }

    private fun httpGet(urlString: String): String {
        var result = ""
        var connection: HttpURLConnection? = null

        try {
            // Инициализация URL
            val url = URL(urlString)
            connection = url.openConnection() as HttpURLConnection

            // Настройка соединения
            connection.requestMethod = "GET"
            connection.connectTimeout = 5000 // Тайм-аут подключения
            connection.readTimeout = 5000   // Тайм-аут чтения

            // Проверка кода ответа
            val responseCode = connection.responseCode
            if (responseCode == HttpURLConnection.HTTP_OK) {
                // Чтение данных из потока
                val reader = BufferedReader(InputStreamReader(connection.inputStream))
                val stringBuilder = StringBuilder()
                reader.forEachLine { stringBuilder.append(it) }
                result = stringBuilder.toString()
                reader.close()
            } else {
                result = "Ошибка: HTTP $responseCode"
            }
        } catch (e: Exception) {
            result = "Ошибка: ${e.message}"
        } finally {
            connection?.disconnect()
        }

        return result
    }
}
```

**3. Разметка XML (res/layout/activity_main.xml)**

```xml
<?xml version="1.0" encoding="utf-8"?>
<RelativeLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <TextView
        android:id="@+id/textView"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="Загрузка данных..."
        android:textSize="18sp"
        android:padding="16dp" />
</RelativeLayout>
```

> [!warning] `StrictMode.permitAll()` + сеть в главном потоке — антипаттерн
> Пример выше специально разрешает сетевой вызов в UI-потоке через `StrictMode.ThreadPolicy.Builder().permitAll()`. В реальном приложении это **гарантированный ANR** на медленной сети. Любой сетевой запрос — только в фоне: корутина на `Dispatchers.IO`, `WorkManager` или пул потоков. `HttpURLConnection` напрямую сегодня почти не используют — берут **OkHttp/Retrofit** (пул соединений, повторы, интерсепторы, поддержка HTTP/2 из коробки).

> [!tip] Идемпотентность и безопасность методов
> • **Безопасные** (не меняют состояние): `GET`, `HEAD`, `OPTIONS`.
> • **Идемпотентные** (повтор даёт тот же результат): `GET`, `PUT`, `DELETE`, `HEAD`, `OPTIONS`. `PUT` идемпотентен (полная замена), а `POST` — **нет** (каждый вызов создаёт новый ресурс).
> • **`PATCH`** формально не идемпотентен. Это важно для логики ретраев: повторять без опаски можно только идемпотентные запросы.

> [!info] Версии HTTP
> • **HTTP/1.0** — новое TCP-соединение на каждый запрос.
> • **HTTP/1.1** — `keep-alive` (соединение переиспользуется), но запросы в рамках соединения идут последовательно (head-of-line blocking).
> • **HTTP/2** — мультиплексирование (много параллельных стримов в одном TCP-соединении), сжатие заголовков (HPACK), server push.
> • **HTTP/3** — поверх **QUIC (UDP)**, убирает head-of-line blocking на транспортном уровне и быстрее устанавливает соединение.
> **HTTPS** — это HTTP поверх **TLS**: шифрование, проверка сертификата сервера, целостность данных (порт 443).
