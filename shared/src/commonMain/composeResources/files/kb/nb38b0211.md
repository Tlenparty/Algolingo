В Kotlin предоставлены мощные и удобные структуры данных, которые можно разделить на **коллекции** (списки, множества, отображения) и более низкоуровневые структуры (массивы). Эти структуры отличаются по функциональности, изменяемости, типам доступа и сценариям использования.

## **Основные структуры данных в Kotlin**

### **1. Массивы (Array)**

• **Описание:**
``Array<T>`` (изменяемый, фиксированный размер)
• Фиксированного размера.
• Быстрее (Array - фиксированный)
• Хранят элементы одного типа.
• Индексация начинается с 0.
• **Ключевые методы:** get(index), set(index, value), size.

• **Создание:**
```kotlin
val array = arrayOf(1, 2, 3)
val intArray = IntArray(5) { it * 2 } // Массив с инициализацией
```

• **Особенности:**
• Подходят для фиксированного числа элементов.
• Быстрый доступ к элементам по индексу.
• Неизменяемый размер.

### **2. Списки (List)**

• **Описание:**
``List<T>`` (неизменяемый)
• Чуть медленнее (List - динамическая структура)
• Последовательность элементов, упорядоченных по индексу.
• Два типа: неизменяемые (List) и изменяемые (MutableList).
• **Ключевые методы:** get(index), add(value), remove(value), size.

• **Создание:**

```kotlin
val immutableList = listOf(1, 2, 3) // Неизменяемый список
val mutableList = mutableListOf(1, 2, 3) // Изменяемый список
```

• **Особенности:**

• Неизменяемые списки безопасны от модификации.
• Изменяемые списки позволяют добавлять, удалять или изменять элементы.
• Эффективный доступ по индексу.

### **Разница между List и ArrayList**

• ``List<T>`` — это ==**интерфейс**== (он может быть неизменяемым или изменяемым, в зависимости от реализации).
• ``ArrayList<T>`` — это **==конкретная изменяемая реализация**== списка на основе массива.

### **3. Множества (Set)**

• **Описание:**
• Коллекция уникальных элементов без повторений. 
• Два типа: неизменяемые (Set) и изменяемые (MutableSet).
• **Ключевые методы:** add(value), remove(value), contains(value), size.
• По умолчанию создается LinkedHashSet, когда пишем setOf(1,2,3)

• **Создание:**

```kotlin
val immutableSet = setOf(1, 2, 3) // Неизменяемое множество
val mutableSet = mutableSetOf(1, 2, 3) // Изменяемое множество
```

• **Особенности:**
• Уникальные элементы.
• Неупорядоченная коллекция (порядок не гарантируется).
• Быстрый поиск элемента.

### Как работает set под капотом?

Добавление элементов в Set (например, HashSet в Java или mutableSetOf в Kotlin) под капотом реализовано через хеш-таблицу. Вот как это работает:

**📂 1. Вычисление хеша:**

Когда вы добавляете элемент в Set, сначала вычисляется его хеш-код с помощью метода hashCode(). Этот хеш-код помогает определить, в какую “ячейку” хеш-таблицы поместить объект.
```java
int hash = element.hashCode();
```

**🗃️ 2. Нахождение индекса:**

На основе хеш-кода вычисляется индекс в массиве хеш-таблицы. Обычно это делается с помощью побитовой операции:
```java
int index = (hash & (table.length - 1));
```
Эта операция эффективно распределяет объекты по доступным ячейкам массива.

**🧮 3. Проверка коллизий:**  

Если в рассчитанной ячейке уже есть элемент:

• **Если объекты равны (equals() возвращает true)**, то новый элемент не добавляется, так как Set не допускает дубликатов.
• **Если объекты не равны**, возникает коллизия. Коллизия разрешается:

• 📌 **Связыванием (Chaining):** Элементы хранятся в виде связанного списка (до Java 8) или в виде красно-чёрного дерева (с Java 8) в случае большого количества коллизий.

• 📦 **Открытой адресацией:** Элемент помещается в следующую свободную ячейку (не используется в HashSet, но встречается в других реализациях).

  
**➕ 4. Добавление элемента:**

Если в ячейке пусто, элемент просто добавляется в таблицу. Если произошла коллизия, элемент добавляется в связанный список или дерево.

Пример
```kotlin
val set = mutableSetOf<Int>()
set.add(10) // Вычисление хеша, определение индекса, добавление
set.add(20) // Аналогично
set.add(10) // Хеш совпадает, equals() вернёт true, не добавится
println(set) // [10, 20]
```

### **Что будет, если добавить 5 объектов Student в HashSet, где hashCode() всегда 1, а equals() не переопределён?**

```kotlin
class Student(val name: String, val secondName: String) {
    override fun hashCode() = 1 // Все объекты будут иметь одинаковый hashCode
}

fun main() {
    val set = HashSet<Student>()

    set.add(Student("Ivan", "Ivanov"))
    set.add(Student("Petr", "Petrov"))
    set.add(Student("Sergey", "Sergeev"))
    set.add(Student("Anna", "Orlova"))
    set.add(Student("Maria", "Smirnova"))

    println("Размер HashSet: ${set.size}")
}
```

**🔹 Разбор ситуации**

> [!success] Ответ: в Set будет **5 элементов**
> Все объекты имеют `hashCode() == 1` → попадают в **один бакет**. Но `equals()` **не переопределён** → используется сравнение по ссылке (из `Any`), а все 5 объектов — разные ссылки. Значит, ни один не считается дубликатом, и `set.size == 5` (просто все лежат в одном бакете цепочкой → поиск по нему деградирует до O(n)).

1. hashCode() **у всех объектов одинаковый (**1**)**

• В HashSet элементы хранятся в **бакетах** (группах), распределённых по hashCode().
• Все объекты Student попадают в **один и тот же бакет** — но это не мешает им всем добавиться, т.к. они различаются по `equals` (по ссылке).

2. equals() **НЕ переопределён**

• По умолчанию equals() в Kotlin (из Any) сравнивает ссылки ``(===).``
• То есть set.contains(student1) будет false, если student1 – это **другой объект**.

1. **Как** HashSet **проверяет дубликаты?**

• HashSet сначала **смотрит** hashCode().
• Если hashCode() совпадает, то **сравнивает через** equals().
• Так как equals() не переопределён, ==**каждый новый объект считается уникальным (разные ссылки).**==

**🔹 Как HashSet хранит элементы?**

**1. Использует hashCode() для размещения элементов**
  
Когда мы добавляем элемент в HashSet, выполняется:

1. Вычисление hashCode() объекта.
2. Определение **бакета** (группы) в хеш-таблице.
3. Помещение элемента в этот бакет.

```kotlin
data class Student(val name: String, val age: Int)

fun main() {
    val set = HashSet<Student>()
    val student1 = Student("Ivan", 20)
    val student2 = Student("Maria", 22)

    set.add(student1) // 1. Вычисляется hashCode() 
    set.add(student2) // 2. Добавляется в другой бакет (если hashCode() разный)

    println(set)
}
//📌 hashCode() помогает **размещать** элементы в HashSet, но **не гарантирует уникальность**.
```

**2. Использует equals() для проверки дубликатов**

Если два объекта имеют **одинаковый** hashCode(), HashSet сравнивает их через equals().
==Если equals() возвращает true, объект **не добавляется**==.

```kotlin
data class Student(val name: String, val age: Int) {
    override fun hashCode() = age // У всех студентов одного возраста один hashCode

    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is Student) return false
        return name == other.name && age == other.age
    }
}

fun main() {
    val set = HashSet<Student>()

    val s1 = Student("Ivan", 20)
    val s2 = Student("Ivan", 20) // Тот же возраст, но другой объект
    val s3 = Student("Maria", 22)

    set.add(s1)
    set.add(s2) // Не добавится, т.к. equals() вернёт true
    set.add(s3)

    println(set) // [Student(name=Ivan, age=20), Student(name=Maria, age=22)]
}
```

• При коллизии (одинаковый hashCode() у разных объектов) элементы **сравниваются через** equals().

### **4. Map**

• **Описание:**
• Коллекция пар “ключ-значение”.
• Два типа: неизменяемые (Map) и изменяемые (MutableMap).
• **Ключевые методы:** get(key), put(key, value), remove(key), containsKey(key), containsValue(value).

Класс **HashMap<K, V>** представляет собой хеш-таблицу для хранения пар ключ-значение. Уникальный ключ и неуникальное значение. Внутри **Hashmap** есть вложенный класс **Node<K,V>** в котором есть 

- **final int hash** - хэш код для объекта К key, 
- V - value, 
- Node <K,V> next - ссылка на следующий элемент
- Позволяет хранить null. **Сapacity** - емкость, или количество элементов (bucket) во внутренней таблице HashMap, по-умолчанию начальная емкость HashMap равна 16, и всегда равна степени 2, при попытке указать в конструкторе начальную емкость равную 28, она автоматически будет увеличена до 32; **loadFactor** (по-умолчанию равен 0.75, должен находиться в пределах от 0.0 до 1.0) отвечает за расширение массива - коэффициент, который показывает что при добавлении в HashMap количества элементов бОльшего чем capacity * loadFactor, емкость коллекции будет увеличена вдвое и произойдет рехеширование записей. 

**Когда мы хотим добавить значение (put)** то вычисляется hash ключа, вычисляется _index_ в массиве (index = (n-1)&hash) ,создается экземпляр вложенного Node<K,V>, если под этим индексом лежит элемент проверить их на равенство ключей, если равны то перезаписывается Value если нет ссылка next добавляемого элемента ссылается на сущесвтующий, добавляется объект.

**Когда мы хотим получить значение (get)** Операция может быть мгновенной (если 1 элемент лежит в бакете) или линейной (итерация по всем элементам в бакете).  Вычисляется хэш ключа, вычисляется индекс в массиве с помощью equals сравниваем объекты по цепочке. Если ключи совпадают, то возвращается значение. Если нет то ссылка next != null переходим к следующему значению. Если null то возвращается null (мы не нашли это значение)

**🚦 Основной процесс добавления в Map:**

**1. Вычисление хеш-кода ключа:**
Когда вы добавляете пару (key, value) в Map, сначала вызывается метод hashCode() для ключа.
```java
int hash = key.hashCode();
```

**2. Вычисление индекса:**

Хеш-код преобразуется в индекс в массиве корзин (buckets):
```java
int index = (hash & (table.length - 1));
```

Это помогает равномерно распределить ключи по таблице.

**3. Проверка коллизий:**

• 🆓 **Если ячейка пустая:** Пара (key, value) сохраняется в виде объекта Map.Entry в этой ячейке.
• 🚧 **Если ячейка занята:**
• Map проверяет equals() у уже существующих ключей в этой корзине.
• **Если ключи равны (equals() == true):** Новый value заменяет старый.

• **Если ключи не равны:**

• До Java 8: элементы хранятся в связанном списке.

• С Java 8: если количество элементов в корзине превышает порог (обычно 8), список превращается в красно-чёрное дерево для ускорения поиска.


**4. Разрешение коллизий:**

• **Связывание (Chaining):** Используется связанный список или дерево, чтобы хранить несколько элементов в одной корзине.

• **Замена значения:** Если ключ уже существует, значение просто заменяется.

**5. Ресайзинг (Rehashing):**

При заполнении 75% таблицы (load factor = 0.75) размер массива удваивается:

• Все существующие элементы перераспределяются по новой таблице.
```kotlin
val map = mutableMapOf<String, Int>()
map["apple"] = 1  // Добавление новой пары (apple -> 1)
map["banana"] = 2 // Добавление новой пары (banana -> 2)
map["apple"] = 3  // Замена значения (apple -> 3), так как ключ "apple" уже существует

println(map) // Вывод: {apple=3, banana=2}
```

## **🆚 Отличие от Set:**

>• В Set хранится только значение, а в Map — пара (key, value).
  • Set проверяет уникальность значения, а Map — уникальность ключей.

• **Создание:**

```kotlin
val immutableMap = mapOf("a" to 1, "b" to 2) // Неизменяемое отображение
val mutableMap = mutableMapOf("a" to 1, "b" to 2) // Изменяемое отображение
```

• **Особенности:**

• Ключи уникальны.
• Значения могут повторяться.
• Быстрый доступ к значениям по ключу.

**Когда использовать каждую структуру данных?**

5. **Массив (**Array**):**
• Используйте, когда известен фиксированный размер данных, и требуется высокая производительность для доступа по индексу.
• Пример: Обработка данных фиксированной длины (например, массив байтов).

6. **Список (**List**):**
• Используйте, когда элементы упорядочены, и их количество может варьироваться.
• Пример: Хранение динамического списка пользователей.

7. **Множество (**Set**):**
• Используйте, когда элементы должны быть уникальными.
• Пример: Хранение уникальных идентификаторов.

8. **Отображение (**Map**):**
• Используйте, когда требуется хранить данные в формате “ключ-значение”.
• Пример: Ассоциация имён пользователей с их идентификаторами.

| Структура | Изменяемость             | Упорядоченность                            | Уникальность        |
| --------- | ------------------------ | ------------------------------------------ | ------------------- |
| Массив    | значения да, размер нет  | да (по индексу)                            | нет                 |
| List      | зависит от типа          | да (по индексу)                            | нет                 |
| Set       | зависит от типа          | нет гарантий (но `LinkedHashSet` хранит)   | да                  |
| Map       | зависит от типа          | по ключам (зависит от реализации)          | уникальность ключей |

## **Может ли коллекция быть ключом в Map?**
 
Да, **коллекция может быть ключом в** Map, но есть важные нюансы!

По умолчанию, коллекции (List, Set, Map) **используют реализацию** equals() **и** hashCode() **из** AbstractCollection, которая делает их **изменяемыми** ключами.
**🔹 Что важно знать?**

9. **Если коллекция изменяется после добавления в** Map**, её** hashCode() **меняется, и ключ становится “потерянным”!**

10. **Лучше использовать неизменяемые коллекции (**List.of()**,** Set.of() **в Java или** listOf()**,** setOf() **в Kotlin).**

11. List**,** Set **и** Map **переопределяют** equals() **и** hashCode()**, поэтому их можно сравнивать по содержимому.**


## **Что такое хэш-таблица?**

**Хэш-таблица** — это структура данных, которая использует хэш-функцию для эффективного хранения, поиска и удаления данных.

В основе хэш-таблицы лежит массив, где:

• Каждый элемент массива называется **бакетом**.
• Индекс для каждого элемента вычисляется с помощью хэш-функции.

### **Как работает хэш-таблица**

12. **Добавление данных:**

• Хэш-функция вычисляет хэш-значение для ключа.
• Хэш-значение преобразуется в индекс массива, где хранятся данные.

13. **Поиск данных:**

• Хэш-функция вычисляет индекс, и данные извлекаются из соответствующего бакета.

14. **Обработка коллизий:**

• Если два ключа имеют одинаковый индекс (из-за одинакового хэш-значения), используются методы обработки коллизий:

• **Цепочки (chaining):** Данные хранятся в связанном списке внутри бакета.
• **Открытая адресация:** Ищется другая свободная ячейка в массиве.

**Преимущества хэш-таблицы**

15. **Быстродействие:**

• В среднем операции поиска, добавления и удаления занимают  O(1) .

16. **Простота использования:**

• Удобный доступ к данным по ключу.

**Пример использования хэш-таблицы в Kotlin**

В Kotlin структура HashMap — это реализация хэш-таблицы:

```kotlin
fun main() {
    val hashMap = hashMapOf<String, Int>()
    hashMap["Alice"] = 25
    hashMap["Bob"] = 30
    println(hashMap["Alice"]) // 25
}
```


**Итог:**

• **Хэш-функция**: Преобразует входные данные в хэш-значение, которое используется для индексации в хэш-таблице.

• **Хэш-таблица**: Эффективная структура данных для хранения пар “ключ-значение”, основанная на массиве и хэш-функции.

• **Основное преимущество**: Быстрый доступ к данным благодаря хэшированию.

### **Что такое коллизия в HashMap?**
**Коллизия** в HashMap — это ситуация, когда два разных ключа имеют одинаковое значение хэша (результат хэш-функции). Это возможно, так как хэш-функция преобразует ключ в целое число, а множество возможных ключей гораздо больше множества возможных хэш-значений.

## **Почему происходят коллизии?**

17. **Ограниченное количество хэш-значений:**

• Хэш-функция преобразует ключи в целое число фиксированного диапазона. При большом количестве ключей неизбежно появляются ключи с одинаковым хэш-значением.

18. **Особенности хэш-функции:**

• Неидеальная хэш-функция может распределять значения неравномерно, увеличивая вероятность коллизий.

### **Как HashMap справляется с коллизиями?**

Чтобы обработать коллизии, используются следующие подходы:

**1. Цепочки (Chaining)**

• Элементы с одинаковым хэш-значением хранятся в виде связного списка (или другого контейнера) в одной “ячейке” массива.

• Пример:
Если два ключа key1 и key2 имеют одинаковый хэш, их значения добавляются в связанный список для одной и той же ячейки.


**2. Открытая адресация (Open Addressing)**

• Вместо создания цепочки, HashMap ищет другую свободную ячейку для хранения нового элемента.
• В Java (и Kotlin) используется цепочечный метод, что делает обработку коллизий более эффективной.

 >**Решение коллизий**. Коллизии возникают, когда два разных ключа имеют одинаковый хеш-код. HashMap решает эту проблему с помощью **связанных списков** (раньше) или **[красно-чёрных деревьев](https://ai-droid.ru/krasno_chernoe_derevo)** (в более поздних версиях). Если несколько ключей имеют один и тот же хеш-код, они помещаются в один бакет в виде списка. Когда количество элементов в бакете превышает определённый порог, список превращается в красно-чёрное дерево для улучшения производительности.

**Влияние коллизий на производительность**

• В идеальном случае, операции в HashMap занимают **O(1)**.
• При коллизиях, особенно если их много, производительность может снизиться до **O(n)** (например, если все ключи попадают в одну и ту же ячейку, превращая её в линейный список).

### **Что такое Iterable?**
Iterable — это интерфейс, который представляет коллекцию элементов, поддерживающих итерацию. Все коллекции в Kotlin, такие как List, Set, Map, реализуют интерфейс Iterable.

**Ключевые особенности:**

19. **Генерация всех элементов сразу:**

• Все операции, такие как map, filter и другие, выполняются сразу для всех элементов коллекции.
• Создаётся новая коллекция для хранения промежуточных результатов.

20. **Жадная обработка (Eager evaluation):**

• Все операции выполняются сразу после вызова.

**Пример:**
```kotlin
val list = listOf(1, 2, 3, 4, 5)
val result = list.filter { it % 2 == 0 }.map { it * 2 }
println(result) // [4, 8]
/// Здесь сначала выполняется filter, создавая новую коллекцию [2, 4], затем map создаёт ещё одну коллекцию [4, 8].
```

## **Что такое Sequence?**

Sequence — это ленивый поток данных, позволяющий выполнять цепочки операций, не создавая промежуточные коллекции.

**Ключевые особенности:**

21. **Ленивая обработка (Lazy evaluation):**

• Операции, такие как map или filter, откладываются до тех пор, пока не потребуется результат.

22. **Постепенная обработка:**

• Каждый элемент обрабатывается до конца цепочки операций, а затем переходит к следующему элементу.
• Это делает Sequence особенно полезным для обработки больших или потенциально бесконечных данных.

23. **Пример:**
```kotlin
val sequence = sequenceOf(1, 2, 3, 4, 5)
val result = sequence.filter { it % 2 == 0 }.map { it * 2 }
println(result.toList()) // [4, 8]
```

24. **Создание** Sequence**:**

• Из коллекции:
```kotlin
val sequence = list.asSequence()
```

• Генерация бесконечного потока:

```kotlin
val infiniteSequence = generateSequence(1) { it + 1 }
println(infiniteSequence.take(5).toList()) // [1, 2, 3, 4, 5]
```

**Основные отличия между Iterable и Sequence**

| Характеристика          | Iterable                                | Sequence                                               |
| ----------------------- | --------------------------------------- | ------------------------------------------------------ |
| Обработка данных        | Жадная: все операции выполняются сразу  | Ленивая: операции откладываются                        |
| Промежуточные коллекции | Создаются на каждом шаге                 | Не создаются                                           |
| Большие данные          | Менее эффективно для больших коллекций  | Эффективно для больших данных                          |
| Пример данных           | списки, множества                       | потоки, большие данные, бесконечные последовательности |
## **Когда использовать Iterable или Sequence?**

25. **Используйте** Iterable**:**

• Когда размер коллекции небольшой.
• Когда важна простота и читаемость кода.
• Когда нет большого количества операций преобразования.

26. **Используйте** Sequence**:**

• Когда коллекция большая, и вы хотите избежать создания промежуточных коллекций.
• Когда работаете с ленивыми данными (например, потоки данных или бесконечные последовательности).
• Для сложных цепочек преобразований, чтобы оптимизировать производительность.

```kotlin
val list = (1..1_000_000).toList()
val result = list.filter { it % 2 == 0 }.map { it * 2 }.take(10)
println(result) // Выполняется фильтрация всех 1_000_000 элементов

val sequence = (1..1_000_000).asSequence()
val result = sequence.filter { it % 2 == 0 }.map { it * 2 }.take(10).toList()
println(result) // Обрабатываются только первые 10 элементов
```
В случае с Sequence будет обработано всего 10 элементов, что существенно быстрее.


## **🚀 Сколько памяти выделяет JVM при создании массива и где он хранится?**

В **Java (и Kotlin)** массивы являются объектами, и JVM выделяет для них память в **Heap (куче)**.

**✅ 1. Где хранится массив в памяти?**

При создании массива JVM выделяет:

• **Ссылку на массив** → хранится в **Stack (стеке)**
• **Сам массив (данные)** → хранятся в **Heap (куче)**

📌 **Пример:**

```kotlin
int[] arr = new int[5];  // Создаем массив из 5 элементов
```
1️⃣ **В стеке (**Stack**)**: переменная arr хранит **ссылку** на массив в куче.
2️⃣ **В куче (**Heap**)**: выделяется память для массива ``(int[5])``.

**✅ 2. Сколько памяти выделяется под массив?**

**🔹 Формула расчета:**

Общий размер массива в памяти:
```kotlin
Memory = (Header + (ElementSize × Length) + Padding)
```

Где:

• **Header** – служебная информация JVM (обычно 12–16 байт)
• **ElementSize** – размер одного элемента
• **Length** – количество элементов
• **Padding** – выравнивание памяти

**🔹 Пример: ``int[] arr = new int[5];``**

27. **Header** = **12 байт** (на 32-битной JVM) или **16 байт** (на 64-битной JVM)
28. **Размер** int = **4 байта**
29. **Количество элементов** = **5**
30. **Padding** (если требуется)

🔢 **Общий размер массива**:

```kotlin
16 + (4 × 5) = 36 байт  (на 64-битной JVM)
12 + (4 × 5) = 32 байта (на 32-битной JVM)
```

**✅ 3. Размер массива для разных типов данных**

| **Тип данных** | **Размер одного элемента (байт)** | **Пример:** new type``[N] (N = 5)`` | **Размер (байт) (64-bit JVM)** |
| -------------- | --------------------------------- | ----------------------------------- | ------------------------------ |
| ``boolean[]``  | **1 байт**                        | new boolean[5]                      | **21 байт**                    |
| ``char[]``     | **2 байта**                       | new char[5]                         | **26 байт**                    |
| ``short[]``    | **2 байта**                       | new short[5]                        | **26 байт**                    |
| ``int[]``      | **4 байта**                       | new int[5]                          | 36 байт                        |

> [!tip] Сложности операций (Big-O) — частый вопрос
> | Структура              | Доступ по индексу | Поиск    | Вставка/удаление          |
> | ---------------------- | ----------------- | -------- | ------------------------- |
> | `Array` / `ArrayList`  | O(1)              | O(n)     | O(n) (в конце амортиз. O(1)) |
> | `LinkedList`           | O(n)              | O(n)     | O(1) (по итератору)       |
> | `HashSet` / `HashMap`  | —                 | O(1)\*   | O(1)\*                    |
> | `TreeMap` / `TreeSet`  | —                 | O(log n) | O(log n)                  |
>
> \* В среднем O(1); при множестве коллизий — O(log n) (дерево с Java 8) или O(n) в худшем случае.
>
> Ключевые факты: `ArrayList` — быстрый доступ по индексу, медленная вставка в середину; `HashMap` — O(1) на ключе, но требует корректных [[EQUALS, HASHCODE|equals/hashCode]]; `TreeMap` — упорядоченный, O(log n).
