**AndroidManifest.xml** — это важный конфигурационный файл в любом Android-приложении, который содержит информацию о структуре приложения и его компонентах, а также разрешениях и настройках, которые необходимы для его работы. Этот файл является обязательным для любого Android-приложения, и без него приложение не будет работать.

**Основные цели и задачи AndroidManifest.xml:**

1. **Определение компонентов приложения:**

В **AndroidManifest.xml** описываются все компоненты приложения, такие как:

• **Activities** (Активности)
• **Services** (Сервисы)
• **Broadcast Receivers** (Приемники широковещательных сообщений)
• **Content Providers** (Поставщики контента)

2. **Настройка разрешений:**

Здесь указываются разрешения, которые требуются для доступа к различным ресурсам и функциям устройства (например, доступ к камере, интернету, GPS и т.д.).

Например, если ваше приложение использует камеру, необходимо добавить разрешение:
```xml
<uses-permission android:name="android.permission.CAMERA"/>
```

3. **Заявка на использование специфических возможностей устройства:**

В манифесте можно указать, какие функции устройства требуются для работы приложения, например, использование сенсора, камеры, Bluetooth, и т.д.

4. **Определение темы и иконки приложения:**

Манифест также указывает иконку приложения, его тему и стиль:
```xml
<application
    android:icon="@drawable/ic_launcher"
    android:theme="@style/Theme.AppCompat">
</application>
```

5. **Указание минимальной и целевой версии API:**

В манифесте устанавливаются минимальные и целевые версии Android, которые необходимы для запуска приложения. Например:
```xml
<uses-sdk
    android:minSdkVersion="21"
    android:targetSdkVersion="30" />
```

6. **Объявление активностей, сервисов и других компонентов:**

Все активности, сервисы и приемники сообщений должны быть объявлены в манифесте, чтобы система знала, как взаимодействовать с ними. Например:
```xml
<activity android:name=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.MAIN"/>
        <category android:name="android.intent.category.LAUNCHER"/>
    </intent-filter>
</activity>
```

В этом примере мы объявляем активность MainActivity как точку входа в приложение с помощью intent-filter, который указывает, что она является основной активностью, которую следует запустить при старте приложения.

### Может ли в Манифесте быть 2 активити с android:name="android.intent.category.LAUNCHER ??
Если в манифесте **две активности с** LAUNCHER, то:
1. **При установке приложения в системе появятся два ярлыка** (иконки) для запуска.
2. **Оба ярлыка ведут в разные активности**, но оба запускают приложение.

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.example.app">

    <application
        android:allowBackup="true"
        android:theme="@style/Theme.App">

        <!-- Первая активити (основной экран) -->
        <activity android:name=".MainActivity">
            <intent-filter>
                <action android:name="android.intent.action.MAIN"/>
                <category android:name="android.intent.category.LAUNCHER"/>
            </intent-filter>
        </activity>

        <!-- Вторая активити (альтернативный стартовый экран) -->
        <activity android:name=".AlternativeActivity">
            <intent-filter>
                <action android:name="android.intent.action.MAIN"/>
                <category android:name="android.intent.category.LAUNCHER"/>
            </intent-filter>
        </activity>

    </application>
</manifest>
```

🔹 **После установки на устройство появятся два ярлыка**: один запускает MainActivity, другой — AlternativeActivity.

**Когда это полезно?**

✅ **Разные режимы запуска** (например, обычный и админский интерфейс).
✅ **Функция быстрого доступа** (например, сразу открывать камеру или сканер QR-кодов).
✅ **Демо-режим или тестирование** (например, ярлык для внутренней версии приложения).

### **Как сделать так, чтобы ярлык был только один, но активность менялась?**

Если нужно **переключать стартовую активити программно**, а не через два ярлыка, можно использовать android.intent.category.DEFAULT и FLAG_ACTIVITY_NEW_TASK:
```kotlin
val intent = Intent(this, AlternativeActivity::class.java).apply {
    addCategory(Intent.CATEGORY_DEFAULT)
    flags = Intent.FLAG_ACTIVITY_NEW_TASK
}
startActivity(intent)
```

## **Разница между permission и uses-permission в Android Manifest**

1. ``<permission>`` – объявляет собственное разрешение.
2. ``<uses-permission>`` – запрашивает у системы доступ к существующему разрешению.

> [!important] Актуальные нюансы манифеста
> - **`android:exported` обязателен (с Android 12 / API 31)** для любого компонента с `intent-filter`. Если не указать — приложение **не соберётся**. `exported="true"` — компонент доступен другим приложениям/системе; `"false"` — только внутри своего приложения. Важно для безопасности (незакрытый `exported` Activity/Receiver — дыра).
> - **`minSdk`/`targetSdk`/`compileSdk` сейчас задают в `build.gradle`**, а не через `<uses-sdk>` в манифесте — Gradle перезаписывает значения манифеста. `<uses-sdk>` в манифесте считается устаревшим.
> - **Manifest merging:** итоговый манифест склеивается из манифеста приложения, библиотек (AAR) и build-флейворов. Конфликты решаются `tools:`-маркерами (`tools:replace`, `tools:node`).
> - **Runtime-разрешения** (камера, геолокация, нотификации с 13) объявляются в манифесте, но **запрашиваются в рантайме** через `requestPermissions` — одного манифеста недостаточно.
