# Jetpack Compose

Jetpack Compose — современный фреймворк для UI на Android от Google. Под капотом он реализует **декларативный** подход, в отличие от традиционного императивного (XML + `findViewById` + ручное обновление View). Пишем на Kotlin, без XML.

## Composable-функции и Composer

**Composable-функции** — базовые строительные блоки Compose, описывающие UI в декларативном стиле. Помечаются аннотацией `@Composable` — маркером для **Compose Compiler Plugin**, который превращает их в код, участвующий в механизмах рекомпозиции.

Ключевые правила:

- **Composable можно вызвать только из другой Composable** (в терминах IDE — «красная» функция вызывается внутри «красной»).
- **Имя с большой буквы** (`Text`, `Column`) — функция возвращает `Unit` и **рендерит** компонент UI. **С маленькой буквы** (`remember`, `rememberCoroutineScope`) — возвращает данные и ничего не рисует.
- **Порядок параметров** (гайдлайн): сначала обязательные, затем с дефолтными значениями; `Modifier` — первым из опциональных, лямбды-колбэки и trailing-контент — последними.

### Что добавляет компилятор

Компилятор Compose добавляет вызовы `$composer` в начало и конец сгенерированной функции. Эти методы открывают и закрывают **группу** — узел дерева, которое строит Compose. Слово `Restart` указывает тип группы:

```kotlin
@Composable
fun MyComposable($composer: Composer) {
    $composer.startRestartGroup() // начало группы

    // тело функции

    $composer.endRestartGroup()   // конец группы
        ?.updateScope { $composer ->
            MyComposable($composer)
        }
}
```

На основе данных из тела функции `$composer` шаг за шагом строит дерево — это первая фаза Compose, **Composition**. Если между началом и концом группы было прочитано состояние, которое умеет оповещать Compose о своём изменении, то `$composer.endRestartGroup()` вернёт **не null** (значит, эту группу нужно уметь перезапускать = рекомпозировать).

### Роль Composer

**Composer** — часть **runtime** Compose. Он отвечает за то, чтобы:

1. **Выполнять composable-функции** и строить из них дерево UI.
2. **Отслеживать изменения состояния:** сравнивает текущее и новое значение и решает, что перерисовать.
3. **Реализовывать декларативность:** вы описываете *что* должно быть на экране, а Composer оптимально это применяет.
4. Работать в связке с **Compose Compiler Plugin**, который и преобразует `@Composable` в код, умеющий отслеживать изменения. См. [[Compose. Composer and Snapshot]].

## Фазы Compose

Как и большинство UI-инструментариев, Compose отрисовывает кадр в несколько фаз. У классической Android View их три: measure → layout → draw. У Compose похоже:

1. **Composition** — *какой* UI отобразить. Compose запускает composable-функции и создаёт описание UI.
2. **Layout** — *как* расположить UI. Два шага: измерение (measurement) и размещение (placement). Элементы измеряют и располагают себя и детей.
3. **Drawing** — *как* отрисовать. Элементы рисуют себя на `Canvas`.

> [!note] Отличие от XML
> В Compose composable-функции можно свободно вкладывать друг в друга — глубина вложенности не бьёт по производительности, потому что **измерение проходит за один проход**. В системе View глубокая вложенность приводит к нескольким проходам measure/layout и тормозит.

## Аргументы composable-функций: `$changed`

Помимо `$composer`, компилятор добавляет параметр `$changed` — `Int`-битовую карту, в которой биты несут информацию об аргументах функции и их изменении:

```kotlin
// Сигнатура composable-функции после работы компилятора
@Composable
fun Header(text: String, $composer: Composer<*>, $changed: Int)
```

Если в родительской функции часть параметров изменилась, а часть нет, эта информация передаётся детям через `$changed` — чтобы они не делали лишних сравнений. Дочерняя функция сравнивает только то, в чём «не уверен» родитель, либо аргументы по умолчанию.

## Ключевые механизмы

### 1. Composition

Когда вызывается `setContent`, Compose строит дерево компонентов UI — это **композиция**.

### 2. Recomposition (рекомпозиция)

Ключевой механизм обновления UI. Вместо полной перерисовки Compose обновляет только участки, зависящие от изменённого состояния:

1. Compose заново вызывает `@Composable`-функции, чьи данные изменились.
2. Для отслеживания используется **snapshot state** (например, `mutableStateOf()`).
3. Пересчитываются только участки, зависящие от изменённого состояния.

```kotlin
var count by remember { mutableStateOf(0) }

Button(onClick = { count++ }) {
    Text("Clicked $count times")
}
// при изменении count перерисуется только этот участок, а не весь экран
```

Подробнее — [[Compose. Recomposition]].

### 3. Slot Table

**Slot Table** — лёгкая **линейная** структура данных, которая:

- хранит информацию о вызовах composable-функций;
- отслеживает их параметры и состояния;
- используется для быстрого сравнения и обновления UI при рекомпозиции.

Это позволяет не перестраивать всё дерево заново. См. [[Compose. Slot table]].

### 4. Преобразования на этапе компиляции

Compose-компилятор оптимизирует выполнение composable-функций: генерирует код, который управляет состоянием, работает со Slot Table и интегрируется с рекомпозицией.

### 5. remember и CompositionLocal

- **`remember`** — хранит данные между рекомпозициями (управляемое Compose кэширование). См. [[Compose. Remember]].
- **`mutableStateOf`** — создаёт отслеживаемое состояние; при изменении UI обновляется автоматически.
- **`CompositionLocal`** — передаёт данные вниз по дереву без явной передачи через параметры. См. [[Compose. Composition Local]].

```kotlin
@Composable
fun RememberExample() {
    var text by remember { mutableStateOf("Hello") }
    TextField(value = text, onValueChange = { text = it })
}
```

### 6. UI-дерево

Compose строит динамическое дерево компонентов (аналог DOM/View-дерева), но легче: оно не использует тяжеловесные `View`, а создаётся и управляется динамически. Каждый узел — часть интерфейса; при изменении состояния пересчитывается только затронутая часть.

### 7. Runtime и Skipping

Compose работает на **Compose Runtime**: он управляет деревом компонентов, отслеживает изменения состояния и решает — рекомпозировать узел или **пропустить (skip)**, если его входные данные стабильны и не изменились. См. [[Compose. Стабильность]].

### 8. Отрисовка через Skia

Compose не использует систему View для рендеринга — он работает с `Canvas` поверх **Skia** (графическая библиотека для высокопроизводительной отрисовки текста, изображений и векторной графики). После (ре)композиции запускаются фазы **Layout** (размеры и позиции) и **Draw** (отрисовка на Canvas).

> [!info] Compose не только на Android
> Тот же Compose-компилятор и рантайм работают в **Compose Multiplatform** — общий UI для iOS, desktop и web. Всё про рекомпозицию, стабильность и `remember` переносится туда без изменений, меняется только бэкенд отрисовки. См. [[KMP. Compose Multiplatform]].
