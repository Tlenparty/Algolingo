# Безопасность в Android

Набор тем по безопасности, который ждут от Senior: где хранить секреты, как защищать трафик, как устроена песочница приложений.

## Модель безопасности платформы

> [!info] Песочница приложений
> Каждое приложение в Android — отдельный **Linux-пользователь (UID)** со своей изолированной директорией. Файлы в `filesDir`/`databases` по умолчанию приватны (`MODE_PRIVATE`), другие приложения к ним не имеют доступа. Межпроцессное взаимодействие — только через явные механизмы (Intent, ContentProvider, Binder). Разрешения (permissions) ограничивают доступ к системным ресурсам.

## Хранение секретов и чувствительных данных

| Что | Чем хранить |
| --- | --- |
| Ключи шифрования | **Android Keystore** (ключ не покидает защищённое хранилище/TEE/StrongBox) |
| Токены/пароли | **EncryptedSharedPreferences** / зашифрованный DataStore (ключ из Keystore) |
| Чувствительные файлы | **EncryptedFile** (Jetpack Security) |
| Биометрия как гейт | **BiometricPrompt** + ключ Keystore с `setUserAuthenticationRequired` |

> [!important] Android Keystore — ключевая концепция
> Keystore хранит **криптографические ключи так, что само приложение их не видит** — оно может только *просить* выполнить операцию (шифрование/подпись). На устройствах с **TEE/StrongBox** ключи изолированы на аппаратном уровне, их нельзя извлечь даже с root. Поэтому правильная схема: данные шифруются ключом, а **ключ живёт в Keystore**, а не в коде/префах.

> [!danger] Чего нельзя делать
> • **Хардкодить** API-ключи/секреты в коде или `BuildConfig` — APK декомпилируется, обфускация ([[R8, ProGuard, обфускация]]) не спасает. Секреты — на сервере, клиент получает короткоживущие токены.
> • Хранить токены в обычных **SharedPreferences** в открытом виде.
> • Логировать чувствительные данные (токены, PII) в release.
> • Доверять клиенту: любую критичную проверку дублировать на бэке.

## Сеть

> [!tip] Certificate pinning и cleartext
> • **Certificate / public-key pinning** — приложение доверяет только конкретному сертификату/ключу сервера, защита от MITM с подменным CA. Настраивается через **Network Security Config** (`<pin-set>`) или `CertificatePinner` в OkHttp.
> • С Android 9 (API 28) **cleartext (HTTP) трафик запрещён по умолчанию** — только HTTPS, иначе нужно явное разрешение в Network Security Config (что в проде делать не стоит). См. [[HTTP]].
> • Минус пиннинга — при ротации сертификата без обновления приложения всё ломается; поэтому пинят несколько ключей/бэкап.

> [!note] Прочее, что могут спросить
> • **Root/tamper detection** (SafetyNet/Play Integrity API) — проверка целостности окружения.
> • **`FLAG_SECURE`** — запрет скриншотов/записи экрана на чувствительных экранах.
> • **Exported-компоненты** — `android:exported` для Activity/Service/Receiver должно быть осознанным (на API 31+ обязателен явный флаг), иначе чужие приложения смогут их вызвать. См. [[Что такое Manifest]].
> • **PendingIntent** — `FLAG_IMMUTABLE` на API 31+ (см. [[Способы передачи геолокации в фоновом режиме]]).
