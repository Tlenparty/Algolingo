# BackPressure в Flow — что это и как решается

**BackPressure (обратное давление)** — это ситуация, когда источник данных (**Producer**) генерирует элементы быстрее, чем их успевает обработать потребитель (**Consumer**).

К чему это приводит:

- **Рост потребления памяти** — если буфер переполняется.
- **Потеря данных** — если элементы приходится сбрасывать.
- **Блокировка потока** — если Consumer не успевает.

> [!important] Главное про Flow
> В Kotlin Flow backpressure по умолчанию решается **приостановкой (suspend)**: `emit()` — это suspend-функция, и если Consumer не успевает, корутина Producer'а просто приостанавливается, пока потребитель не будет готов. То есть «из коробки» данные не теряются и память не растёт — Producer ждёт. Операторы ниже нужны, когда такое ожидание нас **не устраивает** (например, для UI важна свежесть, а не полнота).

## Пример проблемы

```kotlin
fun fastProducer(): Flow<Int> = flow {
    var count = 0
    while (true) {
        emit(count++)  // производим элементы быстро
        delay(50)
    }
}

fun slowConsumer() = runBlocking {
    fastProducer().collect {
        delay(200) // медленный потребитель
        println("Received: $it")
    }
}
```

Producer генерирует элемент каждые 50 мс, Consumer обрабатывает каждые 200 мс. Без операторов `emit()` будет приостанавливаться — Producer фактически замедлится до темпа Consumer'а.

## Как управлять backpressure

### 1. `buffer()` — буферизация элементов

```kotlin
fastProducer()
    .buffer(capacity = 10) // буфер на 10 элементов
    .collect { println(it) }
```

Producer и Consumer начинают работать на разных корутинах: Producer складывает элементы в буфер и не ждёт Consumer'а, пока буфер не заполнится. Можно задать поведение при переполнении через `onBufferOverflow` (`SUSPEND`, `DROP_OLDEST`, `DROP_LATEST`).

### 2. `conflate()` — оставляем только последнее значение

```kotlin
fastProducer()
    .conflate() // промежуточные значения пропускаются
    .collect { println(it) }
```

Если Consumer не успевает, промежуточные значения отбрасываются — остаётся только самое свежее. По сути `buffer(onBufferOverflow = DROP_OLDEST)` с буфером в 1 элемент.

### 3. `collectLatest()` — отмена обработки старого элемента

```kotlin
fastProducer()
    .collectLatest {
        println("Processing $it")
        delay(200) // если пришёл новый элемент — обработка старого отменяется
    }
```

Отличие от `conflate()`: здесь именно **отменяется уже начатая** обработка предыдущего элемента, а не просто пропускается значение в буфере.

### 4. `sample()` — берём значение раз в интервал

```kotlin
fastProducer()
    .sample(500) // элемент раз в 500 мс
    .collect { println(it) }
```

Снижает частоту обновлений — удобно для UI (например, прогресс или поисковый ввод).

### 5. `debounce()` — ждём «паузу» в потоке

```kotlin
searchQueryFlow
    .debounce(300) // эмитит значение, только если 300 мс ничего нового не приходило
    .collect { search(it) }
```

Классика для поля поиска: не дёргаем сеть на каждый символ.

## Сравнение

| Оператор          | Как работает                                                         |
| ----------------- | -------------------------------------------------------------------- |
| `buffer()`        | Складывает элементы в буфер, чтобы Producer не ждал Consumer'а       |
| `conflate()`      | Хранит только последнее значение, промежуточные отбрасывает          |
| `collectLatest()` | При новом элементе отменяет ещё не завершённую обработку предыдущего |
| `sample(time)`    | Берёт элемент с фиксированным интервалом времени                     |
| `debounce(time)`  | Эмитит значение только после паузы во входном потоке                 |
| `drop(n)`         | Пропускает первые `n` элементов (не про backpressure, а про фильтр)  |
