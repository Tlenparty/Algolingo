# Бинарный поиск

**Бинарный (двоичный) поиск** — поиск элемента в **отсортированном** массиве за **O(log n)** делением диапазона пополам.

## Базовый вариант

```kotlin
fun binarySearch(a: IntArray, target: Int): Int {
    var lo = 0
    var hi = a.size - 1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2     // не (lo+hi)/2 — защита от переполнения
        when {
            a[mid] == target -> return mid
            a[mid] < target  -> lo = mid + 1
            else             -> hi = mid - 1
        }
    }
    return -1
}
```

> [!important] Три классические ошибки
> 1. **`(lo + hi) / 2`** — переполнение `Int` на больших индексах. Правильно `lo + (hi - lo) / 2`.
> 2. **Граница цикла** — `while (lo <= hi)` (а не `<`), иначе пропустишь элемент, когда `lo == hi`.
> 3. **Бесконечный цикл** — забыли `+1`/`-1` при сдвиге границ.

## Главное условие применимости

> [!warning] Массив должен быть отсортирован
> Бинарный поиск работает **только на отсортированных** данных (или на монотонном свойстве). Если массив не отсортирован — либо линейный поиск O(n), либо сначала сортировка O(n log n) (оправдано при многих запросах). На собесе первый вопрос: «массив отсортирован?».

## Вариации (то, что реально спрашивают)

> [!tip] Lower / upper bound
> Чаще просят не «найти элемент», а **границу**:
> • **lower bound** — первый индекс, где `a[i] >= target`;
> • **upper bound** — первый индекс, где `a[i] > target`.
> Реализация — тот же бинпоиск, но при совпадении **не возвращаем сразу**, а продолжаем двигать границу, запоминая кандидата. Это основа `Collections.binarySearch` и поиска диапазона дубликатов.

> [!info] Бинарный поиск по ответу
> Мощный приём: если ответ **монотонен** («при X — можно, при X+1 — тоже можно»), бинпоиск ищет не в массиве, а **по диапазону значений ответа**. Примеры: «минимальная скорость, чтобы успеть», «минимальный размер, чтобы влезло». Узнаётся по формулировке «минимальное/максимальное значение, при котором выполняется условие».

> [!note] Сложность и готовое API
> • Время **O(log n)**, память **O(1)** (итеративно) или O(log n) (рекурсивно — стек).
> • В Kotlin/Java есть `Arrays.binarySearch` / `Collections.binarySearch` (возвращает `-(insertionPoint)-1`, если не найдено — удобно для вставки в отсортированный список). См. [[BIG O]] про логарифмическую сложность.
