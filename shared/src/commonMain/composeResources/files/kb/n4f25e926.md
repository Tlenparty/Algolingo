```kotlin
class Counter(var count: Long) {
    fun increment() {
        count++
    }

    fun decrement() {
        count--
    }
}

const val PIECES_OF_WORK = 1000
var counterOfCompletedPiecesOfWork = Counter(0)

fun main() {
    thread {
        Handler(Looper.getMainLooper()).post {
            MainScope().launch {
                coroutineScope {
                    launch {
                        withContext(Dispatchers.Default) {
                            (1..PIECES_OF_WORK).map {
                                async {
                                    delay(2.nanoseconds)
                                    counterOfCompletedPiecesOfWork.increment()
                                }
                            }.awaitAll()
                        }
                    }
                    try {
                        async {
                            delay(10.nanoseconds)
                            if ((0..100).random() == 1) {
                                throw Exception("failed to do simple work")
                            }
                        }
                    } catch (e: Exception) {
                        println(e)
                    }
                    runBlocking(Dispatchers.Main) {
                        for (i in 1..PIECES_OF_WORK) {
                            delay(2.nanoseconds)
                            counterOfCompletedPiecesOfWork.decrement()
                        }
                    }
                }
                println(counterOfCompletedPiecesOfWork.count)
            }
        }
    }

}
```


### Что будет выведено ?

```kotlin
package com.example.mytestapplication  
  
data  class Task(val id: Long, val name: String)  
  
val list = mutableListOf(1, 3, 5)  
val tasks = HashSet<Task>()  
  
fun main() {  
    val task1 = Task(1, "Задача")  
    val task2 = Task( 1, "Задача")  
  
    tasks.add(task1)  
    tasks.add(task2)  
  
    list.add(7)  
  
    list.forEvery { it ->  
        if (it == 3) {  
            return  
        }  
        println("$it")  
    }  
  
    println("tasks contains ${tasks.size} elements")  
    println("Done!")  
  
  
  
    // До  
    //1    //tasks contains 2 elements    //Done  
    //После    //1    //tasks contains 1 elements    //Done  
}  
  
 inline fun <T> List<T>.forEvery(itemAction: (T) -> Unit) {  
    reversed().forEach {  
        itemAction(it)  
    }  
}
```

> [!danger] Часть 1: гонка на общем `Counter`
> Главная проблема — `counterOfCompletedPiecesOfWork` инкрементируется из **1000 параллельных `async`** на `Dispatchers.Default`. `count++` — это **read-modify-write**, не атомарно → классическая гонка: часть инкрементов теряется, итог недетерминирован (обычно < 1000 «фактических» прибавок). Чинится `AtomicLong`/`incrementAndGet`, `Mutex` или сведением к одному потоку.
> Сопутствующие грабли этого «шедевра»:
> • **`async { … if (random) throw }` не оборачивается `try/catch`** так, как кажется: `try` ловит только запуск, а не тело. `async` — дочерний для `coroutineScope`, поэтому брошенное исключение **отменит весь scope** (structured concurrency), а не уйдёт в проигнорированный `Deferred`.
> • **`runBlocking(Dispatchers.Main)` внутри корутины на Main** — блокирует главный поток (потенциальный deadlock/ANR). Внутри корутины блокирующий `runBlocking` не нужен — есть `withContext(Dispatchers.Main)`.
> • **`delay(2.nanoseconds)`** фактически ≈ 0: `delay` оперирует миллисекундами.
> • Обёртка `thread { Handler(mainLooper).post { MainScope().launch { … } } }` — нагромождение способов «попасть в Main», каждый из которых сам по себе уже это делает.

> [!warning] Часть 2: non-local return из inline-лямбды + data class в HashSet
> 1. **`Task` — `data class`**, `task1` и `task2` имеют одинаковые `id` и `name` → равны → в `HashSet` останется **1 элемент** (`tasks.size == 1`). Если бы `Task` был обычным классом — `equals` по ссылке → 2 элемента.
> 2. **`return` внутри лямбды `forEvery` — нелокальный.** Поскольку `forEvery` помечена `inline`, лямбда встраивается, и `return` выходит из **`main` целиком**, а не из итерации. `forEvery` идёт по `reversed()` → `[7, 5, 3, 1]`: печатает `7`, `5`, на `3` срабатывает `return` → **`main` завершается**, строки `tasks contains …` и `Done!` **никогда не выведутся**. Чтобы прервать только итерацию, нужен `return@forEvery` (locally) или метка.

## Как отвечать на собеседовании

> [!tip] Главный инсайт задачи — озвучить его первым
> Задача **двухслойная**: интервьюер проверяет, заметишь ли ты, что (1) `data` меняет поведение `HashSet` через структурный `equals`/`hashCode`, но (2) из-за **нелокального `return` из inline-лямбды** это различие в консоль так и не попадёт — `main` завершится раньше `println("tasks contains ...")`. Кто отвечает «1 элемент vs 2 элемента» — попался: вывод программы в обоих случаях одинаковый (`7`, `5`).

> [!example] Скрипт ответа (порядок важен)
> 1. **Не отвечать сразу.** Проговорить: «Сначала трассирую порядок выполнения, потом отвечу, что выведется».
> 2. **Найти точку невозврата раньше всего остального:** `forEvery` — `inline`, значит голый `return` в лямбде — нелокальный, выходит из `main`. Итерация идёт по `reversed()` → `[7, 5, 3, 1]` → печатается `7`, `5`, на `3` — выход.
> 3. **Только теперь** сказать вывод: `7`, `5` — и всё. `tasks contains ...` и `Done!` недостижимы.
> 4. **Ответить на вопрос про `data` как «а если бы дошло»:** с `data` — структурный `equals`/`hashCode` → сет схлопнет дубликат → 1 элемент; без `data` — сравнение по ссылке от `Any` → 2 элемента. Плюс без `data` пропадают `copy()`, `componentN()`, читаемый `toString()`.
> 5. **Показать, как чинить:** `return@forEvery` (аналог `continue`) или метка — тогда разница между `data`/не-`data` станет наблюдаемой.
> Такой порядок показывает системное мышление: сначала control flow, потом семантика equals — а не наоборот.

> [!check] Чек-лист ловушек в задачах «что выведется» (Kotlin)
> Прежде чем называть вывод, пробежаться по списку:
> - **`inline` + голый `return`** → нелокальный выход из внешней функции (эта задача).
> - **`reversed()` / `sorted()` / `shuffled()`** в кастомных итераторах → порядок не тот, что в объявлении списка.
> - **`data` vs обычный class** в `Set`/`Map`-ключах → структурное vs ссылочное равенство.
> - `data class`: в `equals`/`hashCode` участвуют **только свойства первичного конструктора** — поля из тела класса игнорируются.
> - **Комментарии с «ожидаемым выводом» в самом коде** — могут быть от другой версии кода (здесь «До: 1 / tasks contains 2» — от `forEvery` без `reversed()`). Не доверять, проверять самому.
> - Многопоточность/корутины (часть 1) → искать read-modify-write без атомарности, `try` вокруг `async` (не ловит), `runBlocking` на Main.

> [!abstract] Как себя вести
> - **Думать вслух.** Ценится трассировка, а не угаданный ответ: «инлайнится → return нелокальный → main завершается».
> - **Заметить ловушку = назвать её термином:** «non-local return», «structured concurrency», «структурное равенство» — сигнал, что знаешь тему, а не наткнулся случайно.
> - Если не уверен — **честно сузить:** «точно знаю, что return тут нелокальный; проверю, что печатается до него».
> - В конце — **предложить исправление** (`return@forEvery`, `AtomicLong` для части 1): переводит ответ из «нашёл подвох» в «умею чинить».
