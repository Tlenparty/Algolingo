# Performance. Baseline и Startup Profiles

**Baseline Profiles** — один из самых эффективных и «дешёвых» способов ускорить запуск и убрать jank в первых сессиях. Частый Senior-вопрос: «как ускорили cold start без переписывания кода».

## Проблема, которую решают

Android исполняет код через **ART**. По умолчанию свежеустановленное приложение работает в **интерпретации + JIT**: «горячие» участки компилируются в нативный код только со временем, по мере исполнения. Поэтому **первые запуски медленнее** — AOT-компиляции ещё нет.

> [!info] Что такое Baseline Profile
> Это список классов и методов (`baseline-prof.txt`), которые **важны для запуска и ключевых сценариев**. ART использует его, чтобы **скомпилировать (AOT) эти методы прямо при установке** — ещё до первого запуска. Результат: первые сессии работают так, будто приложение уже «прогрелось».

> [!important] Эффект
> Google заявляет до **~30% ускорения** холодного старта и заметное снижение jank в первых прокрутках. Профиль кладётся в `src/main/baseline-prof.txt` (или генерируется), пакуется в APK/AAB и применяется при установке/обновлении.

## Как генерируются

```kotlin
// модуль :baselineprofile, тест с BaselineProfileRule
@Test
fun generate() = baselineProfileRule.collect(packageName = "com.app") {
    startActivityAndWait()
    // прокрутить ключевой экран, пройти основной сценарий
    device.findObject(By.res("feed")).fling(Direction.DOWN)
}
```
Тест прогоняет критичные пользовательские пути, инструмент записывает использованные методы → готовый профиль.

## Связанные понятия

> [!tip] Startup Profiles
> Подмножество Baseline Profile конкретно для **старта**: влияет ещё и на то, как **D8/R8 раскладывают код в DEX** (`dex layout optimization`) — горячие методы группируются ближе, меньше «прыжков» по файлу при загрузке.

> [!note] Cloud Profiles (Profile-guided optimization от Play)
> Play Store также агрегирует профили от реальных пользователей и раздаёт их новым установкам. Baseline Profile из коробки даёт стартовый буст **сразу**, не дожидаясь накопления облачных профилей.

> [!warning] Чего НЕ делает
> Baseline Profile не уменьшает объём работы при старте — он лишь делает код «предкомпилированным». Если в `Application.onCreate()` синхронно инициализируется полмира (DI-граф, аналитика, БД), профиль это не спасёт. Параллельно с профилем чистят **App Startup** (ленивая инициализация, `androidx.startup`), убирают тяжёлую работу с главного потока.

> [!tip] Как проверить, что профиль применился
> Замерить cold start через [[Performance. Рендеринг, jank и Macrobenchmark|Macrobenchmark]] в режимах `CompilationMode.None()` vs `CompilationMode.Partial()` (с профилем) — увидишь разницу в TTID. Это же ставят в CI как защиту от регрессий.
