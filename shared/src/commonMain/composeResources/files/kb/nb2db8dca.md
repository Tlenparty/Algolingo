# 🔑 Ключи и сигналы — как распознать тип задачи

> Этот файл учит **читать условие и сразу видеть метод**.
> Для каждого приёма: какие слова-маячки, какая идея, мини-пример, как звучит «вслух на собесе».

Связано: [[00 Компас алгоритмов]] · [[02 Шаблон решения]]

---

## Как тренировать распознавание

Возьми любую задачу и задай себе 4 вопроса **до** кода:
1. **Что на входе?** (массив / строка / дерево / граф / число)
2. **Отсортировано ли это?** (да → бинарный поиск или два указателя)
3. **Что просят вернуть?** (одно значение / количество / все варианты / минимум-максимум / путь)
4. **Какие слова-маячки?** (см. ниже)

Ответы на эти 4 вопроса в 90% случаев дают метод.

---

## 1. Hash Map / Set

- **Маячки:** «сколько раз», «частота», «дубликат», «уникальный», «есть ли элемент», «two sum» без сортировки.
- **Идея:** меняем поиск за O(n) на доступ за O(1). Часто храним `элемент → счётчик` или `элемент → индекс`.
- **Мини-пример:** в массиве найти два числа с суммой `target`.
  ```kotlin
  fun twoSum(nums: IntArray, target: Int): Pair<Int, Int>? {
      val seen = HashMap<Int, Int>() // значение -> индекс
      for (i in nums.indices) {
          val need = target - nums[i]
          seen[need]?.let { return it to i } // дополнение уже видели
          seen[nums[i]] = i
      }
      return null
  }
  ```
- **Вслух:** «Массив не отсортирован, ищу пару — беру Map и для каждого числа проверяю, видел ли я уже его дополнение. O(n)».

## 2. Два указателя (Two Pointers)

- **Маячки:** «отсортированный массив», «пара/тройка», «палиндром», «удалить дубликаты на месте», «слить два массива».
- **Идея:** два индекса (`left`, `right`) движутся навстречу или в одном направлении, без вложенного цикла.
- **Мини-пример:** проверка палиндрома.
  ```kotlin
  fun isPalindrome(s: String): Boolean {
      var l = 0; var r = s.length - 1
      while (l < r) {
          if (s[l] != s[r]) return false
          l++; r--
      }
      return true
  }
  ```
- **Вслух:** «Данные отсортированы / симметричны — ставлю указатели по краям и двигаю по условию. Память O(1)».
- Полный разбор: [[Задача на 2 указателя]], [[02 Шаблон решения]].

## 3. Скользящее окно (Sliding Window)

- **Маячки:** «непрерывный подмассив / подстрока», «максимальная/минимальная длина», «без повторов», «сумма ≥ K».
- **Идея:** окно `[left..right]`; `right` расширяет, `left` сжимает при нарушении условия.
- **Мини-пример:** длина самой длинной подстроки без повторяющихся символов.
  ```kotlin
  fun longestUnique(s: String): Int {
      val last = HashMap<Char, Int>()
      var left = 0; var best = 0
      for (right in s.indices) {
          last[s[right]]?.let { if (it >= left) left = it + 1 }
          last[s[right]] = right
          best = maxOf(best, right - left + 1)
      }
      return best
  }
  ```
- **Вслух:** «Просят непрерывный кусок с условием — двигаю правую границу, при нарушении подтягиваю левую. Один проход, O(n)».

## 4. Бинарный поиск

- **Маячки:** «отсортировано», «за O(log n)», «найти позицию», «минимальное/максимальное значение, при котором выполняется условие» (binary search по ответу).
- **Идея:** на каждом шаге отбрасываем половину диапазона.
- **Мини-пример:**
  ```kotlin
  fun binarySearch(nums: IntArray, target: Int): Int {
      var lo = 0; var hi = nums.size - 1
      while (lo <= hi) {
          val mid = lo + (hi - lo) / 2 // защита от переполнения
          when {
              nums[mid] == target -> return mid
              nums[mid] < target -> lo = mid + 1
              else -> hi = mid - 1
          }
      }
      return -1
  }
  ```
- **Вслух:** «Отсортировано → бинпоиск, log n. Слежу за инвариантом: ответ всегда внутри [lo, hi]».
- Полный разбор: [[Бинарный поиск]].

## 5. Стек (Stack)

- **Маячки:** «скобки», «корректная последовательность», «вложенность», «ближайший больший/меньший элемент», «отмена действия».
- **Идея:** LIFO — кладём, пока ждём «пару»; снимаем при совпадении.
- **Мини-пример:** корректность скобок — [[Задача на stack и map]].
- **Вслух:** «Здесь вложенность/парность — кладу открытые в стек, при закрытии проверяю вершину».

---

## 6. BFS (очередь) — обход в ширину

- **Маячки:** «кратчайший путь по числу шагов», «минимум ходов», «по уровням/слоям», невзвешенный граф или матрица.
- **Идея:** очередь, обрабатываем по слоям, отмечаем посещённые.
- **Вслух:** «Кратчайшее по шагам и веса равны → BFS, потому что первый раз дошли = кратчайший путь».
- Полный разбор: [[Задача на поиск в ширину]].

---

## 7. DFS / Backtracking — обход в глубину и перебор

- **Маячки:** «все комбинации / перестановки / подмножества», «все пути», «обход дерева», «существует ли путь».
- **Идея:** рекурсивно уходим вглубь; для backtracking — делаем выбор → рекурсия → откатываем выбор.
- **Мини-пример (backtracking):** все перестановки.
  ```kotlin
  fun permutations(nums: IntArray): List<List<Int>> {
      val res = mutableListOf<List<Int>>()
      val used = BooleanArray(nums.size)
      val cur = mutableListOf<Int>()
      fun dfs() {
          if (cur.size == nums.size) { res.add(cur.toList()); return }
          for (i in nums.indices) if (!used[i]) {
              used[i] = true; cur.add(nums[i])  // выбор
              dfs()                              // рекурсия
              used[i] = false; cur.removeAt(cur.size - 1) // откат
          }
      }
      dfs()
      return res
  }
  ```
- **Вслух:** «Нужны ВСЕ варианты → backtracking: выбор, рекурсия, откат».
- Полный разбор: [[Поиск в глубину (DFS)]].

## 8. Динамическое программирование (DP)

- **Маячки:** «сколько способов», «максимальная/минимальная стоимость», «можно ли набрать сумму», «оптимально», и подзадачи **перекрываются**.
- **Идея:** разбиваем на подзадачи, храним ответы (мемоизация / таблица), строим из меньших.
- **Как распознать против жадности:** если жадный выбор «здесь и сейчас» может оказаться неоптимальным глобально — это DP.
- **Мини-пример:** число способов подняться по лестнице (шаги 1 или 2).
  ```kotlin
  fun climbStairs(n: Int): Int {
      if (n <= 2) return n
      var a = 1; var b = 2
      repeat(n - 2) { val c = a + b; a = b; b = c }
      return b
  }
  ```
- **Вслух:** «Спрашивают количество способов / оптимум, подзадачи повторяются → DP. dp[i] = dp[i-1] + dp[i-2]».
- Полный разбор: [[Динамическое программирование]].

---

## 9. Префиксные суммы

- **Маячки:** «сумма на отрезке [i..j]» с множеством запросов, «количество подмассивов с суммой K».
- **Идея:** `prefix[i] = nums[0]+...+nums[i-1]`; сумма отрезка = `prefix[j+1] - prefix[i]`.
- **Вслух:** «Много запросов суммы на отрезке → префиксные суммы, каждый запрос O(1)».

---

## 10. Heap / Priority Queue

- **Маячки:** «top K», «K-й наибольший/наименьший», «слить K списков», «медиана потока».
- **Идея:** держим кучу размера K → O(n log k).
- **Вслух:** «Нужны K крупнейших — держу min-heap размера K, новое больше корня → заменяю».

---

## Финальный чек-лист распознавания

```
Отсортировано?            → бинарный поиск / два указателя
Непрерывный подотрезок?   → скользящее окно
Частоты / наличие?        → Hash Map / Set
Парность / вложенность?   → стек
Кратчайшее по шагам?      → BFS
Все варианты / пути?      → DFS / backtracking
Количество способов / оптимум? → DP
Top K / K-й?              → heap
Сумма на отрезке?         → префиксные суммы
```
