# 00 Словарь терминов

Все сокращения и названия из уроков System Design: полная форма и что это значит.

## Основа

- **API** (Application Programming Interface, программный интерфейс) — список запросов, которыми приложение общается с сервером.
- **App** — сервер приложения: твой код на бэкенде. «×N» значит, что запущено N одинаковых копий.
- **System Design** (проектирование систем) — интервью, где ты рисуешь устройство сервиса целиком.
- **F и NF** (functional и non-functional) — функциональные требования: что система делает. Нефункциональные: насколько быстро, надёжно и для скольких людей.
- **DAU** (Daily Active Users) — сколько разных людей заходит за день.
- **QPS** (Queries Per Second) — сколько запросов в секунду приходит на сервер.
- **p50, p95, p99** (перцентили) — время, в которое укладываются 50%, 95% или 99% запросов. p99 = 200 мс: только 1 запрос из 100 медленнее.
- **URL** (Uniform Resource Locator) — адрес страницы или файла в интернете.
- **JSON** (JavaScript Object Notation) — текстовый формат данных вида {"имя": "значение"}.
- **CPU** (Central Processing Unit) — процессор.
- **ANR** (Application Not Responding) — Android показал, что приложение зависло.
- **SDK** (Software Development Kit) — готовая библиотека, которую подключают в приложение.
- **UI** (User Interface) — экран и всё, что видит пользователь.
- **UUID** (Universally Unique Identifier) — длинный случайный номер, который почти наверняка ни у кого не совпадёт.
- **TTL** (Time To Live, время жизни) — через сколько запись считается устаревшей и удаляется.

## Сеть

- **DNS** (Domain Name System, система доменных имён) — «телефонная книга» интернета: превращает имя сайта в адрес сервера.
- **IP-адрес** (Internet Protocol) — числовой адрес устройства в сети, например 93.184.216.34.
- **TCP** (Transmission Control Protocol) — надёжная доставка: соединяет две стороны, ничего не теряет и не путает порядок.
- **TLS** (Transport Layer Security) — шифрование соединения. Замок в адресной строке браузера.
- **SSL** (Secure Sockets Layer) — устаревший предшественник TLS. Название по привычке живёт в словах вроде SSLHandshakeException.
- **HTTP** (HyperText Transfer Protocol) — язык запросов и ответов между приложением и сервером: GET, POST, коды вроде 200 и 404.
- **HTTPS** — тот же HTTP, но внутри шифрованного соединения TLS.
- **RTT** (Round-Trip Time) — время на дорогу туда и обратно: запрос дошёл, ответ вернулся.
- **NAT** (Network Address Translation) — роутер оператора: прячет много телефонов за одним IP. Тихие соединения он может молча закрыть.
- **REST** (Representational State Transfer) — обычный стиль API: каждый запрос отдельный, адреса вида GET /users/7.
- **keep-alive** — не закрывать соединение после ответа, чтобы следующий запрос пошёл быстрее.

## Строительные блоки

- **Балансировщик** (балансер; по-английски load balancer, сокращённо LB) — раздаёт входящие запросы между одинаковыми серверами и не шлёт их на упавшие.
- **nginx** — популярная программа, которая работает балансировщиком и принимает запросы первой.
- **API Gateway** (шлюз) — единая входная дверь в разные сервисы: проверяет токен и решает, какому сервису отдать запрос.
- **Health check** — балансировщик регулярно спрашивает сервер «ты жив?» и убирает из работы тех, кто молчит.
- **Stateless** (без состояния) — сервер ничего не помнит между запросами, поэтому запрос может обработать любая копия.
- **Redis** (Remote Dictionary Server) — очень быстрая база в оперативной памяти. Обычно это кеш, сессии и счётчики.
- **Memcached** — простой кеш в памяти: только ключ и значение, без сложных структур Redis.
- **Kafka** — журнал событий (название в честь писателя). Сервисы пишут туда сообщения, другие читают в своём темпе, и события какое-то время хранятся.
- **RabbitMQ** (MQ — Message Queue, очередь сообщений) — брокер очередей: сообщение обрабатывают и удаляют.
- **Worker** (воркер) — фоновая программа, которая берёт задачи из очереди и выполняет их.
- **SQL** (Structured Query Language) — язык запросов к базам из таблиц со связями.
- **PostgreSQL** (Postgres) — самая частая база из таблиц: связи и транзакции. Обычно здесь лежит главная копия данных.
- **NoSQL** («не только SQL») — базы без таблиц со связями. Проще масштабируются, но запросы ограничены.
- **Key-value** (ключ-значение) — самый простой вид NoSQL: по ключу лежит значение, как в HashMap.
- **MongoDB** — NoSQL-база, которая хранит документы, похожие на JSON.
- **Cassandra** — NoSQL-база для огромного потока записей: данные разложены по многим серверам, и она не падает, когда один сломался. Читать удобно по заранее известному ключу (например, все сообщения одного чата). Транзакций как в PostgreSQL нет. Такой тип баз зовут wide-column («широкие колонки»).
- **DynamoDB** — готовая key-value база от Amazon, которую не надо обслуживать самому.
- **AWS** (Amazon Web Services) — облако Amazon.
- **Elasticsearch** — поисковый движок: быстро ищет по словам в тексте.
- **Neo4j** — графовая база: хранит связи вида «кто с кем дружит».
- **S3** (Simple Storage Service) — файловое хранилище Amazon. Файлы лежат в «бакетах» (папках верхнего уровня).
- **CDN** (Content Delivery Network, сеть доставки контента) — сеть серверов по всему миру с копиями файлов. Пользователь получает файл с ближайшего сервера (он зовётся edge), а оригинал лежит на origin — исходном сервере.
- **BLOB** (Binary Large Object) — файл, положенный целиком в ячейку базы данных.
- **Docker** — упаковывает программу со всем нужным в контейнер, который везде запускается одинаково.
- **Kubernetes** (K8s: между K и s восемь букв) — следит за контейнерами: держит нужное число копий и перезапускает упавшие. Одна запущенная копия называется под (pod).
- **Виртуальная машина** (Virtual Machine, VM) — программный компьютер внутри настоящего, со своей операционной системой. Запускается медленнее контейнера и весит больше.
- **Prometheus** — собирает числовые метрики: сколько запросов, сколько ошибок.
- **Grafana** — рисует графики и дашборды по этим метрикам.

## Надёжность запросов

- **Timeout** — сколько ждать, прежде чем сдаться. connect timeout — не смогли соединиться, read timeout — соединились, но ответа нет.
- **Идемпотентность** — повтор запроса не меняет итог. **Idempotency-Key** — ключ, по которому сервер узнаёт повтор и не создаёт второй заказ.
- **Backoff** — ждать перед повтором всё дольше: 1 с, 2 с, 4 с.
- **Jitter** — случайная добавка к паузе, чтобы клиенты не повторяли запрос одновременно.
- **Circuit breaker** (предохранитель) — после серии ошибок перестаёт звать сломанный сервис. Состояния: closed — работает, open — запросы не идут, half-open — пробный запрос.
- **Fail-open / fail-closed** — что делать, если проверка сломалась: пропускать запросы или отказывать.
- **Fallback** — запасной вариант, если основной не сработал, например данные из кеша.
- **Rate limit** — ограничение частоты: не больше N запросов за период.
- **Token bucket** (ведро токенов), **leaky bucket** (дырявое ведро), **fixed window** (фиксированное окно), **sliding log** (скользящий журнал) — алгоритмы подсчёта лимита.
- **DDoS** (Distributed Denial of Service) — атака: тысячи устройств заваливают сервер запросами.
- **Lua** — маленький язык. Скрипт на нём выполняется в Redis целиком, без вклинивания других запросов.
- **LRU** (Least Recently Used) — когда память кончилась, удаляется то, что дольше всего не трогали.

## Шифрование и вход

- **0-RTT** — повторное TLS-соединение без ожидания: данные идут сразу.
- **CA** (Certificate Authority, удостоверяющий центр) — организация, которая подтверждает, что сертификат выдан настоящему владельцу сайта.
- **MITM** (Man-In-The-Middle, человек посередине) — атака, когда кто-то встаёт между телефоном и сервером и читает трафик.
- **SNI** (Server Name Indication) — имя сайта в начале TLS-соединения. Обычно идёт открыто, поэтому провайдер видит, куда ты зашёл.
- **ECDHE** (Elliptic Curve Diffie-Hellman Ephemeral) — способ договориться об общем секретном ключе, не пересылая его по сети. Ключ разовый.
- **AES-GCM** (Advanced Encryption Standard, Galois/Counter Mode) — быстрое шифрование данных общим ключом с защитой от подмены.
- **Forward secrecy** — даже если ключ сервера украдут потом, старый записанный трафик не расшифровать.
- **Pinning** (закрепление) — приложение доверяет только заранее известному сертификату сервера.
- **Access и refresh** — два токена. Access короткоживущий, идёт с каждым запросом. Refresh живёт дольше и нужен только чтобы получить новый access.
- **OAuth2** — вход через чужой сервис («Войти через Google») без передачи пароля приложению.
- **PKCE** (Proof Key for Code Exchange) — защита OAuth2 на телефоне: приложение доказывает, что код входа запросило именно оно.
- **JWT** (JSON Web Token) — токен с данными пользователя и подписью. Сервис проверяет его сам, без запроса в базу.
- **SSO** (Single Sign-On) — один вход сразу во много сервисов.
- **AOF** (Append Only File) — режим Redis: каждая запись дописывается в файл на диске, чтобы пережить перезапуск.
- **Denylist** (чёрный список) — список отозванных токенов.

## Real-time и очереди

- **Polling** — клиент спрашивает сервер по таймеру: «есть новое?». **Long polling** — сервер держит запрос открытым, пока новое не появится.
- **SSE** (Server-Sent Events) — сервер шлёт поток событий поверх HTTP, но только в одну сторону, к клиенту.
- **WebSocket** (сокращённо WS) — постоянное соединение: обе стороны пишут друг другу в любой момент.
- **FCM** (Firebase Cloud Messaging) — сервис Google для пушей на Android.
- **APNs** (Apple Push Notification service) — то же самое для iPhone.
- **Pub/Sub** (Publish/Subscribe, издатель и подписчики) — рассылка всем, кто подписан. В Redis она не хранит сообщение: кто был отключён, тот его пропустил.
- **Heartbeat** (сердцебиение, ping/pong) — регулярное «я жив», чтобы вовремя заметить обрыв и чтобы NAT не закрыл соединение.
- **Offset** — номер позиции в журнале или списке: откуда продолжить читать.
- **Ack** (acknowledgement) — подтверждение: «сообщение получил».
- **DLQ** (Dead Letter Queue, очередь мёртвых писем) — сюда откладывают сообщения, которые не удалось обработать после всех повторов.
- **At-most-once, at-least-once, exactly-once** — доставка не больше одного раза, минимум один раз, ровно один раз.
- **Outbox** (исходящие) — сначала сохранить сообщение локально или в той же транзакции, а потом отдельно отправить. Так оно не потеряется.

## Лента и короткие ссылки

- **MD5** (Message Digest 5) — хеш: превращает любой текст в строку фиксированной длины.
- **Base62** — запись числа 62 символами: цифры, a–z и A–Z. Получается коротко, как в коротких ссылках.
- **JOIN** — SQL-запрос, который склеивает строки из нескольких таблиц.
- **Cache-aside** — сервер сначала смотрит в кеш, при промахе (miss) идёт в базу и кладёт ответ в кеш.
- **Write-through** — запись идёт сразу и в кеш, и в базу.
- **Fan-out** (веерная рассылка) — один пост разложить по лентам всех подписчиков. **Fan-out on write** — сразу при публикации, **on read** — когда лента открыта.
- **Cursor** — метка «читать после этого элемента». В отличие от offset не ломается, когда в начало добавляют новые записи.
- **Sorted set** — структура Redis: элементы всегда отсортированы по числовой оценке (score).
- **Гидрация** — по списку id подтянуть полные данные постов.
- **Round robin** — раздавать по очереди. **Least connections** — отдавать тому серверу, у кого меньше всего соединений.

## Платежи

- **ACID** (Atomicity, Consistency, Isolation, Durability) — гарантии транзакции: всё или ничего, правила данных соблюдены, параллельные операции не мешают, записанное не пропадёт.
- **PSP** (Payment Service Provider) — платёжный провайдер, например Stripe или ЮKassa. Он сам работает с картами.
- **PCI DSS** (Payment Card Industry Data Security Standard) — строгий стандарт для всех, кто хранит или обрабатывает данные карт.
- **Webhook** — другой сервис сам вызывает твой адрес, когда что-то случилось (например, платёж прошёл).
- **2PC** (Two-Phase Commit, двухфазная фиксация) — транзакция на несколько сервисов: сначала все готовятся, потом все подтверждают.
- **Saga** — цепочка шагов в разных сервисах. Если шаг сорвался, предыдущие отменяют обратными действиями.
- **Ledger** (бухгалтерская книга) — журнал денежных операций: записи только добавляются, ошибки исправляют новой записью (сторно).
- **LWW** (Last Write Wins) — при конфликте побеждает последняя запись.

## Несколько баз

- **Реплика** — копия базы для чтения. **Primary** — главная копия, в неё пишут. **Replication lag** — на сколько реплика отстаёт.
- **Шард** — часть данных на своём сервере. **Hot shard** — шард, на который приходится слишком много нагрузки.
- **Consistent hashing** (согласованное хеширование) — распределение ключей, при котором добавление сервера переносит лишь малую часть данных.
- **CDC** (Change Data Capture) — читает изменения прямо из журнала базы и передаёт их дальше. **Debezium** — готовая программа для этого.
- **WAL** (Write-Ahead Log) — журнал базы: сначала изменение пишется туда, потом в таблицы.
- **Deadlock** (взаимная блокировка) — две транзакции вечно ждут друг друга.

## Наблюдаемость

- **SLO** (Service Level Objective) — внутренняя цель, например 99,9% успешных запросов. **Error budget** — сколько ошибок эта цель ещё позволяет.
- **SLA** (Service Level Agreement) — обещание клиентам в договоре, за нарушение которого платят.
- **ELK** (Elasticsearch, Logstash, Kibana) — связка для сбора логов и поиска по ним. **Loki** — более простая альтернатива.
- **RED** (Rate, Errors, Duration) — метрики сервиса: запросы, ошибки, длительность. **USE** (Utilization, Saturation, Errors) — метрики ресурса: загрузка, очередь, ошибки.
- **Трейс** (trace) — путь одного запроса через все сервисы. **Span** — один участок этого пути.
- **OpenTelemetry** (OTel) — общий стандарт сбора логов, метрик и трейсов. **Jaeger** — показывает трейсы.
- **Crashlytics** — сервис Firebase, который собирает падения приложения.

## DNS и TCP подробнее

**DNS находит адрес.** Ты знаешь имя api.example.com, а телефону нужен адрес вида 93.184.216.34. Телефон спрашивает DNS-сервер и запоминает ответ на время TTL, чтобы не спрашивать снова. Нет ответа → UnknownHostException: запрос даже не ушёл к серверу.

**TCP доставляет надёжно.** Сеть режет данные на пакеты, а они теряются и приходят вперемешку. TCP нумерует пакеты, подтверждает получение, пересылает потерянное и собирает всё по порядку. Перед отправкой стороны обмениваются тремя сообщениями: «можно?» → «можно, а мне?» → «да». Это занимает 1 RTT. Сервер не отвечает → connect timeout.

**Вместе, как посылка:** DNS узнал адрес, TCP проложил дорогу, TLS запер фургон на замок, HTTP — сама посылка.
