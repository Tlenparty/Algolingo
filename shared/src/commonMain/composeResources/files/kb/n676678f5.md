1. Внутреннее устройство

``HashSet<E>`` → использует ``HashMap<E, Object>`` под капотом.

``HashMap<K, V>`` → хранит пары ключ-значение (key → value).

2. Как элементы хранятся?

HashSet хранит только ключи (key), а в качестве значений (value) всегда используется заглушка (PRESENT) (Unit).
HashMap хранит и ключи (key), и значения (value).

3. Как добавляются элементы?

В HashSet (использует HashMap):

```java
Set<String> set = new HashSet<>();
set.add("apple");

```
  

Внутри это эквивалентно:

```java
Map<String, Object> map = new HashMap<>();
map.put("apple", PRESENT);

```

  
Где PRESENT – это заглушка (private static final Object PRESENT = new Object();).

В HashMap (хранит пары key -> value):


```java
Map<String, Integer> map = new HashMap<>();
map.put("apple", 1);
map.put("banana", 2);

```
  
Каждый ключ ("apple", "banana") связан со значением (1, 2).

> [!tip] Главное на собесе
> - **`HashSet` — это `HashMap` под капотом**, где элемент множества хранится как **ключ**, а значение — общая заглушка-объект (`PRESENT`). Поэтому уникальность элементов `HashSet` обеспечивается тем же механизмом `hashCode`/`equals`, что и уникальность ключей `HashMap`.
> - Отсюда требование: объекты-элементы `HashSet` и ключи `HashMap` должны корректно реализовывать [[EQUALS, HASHCODE|equals/hashCode]] и быть **неизменяемыми** по полям, участвующим в хэше.
> - Сложность `add`/`contains`/`get` — в среднем **O(1)**, в худшем (много коллизий) — **O(log n)** с Java 8 (бакет превращается из списка в дерево при ≥8 элементах).
