# Иерархия исключений

## Throwable — корень всего

`Throwable` — корневой класс для всех исключений и ошибок. У него две основные ветки: `Error` и `Exception`.

### Error

Серьёзные проблемы, которые приложение обычно **не должно перехватывать** (системные / ошибки JVM):

- `OutOfMemoryError`
- `StackOverflowError`
- `VirtualMachineError`
- `ExceptionInInitializerError` — ошибка в статическом блоке инициализации.

### Exception

Базовый класс для исключений, которые **можно** перехватывать и обрабатывать. Делится на `RuntimeException` (unchecked) и остальные (checked).

**RuntimeException (unchecked)** — ошибки времени выполнения, чаще всего следствие багов:

- `NullPointerException`
- `IndexOutOfBoundsException`
- `IllegalArgumentException`
- `IllegalStateException`
- `ArithmeticException` — например, деление на ноль.
- `ClassCastException`
- `NoSuchElementException`

**Checked-исключения** (прямые наследники `Exception`, не `RuntimeException`):

- `IOException` — ошибки ввода-вывода:
    - `FileNotFoundException`
    - `EOFException`
    - `SocketException`
    - `UnknownHostException`
- `SQLException` — работа с БД:
    - `SQLSyntaxErrorException`
    - `SQLTimeoutException`
- `InterruptedException` — поток был прерван.
- `ClassNotFoundException` — класс не найден загрузчиком.
- `NoSuchMethodException` / `NoSuchFieldException` — не найдено через рефлексию.
- `ParseException` — ошибка парсинга (например, дат).

> `Throwable` также можно расширять своими (пользовательскими) исключениями — обычно наследуют `Exception` или `RuntimeException`.

## Дерево (упрощённо)

```text
Throwable
├── Error
│   ├── OutOfMemoryError
│   └── StackOverflowError
│
└── Exception
    ├── RuntimeException        ← unchecked
    │   ├── NullPointerException
    │   ├── IndexOutOfBoundsException
    │   ├── IllegalArgumentException
    │   ├── IllegalStateException
    │   └── ArithmeticException
    │
    ├── IOException             ← checked
    │   ├── FileNotFoundException
    │   ├── EOFException
    │   └── SocketException
    ├── SQLException            ← checked
    ├── InterruptedException    ← checked
    └── ClassNotFoundException  ← checked
```

## Checked и Unchecked

| Тип            | Когда возникает                                            | Нужно ли обрабатывать                                | Родитель                          |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------- | --------------------------------- |
| **Checked**    | Предсказуемые внешние сбои (файлы, сеть, БД)              | ✅ Обязательно в Java (компилятор требует try/throws) | `Exception` (но не `RuntimeException`) |
| **Unchecked**  | Программные баги (NPE, деление на ноль, выход за границы) | ❌ На усмотрение разработчика                         | `RuntimeException`                |

### Checked в Java

Компилятор **требует** обработки:

```java
import java.io.*;

public class CheckedExample {
    public static void main(String[] args) {
        try {
            FileReader file = new FileReader("file.txt"); // компилятор требует обработку
        } catch (FileNotFoundException e) {
            System.out.println("Файл не найден: " + e.getMessage());
        }
    }
}
```

Другие примеры: `SQLException`, `InterruptedException`, `ClassNotFoundException`.

### Unchecked в Java

Компилятор **не требует** обработки, но программа упадёт в рантайме:

```java
public class UncheckedExample {
    public static void main(String[] args) {
        String text = null;
        System.out.println(text.length()); // NullPointerException
    }
}
```

Другие примеры: `ArithmeticException`, `IndexOutOfBoundsException`, `IllegalArgumentException`.

## Исключения в Kotlin

> [!important] В Kotlin ВСЕ исключения — unchecked
> Kotlin **отказался от checked-исключений**: компилятор никогда не требует try-catch или `throws`. Даже работа с файлами не обязывает ловить `IOException`.

```kotlin
import java.io.FileReader

fun main() {
    val file = FileReader("file.txt") // компилятор НЕ требует try-catch
}
```

В Kotlin не обязательно (но можно) ловить то, что в Java было checked: `IOException`, `SQLException`, `FileNotFoundException`, `InterruptedException`, `ClassNotFoundException`, `CloneNotSupportedException`, `NoSuchMethodException`, `NoSuchFieldException`.

> [!tip] Почему Kotlin убрал checked-исключения
> Опыт показал, что checked-исключения часто приводят к «глушению» (`catch (e) {}`) и захламлению сигнатур `throws`, не повышая надёжность. Поэтому в Kotlin их нет. Минус — про это легко забыть при вызове Java-кода: IDE не подскажет, что метод может бросить `IOException`.

## Глобальный перехват в Android

Все необработанные `RuntimeException` можно поймать глобально через `Thread.setDefaultUncaughtExceptionHandler` (подробнее — [[Как перехватить все исключения в run time]]):

```kotlin
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()

        Thread.setDefaultUncaughtExceptionHandler { _, throwable ->
            Log.e("GlobalException", "Необработанное исключение", throwable)
            sendCrashReport(throwable) // Crashlytics / Sentry / свой сервер
            restartApp()
        }
    }

    private fun sendCrashReport(e: Throwable) { /* ... */ }

    private fun restartApp() {
        val intent = packageManager.getLaunchIntentForPackage(packageName)
        intent?.addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP or Intent.FLAG_ACTIVITY_NEW_TASK)
        startActivity(intent)
        Runtime.getRuntime().exit(0)
    }
}
```

> [!warning]
> Глобальный обработчик **не предотвращает краш** — он лишь позволяет залогировать ошибку и что-то сделать перед завершением. И если подключён Firebase Crashlytics, он ставит свой обработчик — перехватывайте аккуратно, чтобы не сломать его цепочку.
