# Процессы и потоки

## Чем отличается процесс от потока?

При запуске компонента приложения система создаёт **процесс**. Процесс — это совокупность данных и кода, запущенных в одном адресном пространстве. Каждый процесс имеет хотя бы один поток; первоначальный поток процесса называется главным (UI thread). Потоки находятся внутри процесса.

### Процесс (Process)

**Процесс** — это экземпляр приложения, работающий в отдельной области памяти. Это независимая единица выполнения со своим адресным пространством, ресурсами и системными объектами. Каждый процесс изолирован от других, что исключает конфликты между приложениями.

**Основные характеристики:**

- **Изоляция.** У каждого процесса своя память и ресурсы; он не может напрямую обращаться к памяти другого процесса.
- **Ресурсы.** Свой стек, куча, дескрипторы файлов и другие системные ресурсы.
- **Запуск.** Процесс создаётся операционной системой при старте приложения.
- **Межпроцессное взаимодействие (IPC).** Для общения между процессами используются `ContentProvider`, `Binder`, AIDL и т. д.
- **Независимость.** Падение одного процесса не влияет на другие.

### Поток (Thread)

**Поток** — наименьшая единица выполнения внутри процесса. Потоки одного процесса разделяют общую память и ресурсы. В Android каждый процесс стартует с одним потоком — **главным (UI thread)**. Для длительных операций создают дополнительные потоки.

**Основные характеристики:**

- **Легковесность.** Потоки легче процессов, так как разделяют память и ресурсы процесса.
- **Общие ресурсы.** Все потоки процесса имеют доступ к его общей памяти (отсюда — необходимость синхронизации).
- **Параллельное выполнение.** Несколько операций одновременно внутри процесса.
- **UI thread.** Отвечает за интерфейс. Долгая операция в нём вызывает «зависание» и **ANR** (Application Not Responding).

### Сравнение: процесс vs поток

| Аспект                      | Процесс                                                   | Поток                                                          |
| --------------------------- | -------------------------------------------------------- | ------------------------------------------------------------- |
| Ресурсы                     | Своя память, стек, куча, дескрипторы файлов              | Делит память и ресурсы с другими потоками того же процесса    |
| Изоляция                    | Процессы изолированы друг от друга                       | Потоки внутри процесса видят общую память                     |
| Взаимодействие              | Через IPC (`ContentProvider`, `Binder`)                  | Напрямую через общую память                                   |
| Создание и управление       | Дорого; процесс создаёт ОС                               | Дёшево; потоки создаются внутри процесса                      |
| Основное использование      | Изолированное выполнение приложений/служб                | Параллельное выполнение задач внутри одного приложения        |

## Приоритеты процессов в Android

ОС динамически решает, какие процессы держать в памяти, а какие убить при нехватке ресурсов. Чем выше приоритет (importance), тем позже процесс будет убит. От высшего к низшему:

1. **Foreground process** — с которым пользователь активно взаимодействует: видимая `Activity` в `onResume`, foreground-`Service`, активный `BroadcastReceiver`. Убивается **в последнюю очередь**.
2. **Visible process** — виден пользователю, но не на переднем плане: например, `Activity` под диалогом, или сервис, привязанный к видимой `Activity`.
3. **Service process** — выполняет фоновый `Service` (загрузка, синхронизация), не попадающий в первые две категории.
4. **Cached / Background process** — содержит `Activity`, которые сейчас не видны (приложение свёрнуто). Хранятся в LRU-кэше для быстрого возврата; убиваются по мере нехватки памяти.
5. **Empty process** — не содержит активных компонентов, держится только ради кэша. Убивается **в первую очередь**.

> [!note] Кэшированные и пустые процессы
> В современных версиях Android «background» и «empty» обычно объединяют под общим понятием **cached processes**, упорядоченных по LRU. Суть та же: это первые кандидаты на завершение при нехватке памяти.

### Механизм Zygote

Все приложения в Android порождаются из процесса **Zygote** — родительского процесса, который уже держит загруженные классы фреймворка и ресурсы. Новый процесс приложения создаётся через `fork()` от Zygote, что ускоряет запуск и экономит память (общие страницы используются совместно — copy-on-write).

## Заключение

- **Foreground** — активное взаимодействие с пользователем, максимальный приоритет.
- **Visible / Service** — важная, но не приоритетная работа; может быть приостановлена.
- **Cached / Empty** — неактивные процессы; убиваются первыми для освобождения памяти.

Система динамически управляет процессами по их важности, обеспечивая плавную работу UI.
