### **📌 Очередь сообщений: когда и как использовать в Android-приложении**

**🔍 Когда нужна очередь сообщений?**

Если бекенд **не успевает обработать** запросы от мобильного приложения или **работает нестабильно**, то вместо потери данных можно **сначала сохранять их в локальную очередь** и отправлять позже.


**🛠 Сценарии использования:**

1. **Отправка событий (логов, аналитики)**

• Например, пользователь нажал кнопку 100 раз → записываем в очередь → отправляем партиями по 10 событий.

2. **Отправка сообщений в чат**

• Если **нет сети**, сообщение сохраняется локально, а при появлении сети отправляется.

3. **Офлайн-режим (когда сервер недоступен)**

• Пользователь создал заказ в приложении → но сервер упал → данные в **очереди** отправятся, когда сервер снова будет доступен.

4. **Высоконагруженные серверы**

• Если сервер перегружен, можно **буферизовать** запросы и отправлять их через промежутки времени.


## **📌 Как реализовать очередь сообщений на Android?**


### **1️⃣ Самый простой вариант: Room + WorkManager**

Если приложение работает офлайн или сервер не отвечает, **сохраняем данные в SQLite (Room)**, а потом **WorkManager** будет отправлять их в фоне.

**📌 Шаг 1: Создаём Entity для сообщений**

```kotlin
@Entity(tableName = "message_queue")
data class MessageEntity(
    @PrimaryKey(autoGenerate = true) val id: Int = 0,
    val message: String,
    val timestamp: Long = System.currentTimeMillis(),
    val status: String = "pending" // "pending" или "sent"
)
```

**📌 Шаг 2: Создаём DAO**
```kotlin
@Dao
interface MessageDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertMessage(message: MessageEntity)

    @Query("SELECT * FROM message_queue WHERE status = 'pending' ORDER BY timestamp ASC")
    suspend fun getPendingMessages(): List<MessageEntity>

    @Query("UPDATE message_queue SET status = 'sent' WHERE id = :id")
    suspend fun markAsSent(id: Int)
}
```

**📌 Шаг 3: Реализуем базу данных**

```kotlin
@Database(entities = [MessageEntity::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun messageDao(): MessageDao
}
```

**📌 Шаг 4: Добавляем WorkManager для фоновой отправки**
```kotlin
class MessageWorker(context: Context, workerParams: WorkerParameters) : Worker(context, workerParams) {

    private val db = Room.databaseBuilder(
        context,
        AppDatabase::class.java, "app_database"
    ).build()

    override fun doWork(): Result {
        val messages = runBlocking { db.messageDao().getPendingMessages() }

        for (message in messages) {
            val success = sendToServer(message.message) // Функция отправки на сервер
            if (success) {
                runBlocking { db.messageDao().markAsSent(message.id) }
            }
        }

        return Result.success()
    }

    private fun sendToServer(message: String): Boolean {
        println("📤 Отправляем сообщение: $message")
        return true // Здесь должен быть реальный HTTP-запрос
    }
}
```

**📌 Шаг 5: Запускаем WorkManager**
```kotlin
val constraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.CONNECTED) // Только при наличии сети
    .build()

val workRequest = PeriodicWorkRequestBuilder<MessageWorker>(15, TimeUnit.MINUTES)
    .setConstraints(constraints)
    .build()

WorkManager.getInstance(context).enqueue(workRequest)
```

✅ **Как это работает?**

• Когда **нет сети**, сообщения сохраняются в **SQLite (Room)**.
• WorkManager **раз в 15 минут** проверяет **неотправленные сообщения** и отправляет их.
• После успешной отправки **меняем статус сообщения на “sent”**.

### **📌 2️⃣ Другой вариант: Используем очередь в памяти (Queue)**

  
Этот вариант подойдет, **если приложение всегда запущено**, и нам не нужен Room.
```kotlin
val messageQueue: Queue<String> = LinkedList()

fun addMessageToQueue(message: String) {
    messageQueue.add(message)
}

fun processQueue() {
    while (messageQueue.isNotEmpty()) {
        val message = messageQueue.poll()
        val success = sendToServer(message)
        if (!success) {
            messageQueue.add(message) // Если не отправлено, добавляем обратно
        }
    }
}
```

✅ **Когда использовать?**

• Если **данные не критичны**, и можно потерять их при закрытии приложения.


### **📌 3️⃣ Третий вариант: Firebase Firestore (для чатов и офлайна)**


Если данные должны **синхронизироваться между пользователями**, Firebase **сам сохраняет их в офлайне** и отправляет при появлении сети.

```kotlin
val db = FirebaseFirestore.getInstance()

fun sendMessage(message: String) {
    val messageData = hashMapOf(
        "text" to message,
        "timestamp" to System.currentTimeMillis()
    )

    db.collection("messages")
        .add(messageData)
        .addOnSuccessListener { println("📤 Сообщение сохранено и отправлено!") }
        .addOnFailureListener { println("🚨 Ошибка! Firebase сам отправит позже") }
}
```
