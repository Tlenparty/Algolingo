## 2. Таблица «сигнал → метод» (главный инструмент)

Читай условие и ищи **сигнальные слова**. Они почти однозначно указывают на приём:

| Сигнал в условии | Скорее всего метод | Почему |
|------------------|--------------------|--------|
| «отсортированный массив» + «пара/сумма» | **Два указателя** | сортировка позволяет двигаться навстречу |
| «отсортированный» + «найти/позиция/log n» | **Бинарный поиск** | отбрасываем половину |
| «подстрока / подмассив» + «непрерывный» | **Скользящее окно** | окно растёт/сжимается |
| «сколько раз», «частота», «дубликаты», «уникальный» | **Hash Map / Set** | счётчик за O(1) |
| «два числа дают сумму», но массив **не** отсортирован | **Hash Map** (дополнение target - x) | O(n) вместо O(n²) |
| «скобки», «корректная последовательность», «ближайший больший» | **Стек** | LIFO-вложенность |
| «кратчайший путь», «минимум шагов», «по слоям» | **BFS (очередь)** | равные веса = слои |
| «все пути / комбинации / перестановки», «дерево» | **DFS / backtracking** | перебор с откатом |
| «сколько способов», «максимальная выгода», «можно ли набрать» | **DP** | оптимум из подзадач |
| «top K», «K-й наибольший», «медиана потока» | **Heap** | держим K элементов |
| «сумма на отрезке [i..j]», «подмассивов с суммой K» | **Префиксные суммы** | разница префиксов |
| «интервалы», «слить пересечения», «расписание» | **Сортировка + жадность** | сортируем по началу/концу |
| «зависимости», «можно ли упорядочить», «циклы в графе» | **Топологическая сортировка** | DAG |
| «группы / острова / связность» | **Union-Find или DFS/BFS по матрице** | компоненты |

> 💡 Правило большого пальца:
> - Нужно **O(n) вместо O(n²)** → почти всегда **Hash Map** или **два указателя/окно**.
> - Данные **отсортированы** → думай **бинарный поиск** или **два указателя**.
> - Просят **оптимум/количество способов** → думай **DP**.
> - Просят **кратчайшее по шагам** → **BFS**.

## 3. Универсальный алгоритм действий на собесе (что делать руками)

1. **Повтори условие своими словами.** Вход, выход, ограничения (n до 10? до 10⁶?).
   Размер n подсказывает сложность: n ≤ 20 → перебор/DP по маскам; n ≤ 10³ → O(n²) ок; n ≤ 10⁶ → нужен O(n) или O(n log n).
2. **Приведи 1–2 примера руками**, включая крайние случаи (пустой вход, один элемент, дубликаты).
3. **Назови сигналы** (см. таблицу выше) → выбери метод. Скажи вслух: «здесь массив отсортирован и ищем пару — беру два указателя».
4. **Сначала brute force**, оцени его Big O. Это всегда даёт хоть какое-то решение.
5. **Оптимизируй**: какой приём убирает лишнюю работу? (Map вместо вложенного цикла и т.п.)
6. **Псевдокод → код.** Пиши маленькими шагами, проговаривай инварианты.
7. **Прогони на примере и крайних случаях.** Проверь индексы (off-by-one!).
8. **Назови финальную сложность** по времени и по памяти.

## 4. Шпаргалка по сложности (что считается «хорошо»)

| Сложность | Оценка | Типичный приём |
|-----------|--------|----------------|
| O(1) | идеал | хэш-доступ, формула |
| O(log n) | отлично | бинарный поиск |
| O(n) | отлично | один проход, Map, два указателя, окно |
| O(n log n) | хорошо | сортировка, heap |
| O(n²) | приемлемо для малых n | вложенные циклы |
| O(2ⁿ), O(n!) | только если n крошечное | перебор, перестановки |
