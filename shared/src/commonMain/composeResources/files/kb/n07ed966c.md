# 🟢 Уровень 0 — Разминка

Цель уровня: рука сама пишет базовый цикл, индексы и два указателя без раздумий.

## 0.1 Сумма и максимум массива
Верни сумму всех чисел массива и (отдельно) максимальный элемент. Массив непустой.

- 🎯 **Тренируем:** базовый линейный проход с аккумулятором.
- ⏱ **Цель:** 1 минута.

> [!question]- 💡 Подсказка
> Одна переменная-аккумулятор, один `for`. Максимум инициализируй **первым элементом**, не нулём (числа могут быть отрицательными).

> [!success]- ✅ Решение
> ```kotlin
> fun sumAndMax(nums: IntArray): Pair<Int, Int> {
>     var sum = 0
>     var max = nums[0]            // не 0! массив может быть весь отрицательный
>     for (x in nums) {
>         sum += x
>         if (x > max) max = x
>     }
>     return sum to max
> }
> ```
> **Сложность:** время O(n), память O(1).
> ⚠️ **Грабли:** `max = 0` ломается на `[-5, -2]`. Пустой массив — уточни у интервьюера, что делать (кинуть исключение / вернуть null).

## 0.2 Разворот строки на месте
Переверни `CharArray`: `abcd` → `dcba`. Без создания новой строки.

- 🎯 **Тренируем:** два указателя навстречу (скелет [[04 Маркеры + Заготовки|#3]]).
- ⏱ **Цель:** 2 минуты.

> [!question]- 💡 Подсказка
> `l = 0`, `r = n-1`, меняем местами, пока `l < r`. Именно `<`, а не `<=` — иначе средний символ поменяешь сам с собой (не страшно, но лишний шаг).

> [!success]- ✅ Решение
> ```kotlin
> fun reverse(s: CharArray) {
>     var l = 0
>     var r = s.size - 1
>     while (l < r) {
>         val t = s[l]; s[l] = s[r]; s[r] = t
>         l++; r--
>     }
> }
> ```
> **Сложность:** время O(n), память O(1).
> 🔁 **Вариации:** проверка палиндрома — тот же скелет, но вместо swap сравниваем `s[l] != s[r] → return false`.

## 0.3 Палиндром ли строка
Читается ли строка одинаково с обеих сторон? (считаем, что регистр и пробелы уже неважны)

- 🎯 **Тренируем:** два указателя навстречу как проверка.
- ⏱ **Цель:** 2 минуты.

> [!success]- ✅ Решение
> ```kotlin
> fun isPalindrome(s: String): Boolean {
>     var l = 0
>     var r = s.length - 1
>     while (l < r) {
>         if (s[l] != s[r]) return false
>         l++; r--
>     }
>     return true
> }
> ```
> **Сложность:** O(n) / O(1). См. [[Если слово палиндром]].

## 0.4 Бинарный поиск
Найди индекс `target` в **отсортированном** массиве за O(log n), иначе `-1`.

- 🎯 **Тренируем:** каркас бинпоиска и инвариант «ответ всегда внутри `[lo, hi]`».
- ⏱ **Цель:** 3 минуты.

> [!question]- 💡 Подсказка
> `while (lo <= hi)`. Середина `mid = lo + (hi - lo) / 2` (защита от переполнения). Три ветки: нашли / ушли вправо / ушли влево.

> [!success]- ✅ Решение
> ```kotlin
> fun binarySearch(nums: IntArray, target: Int): Int {
>     var lo = 0
>     var hi = nums.size - 1
>     while (lo <= hi) {
>         val mid = lo + (hi - lo) / 2
>         when {
>             nums[mid] == target -> return mid
>             nums[mid] < target  -> lo = mid + 1
>             else                -> hi = mid - 1
>         }
>     }
>     return -1
> }
> ```
> **Сложность:** O(log n) / O(1). Полный разбор: [[Бинарный поиск]].
> ⚠️ **Грабли:** `lo < hi` вместо `<=` пропустит последний элемент; `(lo + hi) / 2` может переполниться на больших индексах.

# 🟢🟢 Уровень 1 — Hash Map / Set

Цель уровня: увидел «частота / наличие / пара» — рука тянется к `HashMap`/`HashSet`. Это самый частый класс на собесах (и почти весь Avito).

## 1.1 Есть ли дубликат
Верни `true`, если в массиве есть хоть один повтор.

- 🎯 **Тренируем:** `HashSet` и трюк `add`.
- ⏱ **Цель:** 1.5 минуты.

> [!question]- 💡 Подсказка
> `set.add(x)` возвращает `false`, если элемент уже был. Одна строка внутри цикла.

> [!success]- ✅ Решение
> ```kotlin
> fun hasDuplicate(nums: IntArray): Boolean {
>     val seen = HashSet<Int>()
>     for (x in nums) if (!seen.add(x)) return true
>     return false
> }
> ```
> **Сложность:** O(n) / O(n).

## 1.2 Первый неповторяющийся символ
Верни первый символ строки, встречающийся ровно один раз, иначе `null`.

- 🎯 **Тренируем:** `Map` частот + **второй проход** (частая ошибка — пытаться в один).
- ⏱ **Цель:** 3 минуты.

> [!question]- 💡 Подсказка
> Первый проход — считаем частоты. Второй проход **по исходной строке** (порядок важен!) — первый символ с частотой 1.

> [!success]- ✅ Решение
> ```kotlin
> fun firstUniqueChar(s: String): Char? {
>     val cnt = HashMap<Char, Int>()
>     for (c in s) cnt[c] = cnt.getOrDefault(c, 0) + 1
>     for (c in s) if (cnt[c] == 1) return c   // второй проход — сохраняет порядок
>     return null
> }
> ```
> **Сложность:** O(n) / O(k), где k — размер алфавита. См. [[Задача на stack и map]].
> ⚠️ **Грабли:** нельзя искать уникальный по самой `Map` — она не хранит порядок вставки гарантированно; иди по строке.

## 1.3 Анаграмма / одинаковый набор букв 🔥Avito
Даны два слова. Состоят ли они из одинакового набора букв с учётом количества? (`йцукен` / `некуцй` → true, `ффффа` / `фффа` → false)

- 🎯 **Тренируем:** сравнение частотных словарей.
- ⏱ **Цель:** 3 минуты.

> [!question]- 💡 Подсказка
> Быстрый выход: разная длина → сразу `false`. Дальше — сравнить две частотные `Map` на равенство.

> [!success]- ✅ Решение
> ```kotlin
> fun sameLetters(a: String, b: String): Boolean {
>     if (a.length != b.length) return false
>     val cnt = HashMap<Char, Int>()
>     for (c in a) cnt[c] = cnt.getOrDefault(c, 0) + 1
>     for (c in b) {
>         val left = (cnt[c] ?: 0) - 1
>         if (left < 0) return false           // буквы b больше, чем было в a
>         cnt[c] = left
>     }
>     return true                              // длины равны + не ушли в минус
> }
> ```
> **Идиоматичный однострочник (для понимания, не для собеса):**
> ```kotlin
> fun sameLetters(a: String, b: String) =
>     a.groupingBy { it }.eachCount() == b.groupingBy { it }.eachCount()
> ```
> **Сложность:** O(n) / O(k). Оригинал задачи: [[Задачи с Avito]].
> ⚠️ **Грабли:** решение «отсортировать обе строки и сравнить» — это O(n log n), на собесе скажи, что Map даёт O(n).

## 1.4 Two Sum (массив НЕ отсортирован)
Верни индексы двух чисел с суммой `target`.

- 🎯 **Тренируем:** Map «значение → индекс», поиск дополнения `target - x`.
- ⏱ **Цель:** 3 минуты.

> [!question]- 💡 Подсказка
> Идём по массиву. Для текущего `x` нужно `target - x`. Если оно уже в Map — ответ. Иначе кладём `x → i` и идём дальше. Один проход, не два.

> [!success]- ✅ Решение
> ```kotlin
> fun twoSum(nums: IntArray, target: Int): Pair<Int, Int>? {
>     val seen = HashMap<Int, Int>()           // значение -> индекс
>     for (i in nums.indices) {
>         val need = target - nums[i]
>         seen[need]?.let { return it to i }   // дополнение уже видели
>         seen[nums[i]] = i
>     }
>     return null
> }
> ```
> **Сложность:** O(n) / O(n).
> ⚠️ **Грабли:** сначала проверь дополнение, потом клади текущий — иначе на `target = 2*x` вернёшь один индекс дважды.

## 1.5 Победители соревнования 🔥Avito
Дана статистика шагов по дням: `List<List<StepEntry(userId, steps)>>`. Верни `userId` тех, кто набрал **максимум шагов**, **участвуя во все дни без пропусков**.

- 🎯 **Тренируем:** две Map одновременно (сумма + счётчик участий) + фильтр.
- ⏱ **Цель:** 7 минут.

> [!question]- 💡 Подсказка 1
> Тебе нужны две вещи на каждого юзера: суммарные шаги и в скольких днях он участвовал. Две `Map` за один двойной проход.

> [!question]- 💡 Подсказка 2
> «Без пропусков» = число дней участия равно `statistics.size`. Сначала отфильтруй таких, потом среди них ищи максимум, потом собери всех с этим максимумом (их может быть несколько!).

> [!success]- ✅ Решение
> ```kotlin
> data class StepEntry(val userId: Int, val steps: Int)
> data class ChampionResult(val userIds: List<Int>, val steps: Int)
>
> fun findChampions(statistics: List<List<StepEntry>>): ChampionResult {
>     val totalDays = statistics.size
>     val totalSteps = HashMap<Int, Int>()
>     val daysActive = HashMap<Int, Int>()
>
>     for (day in statistics) for (e in day) {
>         totalSteps[e.userId] = totalSteps.getOrDefault(e.userId, 0) + e.steps
>         daysActive[e.userId] = daysActive.getOrDefault(e.userId, 0) + 1
>     }
>
>     val full = daysActive.filterValues { it == totalDays }.keys   // участвовали все дни
>     val maxSteps = full.maxOfOrNull { totalSteps[it] ?: 0 } ?: 0
>     val champions = full.filter { totalSteps[it] == maxSteps }
>     return ChampionResult(champions, maxSteps)
> }
> ```
> **Сложность:** O(N) по суммарному числу записей / O(U) по числу юзеров. Оригинал: [[Алгоритмы Avito]].
> ⚠️ **Грабли:** не забудь, что победителей может быть несколько (равный максимум) → возвращаем список, а не одного.

# 🟡 Уровень 2 — Два указателя и окно

Цель уровня: отличать «два указателя навстречу» от «fast/slow в одну сторону» и от «скользящего окна».

## 2.1 Перемещение нулей
Сдвинь все нули в конец, сохранив порядок ненулевых, **на месте**.

- 🎯 **Тренируем:** fast/slow в одну сторону (скелет [[04 Маркеры + Заготовки|#4]]).
- ⏱ **Цель:** 4 минуты.

> [!question]- 💡 Подсказка
> `slow` — куда писать следующий ненулевой. `fast` бежит по всем. Встретил ненулевой → записал в `slow`, `slow++`. В конце добей хвост нулями.

> [!success]- ✅ Решение
> ```kotlin
> fun moveZeroes(nums: IntArray) {
>     var slow = 0
>     for (fast in nums.indices) {
>         if (nums[fast] != 0) {
>             nums[slow] = nums[fast]
>             slow++
>         }
>     }
>     while (slow < nums.size) { nums[slow] = 0; slow++ }
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:** если вместо копирования делать swap — тоже работает, но проще запомнить «slow пишет хорошие, потом добиваем нулями».

## 2.2 K ближайших заправок 🔥Яндекс
Дан **отсортированный** массив координат `gasStations`. Машина у индекса `carIndex`. Верни `k` ближайших к машине станций.

- 🎯 **Тренируем:** два **независимых** указателя, расходящихся наружу от фиксированной точки.
- ⏱ **Цель:** 8 минут.

> [!question]- 💡 Подсказка 1
> Главная ловушка: точка отсчёта — это машина, она **не двигается**. Не веди один бегающий курсор (он «уедет» и возьмёт дубликат). Заведи `left = carIndex-1` и `right = carIndex+1`.

> [!question]- 💡 Подсказка 2
> На каждом из `k` шагов: если слева кончилось — бери справа; если справа кончилось — бери слева; иначе сравни расстояния `carPos - gs[left]` и `gs[right] - carPos`, возьми ближайшего и сдвинь его указатель наружу.

> [!success]- ✅ Решение
> ```kotlin
> fun nearestGasStations(gasStations: IntArray, carIndex: Int, k: Int): List<Int> {
>     val carPos = gasStations[carIndex]
>     var left = carIndex - 1
>     var right = carIndex + 1
>     val result = mutableListOf<Int>()
>     repeat(k) {
>         val takeRight = when {
>             left < 0 -> true                                  // слева пусто
>             right > gasStations.lastIndex -> false            // справа пусто
>             else -> gasStations[right] - carPos < carPos - gasStations[left]
>         }
>         if (takeRight) { result.add(gasStations[right]); right++ }
>         else           { result.add(gasStations[left]);  left-- }
>     }
>     return result
> }
> ```
> **Сложность:** O(k) / O(k) (массив уже отсортирован).
> ⚠️ **Грабли:** обязательно проверяй выход за края **до** сравнения расстояний, иначе `IndexOutOfBounds`. Полный разбор багованной версии: [[Задача от Яндекс со станциями]].
> 🔁 **Вариации:** если точка задана координатой, а не индексом — сперва `binarySearch` за O(log n), затем те же два указателя.

## 2.3 Самая длинная подстрока без повторов
Длина наибольшей подстроки без повторяющихся символов.

- 🎯 **Тренируем:** скользящее окно + Map последних позиций (скелет [[04 Маркеры + Заготовки|#5]]).
- ⏱ **Цель:** 8 минут.

> [!question]- 💡 Подсказка
> `right` расширяет окно. Если символ уже был **внутри окна** (его последняя позиция `>= left`), сдвинь `left` за него. Каждый шаг обновляй `best = max(best, right - left + 1)`.

> [!success]- ✅ Решение
> ```kotlin
> fun longestUnique(s: String): Int {
>     val last = HashMap<Char, Int>()      // символ -> последний индекс
>     var left = 0
>     var best = 0
>     for (right in s.indices) {
>         val prev = last[s[right]]
>         if (prev != null && prev >= left) left = prev + 1   // ужимаем окно
>         last[s[right]] = right
>         best = maxOf(best, right - left + 1)
>     }
>     return best
> }
> ```
> **Сложность:** O(n) / O(k).
> ⚠️ **Грабли:** проверка `prev >= left` обязательна — иначе старая позиция символа вне окна ошибочно сдвинет `left` назад.

## 2.4 Волновая сортировка 🔥Glovo
Переставь элементы так, чтобы `o[0] ≤ o[1] ≥ o[2] ≤ o[3] ≥ o[4] …`. Элементы могут повторяться.

- 🎯 **Тренируем:** жадный однопроходный swap соседей (и понимание, что сортировка — не единственный путь).
- ⏱ **Цель:** 7 минут.

> [!question]- 💡 Подсказка 1
> Простой путь (O(n log n)): отсортируй, потом меняй местами пары `(1,2), (3,4), …`.

> [!question]- 💡 Подсказка 2
> Оптимальный путь (O(n)): иди по чётным индексам. На чётной позиции элемент должен быть «впадиной» (≤ соседей). Если сосед меньше — swap. Локальная починка даёт глобально верную волну.

> [!success]- ✅ Решение — жадное O(n)
> ```kotlin
> fun waveSort(arr: IntArray): IntArray {
>     for (i in arr.indices step 2) {
>         if (i > 0 && arr[i] < arr[i - 1])
>             arr[i] = arr[i - 1].also { arr[i - 1] = arr[i] }
>         if (i < arr.size - 1 && arr[i] < arr[i + 1])
>             arr[i] = arr[i + 1].also { arr[i + 1] = arr[i] }
>     }
>     return arr
> }
> ```
> **Сложность:** O(n) / O(1). Вариант через сортировку: [[Алгоритмы Glovo]].
> ⚠️ **Грабли:** ответ не единственный — не сверяйся с одной «правильной» перестановкой, проверяй само условие волны.

## 2.5 Самый длинный период без снижения 🔥Яндекс
`data class WorkoutData(val squat: Int, val benchPress: Int, val deadlift: Int)` — ежедневные тренировки, отсортированы по дате. Показатели дня = сумма трёх весов. Период «стабильный или улучшающийся», если сумма каждого дня **не меньше** предыдущего. Верни индексы начала и конца **самого длинного** такого периода **длиннее одного дня**, иначе `null`.

```text
[ (2), (1), (0) ] -> null        [ (1), (2), (0) ] -> Pair(0, 1)
```

- 🎯 **Тренируем:** самую длинную серию (streak) — один проход с якорем начала серии.
- ⏱ **Цель:** 8 минут.

> [!question]- 💡 Подсказка 1
> Сигнал: условие связывает **только соседей** (`sum[i] >= sum[i-1]`), а спрашивают самый длинный непрерывный кусок. Значит один проход, O(n). Никаких вложенных циклов.

> [!question]- 💡 Подсказка 2
> Держи `curStart` — где началась текущая серия. Условие держится → серия растёт вправо, сравни её с лучшей. Условие сломалось → серия **не заканчивает функцию**, а начинается заново с текущего индекса.

> [!success]- ✅ Решение
> ```kotlin
> fun longestStableStrengthPeriod(workoutData: List<WorkoutData>): Pair<Int, Int>? {
>     if (workoutData.size < 2) return null
>
>     val totals = workoutData.map { it.squat + it.benchPress + it.deadlift }
>     var bestStart = 0
>     var bestEnd = 0
>     var curStart = 0
>
>     for (i in 1 until totals.size) {
>         if (totals[i] < totals[i - 1]) {
>             curStart = i                 // серия оборвалась — начинаем новую С ЭТОГО дня
>             continue
>         }
>         if (i - curStart > bestEnd - bestStart) {
>             bestStart = curStart
>             bestEnd = i
>         }
>     }
>
>     return if (bestEnd > bestStart) Pair(bestStart, bestEnd) else null
> }
> ```
> **Сложность:** O(n) / O(n) из-за `totals`. Для честных O(1) по памяти считай суммы на лету, без `map`.
> ⚠️ **Грабли (все три — с реального собеса):**
> 1. `return` внутри цикла при первом снижении → отдаёшь первую серию вместо самой длинной. «Самый длинный» = ответ известен **только после полного прохода**.
> 2. Двигать `curStart` при **росте**. Наоборот: начало стоит на месте, пока серия жива; двигается только на обрыве.
> 3. Забыть `null`. Сигнатура `Pair<Int, Int>?` и «длиннее одного дня» — это и есть `bestEnd > bestStart` в финале. `Pair(0, 0)` — не ответ.
> 4. Спроси вслух: **несколько периодов одинаковой длины — какой вернуть?** Строгое `>` оставляет первый. Интервьюер засчитывает такой вопрос в плюс.

## 2.6 Самый длинный строгий рост (порог 3)
Дан `IntArray` весов штанги по дням. Найди самый длинный период **строго растущих** весов длиной **не менее 3 дней**. Верни `Pair(start, end)` или `null`.

```text
[1, 2, 1, 2] -> null (две серии по 2, порог не взят)
[1, 2, 3, 0, 4, 5, 6, 7] -> Pair(3, 7)
```

- 🎯 **Тренируем:** тот же streak, но другой контракт — строгое сравнение вместо `>=` и порог длины вместо 2.
- ⏱ **Цель:** 6 минут.

> [!question]- 💡 Подсказка
> Скелет 2.5 без изменений. Меняются ровно две строки: условие обрыва (`<=` вместо `<`, потому что равенство рвёт **строгий** рост) и финальная проверка контракта (`bestEnd - bestStart + 1 >= 3`).

> [!success]- ✅ Решение
> ```kotlin
> fun longestStrictGrowth(weights: IntArray, minLen: Int = 3): Pair<Int, Int>? {
>     if (weights.size < minLen) return null
>
>     var bestStart = 0
>     var bestEnd = 0
>     var curStart = 0
>
>     for (i in 1 until weights.size) {
>         if (weights[i] <= weights[i - 1]) {   // равенство ТОЖЕ рвёт строгий рост
>             curStart = i
>             continue
>         }
>         if (i - curStart > bestEnd - bestStart) {
>             bestStart = curStart
>             bestEnd = i
>         }
>     }
>
>     return if (bestEnd - bestStart + 1 >= minLen) Pair(bestStart, bestEnd) else null
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:** на `[1, 2, 3, 0, 4, 5, 6, 7]` ответ `(3, 7)`, а не `(4, 7)`. День, оборвавший серию, **сам становится началом новой** — `0, 4, 5, 6, 7` строго растёт. Поэтому `curStart = i`, а не `i + 1`.

## 2.7 Период с допуском в K просадок
Тот же массив сумм. Теперь внутри периода разрешено **не более K** дней просадки (`sum[i] < sum[i-1]`). Верни **длину** самого длинного такого периода.

```text
[5, 1, 2, 3], K=0 -> 3      [5, 1, 2, 3], K=1 -> 4
[5, 4, 5, 4, 5, 4], K=2 -> 5
```

- 🎯 **Тренируем:** границу между streak и **скользящим окном** — момент, когда якоря уже мало.
- ⏱ **Цель:** 9 минут.

> [!question]- 💡 Подсказка 1
> Якорь `curStart` больше не работает: при обрыве нельзя прыгать в текущий индекс — просадка ещё может «поместиться» в допуск. Нужно окно `[left, right]` и счётчик просадок внутри него.

> [!question]- 💡 Подсказка 2
> Расширяй `right`. Просадка → `drops++`. Пока `drops > k` — ужимай `left` слева, и при каждом сдвиге проверяй, не ушла ли просадка из окна. Это скелет 2.3, только считаем просадки вместо повторов.

> [!success]- ✅ Решение
> ```kotlin
> fun longestWithTolerance(totals: IntArray, k: Int): Int {
>     if (totals.isEmpty()) return 0
>
>     var left = 0
>     var drops = 0
>     var best = 1                              // один день валиден всегда
>
>     for (right in 1 until totals.size) {
>         if (totals[right] < totals[right - 1]) drops++
>         while (drops > k) {
>             left++
>             if (totals[left] < totals[left - 1]) drops--   // просадка выпала из окна
>         }
>         best = maxOf(best, right - left + 1)
>     }
>     return best
> }
> ```
> **Сложность:** O(n) / O(1) — `left` суммарно проходит массив один раз.
> ⚠️ **Грабли:** окно `[left, right]` содержит переходы `left+1 … right`. Поэтому при сдвиге сначала `left++`, и только потом проверяем пару `(left-1, left)` — иначе снимешь не ту просадку. И `best = 1`, а не `0`: пустой ответ бывает только на пустом массиве.

## 2.8 Максимальная дистанция до соседа (кинотеатр) 🔥собес
Массив `0/1`: `0` — свободное кресло, `1` — занятое. Гарантирован хотя бы один `0`. Сядь **максимально далеко от ближайшего занятого**. Верни **номер места** (нумерация с 1). При равенстве — самое левое.

```text
[1,0,1]         -> 2        [1,0,0,0,0,1]   -> 3
[0,0,1]         -> 1        [1,0,0]         -> 3
```

- 🎯 **Тренируем:** «лучшая точка между препятствиями» — один проход, интервал закрывается на каждой `1`, края = полуоткрытые дырки со стенкой.
- ⏱ **Цель:** 8 минут.

> 🪜 Не выходит с наскока — не долби эту карточку, пройди [[06 Движок «маркеры и дырки»]]: там та же задача разложена на 5 шагов от «длины серии» до неё.

> [!question]- 💡 Подсказка 1
> Занятые кресла режут ряд на дырки трёх видов: **между двумя `1`** (сосед с двух сторон → садишься в середину, расстояние `(r−l)/2`), **у левой стенки** (ведущие нули → жмёшься к месту 0), **у правой стенки** (хвостовые нули → к последнему месту). Разбери три случая отдельно.

> [!question]- 💡 Подсказка 2
> Держи **две** величины, не одну: `bestDist` (чтобы сравнивать) и `bestPos` (чтобы вернуть). Классическая ошибка — вернуть расстояние вместо места. И вывод 1-indexed → в конце `+1`. Края лови: первую `1` обрабатывай отдельно (левая стенка), хвост — **после** цикла.

> [!success]- ✅ Решение
> ```kotlin
> fun solution(seats: IntArray): Int {
>     var prevOne = -1     // индекс последней встреченной 1 (-1 — ещё не было)
>     var bestDist = -1    // лучшее расстояние до соседа
>     var bestPos = 0      // индекс лучшего места (0-based)
>
>     for (i in seats.indices) {
>         if (seats[i] != 1) continue        // работаем только на границах-единицах
>
>         if (prevOne == -1) {
>             if (i > 0) {                    // ведущие нули: жмёмся к левой стенке
>                 bestDist = i                //   (первая 1 → bestDist ещё -1, сравнение лишнее)
>                 bestPos = 0
>             }
>         } else {
>             val dist = (i - prevOne) / 2    // середина дырки между двумя 1
>             if (dist > bestDist) {          // строгий > → при ничьей левое место
>                 bestDist = dist
>                 bestPos = prevOne + dist
>             }
>         }
>         prevOne = i
>     }
>
>     if (prevOne == -1) return 1             // занятых нет — садимся на место 1
>
>     val lastIdx = seats.size - 1            // хвостовые нули: жмёмся к правой стенке
>     if (lastIdx - prevOne > bestDist) bestPos = lastIdx
>
>     return bestPos + 1                      // ответ 1-indexed: «номер места»
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:** (1) `return bestPos`, а не `bestDist` — контракт просит место, не расстояние. (2) `+1` в конце: `[1,0,1]` → индекс 1, ответ 2. (3) Оба края (ведущие/хвостовые нули) обрабатываются явно — если обновлять ответ только на встреченных `1`, хвост никогда не рассмотришь. (4) Строгий `>` держит левое место при ничьей.

# 🟡🟡 Уровень 3 — Реальные задачи с собесов + стек

## 3.1 Противоположные пары 🔥Avito
Для каждого `x` в массиве должно быть столько же `-x`. Для `1` → `-1`, для `-2` → `2`. Ноль — чётное число раз. Верни `true`/`false`.

- 🎯 **Тренируем:** Map частот + аккуратная проверка симметрии и особого случая (0).
- ⏱ **Цель:** 6 минут.

> [!question]- 💡 Подсказка
> Посчитай частоты. Потом для каждого ключа: если это `0` — частота должна быть чётной; иначе `cnt[x]` должно равняться `cnt[-x]`.

> [!success]- ✅ Решение
> ```kotlin
> fun hasOppositePairs(numbers: List<Int>): Boolean {
>     val cnt = HashMap<Int, Int>()
>     for (x in numbers) cnt[x] = cnt.getOrDefault(x, 0) + 1
>     for ((x, c) in cnt) {
>         if (x == 0) {
>             if (c % 2 != 0) return false
>         } else if (cnt.getOrDefault(-x, 0) != c) {
>             return false
>         }
>     }
>     return true
> }
> ```
> **Сложность:** O(n) / O(n). Оригинал: [[Задачи с Avito]].
> ⚠️ **Грабли:** нельзя забыть ноль — для него нет «противоположного», он сам себе пара. Проверку `cnt[x] == cnt[-x]` пройдут оба ключа `x` и `-x`, это ок.

## 3.2 Корректность скобок
Строка из `()[]{}` — правильная ли вложенность?

- 🎯 **Тренируем:** стек + карта соответствия (скелет [[04 Маркеры + Заготовки|#9]]).
- ⏱ **Цель:** 5 минут.

> [!question]- 💡 Подсказка
> Открывающую — в стек. Закрывающую — сверь с вершиной: пусто или не совпало → `false`. В конце стек должен быть пуст.

> [!success]- ✅ Решение
> ```kotlin
> fun isValidBrackets(s: String): Boolean {
>     val stack = ArrayDeque<Char>()
>     val pair = mapOf(')' to '(', ']' to '[', '}' to '{')
>     for (c in s) {
>         if (c in pair.values) stack.addLast(c)
>         else if (c in pair.keys) {
>             if (stack.isEmpty() || stack.removeLast() != pair[c]) return false
>         }
>     }
>     return stack.isEmpty()
> }
> ```
> **Сложность:** O(n) / O(n). См. [[Задача на stack и map]].
> ⚠️ **Грабли:** забыть финальную проверку `stack.isEmpty()` — тогда `"("` ошибочно пройдёт как валидная.

## 3.3 Количество островов
Матрица из `0`/`1`. Посчитай число связных групп единиц (соседство по 4 сторонам).

- 🎯 **Тренируем:** DFS/BFS по сетке с пометкой посещённых.
- ⏱ **Цель:** 10 минут.

> [!question]- 💡 Подсказка
> Иди по всем клеткам. Встретил `1` — это новый остров, `count++`, и «затопи» весь остров DFS-ом (пометь как `0` или в visited), чтобы не считать дважды.

> [!success]- ✅ Решение
> ```kotlin
> fun numIslands(grid: Array<CharArray>): Int {
>     if (grid.isEmpty()) return 0
>     val rows = grid.size; val cols = grid[0].size
>     var count = 0
>
>     fun sink(r: Int, c: Int) {
>         if (r < 0 || c < 0 || r >= rows || c >= cols || grid[r][c] != '1') return
>         grid[r][c] = '0'                 // помечаем посещённой
>         sink(r + 1, c); sink(r - 1, c)
>         sink(r, c + 1); sink(r, c - 1)
>     }
>
>     for (r in 0 until rows) for (c in 0 until cols) {
>         if (grid[r][c] == '1') { count++; sink(r, c) }
>     }
>     return count
> }
> ```
> **Сложность:** O(rows·cols) / O(rows·cols) на стек рекурсии в худшем случае. См. [[Поиск в глубину (DFS)]].
> ⚠️ **Грабли:** проверку границ делай **первой строкой** `sink`, до обращения к `grid[r][c]`.

## 3.4 Достижимые вершины (BFS)
Дан граф `Map<Int, List<Int>>`. Верни все вершины, достижимые из `start`.

- 🎯 **Тренируем:** BFS с очередью и `visited` (скелет [[04 Маркеры + Заготовки|#11]]).
- ⏱ **Цель:** 6 минут.

> [!question]- 💡 Подсказка
> Очередь + set посещённых. Помечай `visited` **при добавлении в очередь**, а не при извлечении — иначе один узел попадёт в очередь несколько раз.

> [!success]- ✅ Решение
> ```kotlin
> fun bfs(graph: Map<Int, List<Int>>, start: Int): List<Int> {
>     val visited = mutableSetOf(start)
>     val queue = ArrayDeque<Int>().apply { add(start) }
>     while (queue.isNotEmpty()) {
>         val cur = queue.removeFirst()
>         for (next in graph[cur].orEmpty()) {
>             if (visited.add(next)) queue.add(next)   // add=false → уже был
>         }
>     }
>     return visited.toList()
> }
> ```
> **Сложность:** O(V + E) / O(V). См. [[Задача на поиск в ширину]].
> 🔁 **Вариации:** если нужен **кратчайший путь по шагам** — обрабатывай очередь слоями (`repeat(queue.size)`) и считай `steps`.

# 🟠 Уровень 4 — Префиксы, Кадане, топология

## 4.1 Подмассивов с суммой K
Сколько непрерывных подмассивов имеют сумму ровно `k`?

- 🎯 **Тренируем:** префиксные суммы + Map (скелет [[04 Маркеры + Заготовки|#16]]).
- ⏱ **Цель:** 10 минут.

> [!question]- 💡 Подсказка
> Ведём бегущую сумму `sum`. Число подмассивов с суммой `k`, заканчивающихся здесь, = сколько раз раньше встречалась `sum - k`. Копи частоты префиксов в Map, инициализируй `{0: 1}`.

> [!success]- ✅ Решение
> ```kotlin
> fun subarraySum(nums: IntArray, k: Int): Int {
>     val seen = HashMap<Int, Int>().apply { put(0, 1) }
>     var sum = 0; var ans = 0
>     for (x in nums) {
>         sum += x
>         ans += seen.getOrDefault(sum - k, 0)
>         seen[sum] = seen.getOrDefault(sum, 0) + 1
>     }
>     return ans
> }
> ```
> **Сложность:** O(n) / O(n).
> ⚠️ **Грабли:** без `put(0, 1)` потеряешь подмассивы, начинающиеся с индекса 0. Скользящее окно тут **не** работает (числа могут быть отрицательными).

## 4.2 Максимальная сумма подмассива (Кадане)
Найди максимальную сумму непрерывного подмассива.

- 🎯 **Тренируем:** алгоритм Кадане (частный DP).
- ⏱ **Цель:** 5 минут.

> [!question]- 💡 Подсказка
> Для каждого элемента реши: продолжить текущую серию или начать заново с него. `cur = max(x, cur + x)`, `best = max(best, cur)`.

> [!success]- ✅ Решение
> ```kotlin
> fun maxSubArray(nums: IntArray): Int {
>     var cur = nums[0]
>     var best = nums[0]
>     for (i in 1 until nums.size) {
>         cur = maxOf(nums[i], cur + nums[i])
>         best = maxOf(best, cur)
>     }
>     return best
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:** инициализируй `nums[0]`, не `0` — иначе на всех отрицательных вернёшь 0 вместо максимума (например, `[-3, -1, -2]` → `-1`).

## 4.3 Топологическая сортировка (Kahn)
Есть зависимости «A до B». Верни допустимый порядок выполнения или `null`, если есть цикл.

- 🎯 **Тренируем:** входные степени + очередь (скелет [[04 Маркеры + Заготовки|#19]]).
- ⏱ **Цель:** 12 минут.

> [!success]- ✅ Решение
> ```kotlin
> fun topoSort(n: Int, edges: List<Pair<Int, Int>>): List<Int>? {
>     val adj = Array(n) { mutableListOf<Int>() }
>     val indeg = IntArray(n)
>     for ((u, v) in edges) { adj[u].add(v); indeg[v]++ }   // ребро u -> v
>
>     val q = ArrayDeque<Int>()
>     for (i in 0 until n) if (indeg[i] == 0) q.add(i)
>
>     val order = mutableListOf<Int>()
>     while (q.isNotEmpty()) {
>         val u = q.removeFirst(); order.add(u)
>         for (v in adj[u]) if (--indeg[v] == 0) q.add(v)
>     }
>     return if (order.size == n) order else null           // < n → цикл
> }
> ```
> **Сложность:** O(V + E) / O(V + E).
> ⚠️ **Грабли:** `order.size < n` — единственный надёжный признак цикла в этом методе.

## 4.4 Union-Find: число компонент
Даны `n` вершин и рёбра. Сколько связных компонент?

- 🎯 **Тренируем:** DSU со сжатием пути (скелет [[04 Маркеры + Заготовки|#18]]).
- ⏱ **Цель:** 10 минут.

> [!success]- ✅ Решение
> ```kotlin
> fun countComponents(n: Int, edges: List<Pair<Int, Int>>): Int {
>     val parent = IntArray(n) { it }
>     fun find(x: Int): Int {
>         if (parent[x] != x) parent[x] = find(parent[x])   // сжатие пути
>         return parent[x]
>     }
>     for ((a, b) in edges) parent[find(a)] = find(b)
>     return (0 until n).count { find(it) == it }
> }
> ```
> **Сложность:** ~O((V + E)·α(n)) ≈ линейно / O(V).

# 🔴 Уровень 5 — Сложное и дизайн

## 5.1 Climb Stairs (разгон в DP)
Сколько способов подняться на `n` ступеней, шагая на 1 или 2?

- 🎯 **Тренируем:** переход из рекурсии в DP с O(1) памятью (Фибоначчи).
- ⏱ **Цель:** 4 минуты.

> [!success]- ✅ Решение
> ```kotlin
> fun climbStairs(n: Int): Int {
>     if (n <= 2) return n
>     var a = 1; var b = 2
>     repeat(n - 2) { val c = a + b; a = b; b = c }
>     return b
> }
> ```
> **Сложность:** O(n) / O(1). См. [[Динамическое программирование]].

## 5.2 Размен монет (минимум монет)
Минимальное число монет заданных номиналов, чтобы набрать `amount`. Нельзя — `-1`.

- 🎯 **Тренируем:** классический 1D DP «снизу вверх», понимание, почему жадность врёт.
- ⏱ **Цель:** 12 минут.

> [!question]- 💡 Подсказка
> `dp[s]` = минимум монет на сумму `s`. База `dp[0] = 0`. Переход: `dp[s] = min(dp[s - coin] + 1)` по всем монетам, что `<= s`. Заполни «недостижимо» большим числом.

> [!success]- ✅ Решение
> ```kotlin
> fun coinChange(coins: IntArray, amount: Int): Int {
>     val dp = IntArray(amount + 1) { amount + 1 }   // «бесконечность»
>     dp[0] = 0
>     for (s in 1..amount) {
>         for (coin in coins) if (coin <= s) {
>             dp[s] = minOf(dp[s], dp[s - coin] + 1)
>         }
>     }
>     return if (dp[amount] > amount) -1 else dp[amount]
> }
> ```
> **Сложность:** O(amount · coins) / O(amount).
> ⚠️ **Грабли:** жадность «бери крупную монету» ошибётся на `coins=[1,3,4], amount=6` (жадно 4+1+1=3 монеты, а оптимум 3+3=2). Поэтому DP.

## 5.3 Top K частых элементов
Верни `k` самых часто встречающихся чисел.

- 🎯 **Тренируем:** Map частот + min-heap размера K (скелет [[04 Маркеры + Заготовки|#17]]).
- ⏱ **Цель:** 10 минут.

> [!question]- 💡 Подсказка
> Посчитай частоты. Держи **min-heap размера k** по частоте: добавляешь, при переполнении выкидываешь корень (наименее частый). В конце в куче — k самых частых.

> [!success]- ✅ Решение
> ```kotlin
> fun topKFrequent(nums: IntArray, k: Int): List<Int> {
>     val cnt = HashMap<Int, Int>()
>     for (x in nums) cnt[x] = cnt.getOrDefault(x, 0) + 1
>
>     val heap = java.util.PriorityQueue<Int>(compareBy { cnt[it] })  // min-heap по частоте
>     for (num in cnt.keys) {
>         heap.add(num)
>         if (heap.size > k) heap.poll()      // выкидываем наименее частый
>     }
>     return heap.toList()
> }
> ```
> **Сложность:** O(n log k) / O(n).
> ⚠️ **Грабли:** для k **самых частых** нужен именно **min**-heap (контр-интуитивно) — чтобы наверху был кандидат на вылет.

## 5.4 LRU Cache 🔥Android
Реализуй `get(key)` и `put(key, value)` за **O(1)**. При переполнении ёмкости вытесняй давно не используемый элемент.

- 🎯 **Тренируем:** `HashMap` + двусвязный список с sentinel-узлами.
- ⏱ **Цель:** 20 минут (это дизайн-задача, её учат «руками»).

> [!question]- 💡 Подсказка 1
> `HashMap` даёт доступ к узлу по ключу за O(1). Двусвязный список хранит **порядок свежести**: голова — свежие, хвост — «протухшие». И get, и put считаются использованием → двигают узел в голову.

> [!question]- 💡 Подсказка 2
> Заведи фиктивные `head` и `tail` (sentinels), чтобы не проверять `null` на краях. Три приватных метода: `addFront`, `remove`, `moveToFront`.

> [!success]- ✅ Решение
> ```kotlin
> class LRUCache<K, V>(private val capacity: Int) {
>     private class Node<K, V>(val key: K, var value: V) {
>         var prev: Node<K, V>? = null
>         var next: Node<K, V>? = null
>     }
>     private val map = HashMap<K, Node<K, V>>()
>     private val head = Node<K, V>(null as K, null as V)   // sentinels
>     private val tail = Node<K, V>(null as K, null as V)
>     init { head.next = tail; tail.prev = head }
>
>     fun get(key: K): V? {
>         val node = map[key] ?: return null
>         moveToFront(node)
>         return node.value
>     }
>
>     fun put(key: K, value: V) {
>         map[key]?.let { it.value = value; moveToFront(it); return }
>         val node = Node(key, value)
>         map[key] = node; addFront(node)
>         if (map.size > capacity) {
>             val lru = tail.prev!!
>             remove(lru); map.remove(lru.key)
>         }
>     }
>
>     private fun addFront(n: Node<K, V>) {
>         n.prev = head; n.next = head.next
>         head.next!!.prev = n; head.next = n
>     }
>     private fun remove(n: Node<K, V>) { n.prev!!.next = n.next; n.next!!.prev = n.prev }
>     private fun moveToFront(n: Node<K, V>) { remove(n); addFront(n) }
> }
> ```
> **Сложность:** get/put O(1), память O(capacity). Полный разбор: [[LRU Cache]].
> ⚠️ **Грабли:** (1) get тоже «освежает» узел; (2) при обновлении ключа — обновить значение И передвинуть, не плодить дубль; (3) в реальном Android есть `android.util.LruCache` и `LinkedHashMap(accessOrder = true)`, но на собесе просят руками.
