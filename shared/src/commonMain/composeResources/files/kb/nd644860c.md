Для проверки количества вызовов методов на UI и мониторинга отрисовок в Android можно использовать несколько подходов:

**1. Инструмент Layout Inspector (Android Studio)**

• Layout Inspector позволяет в реальном времени отслеживать иерархию View, частоту их перерисовок, а также параметры измерений (measure, layout, draw).

• Вы можете найти его в View > Tool Windows > Layout Inspector.
• В “Layout Validation” можно увидеть, какие элементы отрисовываются и насколько часто.

**Как использовать:**

1. Запустите приложение на устройстве или эмуляторе.
2. Откройте Layout Inspector в Android Studio.
3. Наблюдайте за деревом View и его обновлениями.

---

**2. Profile GPU Rendering (Инструмент разработчика на устройстве)**

• Включите его в Settings > Developer Options > Profile GPU Rendering > On screen as bars.
• Графики покажут частоту отрисовок и помогут найти “тяжелые” кадры.

---

**3. Использование Choreographer**

• Choreographer позволяет получать callback на каждый кадр UI.
• Вы можете посчитать количество перерисовок за определенный интервал времени.

```kotlin
import android.view.Choreographer

class FrameCallbackExample : Choreographer.FrameCallback {
    private var frameCount = 0

    override fun doFrame(frameTimeNanos: Long) {
        frameCount++
        println("Frame rendered: $frameCount")
        Choreographer.getInstance().postFrameCallback(this)
    }

    fun start() {
        Choreographer.getInstance().postFrameCallback(this)
    }

    fun stop() {
        Choreographer.getInstance().removeFrameCallback(this)
    }
}
```

**Пример использования:**

```kotlin
val frameCallback = FrameCallbackExample()

override fun onStart() {
    super.onStart()
    frameCallback.start()
}

override fun onStop() {
    super.onStop()
    frameCallback.stop()
}
```

**4. Debug Опции View**

• View имеет методы setWillNotDraw(false) и invalidate() - их можно обернуть логированием.

• Например, создать кастомный View или ViewGroup и переопределить методы onDraw(), onLayout(), onMeasure():
```kotlin
class DebugView @JvmOverloads constructor(
    context: Context, attrs: AttributeSet? = null
) : View(context, attrs) {

    override fun onDraw(canvas: Canvas?) {
        super.onDraw(canvas)
        Log.d("DebugView", "onDraw called")
    }

    override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
        super.onMeasure(widthMeasureSpec, heightMeasureSpec)
        Log.d("DebugView", "onMeasure called")
    }

    override fun onLayout(changed: Boolean, left: Int, top: Int, right: Int, bottom: Int) {
        super.onLayout(changed, left, top, right, bottom)
        Log.d("DebugView", "onLayout called")
    }
}
```

**5. Использование StrictMode для отслеживания UI вызовов**
```kotlin
if (BuildConfig.DEBUG) {
    StrictMode.setThreadPolicy(
        StrictMode.ThreadPolicy.Builder()
            .detectAll()
            .penaltyLog()
            .build()
    )
    StrictMode.setVmPolicy(
        StrictMode.VmPolicy.Builder()
            .detectAll()
            .penaltyLog()
            .build()
    )
}
```

• StrictMode поможет найти не только избыточные отрисовки, но и долгие операции на главном потоке.

**6. Инструмент Systrace**

• Systrace позволяет получить полную информацию о кадрах, отрисовках и долгих вызовах.

• Запуск через Android Studio или adb:
```sh
adb shell atrace -b 4096 -c -t 10 gfx view sched freq
```

**7. Инструмент RenderThread (для Compose)**

• Для Jetpack Compose можно использовать Layout Inspector, а также включить “Show Layout Bounds” для подсветки отрисовок.

• Логи отрисовок можно посмотреть через Logcat:
```kotlin
@Composable
fun DebugComposable() {
    Log.d("DebugComposable", "Composable recomposed")
    Text("Hello, World!")
}
```

**Рекомендация:**

Если вы видите слишком частые перерисовки:

• Проверьте, не вызывается ли invalidate() или requestLayout() слишком часто.
• Оптимизируйте RecyclerView (использование DiffUtil, ListAdapter).
• В Compose следите за State, не триггерит ли он лишние перерисовки.

**🔥 6. Настроить RecyclerView для быстрого скролла**

📌 **Отключаем анимации ItemAnimator, если они не нужны**

```kotlin
recyclerView.itemAnimator = null
```

📌 **Настраиваем кэширование элементов**
```kotlin
recyclerView.setItemViewCacheSize(20)  // Кэширует 20 элементов
```

📌 **Предзагрузка элементов (Pre-fetching)**
```kotlin
(layoutManager as LinearLayoutManager).initialPrefetchItemCount = 10
```
