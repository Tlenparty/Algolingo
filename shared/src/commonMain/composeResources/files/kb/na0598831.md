# WorkManager

**WorkManager** — Jetpack-библиотека для **гарантированного** выполнения отложенной/фоновой работы, которая **должна выполниться даже после перезапуска приложения или устройства**. Это рекомендованный способ фоновых задач на современном Android.

## Когда нужен (и когда нет)

> [!important] WorkManager ≠ способ «просто уйти в фон»
> Он для **deferrable + guaranteed** работы: синхронизация с сервером, отправка логов/аналитики, периодическая выгрузка, обработка после получения сети. **НЕ** для:
> • работы «прямо сейчас, пока пользователь смотрит» → корутины в `viewModelScope`;
> • непрерывного трекинга в реальном времени → **Foreground Service** (см. [[Способы передачи геолокации в фоновом режиме]]);
> • точного будильника в конкретное время → `AlarmManager` (`setExactAndAllowWhileIdle`).

## Базовое использование

```kotlin
class SyncWorker(ctx: Context, params: WorkerParameters) : CoroutineWorker(ctx, params) {
    override suspend fun doWork(): Result {
        return try {
            repository.sync()
            Result.success()
        } catch (e: IOException) {
            Result.retry()       // повторить с backoff
        }
    }
}

val request = OneTimeWorkRequestBuilder<SyncWorker>()
    .setConstraints(Constraints.Builder()
        .setRequiredNetworkType(NetworkType.CONNECTED)
        .build())
    .build()

WorkManager.getInstance(context).enqueue(request)
```

> [!info] Что под капотом
> WorkManager сам выбирает движок: на API 23+ — **JobScheduler**, на старых — `AlarmManager` + `BroadcastReceiver`. Состояние задач хранится в **локальной БД (Room)** — поэтому работа переживает перезапуск процесса и устройства. Это и есть «гарантированность».

## Ключевые возможности

> [!tip] Что любят спрашивать
> • **Constraints** — сеть, зарядка, `deviceIdle`, достаточно памяти.
> • **`Result`**: `success()` / `failure()` / `retry()` (с `BackoffPolicy` — LINEAR/EXPONENTIAL).
> • **Периодическая работа** — `PeriodicWorkRequest`, минимальный интервал **15 минут** (ограничение системы).
> • **Цепочки** — `beginWith(a).then(b).enqueue()`, параллельные/последовательные графы.
> • **Уникальность** — `enqueueUniqueWork(name, policy)` (`KEEP`/`REPLACE`/`APPEND`), чтобы не плодить дубли.
> • **Expedited work** — срочная задача (на API 31+ через `setExpedited`), для важной короткой работы.
> • Наблюдение статуса — `getWorkInfoByIdLiveData`/Flow.

## Doze, ограничения и почему «воркер не запускается»

> [!warning] Doze, App Standby и убийцы фоновых процессов
> В **Doze** (см. [[Standby Bucket + Doze Mode]]) и при глубоком **App Standby Bucket** выполнение откладывается до окон обслуживания — поэтому периодическая работа может приходить реже, чем заявлено. На многих вендорских прошивках (Xiaomi, Huawei, Samsung) агрессивные «оптимизаторы батареи» **убивают** фоновую работу, если приложение не в белом списке. Это классический баг «WorkManager не срабатывает» — частично решается просьбой отключить оптимизацию батареи и Foreground Service для критичных задач.

> [!note] CoroutineWorker и тестирование
> `CoroutineWorker.doWork()` — `suspend`, удобно для корутин/Flow. Для тестов есть `WorkManagerTestInitHelper` и `TestListenableWorkerBuilder`. DI воркеров — через `WorkerFactory`/`HiltWorker` (см. [[Hilt]]).
