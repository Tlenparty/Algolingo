# LRU Cache

**LRU (Least Recently Used)** — кэш, который при переполнении вытесняет **давно не используемый** элемент. Один из самых частых алгоритмических вопросов именно на **Android**-собесах (его используют Coil/Glide, `LruCache` в SDK, кэш bitmap).

## Требование

Реализовать `get(key)` и `put(key, value)` за **O(1)** при ограниченной ёмкости. При `put` сверх ёмкости — удалить наименее недавно использованный элемент. `get` и `put` считаются «использованием».

## Идея: HashMap + двусвязный список

> [!important] Почему именно эта комбинация
> • **HashMap** даёт доступ к узлу по ключу за **O(1)**.
> • **Двусвязный список** хранит порядок использования: «свежие» — у головы, «протухшие» — у хвоста. Перемещение/удаление узла за **O(1)** (есть ссылки на соседей).
> Связный массив/`ArrayList` не подходит — сдвиг элементов O(n). Это ровно то, что внутри `LinkedHashMap`.

```kotlin
class LRUCache<K, V>(private val capacity: Int) {
    private class Node<K, V>(val key: K, var value: V) {
        var prev: Node<K, V>? = null
        var next: Node<K, V>? = null
    }
    private val map = HashMap<K, Node<K, V>>()
    private val head = Node<K, V>(null as K, null as V) // фиктивные
    private val tail = Node<K, V>(null as K, null as V)
    init { head.next = tail; tail.prev = head }

    fun get(key: K): V? {
        val node = map[key] ?: return null
        moveToFront(node)
        return node.value
    }

    fun put(key: K, value: V) {
        map[key]?.let { it.value = value; moveToFront(it); return }
        val node = Node(key, value)
        map[key] = node; addFront(node)
        if (map.size > capacity) {
            val lru = tail.prev!!          // наименее свежий
            remove(lru); map.remove(lru.key)
        }
    }

    private fun addFront(n: Node<K, V>) {
        n.prev = head; n.next = head.next
        head.next!!.prev = n; head.next = n
    }
    private fun remove(n: Node<K, V>) { n.prev!!.next = n.next; n.next!!.prev = n.prev }
    private fun moveToFront(n: Node<K, V>) { remove(n); addFront(n) }
}
```

> [!tip] Фиктивные head/tail (sentinels)
> Пустые узлы-«заглушки» head и tail убирают проверки на `null` при вставке/удалении на краях — список никогда не пуст с точки зрения логики. Классический приём, упрощающий код двусвязного списка.

> [!info] В реальном Android — `LruCache` из коробки
> `android.util.LruCache<K, V>` уже реализует это (для bitmap-кэша и т.п.). Можно упомянуть на собесе, но **просят реализовать руками**, чтобы проверить понимание HashMap + список. А `LinkedHashMap(initialCapacity, loadFactor, accessOrder = true)` + переопределённый `removeEldestEntry` — ещё более короткий способ.

> [!warning] Сложность и подвохи
> • `get`/`put` — **O(1)** по времени, **O(capacity)** по памяти.
> • Не забыть, что `get` тоже «освежает» элемент (двигает в начало).
> • При обновлении существующего ключа — обновить значение **и** освежить позицию, не создавать дубль.
> • **LFU** (Least Frequently Used) — другой алгоритм (по частоте, а не по свежести), сложнее.
