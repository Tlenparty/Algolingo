# Потоки

Поток (thread, «нить») — независимая последовательность выполнения команд внутри программы. Потоки позволяют выполнять несколько задач параллельно: длительные операции (сеть, обработка данных) выносят в фоновые потоки, чтобы не блокировать основной (UI) поток.

> **На собес одной фразой:** поток — единица выполнения; тяжёлую работу выносим с главного потока, чтобы UI не фризил. В Android UI можно трогать только с [[Главный поток|главного потока]].

```kotlin
import kotlin.concurrent.thread

fun main() {
    val t = thread(start = true) {
        println("Этот код выполняется в другом потоке")
    }
    t.join()   // ждём завершения потока
    println("Этот код — снова в основном потоке")
}
```

## Основные характеристики

- **Параллелизм** — несколько операций одновременно на многоядерном процессоре.
- **Конкуренция** — потоки делят общие ресурсы, поэтому нужны механизмы синхронизации (см. [[Атомарность]]) для защиты от [[Гонка данных|гонок данных]].
- **Жизненный цикл** — создание → выполнение → блокировка → завершение.

Процессор назначает потокам время выполнения: они идут параллельно на разных ядрах либо чередуются через переключение контекста. Многопоточность эффективно использует ресурсы CPU, особенно на многоядерных системах.

## Особенность Android: главный поток

У Android асинхронная модель UI: все операции с интерфейсом должны выполняться в [[Главный поток|основном потоке]] (UI thread). Иначе — краш (`CalledFromWrongThreadException`) или зависание. Долгие операции уводят в фон, а результат возвращают на главный поток.

## Способы создания потоков (Java/Android)

### Класс `Thread`
```java
Thread thread = new Thread(new Runnable() {
    @Override public void run() {
        // код в потоке
    }
});
thread.start();
```

### Интерфейс `Runnable`
```java
Runnable runnable = new Runnable() {
    @Override public void run() {
        // код в потоке
    }
};
Thread thread = new Thread(runnable);
thread.start();
```

### `ExecutorService` (пул потоков)
Переиспользует потоки вместо создания нового на каждую задачу. Подробнее — [[ExecutorService]].
```java
ExecutorService executorService = Executors.newSingleThreadExecutor();
executorService.execute(new Runnable() {
    @Override public void run() {
        // код в потоке
    }
});
executorService.shutdown();
```

> На практике в Kotlin/Android вместо «голых» потоков используют **корутины** — они легче, поддерживают structured concurrency и отмену. «Голые» `Thread`/`ExecutorService` — база, которую спрашивают на теории.
