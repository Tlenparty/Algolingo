**Лямбда** — это анонимная функция, которая может быть передана как аргумент в другую функцию, возвращена как результат функции или использована непосредственно в выражении. Лямбда-выражение в Kotlin записывается с использованием синтаксиса {}.

Пример лямбды в Kotlin:
```kotlin
val sum = { a: Int, b: Int -> a + b }
println(sum(2, 3)) // Выведет 5
```
Здесь sum — это лямбда, которая принимает два параметра a и b, и возвращает их сумму.

### **Что такое захват лямбды?**

**Захват лямбды** (или **capturing lambda** в Kotlin) — это процесс, при котором лямбда-выражение “захватывает” переменные из своей окружающей области видимости. Это позволяет лямбде использовать переменные, которые были определены в контексте, в котором она была создана.

В Kotlin лямбда может захватывать как изменяемые (изменяющиеся), так и неизменяемые переменные из внешней области видимости. Эти переменные могут быть использованы внутри лямбды, и при необходимости изменяться.

**Пример захвата лямбды в Kotlin:**

1. **Захват неизменяемых переменных (по значению)**:

Лямбда “захватывает” значения переменных, которые были определены в окружающем контексте на момент её создания.

Пример:
```kotlin
val a = 5
val lambda = { println(a) }
// При вызове лямбда "захватывает" значение переменной a
lambda() // Выведет 5
```

2. **Захват изменяемых переменных (по ссылке)**:

Если лямбда захватывает изменяемую переменную (например, переменную типа var), то она будет ссылаться на эту переменную. Изменения внутри лямбды будут отражаться на исходной переменной.

Пример:
```kotlin
var x = 10
val lambda = { x++ } // Захватывает переменную x по ссылке
lambda()
println(x) // Выведет 11
```

3. **Захват переменных с изменяемыми и неизменяемыми значениями**:

Если переменная внутри лямбды изменяется, она будет захвачена по ссылке. Если переменная не изменяется, она будет захвачена по значению.

Пример:
```kotlin
var a = 1
val lambda = { 
    a++       // Изменяет переменную a
    val b = a // Создает новую переменную b с измененным значением a
    println("a: $a, b: $b")
}
lambda()  // Выведет: a: 2, b: 2
```

### **Всегда ли создается анонимный класс для лямбды в Kotlin?**

В Kotlin ==**не всегда**== создается анонимный класс для лямбды. Лямбды могут быть реализованы без явного создания анонимного класса, особенно когда они используются ==с функциональными интерфейсами.==

1. **Лямбды с функциональными интерфейсами**:

Когда лямбда используется для реализации интерфейса с одним абстрактным методом (например, интерфейса Runnable или Comparator), компилятор Kotlin может использовать **инлайнинг** (inline), чтобы избежать создания анонимного класса и эффективно скомпилировать лямбду в код, который работает без необходимости создавать новый объект.

```java
@FunctionalInterface
interface Greeting {
    void sayHello(String name);  // единственный абстрактный метод
}


public class Main {
    public static void main(String[] args) {

        // Лямбда-выражение, реализующее интерфейс Greeting
        Greeting greeting = (name) -> System.out.println("Hello, " + name);
        // Вызов метода интерфейса через лямбду
        greeting.sayHello("Alice");
    }
}
```

```kotlin
fun interface Greeting {
    fun sayHello(name: String)
}

fun main() {

    // Лямбда-выражение, реализующее интерфейс Greeting
    val greeting = Greeting { name -> println("Hello, $name") }
    // Вызов метода интерфейса через лямбду

    greeting.sayHello("Alice")

}
```

2. **Инлайнинг лямбд**:

Когда лямбда передается в **инлайн-функцию** (функцию, которая помечена ключевым словом inline), компилятор может **инлайнить** код лямбды, то есть заменить вызов функции на тело лямбды во время компиляции. Это позволяет избежать создания анонимного класса для лямбды и улучшить производительность.

Пример инлайнинга:

```kotlin
inline fun execute(action: () -> Unit) {
    action()
}

fun main() {
    var count = 0
    execute {
        count++
        println(count)
    }
    // Лямбда будет инлайнина в код, и анонимный класс не создастся
}
```

Таким образом, **анонимный класс** создается для лямбды только в случае, если лямбда не используется в контексте инлайнинга, и компилятор не может заменить её код на месте.

> [!important] Захват по ссылке отличает Kotlin от Java
> В **Java** лямбда может захватывать только **effectively final** переменные (менять захваченную переменную нельзя). В **Kotlin** можно захватывать и изменять `var`: компилятор оборачивает такую переменную в специальный объект-обёртку (`Ref.IntRef` и т.п.) и захватывает ссылку на него. Поэтому `var x; val l = { x++ }` работает — но это **скрытая аллокация** обёртки.

> [!tip] Производительность лямбд
> - **Лямбда без захвата** (`{ it * 2 }`) компилируется в **синглтон** — один экземпляр на всю программу, без аллокаций.
> - **Лямбда с захватом** создаёт **новый объект** при каждом проходе (несёт захваченные значения) — в горячем коде/циклах это давит на GC.
> - **`inline`-функция** «встраивает» тело лямбды в место вызова → объекта лямбды нет вообще (см. [[Inline, Noinline, cross inline, reified]]). Поэтому `forEach`, `map`, `let` и т.п. помечены `inline`.
> - **`fun interface`** (SAM) позволяет передавать лямбду туда, где ожидается интерфейс с одним методом.
