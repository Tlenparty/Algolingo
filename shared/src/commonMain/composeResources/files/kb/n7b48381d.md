
SubcomposeLayout — это **низкоуровневый layout в Jetpack Compose**, который позволяет **откладывать** (отложенную композицию) части UI до момента, когда известны размеры других элементов.

🚀 **Используется, когда:**

• Размер одного элемента **зависит от размера другого** (например, текст + иконка с динамическим масштабом)
• Нужно **измерить дочерние элементы в несколько этапов**, а не сразу.
• Обычные Modifier.layout {} или BoxWithConstraints {} **не подходят**.

### **Когда нужен SubcomposeLayout?**
**✅ Пример: список с заголовками, зависящими от содержимого**

Допустим, у нас есть **LazyColumn**, где **заголовок “Section 1” должен быть такой же ширины, как самый широкий элемент в секции**.

Обычные Modifier.layout {} **не помогут**, потому что:

• В LazyColumn элементы **измеряются отдельно** и не знают размеры друг друга.
• Нам нужно **сначала измерить содержимое секции**, а потом **отрендерить заголовок** с нужной шириной.

### **Как работает SubcomposeLayout под капотом?**

1️⃣ **Выполняется первая фаза измерения (premeasure)**

• Измеряем **основной контент** (content).
• Определяем его размер.

2️⃣ **Выполняется вторая фаза (subcompose)**

• После получения размеров **отрисовываем остальные элементы** (header).

3️⃣ **Компоновка элементов с уже известными размерами**

• Теперь header получает правильную ширину и отрисовывается.

📌 **Обычный** Layout **измеряет всё сразу, а** SubcomposeLayout **делает это в два этапа!**

**Реальный пример использования SubcomposeLayout**

```kotlin
@Composable
fun CustomListWithHeaders(items: List<String>) {
    SubcomposeLayout { constraints ->
        // 1️⃣ Сначала измеряем основной контент (все элементы списка)
        val contentPlaceables = subcompose("content") {
            items.forEach { Text(it, fontSize = 18.sp) }
        }.map { it.measure(constraints) }

        // Определяем максимальную ширину содержимого
        val maxWidth = contentPlaceables.maxOf { it.width }

        // 2️⃣ Теперь можем измерить заголовок (header)
        val headerPlaceable = subcompose("header") {
            Text("Section Header", fontSize = 20.sp, modifier = Modifier.width(maxWidth.toDp()))
        }.first().measure(constraints)

        layout(maxWidth, headerPlaceable.height + contentPlaceables.sumOf { it.height }) {
            var yPosition = 0

            // Размещаем заголовок
            headerPlaceable.place(0, yPosition)
            yPosition += headerPlaceable.height

            // Размещаем список
            contentPlaceables.forEach { placeable ->
                placeable.place(0, yPosition)
                yPosition += placeable.height
            }
        }
    }
}
```

### Custom Layout

  В **Jetpack Compose**, если вам нужно **измерить дочерние элементы внутри кастомного** Layout {}, вы можете воспользоваться методом .measure().
```kotlin
@Composable
fun CustomColumnLayout(modifier: Modifier = Modifier, content: @Composable () -> Unit) {
    Layout(
        modifier = modifier,
        content = content
    ) { measurables, constraints ->

        // 1️⃣ Измеряем всех детей
        val placeables = measurables.map { measurable ->
            measurable.measure(constraints)
        }

        // 2️⃣ Находим самую большую ширину
        val maxWidth = placeables.maxOf { it.width }

        // 3️⃣ Вычисляем общий размер Layout
        val totalHeight = placeables.sumOf { it.height }

        layout(maxWidth, totalHeight) {
            var yPosition = 0

            // 4️⃣ Размещаем дочерние элементы
            placeables.forEach { placeable ->
                placeable.place(0, yPosition)
                yPosition += placeable.height
            }
        }
    }
}

@Composable
fun TestScreen() {
    CustomColumnLayout {
        Text("Short", fontSize = 16.sp)
        Text("This is a longer text", fontSize = 16.sp)
        Text("Very very very long text", fontSize = 16.sp, color = Color.Red)
    }
}
```

**📌 Разбор кода**

**✅ 1. Как измеряются дочерние элементы?**
```kotlin
val placeables = measurables.map { measurable ->
    measurable.measure(constraints)
}
```

• measurables — список всех дочерних Composable, переданных в Layout.
• .measure(constraints) измеряет каждого ребёнка по **заданным ограничениям (**constraints**)**.
• placeables — список объектов, содержащих ширину, высоту и методы .place(x, y).

**✅ 2. Как найти максимальную ширину?**

```kotlin
val maxWidth = placeables.maxOf { it.width }
```

• Мы **измеряем все элементы** и ищем **самый широкий**.

**✅ 3. Как расположить дочерние элементы?**
```kotlin
layout(maxWidth, totalHeight) {
    var yPosition = 0
    placeables.forEach { placeable ->
        placeable.place(0, yPosition) // Размещаем элемент в нужной позиции
        yPosition += placeable.height // Двигаем следующий вниз
    }
}
```

• Мы **размещаем** все элементы в колонке.
• placeable.place(x, y) — устанавливает **позицию каждого элемента**

## Интринзики

**Интринзики (**intrinsics**)** в Jetpack Compose — это **минимальные и максимальные размеры компонента** без его фактического измерения (measure).

> Они **используются в кастомных** Layout {}, когда нужно **определить размеры дочерних элементов до их реального измерения**.

**Зачем нужны интринзики?**

1. **Когда размер родителя зависит от размеров детей.**
2. **Когда дочерний элемент должен адаптироваться к родителю без прямого измерения.**
3. **Когда компонент имеет динамический контент (например, текст).**

🔹 **Простыми словами:**

• **Минимальная ширина (**minIntrinsicWidth**)** — текст без переносов.
• **Максимальная ширина (**maxIntrinsicWidth**)** — текст в **одну строку**.
• **Минимальная высота (**minIntrinsicHeight**)** — высота текста при данной ширине.
• **Максимальная высота (**maxIntrinsicHeight**)** — высота при **минимальной ширине**.

**🚀 Пример использования интринзиков**


Представим, что у нас есть **кнопка с иконкой и текстом**, где:

• **Текст должен занимать минимум места.**
• **Иконка должна занимать ровно столько места, сколько нужно.**

**❌ Обычный Layout {} без интринзиков**
```kotlin
@Composable
fun CustomButton(text: String, icon: @Composable () -> Unit) {
    Layout(
        content = {
            icon()
            Text(text, fontSize = 16.sp)
        }
    ) { measurables, constraints ->
        // Измеряем иконку
        val iconPlaceable = measurables[0].measure(constraints)

        // Измеряем текст
        val textPlaceable = measurables[1].measure(constraints)

        // Итоговая ширина = иконка + текст
        val width = iconPlaceable.width + textPlaceable.width
        val height = maxOf(iconPlaceable.height, textPlaceable.height)

        layout(width, height) {
            iconPlaceable.place(0, (height - iconPlaceable.height) / 2)
            textPlaceable.place(iconPlaceable.width, (height - textPlaceable.height) / 2)
        }
    }
}
```

🔴 **Проблема:** если текст длинный, он **может обрезаться** или **занять слишком много места**.

**✅ Решение: используем интринзики**

```kotlin
@Composable
fun CustomButtonWithIntrinsics(text: String, icon: @Composable () -> Unit) {
    Layout(
        content = {
            icon()
            Text(text, fontSize = 16.sp)
        }
    ) { measurables, constraints ->

        // Используем интринзики для текста
        val textMinWidth = measurables[1].minIntrinsicWidth(constraints.maxHeight)
        
        // Измеряем иконку и текст
        val iconPlaceable = measurables[0].measure(constraints)
        val textPlaceable = measurables[1].measure(constraints.copy(minWidth = textMinWidth))

        // Итоговая ширина = иконка + текст
        val width = iconPlaceable.width + textPlaceable.width
        val height = maxOf(iconPlaceable.height, textPlaceable.height)

        layout(width, height) {
            iconPlaceable.place(0, (height - iconPlaceable.height) / 2)
            textPlaceable.place(iconPlaceable.width, (height - textPlaceable.height) / 2)
        }
    }
}
```

✅ **Что изменилось?**

• Теперь **текст минимально сжимается**, а иконка остается неизменной.
• **Размер кнопки адаптируется к контенту**.

**📌 Когда использовать интринзики?**

✅ **Если размер родителя зависит от детей**.
✅ **Если дочерние элементы не должны сами себя измерять сразу**.
✅ **Если нужно адаптировать UI к динамическому контенту (например, текст)**.


## **🔥 Кто использует SubcomposeLayout под капотом?**
**🔹 1. LazyColumn / LazyRow (и другие Lazy списки)**
**🔹 2. ConstraintLayout (из compose.constraintlayout)**
**🔹 3. BoxWithConstraints**
**🔹 4. Pager (из Accompanist Pager и Compose Foundation 1.3.0+)**

**Где используется** SubcomposeLayout**?**

| **Компонент**          | **Почему использует** SubcomposeLayout**?** |
| ---------------------- | ------------------------------------------- |
| LazyColumn / LazyRow   | Ленивое измерение и композиция списка       |
| ConstraintLayout       | Измерение зависимых элементов               |
| BoxWithConstraints     | Динамическое измерение размеров экрана      |
| Pager (из Accompanist) | Ленивый ViewPager для Compose               |

> [!warning] Цена SubcomposeLayout
> `SubcomposeLayout` делает композицию в **две фазы** (сначала измеряем, потом докомпозируем), что **дороже** обычного `Layout`. Не используйте его, когда хватает `Layout` или `BoxWithConstraints`. Он оправдан только если для размещения одного элемента действительно нужно сначала измерить другой.

> [!tip] Layout vs SubcomposeLayout — на собесе
> - **`Layout`** — композиция и измерение в один проход; стандартный способ кастомного лейаута.
> - **`SubcomposeLayout`** — позволяет отложить композицию части детей до тех пор, пока не измерены другие. Цена — вторая фаза.
> - **Интринзики** (`minIntrinsicWidth` и т.п.) — способ узнать «желаемый» размер ребёнка **без** полноценного measure, часто закрывают задачу без `SubcomposeLayout`.
