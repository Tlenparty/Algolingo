# Flow vs SharedFlow vs StateFlow

В Kotlin есть три основных типа потоков:

- **Flow** — холодный (cold) поток **без кеша**: каждый подписчик запускает поток заново и получает значения с начала.
- **SharedFlow** — горячий (hot) поток для многих подписчиков, **без сохранённого состояния** (если `replay = 0`).
- **StateFlow** — горячий (hot) поток, **всегда хранящий последнее значение** (state).

## 1. Flow — холодный поток (cold stream)

- Каждый подписчик начинает с нуля.
- Не запоминает прошлые значения.
- Тело `flow { }` запускается заново для **каждого** подписчика.
- Один подписчик = один запуск.

```kotlin
fun numbersFlow(): Flow<Int> = flow {
    for (i in 1..3) {
        delay(100)
        emit(i)
    }
}

scope.launch {
    numbersFlow().collect { println(it) } // 1, 2, 3
}

scope.launch {
    delay(150)                            // поздний подписчик
    numbersFlow().collect { println(it) } // снова с начала: 1, 2, 3
}
```

**Вывод в консоль:**

```text
1
2
3
1
2
3
```

Каждый подписчик начинает поток заново.

## 2. SharedFlow — горячий поток для многих подписчиков

- Может иметь **несколько подписчиков**, всем приходит одно и то же значение.
- Может накапливать прошлые значения (`replay`).
- Может буферизовать (`extraBufferCapacity`, `onBufferOverflow`).
- Если подписчиков нет, значение **теряется** (при `replay = 0`).

```kotlin
val sharedFlow = MutableSharedFlow<Int>()

scope.launch {
    sharedFlow.emit(1) // нет подписчиков → значение пропадёт
}

scope.launch {
    delay(100)
    sharedFlow.collect { println(it) } // подписался поздно → 1 не получит
}
```

**Вывод:** ничего (значение `1` потеряно, т.к. `replay = 0`).

## 3. StateFlow — хранит последнее состояние (аналог LiveData)

- Всегда хранит **последнее значение** (доступно через `.value`).
- Новый подписчик **сразу получает текущее состояние** при подписке.
- Работает только с одним значением (без `replay`, без буфера).
- Эмитит только **различающиеся** значения (сравнение через `equals`) — повторное присвоение того же значения подписчиков не разбудит.

```kotlin
val stateFlow = MutableStateFlow(0) // начальное значение 0

scope.launch {
    delay(100)
    stateFlow.value = 1 // обновили состояние
}

scope.launch {
    delay(200)
    stateFlow.collect { println(it) } // сразу получит актуальное: 1
}
```

## Отличия SharedFlow и StateFlow

| Свойство                                  | SharedFlow                            | StateFlow                      | Flow                              |
| ----------------------------------------- | ------------------------------------- | ------------------------------ | --------------------------------- |
| Сохраняет последнее значение?             | ❌ Нет (если `replay = 0`)            | ✅ Да (через `.value`)         | ❌ Нет                            |
| Новые подписчики получают прошлые данные? | 🔹 Только если `replay > 0`           | ✅ Да, текущий `value` сразу    | ✅ Да, но поток начинается заново  |
| Значения теряются без подписчиков?        | Да (если `replay = 0`)                | Нет (всегда хранит `value`)    | Нет (ждёт `collect`)              |
| Буфер / реплей прошлых значений           | ✅ `replay` и `extraBufferCapacity`   | ❌ Нет (только 1 значение)     | ❌ Нет                            |
| Дедупликация одинаковых значений          | ❌ Нет                                | ✅ Да (по `equals`)            | ❌ Нет                            |
| Горячий или холодный?                     | 🔥 Горячий                            | 🔥 Горячий                     | ❄️ Холодный                       |
| Где использовать?                         | События (навигация, тосты, сигналы)   | Состояние UI (аналог LiveData) | Запросы API, datasource, датчики  |

## Как они работают под капотом

**SharedFlow** — буферизованный многопоточный «вещатель»: хранит список подписчиков и буфер значений; при `replay > 0` последние значения сохраняются для новых подписчиков.

**StateFlow** — по сути частный случай `SharedFlow`:

```kotlin
MutableSharedFlow(
    replay = 1,
    extraBufferCapacity = 0,
    onBufferOverflow = BufferOverflow.DROP_OLDEST,
)
```

Всегда хранит ровно одно последнее значение, при обновлении `value` заменяет предыдущее и не теряет состояние (`replay = 1`), плюс отсекает повторы.

> [!tip] Что отвечать на собесе
> - **`StateFlow`** — для **состояния** экрана (всегда есть актуальное значение, есть `.value`, дедуп одинаковых значений).
> - **`SharedFlow`** — для **одноразовых событий** (показать тост, навигация): их нельзя «хранить как состояние», иначе они повторятся при повороте экрана. Обычно `replay = 0`.
> - **`Flow`** — для **источника данных** (сеть, БД, Room возвращает `Flow`): холодный, перезапускается на каждого подписчика.
> - Превратить холодный `Flow` в горячий, разделяемый между подписчиками, можно через `.stateIn(...)` / `.shareIn(...)`.
