В Android существует несколько способов передачи данных между фрагментами. Эти способы зависят от контекста, в котором нужно передавать данные, и от того, как организована архитектура приложения. Рассмотрим наиболее популярные и эффективные методы передачи данных между фрагментами:

**1. Использование Bundle для передачи данных через ==setArguments()**==

Этот способ используется для передачи данных **при создании** фрагмента, до его отображения на экране. Данные передаются через объект Bundle и можно получить их внутри фрагмента с помощью метода getArguments().

**Пример:**
```kotlin
// Отправка данных в фрагмент
val fragment = MyFragment()
val bundle = Bundle()
bundle.putString("key", "Hello, Fragment!")
fragment.arguments = bundle

// Получение данных внутри фрагмента
class MyFragment : Fragment() {
    override fun onCreateView(
        inflater: LayoutInflater, container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View? {
        val value = arguments?.getString("key")
        return inflater.inflate(R.layout.fragment_my, container, false)
    }
}
```

**2. Использование FragmentResult API**

Этот механизм был введен в **AndroidX** и позволяет передавать данные между фрагментами с использованием методов ==*setFragmentResult()*== и ==*setFragmentResultListener()*==. Это удобный и современный способ обмена данными между фрагментами без использования устаревших методов, таких как ==startActivityForResult()==.

**Пример:**

```kotlin
// Отправка данных
class SenderFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        val result = Bundle().apply {
            putString("resultKey", "Hello from SenderFragment!")
        }

        parentFragmentManager.setFragmentResult("requestKey", result)
    }
}

// Получение данных
class ReceiverFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        parentFragmentManager.setFragmentResultListener("requestKey", viewLifecycleOwner) { key, bundle ->
            val result = bundle.getString("resultKey")
            Log.d("ReceiverFragment", "Received result: $result")
        }
    }
}
```

**3. Использование ViewModel**

ViewModel — это компонент архитектуры Android, который предназначен для хранения данных, которые должны пережить изменения конфигурации (например, повороты экрана). Вы можете использовать одну и ту же ViewModel для нескольких фрагментов, если они находятся в пределах одной активности. Это позволяет передавать данные между фрагментами без необходимости использования Bundle.
```kotlin
// Создаем ViewModel
class SharedViewModel : ViewModel() {
    val selectedItem = MutableLiveData<String>()
}

// В SenderFragment
class SenderFragment : Fragment() {
    private lateinit var sharedViewModel: SharedViewModel

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        sharedViewModel = ViewModelProvider(requireActivity()).get(SharedViewModel::class.java)

        val button: Button = view.findViewById(R.id.send_button)
        button.setOnClickListener {
            sharedViewModel.selectedItem.value = "Hello from SenderFragment!"
        }
    }
}

// В ReceiverFragment
class ReceiverFragment : Fragment() {
    private lateinit var sharedViewModel: SharedViewModel

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        sharedViewModel = ViewModelProvider(requireActivity()).get(SharedViewModel::class.java)

        sharedViewModel.selectedItem.observe(viewLifecycleOwner, Observer {
            // Данные, переданные из SenderFragment
            Log.d("ReceiverFragment", "Received result: $it")
        })
    }
}
```

**4. Использование Activity как посредника**
Если фрагменты находятся в одной активности, можно использовать активность как посредника для хранения и передачи данных между фрагментами. Это делается через методы активности, которые вызываются фрагментами.

**Пример:**
```kotlin
// В Activity
class MainActivity : AppCompatActivity() {
    private val data = "Hello from Activity!"

    fun getData(): String {
        return data
    }
}

// В SenderFragment
class SenderFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        val activityData = (requireActivity() as MainActivity).getData()
        Log.d("SenderFragment", activityData)
    }
}

// В ReceiverFragment
class ReceiverFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        val activityData = (requireActivity() as MainActivity).getData()
        Log.d("ReceiverFragment", activityData)
    }
}
```

**5. Использование SharedPreferences**

Если нужно хранить небольшие объемы данных между фрагментами или сохранить данные, которые должны быть доступны при перезапуске приложения, можно использовать SharedPreferences. Это более глобальный способ обмена данными между фрагментами, так как данные хранятся в виде пар “ключ-значение”.

```kotlin
// В SenderFragment
class SenderFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        val sharedPreferences = requireActivity().getSharedPreferences("MyPrefs", Context.MODE_PRIVATE)
        val editor = sharedPreferences.edit()
        editor.putString("key", "Hello from SenderFragment!")
        editor.apply()
    }
}

// В ReceiverFragment
class ReceiverFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        val sharedPreferences = requireActivity().getSharedPreferences("MyPrefs", Context.MODE_PRIVATE)
        val data = sharedPreferences.getString("key", "Default value")
        Log.d("ReceiverFragment", "Received data: $data")
    }
}
```

## Где хранится Bundle? 

**Shared Memory (Разделяемая память)** — это участок памяти, к которому могут одновременно обращаться несколько процессов. В Android и других операционных системах это один из способов организации **межпроцессного взаимодействия (IPC, Inter-Process Communication)**, позволяющий передавать данные между процессами без необходимости их копирования.

**📂 1. Как работает Shared Memory?**

**🔍 Основной принцип:**

• Операционная система выделяет участок памяти, доступный нескольким процессам.
• Процессы могут **читать и записывать** данные в эту область напрямую.
• Доступ к памяти организован через специальные механизмы синхронизации (например, **mutex**, **semaphore**) для избежания конфликтов.

**🧠 2. Shared Memory в Android: Где используется?**

**🔑 Binder (Основной IPC в Android):**

• Binder использует Shared Memory для передачи данных между процессами.
• Например, когда вы передаёте Bundle через Intent в Service, данные сериализуются в Parcel, который затем помещается в Shared Memory через Binder.
  

**📦 Ashmem (Anonymous Shared Memory):**

• Специализированный механизм в Android для выделения разделяемой памяти.
• Чаще всего используется при работе с **графическими буферами** (например, в **SurfaceFlinger**)
• Поддерживает автоматическое освобождение памяти, если процесс, её использующий, завершился.

  
**📲 SharedMemory API (начиная с Android 8.0, API 26):**

• Позволяет создавать и использовать разделяемую память в Java/Kotlin.
• Использует MemoryFile для работы с байтовыми буферами.

```kotlin
import android.os.SharedMemory
import java.nio.ByteBuffer

val sharedMemory = SharedMemory.create("shared_memory", 1024) // 1KB памяти
val buffer: ByteBuffer = sharedMemory.mapReadWrite()

// Запись данных
buffer.putInt(42)

// Чтение данных (например, из другого процесса)
buffer.position(0)
val value = buffer.getInt() // 42
```

> [!tip] Что выбрать на собесе
> - **Аргументы при создании фрагмента** → `Bundle` через `arguments` (или `by navArgs()` в Navigation Component). Лимит транзакции Binder ~1 МБ — большие данные через Bundle не передают.
> - **Результат с дочернего экрана** (диалог, выбор) → **Fragment Result API** (`setFragmentResult`/`setFragmentResultListener`) — современная замена `startActivityForResult`/таргет-фрагментам.
> - **Общее состояние нескольких фрагментов одной Activity** → **shared ViewModel** через `by activityViewModels()` (вместо `ViewModelProvider(requireActivity())`).
> - ⚠️ **Activity как посредник** (каст `requireActivity() as MainActivity`) и **SharedPreferences** для передачи между фрагментами — **антипаттерны**: жёсткая связанность / неподходящий инструмент. SharedPreferences — для настроек, а не для коммуникации экранов.
