# 03 SQL: SELECT, JOIN, GROUP BY

Три запроса, которые бэкендер пишет каждый день: выборка с фильтром, соединение двух таблиц, сводка по группам. Диалект — PostgreSQL. Про базы в целом — [[08 Базы данных]].

Урок: `bk5.1` на вкладке Backend. Таблицы в примерах: `users(id, name, city)` и `orders(id, user_id, amount, created_at)`.

## Порядок выполнения

SQL читается не сверху вниз. База выполняет части запроса в таком порядке:

```text
FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

Отсюда главные правила:

- `WHERE` работает до группировки, поэтому не видит агрегаты. `WHERE SUM(amount) > 100` — ошибка.
- `HAVING` работает после `GROUP BY` и фильтрует уже группы.
- Псевдоним из `SELECT` (`AS total`) виден в `ORDER BY`, но не в `WHERE`.

## Выборка с фильтром

```sql
SELECT name, city
FROM users
WHERE city = 'Москва'
ORDER BY name
LIMIT 10;
```

- `WHERE` оставляет строки, для которых условие истинно. Строки — в одинарных кавычках.
- `ORDER BY name` — сортировка; `DESC` — по убыванию.
- `LIMIT 10` — первые десять после сортировки. Без `ORDER BY` порядок не гарантирован.

## Соединение

```sql
SELECT o.id, u.name, o.amount
FROM orders o
JOIN users u ON u.id = o.user_id
WHERE o.amount > 1000;
```

- `JOIN … ON` — какие строки двух таблиц считать парой. Здесь пара — заказ и его пользователь: `u.id = o.user_id`.
- `JOIN` (он же `INNER JOIN`) оставляет только пары. `LEFT JOIN` оставляет все строки левой таблицы, а справа подставляет `NULL`, если пары нет.
- `o` и `u` — псевдонимы таблиц, чтобы не писать `orders.user_id`.

> [!question]- Когда нужен LEFT JOIN?
> Когда правой стороны может не быть, а строку терять нельзя: «все пользователи и число их заказов, включая тех, у кого заказов нет».

## Группировка и агрегаты

```sql
SELECT u.city, COUNT(*) AS orders, SUM(o.amount) AS total
FROM orders o
JOIN users u ON u.id = o.user_id
GROUP BY u.city
HAVING SUM(o.amount) > 10000
ORDER BY total DESC;
```

- `GROUP BY u.city` — одна строка результата на город.
- Агрегаты: `COUNT(*)` — сколько строк в группе, `SUM`, `AVG`, `MIN`, `MAX`. `COUNT(column)` не считает `NULL`.
- Всё, что в `SELECT` не агрегат, обязано стоять в `GROUP BY`. Иначе Postgres откажет: «column must appear in the GROUP BY clause».
- `HAVING` фильтрует группы по агрегату. Условие на отдельные строки (`o.amount > 100`) ставят в `WHERE`, до группировки: так меньше строк дойдёт до `GROUP BY`.

## ⚠️ Грабли

- `WHERE` с агрегатом: «aggregate functions are not allowed in WHERE». Нужен `HAVING`.
- `GROUP BY` вместо `ORDER BY`: без агрегатов схлопнет одинаковые значения и потеряет строки.
- `ON u.id = o.id` — сравнил id пользователя с номером заказа: случайные пары вместо связи.
- Колонка не из той таблицы: `u.user_id` — «column u.user_id does not exist».
- `LIMIT` без `ORDER BY` — «первые 10» каждый раз разные.
- `COUNT(*)` и `COUNT(o.amount)` совпадают только пока `amount` не бывает `NULL`.
- `AVG` вместо `SUM`: средний чек вместо оборота — числа правдоподобные, ошибка незаметна.
