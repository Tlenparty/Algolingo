# Оптимизация Compose

## Типовые приёмы

1. **Стабильность типов** — `@Immutable`, `@Stable`, `data class`, `sealed class`. Стабильный тип позволяет Compose **пропускать** рекомпозицию.
2. **Эквивалентность** — корректный `equals` (например, `data class SimpleText(val value: String)`), чтобы Compose видел, что значение не изменилось.
3. **Обёртки над нестабильными типами** — если чужой SDK не даёт гарантий стабильности, оборачиваем его в свой стабильный тип.

> [!tip] Главные принципы оптимизации (на собес)
> 1. **Defer reads** — читай состояние как можно ниже по дереву (передавай лямбду `() -> State`, а не само значение).
> 2. **Стабильность** — Compose пропускает рекомпозицию только для стабильных параметров. Проверяй отчёт компилятора (compiler metrics: `stable`/`unstable`/`skippable`).
> 3. **Анимации и частые изменения** — выноси на фазы Layout/Draw (`graphicsLayer`, `drawBehind`), чтобы не триггерить Composition.
> 4. **Не создавай объекты в теле composable** (новые лямбды/списки на каждой рекомпозиции) — оборачивай в `remember`.
> 5. **`key()` в списках** и стабильные `key` в `LazyColumn` — чтобы Compose переиспользовал узлы.
