## Collection

**1. Collection (например, List, Set, Map)**

**Особенности:**

• Коллекции в Kotlin хранят данные в памяти.
• Все операции (например, map, filter) выполняются немедленно.
• Каждая операция ==создает новую коллекцию (eager evaluation).==

**Пример:**
```kotlin
val numbers = listOf(1, 2, 3, 4)
val doubled = numbers.map { it * 2 }.filter { it > 4 }
println(doubled) // [6, 8]
```

**Как работает под капотом:**

1. map создаёт новую промежуточную коллекцию ``[2, 4, 6, 8].``
2. filter создаёт ещё одну коллекцию ``[6, 8].``
3. Итого — две промежуточные коллекции.

**Когда использовать:**

• Когда коллекция небольшая.
• Когда важна предсказуемость по памяти.
• Подходит для однократных вычислений.
## Sequence

**🚦 1. Основной принцип: Ленивость (Lazy Evaluation)**

• Sequence не выполняет операции (map, filter, flatMap и т.д.) до тех пор, пока не будет вызвана терминальная операция (например, toList(), first(), forEach()).

• Это достигается с помощью ленивого итератора (Iterator), который выполняет операции над элементами по мере их запроса.

**Как это реализовано под капотом:**

**3.1. Sequence и Iterator**

• Sequence — это интерфейс с единственным методом iterator(), который возвращает ``Iterator<T>.``

• Iterator определяет методы:
```kotlin
interface Iterator<T> {
    fun hasNext(): Boolean
    fun next(): T
}
```
==• Все операции (например, map, filter) возвращают новый Sequence, который оборачивает старый, формируя цепочку итераторов==

**3.2. Пример реализации map:**
```kotlin
fun <T, R> Sequence<T>.map(transform: (T) -> R): Sequence<R> = Sequence {
    val originalIterator = this.iterator()
    object : Iterator<R> {
        override fun hasNext() = originalIterator.hasNext()
        override fun next(): R {
            return transform(originalIterator.next())
        }
    }
}
```

• map создает новый Iterator, который применяет transform только при вызове next().

• Обработка происходит «на лету» — элемент за элементом.

**3.3. Пример реализации filter:**
```kotlin
fun <T> Sequence<T>.filter(predicate: (T) -> Boolean): Sequence<T> = Sequence {
    val originalIterator = this.iterator()
    object : Iterator<T> {
        var nextItem: T? = null
        var nextState: Int = -1 // -1 = не известно, 0 = нет элемента, 1 = есть элемент

        override fun hasNext(): Boolean {
            if (nextState == -1) calcNext()
            return nextState == 1
        }

        override fun next(): T {
            if (!hasNext()) throw NoSuchElementException()
            nextState = -1
            return nextItem as T
        }

        private fun calcNext() {
            while (originalIterator.hasNext()) {
                val item = originalIterator.next()
                if (predicate(item)) {
                    nextItem = item
                    nextState = 1
                    return
                }
            }
            nextState = 0
        }
    }
}
```

• filter тоже оборачивает Iterator, но с предикатом.

• Элементы проходят через предикат только при запросе следующего элемента.

**🧠 Основные преимущества:**

1. **Экономия памяти:** Нет промежуточных коллекций.
2. **Высокая производительность:** Операции прерываются, как только достигнут результат (например, first()).
3. **Поддержка бесконечных последовательностей:**
```kotlin
val naturals = generateSequence(1) { it + 1 }
println(naturals.take(5).toList()) // [1, 2, 3, 4, 5]
```

## Stream

**🚦 1. Основной принцип: Ленивые вычисления (Lazy Evaluation)**

• Stream в Java также использует ленивые вычисления, откладывая выполнение операций (map, filter, flatMap) до вызова терминальной операции (collect, forEach, reduce и т.д.).

• Однако в отличие от Sequence, Stream использует концепцию “Source → Intermediate Operations → Terminal Operation”.

**🛠️ 2. Как это реализовано под капотом:**


**2.1. Компоненты Stream:**

• **Источник (Source):** Начало стрима (например, List.stream(), Stream.of(), Files.lines()).

• **Промежуточные операции (Intermediate Operations):** map, filter, sorted — возвращают новый Stream, ленивые.

• **Терминальные операции (Terminal Operations):** collect, forEach, reduce — запускают вычисления, могут быть “потребляющими” (consume stream).

**🛠️ 3. Как это работает внутри:**

**3.1. StreamPipeline:**

• Stream строит “конвейер” (Pipeline) из операций.

• Промежуточные операции не создают новых коллекций, а добавляют шаг в конвейер.


**3.2. Важные классы:**

• ReferencePipeline: основа для большинства операций.

• StreamOpFlag: определяет характеристики потока (например, SIZED, SORTED, DISTINCT).

• Spliterator: используется для итерации данных, особенно важен при параллельных потоках.

**🚀 5. Параллельные потоки (parallelStream()):**
```java
numbers.parallelStream()
    .map(n -> n * 2)
    .filter(n -> n > 4)
    .forEach(System.out::println);
```

• Использует ForkJoinPool.commonPool(), что позволяет обрабатывать данные в нескольких потоках.
• Параллелизм может ускорить обработку на больших объёмах данных.
• Порядок выполнения может измениться, нужно использовать forEachOrdered, если важен порядок.

---

**🧠 Заключение:**

• Stream в Java использует концепцию “конвейера” (Pipeline), где операции выстраиваются в цепочку.

• Работает лениво, но не поддерживает многократное использование.

• Отличается поддержкой параллельных потоков (parallelStream()), что даёт преимущество при работе с большими данными.

• По сравнению с Kotlin Sequence, Stream более гибок в многопоточности, но требует осторожности с ресурсами (например, Stream из IO ресурсов нужно закрывать).

> [!tip] Collection vs Sequence — когда что (на собесе)
> - **Collection (eager):** каждая операция (`map`, `filter`) сразу создаёт **новую коллекцию** и проходит **все** элементы. Для маленьких коллекций — нормально и даже быстрее (меньше накладных расходов).
> - **Sequence (lazy):** операции выполняются **поэлементно по цепочке** и только при терминальной операции; промежуточных коллекций нет. Выгодно на **больших данных**, длинных цепочках операций и с ранним выходом (`first`, `take`, `find`).
>
> Пример разницы:
> ```kotlin
> // Collection: проходит ВСЕ 1_000_000, потом фильтрует, потом берёт первый
> list.map { it * 2 }.filter { it > 10 }.first()
> // Sequence: остановится на первом подходящем элементе
> list.asSequence().map { it * 2 }.filter { it > 10 }.first()
> ```
> Не оборачивай в `asSequence()` маленькие списки или одиночные операции — выигрыша не будет, а накладные расходы есть.
