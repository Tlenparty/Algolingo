# 🪜 Движок «маркеры и дырки» — лестница из 5 шагов

> Этот файл — про **один приём**, который закрывает кинотеатр, лучший спортивный период без пропусков, «расстояние до ближайшей заправки» и ещё десяток задач с собесов.
> Проходить строго по порядку, **один шаг = одно занятие**. Каждый шаг меняет ровно одну деталь по сравнению с предыдущим — если прошёл шаг N, шаг N+1 пишется дописыванием 2–3 строк.
> Правило прежнее: **сначала пишешь сам, потом раскрываешь спойлер.**

## 🧠 Главная идея (прочитай два раза)

Во всех этих задачах массив состоит из **маркеров** и **промежутков между ними**.

- Маркер — это то, что «рвёт» ряд: занятое кресло `1`, день пропуска, заправка, снижение веса.
- Дырка — непрерывный кусок между двумя соседними маркерами.

```text
индексы:   0  1  2  3  4  5  6  7
массив:  [ 0, 0, 1, 0, 0, 0, 1, 0 ]
              ↑        ↑        ↑
          левый     средняя    правый
           край      дырка      край
```

**Дырок ровно три вида, и это весь ответ на задачу:**

| Вид            | Когда возникает                    | Чем особенна                                          |
| -------------- | ---------------------------------- | ----------------------------------------------------- |
| **левый край** | до первого маркера                 | сосед только справа → слева «стенка»                  |
| **средняя**    | между двумя маркерами              | соседи с обеих сторон                                  |
| **правый край**| после последнего маркера           | сосед только слева → справа «стенка»                  |

Почти все провалы на собесе — это **не** ошибка в математике, а **забытый край**. Ты обрабатываешь средние дырки внутри цикла и не замечаешь, что хвост после последнего маркера цикл вообще не увидел.

### Скелет, который надо выучить наизусть

```kotlin
var prev = -1                       // индекс предыдущего маркера; -1 = маркеров ещё не было
var best = 0                        // лучший ответ

for (i in a.indices) {
    if (!маркер(a[i])) continue     // работаем ТОЛЬКО на маркерах

    if (prev == -1) {
        // ветка 1: закрылся ЛЕВЫЙ КРАЙ — дырка [0 .. i-1]
    } else {
        // ветка 2: закрылась СРЕДНЯЯ дырка [prev+1 .. i-1]
    }
    prev = i                        // маркер стал предыдущим
}

// ветка 3: ПРАВЫЙ КРАЙ — дырка [prev+1 .. n-1]. Только ПОСЛЕ цикла, цикл её не видел.
```

Три ветки. Всегда три. Дальше вся лестница — про то, чем их заполнять.

# Шаг 1 — Самая длинная серия (только длина)

Дан `IntArray` из `0/1`: `1` — в этот день была тренировка, `0` — пропуск.
Верни **длину** самого длинного периода без пропусков.

```text
[1,1,0,1,1,1,0,1] -> 3
[0,0,0]           -> 0
[1,1,1]           -> 3
```

- 🎯 **Тренируем:** «текущее» и «лучшее» — две отдельные переменные. База всего остального.
- ⏱ **Цель:** 3 минуты.

> [!question]- 💡 Подсказка
> `cur` растёт на единичке и **обнуляется** на нуле. `best` только растёт и никогда не обнуляется. Обновлять `best` надо в тот же момент, когда растёт `cur`, — иначе серия, дошедшая до конца массива, потеряется.

> [!success]- ✅ Решение
> ```kotlin
> fun longestStreak(days: IntArray): Int {
>     var best = 0
>     var cur = 0
>
>     for (x in days) {
>         if (x == 1) {
>             cur++
>             if (cur > best) best = cur   // сравниваем СРАЗУ, а не после обрыва
>         } else {
>             cur = 0                      // пропуск рвёт серию
>         }
>     }
>     return best
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:** если обновлять `best` только в ветке `else` (на обрыве), то на `[1,1,1]` вернётся `0` — серия не оборвалась ни разу. Это ошибка №1 всей темы: **ответ на «самый длинный» известен только после полного прохода.**

**Прогон руками** на `[1,1,0,1,1,1,0,1]`:

```text
i:    0   1   2   3   4   5   6   7
x:    1   1   0   1   1   1   0   1
cur:  1   2   0   1   2   3   0   1
best: 1   2   2   2   2   3   3   3   -> 3
```

# Шаг 2 — Та же серия, но верни ГРАНИЦЫ

Тот же массив. Верни `Pair(начало, конец)` самого длинного периода без пропусков, или `null`, если тренировок не было. При равенстве длин — **самый левый**.

```text
[1,1,0,1,1,1,0,1] -> Pair(3, 5)
[0,0,0]           -> null
[1,1,0,1,1]       -> Pair(0, 1)   // ничья → левый
```

- 🎯 **Тренируем:** вернуть **позицию**, а не значение. Ради этого появляется якорь `curStart`.
- ⏱ **Цель:** 6 минут.

> [!question]- 💡 Подсказка 1
> Счётчика `cur` уже мало: длина не говорит, **где** серия началась. Заведи `curStart` — индекс начала текущей серии. Длина тогда считается сама: `i - curStart + 1`.

> [!question]- 💡 Подсказка 2
> `curStart` ставится **один раз**, когда серия только началась (то есть когда `curStart == -1`), и сбрасывается в `-1` на пропуске. Если ставить его на каждой единичке — серия будет вечно длиной 1.

> [!success]- ✅ Решение
> ```kotlin
> fun longestStreakRange(days: IntArray): Pair<Int, Int>? {
>     var bestStart = -1
>     var bestLen = 0
>     var curStart = -1                  // -1 = серия сейчас не идёт
>
>     for (i in days.indices) {
>         if (days[i] == 0) {
>             curStart = -1              // пропуск: серия закрыта
>             continue
>         }
>         if (curStart == -1) curStart = i          // серия только что началась
>         val len = i - curStart + 1
>         if (len > bestLen) {           // строгий > → при ничьей остаётся левый
>             bestLen = len
>             bestStart = curStart
>         }
>     }
>
>     return if (bestLen == 0) null else Pair(bestStart, bestStart + bestLen - 1)
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:**
> 1. Вернуть `bestLen` вместо пары индексов — контракт просит **где**, а не **сколько**.
> 2. `if (curStart == -1) curStart = i` — без проверки якорь едет вправо на каждом шаге.
> 3. `bestEnd` держать отдельной переменной необязательно: конец = `bestStart + bestLen - 1`. Меньше переменных — меньше рассинхрона.
> 4. Нестрогое `>=` вместо `>` отдаст **правый** период при ничьей. На собесе спроси вслух, какой нужен.

> 🔗 Это ровно движок задач [[05 Тренажёр решений#2.10 Самый длинный период без снижения 🔥Яндекс|2.10]] и 2.11 — там вместо `days[i] == 1` стоит условие на соседей (`sum[i] >= sum[i-1]`), а всё остальное совпадает буква в букву.

# Шаг 3 — Переворот: самая длинная ДЫРКА

Тот же массив `0/1`, но теперь `1` — это **маркер** (занятое кресло / заправка), а интересуют нас нули между ними.
Верни **длину** самой длинной непрерывной дырки из нулей. Края считаются тоже.

```text
[0,0,1,0,0,0,1,0] -> 3
[1,1,1]           -> 0
[0,0,0]           -> 3     // маркеров нет — вся строка одна дырка
[1,0,0]           -> 2
```

- 🎯 **Тренируем:** тот самый скелет с `prev`. Считать надо **не нули**, а расстояния между маркерами.
- ⏱ **Цель:** 7 минут.

> [!warning] Условие тренировки
> Решить это счётчиком нулей (как в шаге 1) — легко, но **не засчитывается**. Пиши через `prev`: в шаге 4 счётчик работать перестанет, а `prev` — останется.

> [!question]- 💡 Подсказка 1
> Сколько нулей строго между маркерами на позициях `prev` и `i`? Возьми `[1,0,0,0,1]`, `prev = 0`, `i = 4`. Нулей три. Формула: `i - prev - 1`.

> [!question]- 💡 Подсказка 2
> Красивый трюк: стартовое `prev = -1` — это «воображаемый маркер перед массивом». Подставь его в ту же формулу: `i - (-1) - 1 = i` — ровно число ведущих нулей. **Левый край считается сам собой, отдельная ветка не нужна.**
> А вот правый край так не схлопнешь: воображаемого маркера справа нет. Его — руками после цикла: `n - prev - 1`.

> [!success]- ✅ Решение
> ```kotlin
> fun longestGap(a: IntArray): Int {
>     var prev = -1                     // «маркер» перед началом массива
>     var best = 0
>
>     for (i in a.indices) {
>         if (a[i] != 1) continue       // интересуют только маркеры
>
>         val gap = i - prev - 1        // нулей строго между prev и i
>         if (gap > best) best = gap    //   при prev = -1 это ведущие нули
>         prev = i
>     }
>
>     val tail = a.size - prev - 1      // хвост после последнего маркера
>     if (tail > best) best = tail      //   при prev = -1 это весь массив
>     return best
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли:** без строки `tail` массив `[1,0,0]` вернёт `0`. Хвостовые нули цикл **физически не может** увидеть: он реагирует только на маркеры, а справа их больше нет.

**Прогон** на `[0,0,1,0,0,0,1,0]`, `n = 8`:

```text
i=2 (маркер): gap = 2 - (-1) - 1 = 2   best=2   prev=2
i=6 (маркер): gap = 6 -   2  - 1 = 3   best=3   prev=6
после цикла:  tail = 8 -   6  - 1 = 1   best=3   -> 3
```

# Шаг 4 — Кинотеатр 🔥собес

`0` — свободное кресло, `1` — занятое. Гарантирован хотя бы один `0`. Надо сесть **максимально далеко от ближайшего занятого**. Верни **номер места** (нумерация с 1). При равенстве — самое левое.

```text
[1,0,1]         -> 2       [1,0,0,0,0,1] -> 3
[0,0,1]         -> 1       [1,0,0]       -> 3
[0,0,0]         -> 1
```

- 🎯 **Тренируем:** тот же скелет, но в дырке нас интересует **не длина, а лучшая точка внутри неё**. Здесь края и середина расходятся — и вот из-за этого задача валит людей.
- ⏱ **Цель:** 10 минут.

> [!question]- 💡 Подсказка 1 — почему шаг 3 напрямую не подходит
> В **средней** дырке соседи с двух сторон, поэтому садиться надо в середину: расстояние получается вдвое меньше длины, `(i - prev) / 2`.
> В **краевой** дырке сосед один, жаться к стенке можно вплотную: расстояние равно всей длине дырки.
> Значит, дырка длины 4 у стенки (`расстояние 4`) **лучше** средней дырки длины 5 (`расстояние 2`). Одной формулой это не покрыть → трюк с `prev = -1` из шага 3 здесь **не работает**, левый край пишем явной веткой.

> [!question]- 💡 Подсказка 2 — арифметика середины
> `[1,0,0,0,0,1]`: `prev = 0`, `i = 5`. Середина: `dist = (5 - 0) / 2 = 2`, место `prev + dist = 2`. Проверь руками: до левого занятого 2, до правого 3, ближайший — 2. ✅
> Чётная дырка `[1,0,0,0,1]`: `dist = (4 - 0) / 2 = 2`, место 2, до обоих ровно 2. Целочисленное деление вниз само даёт **левое** из двух одинаково хороших мест — как раз то, что просит условие.

> [!question]- 💡 Подсказка 3 — две переменные, не одна
> Нужны **и** `bestDist` (по нему сравниваем), **и** `bestPos` (его возвращаем). Классический провал — вернуть расстояние вместо номера места. И не забудь `+1` в самом конце: ответ 1-indexed.

> [!success]- ✅ Решение
> ```kotlin
> fun bestSeat(seats: IntArray): Int {
>     var prev = -1          // индекс последнего занятого кресла
>     var bestDist = -1      // лучшее расстояние до ближайшего соседа
>     var bestPos = 0        // индекс лучшего места (0-based)
>
>     for (i in seats.indices) {
>         if (seats[i] != 1) continue
>
>         if (prev == -1) {
>             // ЛЕВЫЙ КРАЙ: жмёмся к стенке, место 0, расстояние = i
>             if (i > bestDist) {           // при i == 0 дырки нет, и 0 > -1 безвредно
>                 bestDist = i
>                 bestPos = 0
>             }
>         } else {
>             // СРЕДНЯЯ ДЫРКА: садимся ровно посередине
>             val dist = (i - prev) / 2
>             if (dist > bestDist) {        // строгий > → при ничьей левое место
>                 bestDist = dist
>                 bestPos = prev + dist
>             }
>         }
>         prev = i
>     }
>
>     if (prev == -1) return 1              // занятых нет вообще — садимся на первое
>
>     // ПРАВЫЙ КРАЙ: хвостовые нули, жмёмся к последнему месту
>     val tail = seats.size - 1 - prev
>     if (tail > bestDist) bestPos = seats.size - 1
>
>     return bestPos + 1                    // контракт: номер места, нумерация с 1
> }
> ```
> **Сложность:** O(n) / O(1).
> ⚠️ **Грабли (по частоте на собесах):**
> 1. Забыт правый край → `[1,0,0]` вернёт 1 вместо 3.
> 2. Возвращён `bestDist` вместо `bestPos`.
> 3. Забыт `+1` → `[1,0,1]` вернёт 1 вместо 2.
> 4. `(i - prev) / 2` перепутано с `(i - prev - 1) / 2` — это длина дырки, а не расстояние до соседа. Проверяй на `[1,0,1]`: ответ должен быть `dist = 1`, место 1.
> 5. Не обработан случай «занятых нет» — `prev` так и остался `-1`, и `seats.size - 1 - prev` даст мусор.

**Прогон** на `[0,0,1,0,0,0,1,0]` (`n = 8`):

```text
i=2, prev=-1  ->  левый край:  dist = 2,  pos = 0    best=(2, 0)   prev=2
i=6, prev=2   ->  середина:    dist = (6-2)/2 = 2,  pos = 2+2 = 4
                  2 > 2? нет  -> не меняем (ничья, держим левое)   prev=6
после цикла:      правый край: tail = 7 - 6 = 1,  1 > 2? нет
ответ: bestPos 0 -> место 1
```

# Шаг 5 — Универсальный запасной вариант: два прохода

Дан массив: `1` — заправка, `0` — участок трассы. Верни массив `d`, где `d[i]` — расстояние от `i` до **ближайшей** заправки в любую сторону. Гарантирована хотя бы одна заправка.

```text
[1,0,0,0,0,1] -> [0,1,2,2,1,0]
[0,0,1]       -> [2,1,0]
```

- 🎯 **Тренируем:** приём «слева направо, потом справа налево». Он **дороже** по памяти, но в нём **нет краевых веток** — а значит, нет и главного источника ошибок.
- ⏱ **Цель:** 8 минут.

> [!question]- 💡 Подсказка 1
> Задача «ближайший в любую сторону» = два независимых вопроса: ближайший **слева** и ближайший **справа**. Ответ — минимум из двух. Каждый вопрос решается тривиальным проходом с одной переменной `last`.

> [!question]- 💡 Подсказка 2
> В первом проходе `last` — индекс последней встреченной заправки слева. Если её ещё не было (`last == -1`), позицию просто **не трогаем**: второй проход её закроет. Ставить `Int.MAX_VALUE` и потом делать `min` — работает, но легко словить переполнение при `+`; проще пропустить.

> [!success]- ✅ Решение
> ```kotlin
> fun distToNearestStation(a: IntArray): IntArray {
>     val n = a.size
>     val d = IntArray(n) { -1 }        // -1 = ещё не знаем
>
>     var last = -1
>     for (i in 0 until n) {            // ← проход слева направо
>         if (a[i] == 1) last = i
>         if (last != -1) d[i] = i - last
>     }
>
>     last = -1
>     for (i in n - 1 downTo 0) {       // ← проход справа налево
>         if (a[i] == 1) last = i
>         if (last != -1) {
>             val fromRight = last - i
>             if (d[i] == -1 || fromRight < d[i]) d[i] = fromRight
>         }
>     }
>     return d
> }
> ```
> **Сложность:** O(n) / O(n).
> ⚠️ **Грабли:** второй цикл — `for (i in n - 1 downTo 0)`, без `until`. `downTo` включает обе границы, `until` в обратном направлении вообще не работает.

**Прогон** на `[1,0,0,0,0,1]`:

```text
слева направо:  d = [0, 1, 2, 3, 4, 0]
справа налево:  d = [0, 1, 2, 2, 1, 0]     (позиции 3 и 4 стали ближе к правой заправке)
```

### Зачем это, если шаг 4 уже решён

Потому что **кинотеатр решается через это в три строки** — и на собесе, если паникуешь и путаешься в краях, пиши так:

```kotlin
fun bestSeatViaTwoPasses(seats: IntArray): Int {
    val d = distToNearestStation(seats)      // расстояние до ближайшего занятого
    var bestPos = 0
    var bestDist = -1
    for (i in seats.indices) {
        if (seats[i] == 1) continue          // занятые нам не подходят
        if (d[i] > bestDist) {               // строгий > → левое при ничьей
            bestDist = d[i]
            bestPos = i
        }
    }
    return bestPos + 1
}
```

Никаких трёх веток, никаких `(i - prev) / 2`. Цена — O(n) памяти вместо O(1). Интервьюер это принимает; после чего сам скажешь: «в один проход можно и за O(1) памяти» — и напишешь шаг 4. Это сильный ход: сначала рабочее решение, потом оптимизация.

## 🎯 Как узнать движок на собесе

Три сигнала — если хотя бы два совпали, пиши скелет с `prev`:

1. В условии есть **два состояния**: занято/свободно, тренировался/пропустил, есть заправка/нет.
2. Спрашивают про **непрерывный кусок** или **расстояние** — «самый длинный», «максимально далеко», «ближайший».
3. Ответ зависит только от **соседних** маркеров, а не от всего массива сразу.

Дальше по контракту выбираешь заполнение веток:

| Что просят                        | Внутри дырки считаем          | Ответ         |
| --------------------------------- | ----------------------------- | ------------- |
| длина серии                       | `i - curStart + 1`            | число         |
| границы серии                     | то же + якорь `curStart`      | `Pair`        |
| длина дырки                       | `i - prev - 1`                | число         |
| лучшая точка в дырке (кинотеатр)  | `(i - prev) / 2`, края особые | индекс + 1    |
| расстояние для каждой точки       | два прохода                   | массив        |

> ⚠️ **Не путать с задачей про k ближайших заправок** ([[05 Тренажёр решений#2.7 K ближайших заправок 🔥Яндекс|2.7]]). Там массив **отсортированных координат** и просят `k` штук вокруг точки — это движок «два указателя расходятся». Общее у задач только слово «заправка». Сигнал-различитель: здесь массив **признаков по позициям**, там — массив **координат**.
