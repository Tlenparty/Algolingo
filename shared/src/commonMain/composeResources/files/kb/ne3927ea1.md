**1. Как сервер управляет кэшированием через заголовки?**

Сервер может отправлять специальные **HTTP-заголовки**, чтобы сообщить клиенту, можно ли кэшировать ответ и на какой срок.

**Основные заголовки для кэширования**

1. **Cache-Control** – управляет кэшированием.
2. **ETag** – уникальный идентификатор версии ресурса.
3. **Last-Modified** – дата последнего изменения ресурса.
4. **Expires** – устаревший заголовок, заменён Cache-Control.


**2. Как сервер сообщает, что данные можно кэшировать?**

📌 **Пример ответа сервера с кэшем на 10 минут (600 секунд):**
```http
HTTP/1.1 200 OK
Cache-Control: public, max-age=600
ETag: "abc123"
Last-Modified: Tue, 27 Feb 2024 12:00:00 GMT
```

Здесь:

• max-age=600 – клиент может использовать кэшированные данные 10 минут.
• ETag: "abc123" – уникальный идентификатор версии данных.
• Last-Modified – указывает, когда ресурс последний раз изменялся.

**3. Как понять, что данные вернулись из кэша?**

Если клиент отправляет повторный запрос, сервер проверяет заголовки If-None-Match (с ETag) или If-Modified-Since (с Last-Modified).

📌 **Пример запроса с проверкой кэша (от клиента к серверу):**
```http
GET /data HTTP/1.1
If-None-Match: "abc123"
If-Modified-Since: Tue, 27 Feb 2024 12:00:00 GMT
```

Если данные **не изменились**, сервер вернёт ==**304 Not Modified** (без тела ответа)==, и клиент использует кэшированные данные.

📌 **Пример ответа, если кэш актуален:**
```http
HTTP/1.1 304 Not Modified
Cache-Control: public, max-age=600
ETag: "abc123"
```

Если данные **изменились**, сервер вернёт ==**200 OK** с новым содержимым==.


**4. Настройка кэша в OkHttp (Android)**

📌 **Шаг 1: Добавляем поддержку кэша**

OkHttp умеет автоматически кэшировать данные, если указать Cache-Control и настроить кэш.
```kotlin
val cacheSize = (10 * 1024 * 1024).toLong() // 10MB кэша
val cache = Cache(application.cacheDir, cacheSize)

val client = OkHttpClient.Builder()
    .cache(cache)
    .build()
```

Теперь OkHttp автоматически кэширует ответы, если сервер правильно отправляет заголовки.

📌 **Шаг 2: Отправляем запрос с кэшированием**

```kotlin
val request = Request.Builder()
    .url("https://api.example.com/data")
    .build()

val response = client.newCall(request).execute()

if (response.networkResponse != null) {
    println("Данные загружены с сервера")
} else if (response.cacheResponse != null) {
    println("Данные получены из кэша")
}

val body = response.body?.string()
println(body)
```

Здесь:

• response.networkResponse != null → данные с сервера.
• response.cacheResponse != null → данные из кэша.

📌 **Шаг 3: Принудительное использование кэша или игнорирование**

• **Только кэш (без интернета):**
```kotlin
val request = Request.Builder()
    .url("https://api.example.com/data")
    .cacheControl(CacheControl.FORCE_CACHE) // Используем кэш
    .build()
```

• **Принудительное обновление (обход кэша):**
```kotlin
val request = Request.Builder()
    .url("https://api.example.com/data")
    .cacheControl(CacheControl.FORCE_NETWORK) // Запрос с сервера
    .build()
```

📌 **Шаг 4: Проверка актуальности кэша (If-None-Match, ETag)**

Если сервер поддерживает ETag, OkHttp автоматически отправит If-None-Match, и сервер ответит 304 Not Modified, если данные не изменились.

Чтобы увидеть заголовки кэширования в ответе:
```kotlin
val cacheControl = response.header("Cache-Control")
val eTag = response.header("ETag")
println("Cache-Control: $cacheControl, ETag: $eTag")
```

**6. Итог**

1. **Backend** должен отправлять **Cache-Control**, **ETag** и **Last-Modified**.
2. **OkHttp** автоматически использует кэш, если сервер поддерживает заголовки.
3. Можно **форсировать кэш** (FORCE_CACHE) или **игнорировать его** (FORCE_NETWORK)
4. Если сервер вернул **304 Not Modified**, OkHttp использует данные из кэша.
