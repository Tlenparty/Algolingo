# Корутины + callback

В Android часто встречаются callback-ориентированные API (загрузка данных, обработка событий). Корутины позволяют обернуть такой API в удобный последовательный код.

## Преобразование Callback в корутину

Kotlin даёт две функции, чтобы «подвесить» корутину до вызова колбэка:

- `suspendCoroutine` — без поддержки отмены;
- `suspendCancellableCoroutine` — с поддержкой отмены (предпочтительнее).

### suspendCoroutine

Низкоуровневая функция: приостанавливает корутину и возобновляет её вручную позже. Даёт полный контроль над возобновлением — удобно для интеграции с callback-API.

```kotlin
suspend fun <T> suspendCoroutine(block: (Continuation<T>) -> Unit): T
```

- `T` — тип результата.
- `block` — лямбда, принимающая `Continuation<T>`.

Объект `Continuation<T>` управляет жизненным циклом приостановленной корутины:

- `resume(value: T)` — возобновить с результатом;
- `resumeWithException(exception: Throwable)` — возобновить с ошибкой.

**Как работает:**

1. При вызове `suspendCoroutine` корутина приостанавливается, управление уходит в `block`.
2. Объект `Continuation` можно сохранить и возобновить позже.
3. Как только вызван `resume` / `resumeWithException`, корутина продолжается с результатом или исключением.

**Оборачиваем callback-API:**

```kotlin
import kotlin.coroutines.suspendCoroutine
import kotlin.coroutines.resume
import kotlin.coroutines.resumeWithException

suspend fun getDataFromCallback(): String = suspendCoroutine { continuation ->
    simulateCallbackAPI { result, error ->
        if (error != null) {
            continuation.resumeWithException(error)
        } else {
            continuation.resume(result)
        }
    }
}

fun simulateCallbackAPI(callback: (String?, Throwable?) -> Unit) {
    Thread {
        Thread.sleep(1000) // имитация задержки
        callback("Result from API", null)
    }.start()
}

fun main() = kotlinx.coroutines.runBlocking {
    try {
        val result = getDataFromCallback()
        println("Получен результат: $result")
    } catch (e: Throwable) {
        println("Ошибка: ${e.message}")
    }
}
```

### suspendCancellableCoroutine

Если операцию можно отменить — используйте этот вариант. Он умеет реагировать на отмену корутины через `invokeOnCancellation`.

**Исходный callback:**

```kotlin
fun downloadFile(url: String, callback: (Boolean) -> Unit) {
    Thread {
        Thread.sleep(2000)
        callback(true)
    }.start()
}
```

**Преобразование:**

```kotlin
import kotlinx.coroutines.suspendCancellableCoroutine
import kotlin.coroutines.resume
import kotlin.coroutines.resumeWithException

suspend fun downloadFileAsync(url: String): Boolean =
    suspendCancellableCoroutine { continuation ->
        downloadFile(url) { success ->
            if (success) {
                continuation.resume(true)
            } else {
                continuation.resumeWithException(Exception("Download failed"))
            }
        }

        continuation.invokeOnCancellation {
            println("Download cancelled")
            // здесь отменяем реальный запрос / освобождаем ресурсы
        }
    }
```

**Преимущества корутин для callback:**

1. **Читаемость.** Асинхронные вызовы выглядят как синхронные.
2. **Обработка ошибок.** Обычный try-catch вместо колбэка с ошибкой.
3. **Отмена.** Корутину легко отменить, что важно для долгих операций.

## Зачем нужен suspendCancellableCoroutine

Он оборачивает асинхронные операции с **поддержкой отмены** — полезно для долгих задач (сеть, I/O, таймеры), которые пользователь может прервать.

**Что делает:**

1. **Обёртка асинхронных операций.** Превращает колбэки в suspend-функции.
2. **Поддержка отмены.** Через `invokeOnCancellation` корутина «слушает» отмену: при отмене можно прервать реальный запрос.
3. **Интеграция со старыми API.** Старый callback-API становится частью structured concurrency.

### Пример: сетевой запрос с колбэком

```kotlin
import kotlinx.coroutines.suspendCancellableCoroutine
import kotlin.coroutines.resume
import kotlin.coroutines.resumeWithException

suspend fun makeNetworkRequest(): String = suspendCancellableCoroutine { continuation ->
    val networkRequest = object : NetworkRequest() {
        override fun onSuccess(response: String) {
            continuation.resume(response)
        }
        override fun onFailure(error: String) {
            continuation.resumeWithException(Exception(error))
        }
    }

    networkRequest.start()

    continuation.invokeOnCancellation {
        networkRequest.cancel() // отменяем запрос при отмене корутины
    }
}
```

> [!warning] GlobalScope в примере
> Внутри `NetworkRequest.start()` для имитации удобно написать `GlobalScope.launch`, но в реальном коде так делать нельзя — корутина окажется вне дерева задач и не отменится. В проде здесь был бы реальный сетевой клиент (OkHttp `Call`), который и отменяется в `invokeOnCancellation`.
