# Динамическое программирование (основы)

**ДП (Dynamic Programming)** — решение задачи через разбиение на **перекрывающиеся подзадачи**, результаты которых **запоминаются**, чтобы не считать дважды. Превращает экспоненциальный перебор в полиномиальный.

## Когда применимо: два признака

> [!important] ДП работает, если есть оба свойства
> 1. **Оптimal substructure** — оптимальное решение строится из оптимальных решений подзадач.
> 2. **Overlapping subproblems** — одни и те же подзадачи встречаются многократно (иначе ДП не нужно — хватит «разделяй и властвуй»).
> Классический маркер: наивная рекурсия пересчитывает одно и то же (как Фибоначчи `fib(n-1)+fib(n-2)` → O(2^n)).

## Два стиля

```kotlin
// 1) Top-down: рекурсия + memoization (запоминаем посчитанное)
fun fib(n: Int, memo: HashMap<Int, Long> = HashMap()): Long {
    if (n < 2) return n.toLong()
    memo[n]?.let { return it }
    val res = fib(n - 1, memo) + fib(n - 2, memo)
    memo[n] = res
    return res
}

// 2) Bottom-up: таблица, считаем от базовых случаев вверх
fun fibTab(n: Int): Long {
    if (n < 2) return n.toLong()
    var a = 0L; var b = 1L
    repeat(n - 1) { val c = a + b; a = b; b = c }
    return b                       // O(n) время, O(1) память
}
```

> [!tip] Top-down vs Bottom-up
> • **Top-down (мемоизация)** — пишется как обычная рекурсия + кэш; проще вывести из наивного решения, считает только нужные подзадачи. Риск `StackOverflow` на большой глубине.
> • **Bottom-up (табуляция)** — цикл по таблице, без рекурсии; часто позволяет **оптимизировать память** (хранить только последние состояния, как в `fibTab` — O(1) вместо O(n)).

## Как подходить к ДП-задаче (рецепт для собеса)

> [!info] Шаги
> 1. **Определить состояние** — что описывает подзадачу (`dp[i]` = ответ для префикса длины i / для суммы i).
> 2. **Рекуррента** — как `dp[i]` выражается через предыдущие (`dp[i] = dp[i-1] + dp[i-2]`).
> 3. **Базовые случаи** — `dp[0]`, `dp[1]`.
> 4. **Порядок вычисления** — bottom-up по возрастанию.
> 5. **Оптимизация памяти** — нужны ли все состояния или хватит последних k.

## Классические задачи

> [!note] Что узнавать
> • 1D: Фибоначчи, climbing stairs, house robber, **knapsack** (рюкзак), coin change.
> • Строки: **LCS** (наибольшая общая подпоследовательность), edit distance (расстояние Левенштейна), longest palindromic substring.
> • 2D-сетки: unique paths, min path sum.
> Сигнал «это ДП»: «сколько способов», «минимум/максимум по последовательности выборов», «можно ли набрать сумму» — и наивное решение перебирает экспоненту.

> [!warning] ДП ≠ всегда лучший выбор
> Если у задачи нет перекрывающихся подзадач — ДП не ускорит. Иногда **жадный** алгоритм (greedy) даёт O(n) там, где ДП O(n²), но greedy верен **не всегда** (нужно доказать). DFS/[[Поиск в глубину (DFS)|backtracking]] — когда нужно перечислить решения, а не посчитать оптимум.
