# 01 Словарь Spring

Слова, которые встречаются в уроках трека Backend. Сначала короткая расшифровка, потом что это значит на практике. Сетевые и инфраструктурные термины — в [[00 Словарь терминов]].

## Spring и Spring Boot

- **Spring** — самый распространённый фреймворк для серверов на JVM. Главная идея: ты пишешь классы, а Spring сам их создаёт, связывает между собой и вызывает при HTTP-запросе.
- **Spring Boot** — надстройка над Spring, которая настраивает всё по умолчанию: встроенный веб-сервер, JSON, логи. Приложение запускается обычным `main`, без внешнего Tomcat.
- **Стартер** (starter) — зависимость вида `spring-boot-starter-web`: тянет за собой всё нужное для одной задачи (web, data-jpa, security, test).
- **Автоконфигурация** (auto-configuration) — Spring Boot смотрит, какие библиотеки лежат в classpath, и сам создаёт бины для них. Есть драйвер Postgres и настройки в `application.yaml` — будет готовый `DataSource`.
- **`@SpringBootApplication`** — аннотация на классе с `main`: включает автоконфигурацию и поиск компонентов в этом пакете и ниже.
- **Classpath** — список jar-файлов, которые видит JVM при запуске. То, что лежит в зависимостях Gradle.

## Бины и DI

- **Бин** (bean) — объект, которым управляет Spring: он его создал, хранит и отдаёт другим. Обычно один на приложение (singleton).
- **Контекст** (ApplicationContext) — контейнер всех бинов. Поднимается при старте; если какой-то бин нельзя создать, приложение не запустится.
- **DI** (Dependency Injection, внедрение зависимостей) — класс не создаёт то, что ему нужно, а получает готовое через конструктор. Spring подставляет бины по типу.
- **Конструкторная инъекция** — зависимости приходят параметрами конструктора: `class UserService(private val repo: UserRepository)`. Рекомендуемый способ: зависимости видны, объект нельзя собрать наполовину.
- **`@Autowired`** — старый способ: аннотация на поле или сеттере. На поле в Kotlin нужен `lateinit var`, и класс нельзя создать в тесте без Spring. Поэтому в уроках его нет.
- **`@Component`** — базовая пометка «сделай из этого класса бин». Остальные три — её разновидности с понятной ролью.
- **`@Service`** — бин с бизнес-логикой: «создать заказ», «посчитать скидку».
- **`@Repository`** — бин, который ходит в базу. Spring дополнительно переводит исключения драйвера в свои.
- **`@Controller`** и **`@RestController`** — бин, который принимает HTTP-запросы. `@RestController` = `@Controller` + `@ResponseBody`: результат метода уходит в тело ответа как JSON. Голый `@Controller` ищет HTML-шаблон по возвращённой строке.
- **`@Configuration`** и **`@Bean`** — класс с методами-фабриками: когда бин создаёт не твой класс, а чужой (клиент, пул, часы). `@Bean fun clock(): Clock = Clock.systemUTC()`.
- **`@Qualifier`** и **`@Primary`** — выбор, если бинов одного типа несколько.
- **Scope** — сколько экземпляров бина живёт: singleton (один, по умолчанию), prototype (новый на каждый запрос бина), request (один на HTTP-запрос).

## Web-слой

- **Spring MVC** — классический web-слой на потоках: один запрос — один поток из пула. **Spring WebFlux** — реактивный, неблокирующий; в нём контроллеры могут быть `suspend`.
- **`@RequestMapping("/users")`** — общий префикс пути для всех методов контроллера.
- **`@GetMapping`, `@PostMapping`, `@PutMapping`, `@PatchMapping`, `@DeleteMapping`** — метод HTTP + хвост пути: `@GetMapping("/{id}")`.
- **`@PathVariable`** — кусок пути: `/users/{id}` → `id`.
- **`@RequestParam`** — параметр строки запроса: `/users?limit=20` → `limit`. По умолчанию обязателен; `defaultValue` делает необязательным.
- **`@RequestBody`** — тело запроса, обычно JSON, превращённое в объект.
- **`ResponseEntity`** — ответ целиком: статус, заголовки, тело. Когда статус зависит от результата.
- **`@ResponseStatus(HttpStatus.CREATED)`** — фиксированный статус для метода (201 вместо 200).
- **`@ControllerAdvice`** и **`@ExceptionHandler`** — один класс, который превращает исключения в HTTP-ответы для всех контроллеров.
- **`@Valid`** — проверить тело по аннотациям `@NotBlank`, `@Size`, `@Min`; ошибка даёт 400.
- **Jackson** — библиотека, которая превращает объекты в JSON и обратно. В Spring Boot стоит по умолчанию; для Kotlin нужен модуль `jackson-module-kotlin`.
- **DTO** (Data Transfer Object) — класс только для передачи данных по сети: `UserDto`, `CreateUser`. Не путать с сущностью базы.

## Данные

- **Spring Data JPA** — репозитории без кода: `interface UserRepository : JpaRepository<User, Long>`, методы вида `findByCity(city)` генерируются по имени.
- **JPA / Hibernate** — стандарт и его реализация для отображения классов на таблицы (`@Entity`).
- **`@Transactional`** — метод выполняется в одной транзакции: либо все записи, либо ни одной.
- **HikariCP** — пул соединений с базой, стоит в Spring Boot по умолчанию.
- **Flyway** — миграции схемы: пронумерованные SQL-файлы, которые применяются при старте.

## Эксплуатация

- **`application.yaml`** — настройки приложения: порт, база, свои параметры. **Профиль** (`application-prod.yaml`) — набор настроек для окружения.
- **`@ConfigurationProperties`** — класс, в который Spring складывает группу настроек из yaml.
- **Actuator** — готовые служебные ручки: `/actuator/health`, `/actuator/metrics`.
- **Micrometer** — метрики из приложения в Prometheus и другие системы; см. [[12 Наблюдаемость]].
