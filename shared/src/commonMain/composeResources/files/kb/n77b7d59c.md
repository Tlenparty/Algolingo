**1. Что такое Serializable?**

• Serializable — это интерфейс из стандартной библиотеки Java (java.io.Serializable).
• Используется для преобразования объекта в поток байтов и обратно.
• Основная цель — сохранение состояния объекта или передача его через потоки, сети, файловые системы и т. д.
• Это ==**маркерный интерфейс**==, то есть он не содержит методов, а просто помечает класс как сериализуемый.

**Принцип работы Serializable:**

1. **Рефлексия:** Система анализирует объект и его поля во время выполнения (runtime), чтобы преобразовать их в поток байтов.
2. **Десериализация:** Поток байтов считывается и восстанавливается в объект.

```kotlin
import java.io.Serializable

data class User(val name: String, val age: Int) : Serializable
```

**2. Что такое Parcelable?**

• Parcelable — это интерфейс из Android SDK (android.os.Parcelable).
• Создан специально для работы в Android и оптимизирован для передачи объектов через Binder, который используется для IPC (межпроцессного взаимодействия).
• Требует явной реализации методов для упаковки (writeToParcel) и распаковки (CREATOR).

**Принцип работы Parcelable:**

1. **Ручная реализация упаковки и распаковки:** Вы описываете, как объект должен преобразовываться в Parcel (специальный формат для Android).
2. **Производительность:** Используется напрямую запись и чтение из памяти, что делает его более быстрым, чем Serializable.
  
**Пример:**

```kotlin
import android.os.Parcel
import android.os.Parcelable

data class User(val name: String, val age: Int) : Parcelable {
    constructor(parcel: Parcel) : this(
        parcel.readString() ?: "",
        parcel.readInt()
    )

    override fun writeToParcel(parcel: Parcel, flags: Int) {
        parcel.writeString(name)
        parcel.writeInt(age)
    }

    override fun describeContents(): Int = 0

    companion object CREATOR : Parcelable.Creator<User> {
        override fun createFromParcel(parcel: Parcel): User = User(parcel)
        override fun newArray(size: Int): Array<User?> = arrayOfNulls(size)
    }
}
```

> [!important] На практике пишут `@Parcelize`, а не CREATOR вручную
> Весь бойлерплейт выше (`writeToParcel`, `CREATOR`, конструктор из `Parcel`) **не нужно** писать руками. Плагин **`kotlin-parcelize`** генерирует его автоматически:
> ```kotlin
> @Parcelize
> data class User(val name: String, val age: Int) : Parcelable
> ```
> Подключение: `plugins { id("kotlin-parcelize") }`. Это и быстрее (Parcelable), и без ручного кода. Ручную реализацию показывают, только чтобы объяснить «как оно работает под капотом».

**3. В чем разница между Parcelable и Serializable?**

**Основные различия:**

| Критерий           | Parcelable                                              | Serializable                                                              |
| ------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------- |
| Производительность | Быстрее так как работает напрямую с памятью             | Медленнее, т.к. использует рефлексию                                      |
| Простота рализации | Требует больше кода надо писать writeToParcel и CREATOR | Просто: Достаточно реализовать интерфейс                                  |
| Память + платформа | Экономичен и только Android                             | Кросс платформа, накладный                                                |
| Вложенность        | Вложенные объекты должны быть Parcelable                | Вложенные обьекты автоматически сериализуются, если они тоже Serializable |
  **4. Как устроены Parcelable и Serializable?**

### **Serializable:**

• Использует механизм рефлексии.
• Во время сериализации JVM проверяет структуру объекта и записывает данные в поток байтов.
• Восстановление объекта происходит из байтового представления.
• Можно использовать нестандартную сериализацию, реализуя методы writeObject и readObject.

### **Parcelable:**

• Требует явного указания того, как объект будет записываться и восстанавливаться.
• Использует Parcel, который предоставляет методы для работы с примитивами и объектами.
• Создаем сами, не надо через рефлексию

• Устройство:

1. writeToParcel: Упаковывает объект в Parcel.
2. CREATOR: Это статический объект, который отвечает за создание экземпляров класса из Parcel.

Рефлексия (Reflection) в программировании — это механизм, который позволяет программе исследовать и изменять свою структуру и поведение во время выполнения. С помощью рефлексии можно:

• Узнавать информацию о классах, методах, конструкторах, полях и аннотациях.
• Вызывать методы, создавать объекты или изменять значения полей, даже если они недоступны напрямую через обычный код.

В Java и Android рефлексия предоставляется через API из пакета java.lang.reflect.

### **Как работает рефлексия?**

Она исследует объекты, для исслледования создаются новые обьекты и они требует памяти и вызова GC

1. **Получение метаданных о классе:**

• С помощью класса Class можно получить доступ к метаданным (методы, поля, конструкторы и аннотации) любого объекта или класса.

• Например:
```java
Class<?> clazz = MyClass.class; // Получение объекта Class для класса
Class<?> clazz = myObject.getClass(); // Получение объекта Class для объекта
```

2. **Исследование структуры класса:**

• Методы для исследования:

• getMethods(): возвращает все методы (публичные, включая унаследованные).
• getDeclaredMethods(): возвращает методы, объявленные только в этом классе.
• getFields(): возвращает все публичные поля.
• getDeclaredFields(): возвращает все поля, независимо от модификатора доступа.

• Пример:

```java

Method[] methods = clazz.getDeclaredMethods();
for (Method method : methods) {
    System.out.println("Method: " + method.getName());
}
```

3. **Создание объектов через рефлексию:**

• Вы можете создать экземпляр класса, даже если он неизвестен на этапе компиляции.

• Пример:

```java
Constructor<?> constructor = clazz.getConstructor(String.class);
Object obj = constructor.newInstance("Hello");
```

4. **Доступ и изменение полей:**

• С помощью рефлексии можно получить и изменить значение приватных и публичных полей.

• Пример:

```java
Field field = clazz.getDeclaredField("name");
field.setAccessible(true); // Для доступа к приватным полям
field.set(obj, "New Value");
```

5. **Вызов методов:**

• Рефлексия позволяет вызывать методы, даже если они приватные.

• Пример:

```java
Method method = clazz.getDeclaredMethod("sayHello");
method.setAccessible(true); // Для приватных методов
method.invoke(obj);
```

**Преимущества рефлексии**

1. **Динамичность:**
• Позволяет работать с классами и объектами, которые неизвестны на этапе компиляции.
• Это полезно для библиотек, фреймворков и плагинов.
2. **Инструменты и фреймворки:**
• Используется во многих инструментах, например, в JUnit, Spring, Hibernate.
3. **Работа с аннотациями:**
• Рефлексия позволяет анализировать и использовать аннотации для управления поведением приложения.
**Недостатки рефлексии**
1. **Производительность:**
• Рефлексия медленнее обычного вызова методов или доступа к полям.
• Использует больше ресурсов из-за анализа метаданных и проверки доступа.
2. **Отсутствие безопасности:**
• Позволяет обходить модификаторы доступа (private, protected), что может нарушить инкапсуляцию.
3. **Сложность в отладке:**
• Код, использующий рефлексию, труднее читать, понимать и отлаживать.
4. **Ошибки во время выполнения:**
• Проблемы (например, отсутствие метода или конструктора) обнаруживаются только во время выполнения, а не на этапе компиляции.

### **Где используется рефлексия?**

1. **Фреймворки и библиотеки:**

• Spring, Hibernate, Retrofit, Dagger используют рефлексию для автоматической обработки зависимостей и аннотаций.

2. **Тестирование:**

• JUnit и TestNG используют рефлексию для запуска тестовых методов.

3. **Инструменты анализа:**

• Инструменты вроде Jackson (сериализация/десериализация JSON) или Gson используют рефлексию для работы с объектами.

4. **Системы плагинов:**

• Используется для загрузки и анализа плагинов, написанных на Java.

> [!note] Про ClassLoader
> `ClassLoader` нужен, чтобы по имени класса (из байтов) восстановить объект при десериализации. У `Serializable` он берётся из контекста; результат можно сохранить в постоянное хранилище/файл. У `Parcelable` ClassLoader **указывается явно** (`parcel.readParcelable(classLoader)`), т.к. это часть Android и используется для **IBinder-транзакций (IPC)**.

> [!tip] Что отвечать на собесе
> - **Parcelable** — для передачи между компонентами Android (`Intent`, `Bundle`), быстрый (IPC через Binder). Пиши через **`@Parcelize`**.
> - **Serializable** — кросс-платформенный (Java), но медленный (рефлексия) и **создаёт мусор** (нагрузка на GC). Подходит для сохранения в файл/сеть вне Android-IPC.
> - В `Bundle`/`Intent` помещай **Parcelable**; Serializable там тоже примут, но это медленнее.
> - В Compose/Navigation для аргументов экранов тоже предпочитают Parcelable (через `@Parcelize`) или сериализацию `kotlinx.serialization`.
