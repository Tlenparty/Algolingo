# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3 (Lesson & Exercise UI). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Platform: Compose Multiplatform (Android + iOS), shared UI. All sizes are in `dp` (layout) and `sp` (text). "px" in the template means `dp` here.

**Sources:** customer decisions and approved wireframes (LOCKED), REQUIREMENTS.md (LESS-02/04/06, EXER-01..04, 06..10, UI-01), research/SUMMARY.md, STACK.md, FEATURES.md. The palette, fonts and exact numbers are the researcher's defaults; the customer only fixed "playful Duolingo-like, green accent, white light bg, 3D buttons and chips, system light/dark".

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Compose Multiplatform; the shadcn gate does not apply) |
| Preset | not applicable |
| Component library | `org.jetbrains.compose.material3` (1.12.0-alpha03) as the base. It is customized through `MaterialTheme(colorScheme, typography, shapes)` plus one `AppColors` `staticCompositionLocalOf` for colors that M3 has no slot for (success, amber, focus, ledges, syntax). No other UI libraries. |
| Icon library | none. Use emoji glyphs from the wireframes (🔥 ⭐ 💡 ✅ ❌ ⚠️ 🔁 🔒 ▶) and the `✕` text glyph. Every icon-only control gets a `contentDescription` (see Accessibility). |
| UI font | **Nunito** (OFL, Cyrillic): Regular 400 + Bold 700, bundled as `composeResources/font/` TTFs. It provides the rounded, friendly feel. Fallback is `FontFamily.Default` if the customer vetoes it. |
| Code font | **JetBrains Mono** (OFL, Cyrillic): Regular 400 + Bold 700, bundled as `composeResources/font/`. Used for the code template, code inside chips and holes, the reference solution, and theory skeletons. |
| Theme switching | `isSystemInDarkTheme()`, no in-app toggle (UI-01) |

### Shared components to build (in `ui/components/`, one file each at most)

| Component | Purpose |
|-----------|---------|
| `ChunkyButton(text, onClick, enabled, style = Primary/Secondary/Danger/Amber)` | The 3D button used for every CTA |
| `TokenChip(text, state = Normal/Ghost/Placed/Selected/Ok/Acceptable/Wrong)` | Chip in the bank, and the chip rendered inside a hole |
| `CodeTemplate(segments, holes, selectedHole, results)` | Monospace template with inline holes |
| `CodeBlock(code)` | Read-only highlighted code (reference solution, theory skeleton) |
| `LessonProgressBar(fraction)` | Top progress bar |
| `ResultPanel(kind, title, body, button)` | Bottom feedback panel |
| `highlight(token): AnnotatedString` | Keyword set + 3 regexes (string, number, `//`), per STACK.md |

## Spacing Scale

Declared values (multiples of 4, unit `dp`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | The "3D" ledge height under buttons/chips/nodes, icon-to-text gaps, hole inner vertical padding |
| sm | 8dp | Gap between chips in the FlowRow (horizontal and vertical), hole horizontal padding, gap between hint cards |
| md | 16dp | Screen horizontal padding, chip horizontal padding, gap between stacked blocks, card padding (compact) |
| lg | 24dp | Theory/result card padding, gap between title and code block, gap between code block and bank |
| xl | 32dp | Gap between lesson-path nodes, top padding of the summary screen |
| 2xl | 48dp | Minimum touch target, horizontal zig-zag offset of path nodes |
| 3xl | 64dp | Summary hero emoji box, bottom inset of the home path |

Fixed component sizes (all multiples of 4):

| Element | Size |
|---------|------|
| `ChunkyButton` | height 56dp total (52dp face + 4dp ledge), full width minus 2×16dp, corner 16dp |
| Bank `TokenChip` | min height 48dp total (44dp face + 4dp ledge), horizontal padding 16dp, corner 12dp, border 2dp |
| Inline hole | height 32dp, min width 48dp, horizontal padding 8dp, corner 8dp |
| Code template line | height 40dp (fits a 32dp hole with 4dp above and below) |
| Lesson top bar | height 56dp: ✕ (48×48 target) · progress bar (flex) · 💡 (48×48 target) |
| Progress bar | height 16dp, fully rounded |
| Path node | 72dp circle + 4dp ledge |
| Result panel | padding 16dp horizontal, 24dp top, 16dp bottom + system nav inset |

Exceptions:
- Inline holes are 32dp tall visually (smaller than the 48dp target) so they fit into a code line. Their touch area is the full 40dp line height × max(48dp, hole width). This is the only sub-48dp target.
- Border widths are 2dp (outline) and the ledge is 4dp. These are strokes, not spacing.

## Typography

UI font = Nunito; exactly 2 weights in the whole app: **400 Regular** and **700 Bold**.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 16sp | 400 | 1.5 (24sp) | Task statement, theory text, pitfall explanations, hint text |
| Label | 14sp | 700 | 1.43 (20sp) | Path node captions, "Подсказка 1/2" captions, complexity row, header counters (🔥 3, ⭐ 40), section captions inside cards ("Сигналы", "Скелет", "Грабли") |
| Heading | 20sp | 700 | 1.2 (24sp) | Task title, theory card title, result panel title, reveal section title |
| Display | 28sp | 700 | 1.2 (34sp) | Summary title «Урок пройден!», reveal headline «✅ Решено! +10 XP» |

Button labels: 16sp / 700, sentence case (the Body size at the Bold weight, no new size).

Code font (JetBrains Mono), reusing the same sizes:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Code (template, reference, skeleton) | 14sp | 400 | 20sp text inside a 40dp line (template) / 1.43 (read-only blocks) |
| Code inside a placed chip/hole | 14sp | 700 | 20sp |
| Code inside a bank chip | 16sp | 700 | 24sp |

Emoji used as icons are sized as icons, not text roles: 24dp inline (top bar, header), 32dp in path nodes, 64dp hero on the summary screen.

Code rendering rules (locked): no soft wrap; the whole template/block is in one `horizontalScroll` so all lines scroll together; `softWrap = false`, `maxLines = 1` per line.

Two schemes, picked by `isSystemInDarkTheme()`. All text-on-fill pairs below were checked for contrast (WCAG ratio in brackets).

| Border / ledge for neutral elements — `outline` | `#E5E5E5` | `#37464F` | 2dp borders on cards/chips, the ledge under neutral chips, progress-bar track, ghost fill, empty hole fill, locked path node |
| Text primary — `onBackground` | `#3C3C3C` (11.0) | `#F1F7FB` (15.6) | All body/heading text, default code text |
| Text secondary | `#6B6B6B` (5.3) | `#9AA9B1` (7.0) | Captions, statement subtitle, complexity row label, inactive counters |
| Accent (10%) — `primary` | `#58CC02` | `#58CC02` | See reserved list |
| Accent ledge | `#58A700` | `#58A700` | 4dp ledge under green buttons/nodes |
| On-accent ink — `onPrimary` | `#131F24` (8.1 on accent) | `#131F24` | Labels on every colored button (green, red, amber) |
| Destructive — `error` | `#FF4B4B`, ledge `#EA2B2B` | `#FF4B4B`, ledge `#EA2B2B` | Wrong hole border, error panel button fill, «Выйти» text in the exit dialog |

Accent green (`#58CC02`) is reserved for:
1. The primary `ChunkyButton` fill: «Проверить», «Дальше», «Продолжить», «Понятно» on the success panel, «Начать» on the home path
2. The progress-bar fill
3. The border of an `Ok` hole and the success panel accent
4. Done and current path nodes
5. «+N XP» text on the reveal and summary screens (dark scheme `#58CC02`, light scheme `#2F7A00` for contrast on white)

Accent is never used for: bank chips, links, the hint button, selected-hole highlighting, or plain text.

## Screens & Layout Contract

General: `Scaffold`-free plain `Column`s on `background`; `WindowInsets.safeDrawing` padding on every screen; content max width 600dp, centered (tablets/landscape).

### 1. Home (entry point; Phase 4 wires the data)
- Header row (16dp padding, 56dp tall): `🔥 N` left, `⭐ N` right, Label style. **Phase 3:** hide the header and the «Повтор сегодня (N)» button; Phase 4 adds them (LESS-01, PROG-*).
- «Повтор сегодня (N)»: Secondary `ChunkyButton` (white/`#202F36` fill, 2dp outline border, outline ledge, text primary), under the header. Hidden when N = 0. Phase 4.
- Vertical path: `LazyColumn` of nodes 0.1–0.4, 32dp between nodes, horizontal offsets cycle `0, +48dp, 0, -48dp`. Under each node: caption «0.1 Сумма и максимум» (Label, text secondary, max 2 lines, centered, width 160dp).
- Node states: done = green fill + `✅`; current = green fill + `▶` + a floating Primary pill «Начать» above it; locked = outline fill + `🔒`, tap does nothing. **Phase 3:** all nodes render as "current" style and are tappable; Phase 4 supplies the real statuses.

### 2. Lesson top bar (theory, exercise, reveal)
`✕` (48×48, text secondary) · `LessonProgressBar` (flex, 16dp horizontal margin) · `💡` hint button (48×48). The hint button is rendered **only** on exercise screens with ≥1 hint (EXER-09); otherwise a 48dp spacer keeps the bar centered. Progress = completed items / total items in the queue, including re-queued exercises (LESS-04); animate the fill over 300ms.

### 3. Theory card (LESS-02)
- Card: `surfaceVariant`, 2dp outline border, corner 16dp, padding 24dp, vertical scroll if long.
- Content: Heading title → optional «Сигналы» (Label caption + bullet lines in Body) → optional «Скелет» (Label caption + `CodeBlock`) → optional «Грабли» (Label caption `⚠️ Грабли` + Body bullets).
- Bottom bar: Primary `ChunkyButton` «Дальше», 16dp padding. No back navigation between cards in MVP.

### 4. Exercise (EXER-01..04, 06, 09)
Layout, top to bottom:
1. Top bar (see 2).
2. **Scrollable area** (`weight(1f)`, vertical scroll): task title (Heading) → statement (Body, text secondary for the `🎯` line) → 24dp → revealed hint cards (see Hints) → `CodeTemplate` card (`surfaceVariant`, corner 16dp, padding 16dp, one horizontal scroll for all lines).
3. **Pinned bottom section** (`background`, 2dp top divider in outline): chip bank `FlowRow` (8dp gaps, start-aligned, 16dp padding) → 16dp → «Проверить» `ChunkyButton`. The bank never scrolls away from the code.

Holes in `CodeTemplate`:
| Hole state | Visual |
|------------|--------|
| Empty | outline fill (`#E5E5E5` / `#37464F`), no text, width 48dp |
| Empty + selected | Focus tint fill, 2dp Focus border |
| Filled | `background` fill, 2dp outline border, chip text (code 14sp/700), width fits text |
| Filled + selected | Same as Filled, with a 2dp Focus border |
| After check: ok / acceptable / wrong | State tint fill + 2dp state border + text in the state text color |

Bank chips:
| Chip state | Visual |
|------------|--------|
| Normal | `background` fill, 2dp outline border, 4dp outline ledge, code 16sp/700, text primary |
| Pressed | Face translates down 4dp, ledge disappears (80ms) |
| Ghost (placed elsewhere) | Same size, outline fill, no text, no ledge, not clickable |
| After check | Bank is disabled (no taps) until the panel is dismissed |

Interaction rules (locked by requirements):
- Default selected hole = first empty hole. Tap a hole → it becomes selected (whether empty or filled).
- Tap a bank chip → it goes into the selected hole. If that hole was filled, the old chip returns to the bank. Then the selection moves to the next empty hole (first empty after the current one, wrapping); if none, nothing is selected.
- Tap a placed chip inside a hole → the chip returns to the bank, its ghost becomes a normal chip again, and that hole becomes selected.
- Chip identity is `chip.id`. Compose keys use `id`, never `text` (EXER-05).
- Chip move animation: none in MVP. The hole and ghost swap with a 100ms crossfade.
- «Проверить» is disabled until every hole is filled (EXER-06).

### 5. Check result (EXER-07, 08)
- On «Проверить»: holes recolor (200ms color tween); the bank and holes become non-interactive; the `ResultPanel` slides up from the bottom (250ms, `slideInVertically` + fade) and **replaces** the pinned bottom section. It is not a modal `ModalBottomSheet`: there is no scrim, and the code stays visible above it.
- Haptics: `HapticFeedbackType.Confirm` on all-ok / acceptable, `HapticFeedbackType.Reject` on any wrong. (If the CMP version lacks these types, use `LongPress` for both.)
- Panel variants (tint background, 2dp top border in state color):

| Outcome | Title (Heading, state text color) | Body | Button |
|---------|-----------------------------------|------|--------|
| All holes ok | «✅ Отлично!» | none | Primary «Дальше» → Reveal |
| ≥1 acceptable, no wrong | «👌 Принято, но…» | For each acceptable hole: the chip in code font + its `note` (Body) | Amber `ChunkyButton` «Дальше» → Reveal |
| ≥1 wrong | «❌ Не совсем» | For each wrong hole, in template order: the wrong chip in code font + its `why` (e.g. «`max = 0` ломается на `[-5, -2]`»), then «Верно: `nums[0]`» (Label caption + code). If more than one, separate them with 16dp. Then, under a «Принято, но…» caption, each acceptable hole: the chip in code font + its note (customer decision 2026-10-21: show everything at once). | Danger `ChunkyButton` «Понятно, дальше» → next item (the exercise is re-queued at the end) |

- The panel body scrolls if taller than 50% of the screen height.

### 6. Hints (EXER-09)
- The 💡 button shows the emoji and a small counter `1` = number of hints **remaining** (Label, Focus text color; hidden at 0). Tap → the next hint appears as a card at the top of the scroll area (Focus tint, 2dp Focus border, corner 12dp, padding 16dp): caption «Подсказка 1 из 2» (Label, Focus text color) + text (Body). The newest card is appended below the earlier ones, and the area scrolls to it.
- When all hints are shown, the button is disabled (text secondary, no counter).
- No confirmation dialog. The first card shows a caption under its text: «Подсказка снижает оценку до 💡» (Label, text secondary), once per exercise.
- 0 hints → the button is not rendered.

### 7. Reveal after solving (EXER-10)
Vertical scroll, 16dp horizontal padding, 24dp between sections:
1. Display headline: «✅ Решено! +10 XP» (the XP value comes from the domain; the `+N XP` part is in the accent color). If the exercise ended without a solve (❌, retries exhausted): «❌ Разберём решение», no XP.
2. «Эталон» (Heading) + `CodeBlock` of the reference solution; the hole spans get a Success tint background so the user sees which decisions mattered.
3. «Сложность» (Heading) + Body «Время O(n) · Память O(1)».
4. «⚠️ Грабли» (Heading) + Body bullets. Hidden if empty.
5. «🔁 Вариации» (Heading) + Body bullets. Hidden if empty.
6. Pinned bottom: Primary «Продолжить».

### 8. Lesson summary (LESS-06)
Centered column, 32dp top padding: hero emoji 64dp (`✅` / `💡` / `❌`) → Display title → Body subtitle → 24dp → XP row «+N XP» (Heading, accent) → pinned Primary «Продолжить» → Home.

| Grade | Title | Subtitle |
|-------|-------|----------|
| ✅ | «Чисто!» | «Без подсказок и ошибок. Так держать.» |
| 💡 | «Решено с подсказкой» | «Задача решена, но с подсказками или повтором. Вернись к ней завтра.» |
| ❌ | «Пока не вышло» | «Разобрали решение — попробуй ещё раз позже.» |

## Motion

| Interaction | Spec |
|-------------|------|
| Button/chip press | Face translates down 4dp and the ledge collapses, 80ms, `tween` |
| Chip place/return | 100ms crossfade between the hole content and the ghost |
| Hole recolor after check | 200ms `animateColorAsState` |
| Result panel | 250ms slide up + fade in; 200ms slide down on dismiss |
| Progress bar | 300ms `animateFloatAsState` |
| Screen transitions inside the lesson (theory → exercise → reveal) | 200ms horizontal slide + fade (`AnimatedContent`) |

## Accessibility

- `contentDescription`: ✕ «Закрыть урок»; 💡 «Подсказка, осталось N»; hole «Дырка N: пусто» / «Дырка N: выбрана» / «Дырка N: <текст>»; ghost — `clearAndSetSemantics {}`; result panel title has `liveRegion = Polite`.
- All text in `sp` and respects system font scale; the code template scrolls horizontally, so large fonts never wrap code.
- State is never conveyed by color alone: the panel title carries ✅/👌/❌, and wrong holes are listed in the panel by name.
- Minimum touch target 48dp (the exception for inline holes is documented in Spacing).

## Copywriting Contract

Tone: friendly, informal «ты», short, no exclamation spam (at most one «!» per screen).

| Element | Copy |
|---------|------|
| Primary CTA (exercise) | «Проверить» |
| Theory card advance | «Дальше» |
| Success panel / acceptable panel button | «Дальше» |
| Error panel button | «Понятно, дальше» |
| Reveal and summary button | «Продолжить» |
| Home node CTA pill | «Начать» |
| Review button (Phase 4) | «Повтор сегодня (N)» |
| Result titles | «✅ Отлично!» / «👌 Принято, но…» / «❌ Не совсем» |
| Correct-answer caption in the error panel | «Верно:» |
| Fallback when a wrong chip has no `why` | «Здесь нужно другое. Верно: `<chip>`» |
| Hint caption | «Подсказка N из M» |
| Hint penalty note | «Подсказка снижает оценку до 💡» |
| Reveal headline | «✅ Решено! +N XP» / «❌ Разберём решение» |
| Reveal sections | «Эталон», «Сложность», «⚠️ Грабли», «🔁 Вариации» |
| Complexity line | «Время O(…) · Память O(…)» |
| Summary | See the grade table in section 8 |
| Empty state heading (home, no lessons in `index.json`) | «Уроков пока нет» |
| Empty state body | «Контент не найден. Пересобери приложение с папкой content.» |
| Error state (lesson JSON fails to load/parse) | Title «Не удалось открыть урок», body «Файл урока повреждён или отсутствует. Попробуй другой урок или переустанови приложение.», button «На главную» |
| Destructive confirmation | Leave lesson (✕ or system back during a lesson): `AlertDialog` titled «Выйти из урока?», body «Прогресс этого урока не сохранится.», confirm «Выйти» (text button, error color), dismiss «Остаться» (Secondary `ChunkyButton`). The dialog appears on theory, exercise and reveal screens. On the summary screen, back goes straight Home with no dialog (the result is already earned). |
