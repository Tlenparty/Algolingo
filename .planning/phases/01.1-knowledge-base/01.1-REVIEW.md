# Phase 01.1: Code Review Report

**Reviewed:** 2026-10-21T13:18:24Z
**Depth:** standard
**Files Reviewed:** 19

## Narrative Findings (AI reviewer)

## Summary

Reviewed the knowledge-base feature: the Markdown parser, the repository and search, the KB list and note screens, callouts, the highlighter, the theme, navigation in `App.kt`, the sync script and the tests. The bundled notes (`files/kb/n*.md`) were probed for parser edge cases.

The parser and search are small and mostly sound. The serious problem is lifecycle. `KbRepository.notes` is a plain `var` and not Compose state, so the note route never recomposes after an Activity recreation and stays stuck on "Заметка не найдена". Other real defects:
- the sync script deletes the bundle before it reads the vault;
- the anchor scroll fires again when you return to a note;
- standard Markdown `[text](#anchor)` links show up raw in the shipped note n04;
- table columns do not line up.

The known cosmetic issues are recorded under Info (IN-01..IN-03).

## Critical Issues

### CR-01: Note screen is stuck on "Заметка не найдена" after Activity recreation (rotation, dark-mode toggle, process restore)

**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/App.kt:55-56, 85-94`; `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/KbRepository.kt:7`
**Issue:** `AndroidManifest.xml` declares no `configChanges`, so rotating the device or toggling the system theme recreates `MainActivity`. `rememberNavController` restores the back stack with the `NoteRoute` on top. A fresh `KbRepository()` is created with `notes = emptyList()`, and the `NoteRoute` destination composes right away. `repo.byId(route.id)` returns `null` and the screen shows "Заметка не найдена".

When `produceState` later sets `loaded = true`, only the `KbList` content lambda recomposes, because it is the only scope that reads `loaded`. `repo.notes` is a plain `var` and not snapshot state, so nothing invalidates the `NoteRoute` scope. The user stays on "Заметка не найдена" until they navigate away. The same happens after process death and restore.
**Fix:** Gate the note route on `loaded` the same way KbList is gated. Better, make `notes` observable.
```kotlin
composable<NoteRoute> {
    if (!loaded) { Text("…"); return@composable }
    val route = it.toRoute<NoteRoute>()
    ...
}
// or in KbRepository:
var notes by mutableStateOf<List<Note>>(emptyList()); private set
```

## Warnings

### WR-01: sync_notes.py wipes the bundled KB before reading the vault, so a failed read leaves the app without an index.json

**File:** `tools/sync_notes.py:46-49`
**Issue:** Old `n*.md` files and `index.json` are deleted on line 46. The vault is read only on line 49. If any note fails to decode (a non-UTF-8 file raises `UnicodeDecodeError`) or a read fails, the script aborts with the bundle already deleted. The next build then ships without `files/kb/index.json`, and `KbRepository.load()` throws, which crashes the app (see IN-05). Git can recover the files, but the failure is silent unless someone notices.
**Fix:** Read and validate everything first, then delete and write:
```python
notes = sorted(((nfc(p.stem), nfc(p.read_text(encoding="utf-8"))) for p in vault.glob("*.md")))
if not notes:
    print("no notes found"); return 1
for old in list(out.glob("n*.md")) + [out / "index.json"]:
    old.unlink(missing_ok=True)
```

### WR-02: The anchor scroll fires again every time the note re-enters composition, which throws away the user's scroll position

**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/ui/NoteScreen.kt:29-32`
**Issue:** `rememberLazyListState()` is saveable and restores the user's position. But `LaunchedEffect(note.id, anchor)` runs on every new composition of the entry. Example flow: open `[[05 …#2.2 …]]`, scroll down, tap another link, press back. Note 05 is recomposed, the effect runs again, and the list jumps back to the "2.2" heading. Rotation does the same.
**Fix:** Consume the anchor once:
```kotlin
var anchorDone by rememberSaveable(note.id, anchor) { mutableStateOf(false) }
LaunchedEffect(note.id, anchor) {
    if (!anchorDone && anchor != null) findAnchorIndex(blocks, anchor)?.let { listState.scrollToItem(it) }
    anchorDone = true
}
```

### WR-03: Standard Markdown links `[text](#anchor)` render as raw syntax in shipped content

**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/MarkdownParser.kt:129-169`; content `files/kb/n04.md:8, 328-331`
**Issue:** `parseInline` only handles `[[wikilinks]]`. Note n04 ("04 Маркеры + Заготовки") opens with a navigation line of 20 `[Hash](#1-hash-map--частоты) · …` links, and its final table has more. Both render as a wall of raw `[..](#..)` text, and that is the main reference note. The slug anchors (`#1-hash-map--частоты`) would not match `findAnchorIndex` either, because that function compares against the heading text ("1. Hash Map — частоты").
**Fix:** Add a `[label](target)` case to `parseInline`. For `#slug` targets, emit a `Link` to the current note with the anchor matched by slug, by adding a slugify comparison in `findAnchorIndex`. At minimum, render the label and drop the URL.

### WR-04: Table columns are not aligned, because each cell sizes itself independently

**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/ui/BlockView.kt:130-137`
**Issue:** Each row is its own `Row`, and each cell has `widthIn(min = 120.dp, max = 240.dp)`. A cell with longer text grows up to 240dp in its own row only. Column N in one row then starts at a different x than column N in another row, so headers and cells drift apart. Tables are common in the notes (n03, n04, and others).
**Fix:** Use a fixed width per column, either `Modifier.width(160.dp)` or a per-column width computed from the max text length. Another option is to lay out the table in columns, with a `Column` per table column inside one `Row` and `height(IntrinsicSize.Min)` per row.

### WR-05: Double-tapping "Назад" pops two back-stack entries

**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/ui/NoteScreen.kt:34`; `App.kt:92`
**Issue:** `onBack = { nav.popBackStack() }` is not guarded. During the exit transition the button can still be clicked. A quick double tap from a note (`KbList → Note`) pops the note and then KbList, which lands the user on Home. Starting from a note chain, it skips a note. This is a known Navigation-Compose pitfall.
**Fix:** `lifecycle-runtime-compose` is already a dependency:
```kotlin
onBack = dropUnlessResumed { nav.popBackStack() },
```
Apply the same guard to `onLink` and `onOpen` navigations.

### WR-06: Note IDs are positional, so every sync can silently remap IDs to different notes

**File:** `tools/sync_notes.py:49-54`
**Issue:** `nid = f"n{i:02d}"` is the index in the title-sorted list. Adding, removing or renaming one vault note shifts every later ID. Today that affects saved navigation state (`NoteRoute(id)`) and the test fixtures. It will also break any future persisted reference (bookmarks, progress, "theory linked to lesson"), which will open the wrong note without any error.
**Fix:** Derive the ID from the title in a stable way, for example `"n" + hashlib.sha1(title.encode()).hexdigest()[:8]`, which stays ASCII-only as the test requires. Alternatively, persist a title→id map in the repo and only append to it.

### WR-07: KbContentTest hard-codes the note count and asserts almost nothing about parse results

**File:** `shared/src/androidHostTest/kotlin/com/tlenparty/algolingo/kb/KbContentTest.kt:17, 41-59`
**Issue:**
- `assertEquals(23, entries.size)` fails on every legitimate vault sync. That trains people to bump the number blindly.
- `allNotesParse` calls `parseInline` and discards the result. It does not recurse into `Callout`/`Quote` blocks, which hold most of the content (100+ callouts), so their inline text is never even exercised.
- Nothing checks that every `[[wikilink]]` in the bundle resolves, even though that is the property the feature depends on.

**Fix:** Replace the magic count with `assertTrue(entries.isNotEmpty())` plus an ID-uniqueness check. Recurse into nested blocks. Add a check that collects every `Link` from parsed inlines and asserts `resolveNote(notes, it.target) != null`. That check would also catch the unresolved-link class of bug in WR-03.

## Info

### IN-01: (known) Callout titles render raw Markdown such as backticks
**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/ui/CalloutView.kt:56-61`
**Issue:** `c.title` is passed as a plain `String`, not through `inlineText(parseInline(...))`.
**Fix:** Render it with `inlineText(parseInline(title), resolvable, onLink)`.

### IN-02: (known) Search snippets show raw Markdown
**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/KbRepository.kt:33-38`
**Issue:** Snippets are slices of `raw`, so they include `**`, `>`, `[[` and code fences.
**Fix:** Strip the markers before slicing, or search over plain text derived from the parsed blocks.

### IN-03: (known) The search field scrolls away with the list
**File:** `shared/src/commonMain/kotlin/com/tlenparty/algolingo/kb/ui/KbListScreen.kt:31-39`
**Issue:** The field is `item(key = "search")` inside the `LazyColumn`.
**Fix:** Move it above the `LazyColumn` in a `Column`, or use `stickyHeader`.

### IN-04: Unused `Color` imports
**File:** `kb/ui/BlockView.kt:23`, `kb/ui/CalloutView.kt:18`
**Fix:** Remove them.

### IN-05: An unhandled exception in `KbRepository.load()` crashes the app
**File:** `App.kt:56`
**Issue:** If `produceState { repo.load() }` throws (a missing or malformed `index.json`, see WR-01), the exception propagates into composition and crashes the app, even on the Home tab.
**Fix:** Use `runCatching` and show an error state on the KB tab.

### IN-06: `findAnchorIndex` only matches top-level headings by their raw text
**File:** `kb/KbRepository.kt:49-52`
**Issue:** Headings nested in callouts or quotes cannot be reached. Headings that contain inline Markdown (`**`, backticks, `[[..]]`) never match the Obsidian anchor, which uses rendered text. A miss is a silent no-op. Current wikilink anchors (n05 "2.2…", "2.5…") do match.
**Fix:** Compare against the text with markers stripped. Accept a miss, but consider a toast.

### IN-07: Obsidian syntax the parser does not support (absent from current content, but it will break silently after a future sync)
**File:** `kb/MarkdownParser.kt`
**Issue:**
- `[[#Heading]]` (same-note link) gives target `""`, so the label is `""` and the link text **disappears entirely** (lines 155-158).
- `[[X\|alias]]` inside tables (Obsidian's required escape) gives target `X\`, which is unresolvable. A bare `\|` in a cell still splits the cell (lines 105-127).
- `![[embed]]` renders as `!embed`.
- Tab-indented nested lists get depth 0 (line 90, `length / 2`).
- `_italic_`, `~~strike~~` and `==highlight==` are shown raw.

**Fix:** At minimum, fall back to `body` as the label when `target` is empty, and strip a trailing `\` from `ref`.

### IN-08: Aliased links `[[04 Маркеры + Заготовки|#11]]` open the top of the note, not section #11
**File:** content `files/kb/n0*.md` (9 occurrences)
**Issue:** The label suggests a section jump, but the link has no `#heading` part, so the user lands at the top of a 346-line note. This is a content issue that the app cannot fix without a heuristic.
**Fix:** Change the vault links to `[[04 Маркеры + Заготовки#11. BFS — …|#11]]`.

### IN-09: `searchNotes` takes an index from the lowercased string and slices the original string with it
**File:** `kb/KbRepository.kt:34-36`
**Issue:** `lowercase()` can change the string length (for example `İ` becomes `i̇`). The snippet window then shifts, and `substring(start, end)` can get `start > end` and throw. Slicing can also split surrogate pairs, and the content contains emoji.
**Fix:** Slice the lowercased string, or clamp `start` to `min(start, end)`.

### IN-10: Highlighter gaps
**File:** `ui/theme/Highlight.kt:14`; `kb/ui/BlockView.kt:122`
**Issue:**
- Only `lang == "kotlin"` is highlighted (17 `text` blocks and 1 `java` block are plain, which is acceptable).
- There is no `/* */` block comment support.
- `"""raw"""` strings tokenize as `""` followed by a stray quote.
- `0xFF` becomes the number `0` followed by the identifier `xFF`.
- Keywords like `const`, `vararg` and `until` are missing.

**Fix:** Add the block-comment and raw-string alternatives at the front of `tokenRe`.

### IN-11: sync_notes.py only scans the vault root
**File:** `tools/sync_notes.py:49`
**Issue:** `vault.glob("*.md")` is not recursive. Notes in subfolders are dropped, and links to them are reported as "unresolved" with no hint about why.
**Fix:** Use `rglob("*.md")` and warn about duplicate stems, or document the limitation in the usage text.

### IN-12: README environment versions disagree with CLAUDE.md
**File:** `README.md:7-17`
**Issue:** The README says JDK 21 and Xcode 26.2. The project stack in CLAUDE.md says JDK 17 and Xcode 26.4.
**Fix:** Pick one and make the two files match.
