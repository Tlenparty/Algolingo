## Summary

The real vault (23 `.md`, about 198 KB, 7 of them with tables) uses a small markdown subset. There are no frontmatter blocks, no images or embeds, no URLs, no HTML, no task lists, no `==highlight==` or `%%comments%%`. What does occur: `#`/`##`/`###` headings, paragraphs, `-`/`*` bullets (some nested by 2+ space indent), `1.` lists, GFM tables (7 notes), `---` rules, fenced code (kotlin 62+6, text 17, java 1, untagged ~94), plain `>` blockquotes (about 20), Obsidian callouts, and inline `**bold**` (1318), `*italic*`, `` `code` ``, `[[wikilinks]]`.

Callouts are the heavy part. Counts across the vault: `question-` 68, `success-` 34 (both collapsed), plus `warning` 5, `important` 4, `tip` 4, `info` 3, `note` 3 (not collapsible). The collapsed ones contain fenced `kotlin` code inside `> ` lines (`> ```kotlin`). There is no nesting (`> >`). A generic markdown library cannot do this: mikepenz's alert support covers GitHub alerts, not `[!type]-` folding with custom titles.

**Primary recommendation:** Do NOT add a markdown library. Write a small in-house, line-based block parser (about 150 lines, pure Kotlin in commonMain, unit-tested) plus an inline parser (code, bold, italic, wikilink) that builds `AnnotatedString` with `LinkAnnotation.Clickable`. Render blocks in a `LazyColumn`. Ship the notes as `composeResources/files/kb/*.md` plus a generated `kb/index.json`, produced by a stdlib-only `python3` script `tools/sync_notes`. Add `navigation-compose` 2.9.2 (already the CLAUDE.md choice). Build the theme, fonts and `highlight()` here per 03-UI-SPEC, because Phase 1 contains none of them (verified).

## Real Content Inventory (from the vault, not hypotheticals)

Files (23): `00 Компас алгоритмов`, `01 Ключи и сигналы`, `02 Шаблон решения`, `03 Тренажёр задач`, `04 Маркеры + Заготовки`, `05 Тренажёр решений` (39.6 KB, largest), `06 Движок «маркеры и дырки»`, `BIG O`, `LRU Cache`, `Алгоритмические сложности` (324 bytes, effectively a stub), `Алгоритмы Avito`, `Алгоритмы Glovo`, `Бинарный поиск`, `Бублесорт`, `Динамическое программирование`, `Если слово палиндром`, `Задача на 2 указателя`, `Задача на stack и map`, `Задача на поиск в ширину`, `Задача от Яндекс со станциями`, `Задачи с Avito`, `Поиск в глубину (DFS)`, `Проверка является ли слово анаграммой`.

Facts that drive design:
- **NFD names:** `05 Тренажёр решений.md` and `Проверка является ли слово анаграммой.md` are NFD on disk (the others NFC). Normalize both filenames and wikilink targets and also the file text with `unicodedata.normalize("NFC", ...)`. Without this, `[[05 Тренажёр решений]]` fails to match its file (8+ links point to such notes). On the runtime side also NFC-normalize? Kotlin common has no NFC API, so ALL normalization must happen in the script. Runtime compares plain strings.
- **Wikilink forms present:** `[[Name]]`, `[[Name|alias]]` (e.g. `[[04 Маркеры + Заготовки|#9]]`, `[[Поиск в глубину (DFS)|backtracking]]`), `[[Name#Heading|alias]]` (`[[05 Тренажёр решений#2.5 Самый длинный период без снижения 🔥Яндекс|2.5]]`), and `[[Name#Heading]]` is allowed by the spec. Heading anchors contain spaces, dots and emoji.
- **Wikilinks occur inside tables** (00 compass table, 04). Cell splitting must not split on a `|` inside `[[...]]`.
- **Broken or non-matching targets (must not crash):** `Структуры данных` (4x), `Heap & Stack`, `Как работает HashMap`, `Performance. Память и утечки`, `HashMap vs HashSet`, `Coil` (6 distinct, no such notes among the 23). Case mismatch: `[[Big O]]` points to the file `BIG O` (so resolve case-insensitively). Broken links render as plain text (KB-05).
- **Callouts:** all lines begin `> `. Syntax `> [!type]± Title` where the title may hold emoji (`💡 Подсказка 1`). Body lines contain text, lists and fenced code (`> ```kotlin`). Several callouts sit adjacent, separated by a blank line (each starts with its own `> [!...]`). Types: question, success, warning, important, tip, info, note. Fold marker `-` only appears on question and success. A line inside a fence in 06 contains `2 > 2? нет` (a `>` mid-line in code, harmless once fences are tracked).
- **Plain blockquotes** (`> text`, `> - list`) appear ~20 times (intro lines in 00, 01, 02, "Правило большого пальца"). Render with a left bar.
- **Tables:** 7 notes, GFM pipe tables with an alignment row, long cells (Russian prose), up to 5-6 columns.
- **Inline:** bold dominates; italic `*...*` appears a few times; backticked code includes generics like `` `Map<Int, Int>` `` (so no HTML handling needed; render literally). Trailing double-space line breaks: a handful.
- **Absent (do not implement):** frontmatter, images/embeds `![[...]]`, URLs, HTML tags, task lists, tags, highlights, comments, footnotes, `####` headings, nested callouts.
- Headings: `#` 23 (one per file, equals the title), `##` 97, `###` 48.

### Sync script (`tools/sync_notes`, Python 3, stdlib only)
- Usage: `python3 tools/sync_notes.py <vault_dir>` (or env `ALGOLINGO_VAULT`). No default path in the repo.
- For each `*.md`: NFC-normalize name and content, assign an ASCII file name `n00.md`...`n22.md` (stable by sorted NFC title; prefer deriving from a numeric prefix when present), write to `files/kb/`, delete stale files in that dir, then write `index.json` with `{id, title (NFC stem), section, file}`. Fail loudly if count != 23 is not wanted; instead print the count and the list of unresolved wikilinks as a report (informational).
- Section mapping is a hard-coded table in the script, in the display order from KB-02: Навигация = files starting `00`–`04`; Тренажёры = `05`, `06`; Задачи с собесов = `Алгоритмы Avito`, `Алгоритмы Glovo`, `Задачи с Avito`, `Задача от Яндекс со станциями`; Темы = the remaining 12. Unknown new files default to «Темы». The four "interview" assignments and the 12 topics are my reading of the titles, not verified against the note bodies [ASSUMED] (A1).
- Run `python3 -I` style isolation is not required for the project's own script, but never run it from inside a downloaded dir.
- Ids are ASCII file stems so `Res.readBytes("files/kb/$file")` works on iOS.

### Block parser (line-based, subset only)
Block types: `Heading(level, text)`, `Paragraph(text)`, `Bullet/Ordered` items with indent depth, `Code(lang, text)`, `Table(header, rows)`, `Quote(blocks)`, `Callout(type, foldable, collapsedByDefault, title, blocks)`, `Rule`.
Algorithm: iterate lines; fenced code first (``` open/close, keep inner text verbatim); a run of `>` lines strips one `> ` prefix and, if the first stripped line matches `^\[!(\w+)\]([-+]?)\s*(.*)$`, becomes a Callout, else a Quote; the stripped body is parsed by the same function recursively (this is how fences inside callouts work, since the fence is parsed after stripping, not before). A new `> [!` line after a blank line starts a separate callout, and a `>` run that contains a second `[!type]` line at its first position of a block should also split (end the current run at a blank line, which already separates them in the real notes). Tables: line starting `|` followed by an alignment row `^\|?[\s:-|]+$`; cell split respects `[[...]]` and backticks. Lists: `^(\s*)([-*]|\d+\.)\s`; depth = indent/2. Unknown constructs fall back to Paragraph (never throw).
Inline parser: scan for `` `code` `` (highest priority, so a `[[x]]` inside code stays literal), `**bold**`, `*italic*`, `[[target(#anchor)?(|alias)?]]`, else text. The link is `LinkAnnotation.Clickable(tag) { onLink(target, anchor) }` inside `buildAnnotatedString` (stable Compose text API; avoid deprecated `ClickableText`) [ASSUMED from training; confirm it compiles on CMP 1.12.2] (A2).

### Callouts
`AppColors` callout mapping (reuses the 03-UI-SPEC tints; proposal): question -> Focus blue, success -> Success green, warning -> Acceptable amber, important -> Wrong red, tip -> Success green, info -> Focus blue, note and unknown -> neutral `surfaceVariant`/`outline`. A collapsed callout shows only the title row with a chevron; tap toggles. Persist state with `rememberSaveable(noteId, calloutIndex)`. Non-foldable callouts always open. Code inside callouts uses the shared `CodeBlock`.

### Navigation and the "tab"
Phase 1 has no navigation and no tabs (verified: `App()` is a single hello screen). The success criterion says tab «База знаний». Minimal approach: top-level `NavHost` with `Home` (stub «Скоро уроки», replaced by Phase 3) and `KbList` shown through a material3 `NavigationBar` with two items; the bar is hidden on `Note`. Routes: `@Serializable object Home`, `object KbList`, `data class Note(val id: String, val anchor: String? = null)`, `object KbSearch` (or search field in the list screen, which is simpler and sufficient). Back: `navController.popBackStack()`; link taps `navigate(Note(...))`, so the back button returns to the previous note.

### Search
Hold all notes in memory (200 KB). Case-insensitive (`lowercase()` works for Cyrillic) substring match: title hits first, then body hits, with a short snippet around the first match. 23 notes, so no index and no debounce needed. A search field at the top of `KbList` switching the list to results is enough.

### Anchors
`[[Name#Heading]]`: after opening, find the heading Block whose text equals the anchor (trim and compare lowercase) and `LazyListState.scrollToItem(index)`. If not found, just open at the top. Cheap, and 2 real links use it.

### Theme and code highlighting
03-UI-SPEC is not implemented anywhere yet. Implement the part this phase needs: `AppTheme` (light and dark by `isSystemInDarkTheme()`), `AppColors` (including syntax colors and callout tints), Nunito 400/700 and JetBrains Mono 400/700 as `composeResources/font/*.ttf` (OFL, Cyrillic), and `highlight(code): AnnotatedString` (Kotlin keyword set plus regexes for string, number and `//` per STACK.md). Phase 3 reuses all of it. Code blocks: monospace, no wrap, `horizontalScroll`, background `surfaceVariant`. Only `kotlin` fences get highlighted; `text`, `java` and untagged render monochrome (untagged blocks in the notes are mostly diagrams or pseudo-output). The fonts are not on this machine (no Nunito/JetBrains Mono found); the plan needs a step to download the TTFs from the official OFL sources, with `FontFamily.Default`/`Monospace` as the fallback the UI-SPEC already allows. Emoji in headings fall back to the system emoji font.

## Common Pitfalls

1. **NFD filenames/targets** break link resolution (see the inventory). Normalize everything in the script, assert in a test that every index title is NFC-equal to itself, and look up wikilinks by lowercased title.
2. **Fence inside callout** parsed before stripping `>`. Strip the prefix first, then parse the body recursively.
3. **Pipes in table cells inside wikilink aliases** split the row. Split cells outside `[[...]]`/backticks.
4. **Crash on unresolved link or missing anchor.** Resolution returns null, render plain text; anchors fall back to top.
5. **Whole note as one `Text`** gets slow on the 39 KB note. Use a `LazyColumn` of blocks; callout bodies and tables are single items.
6. **Resource names:** non-ASCII names are unreliable in Compose Resources on iOS. ASCII ids only.
7. **No directory listing** for `files/`: the app discovers notes only through `index.json`; the script must regenerate it each run.
8. **Wide tables** overflow the phone: give columns a fixed min width and wrap the table in `horizontalScroll`. Cells hold wikilinks, so render cells through the same inline parser.
9. **Soft line breaks:** Obsidian shows single newlines inside a paragraph as breaks. Keep them (and the few trailing-double-space breaks).
10. **Public repo:** the 23 notes are personal study content that will become public in git. Confirm with the customer that committing them is acceptable (A3). Do not write the vault path anywhere in the repo.
