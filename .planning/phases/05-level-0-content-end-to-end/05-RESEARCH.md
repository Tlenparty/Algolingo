## Summary

Everything this phase needs is already in the repo. The note «05 Тренажёр решений» is bundled as `shared/src/commonMain/composeResources/files/kb/n07ed966c.md`, with an ASCII name and NFC text, and `tools/sync_notes.py` keeps it fresh. The lesson schema and `validate()` are frozen in `lesson/Model.kt`. `l0.4.json` is a hand-written reference. Home reads `content/index.json`, and its array order is the unlock order. So the generator should read the **bundled kb copy, not the vault**. That removes every Yandex.Disk and NFD problem and makes the golden test runnable anywhere. The generator should be a **Python 3.9 stdlib script, `tools/gen_content.py`**, written in the same style as `sync_notes.py`. Its output is committed. Gradle never runs it.

The sidecar is one Markdown file per lesson (`content/authoring/l0.N.md`). Each exercise contains the full reference function with `⟦ok | ~acceptable⟧` holes, then bullet lines for distractors (`` - `text`: why ``), per-hole overrides (`` - @2 `text`: why ``), acceptable notes (`` - ~`text`: note ``) and hints (`? …`). The note supplies the statement, 🎯, ⏱, the reference code, the complexity, ⚠️ Грабли and 🔁 Вариации. The sidecar supplies theory cards, holes, distractors and hints, and it can override any note-derived field. I verified that `json.dumps(lesson, ensure_ascii=False, indent=2) + "\n"` reproduces the current `l0.4.json` **byte for byte**. So the strongest acceptance test for the generator is: write `content/authoring/l0.4.md`, regenerate, and `git diff --exit-code` on `l0.4.json`.

For CONT-05, the generator also writes **one Kotlin `commonTest` file**. Each code variant goes into its own `private object`: the reference, plus each `ok`/`acceptable` substitution per hole. Each object gets one `@Test` that runs the sidecar's `examples:` assertions inside `with(obj) { … }`. The tested code is then exactly the code in the JSON, it runs on both the Android host and the iOS simulator, and no kotlinc is needed. For PLAT-03, Android has hard proof: `aapt2 dump permissions` on the current APK shows **no `android.permission.INTERNET`**, so the app cannot reach the network at all, and the walkthrough also runs in airplane mode. The iOS simulator has no per-device network switch, so iOS offline is shown statically: no networking dependency in `libs.versions.toml` and no URLSession/NSURL/ktor in the sources. The full four-lesson walkthrough is driven by the agent (adb uiautomator, idb), as in Phase 4.

**Primary recommendation:** Build `tools/gen_content.py` with a sidecar markup language, prove it by regenerating `l0.4.json` byte-identically, then author `l0.1`–`l0.3`, generate the reference tests, get the customer's approval through a `checkpoint:human-verify`, and finish with the scripted offline walkthrough on both platforms.

### Pattern 1: Note parser (line-based, no markdown lib)
Facts checked against the bundled note bytes [VERIFIED: codepoint dump]:
- Lesson section: from `^## 0\.N ` up to the next `^## ` or `^# ` or `^---`.
- Statement: the lines after the heading, up to the first `- 🎯` line. 0.4 gives exactly `Найди индекс \`target\` в **отсортированном** массиве за O(log n), иначе \`-1\`.`, which matches the current JSON.
- `- 🎯 **Тренируем:** X.` → `trains` with the trailing `.` stripped. 🎯 = U+1F3AF, no VS16.
- `- ⏱ **Цель:** N минут[аы].` → `targetTimeSec = N*60`. ⏱ = U+23F1, **no VS16** in this note, but match `⏱️?` anyway.
- Callouts: unprefix rule `line == ">"` → `""`, `line.startswith("> ")` → `line[2:]`, anything else ends the block. **Never** `lstrip('>')`, because the code contains `->` and `>=`.
- `[!question]-` callouts are note hints: 0.1:1, 0.2:1, **0.3:0**, 0.4:1. They are parsed for the golden test only, because sidecar hints are authored (l0.4 hints are edited versions of the note hint, not verbatim).
- `[!success]-` callout: the **first** ```` ```kotlin ```` fence is the reference. `**Сложность:**` comes in two forms, `время O(n), память O(1).` (0.1, 0.2) and `O(n) / O(1). См. …` (0.3, 0.4). Regex: `(O\([^)]*\))` twice.
- `⚠️ **Грабли:**` is `U+26A0 U+FE0F` [VERIFIED], so match `⚠️?\s*\*\*Грабли[^*]*:\*\*`. It is present in 0.1 and 0.4 only. Split it into items on `;\s+` or `(?<=\.)\s+(?=[А-ЯA-Z`])` and strip the trailing `.`. For 0.4 that gives exactly the two current pitfalls.
- `🔁 **Вариации:**` (U+1F501) is in 0.2 only. Gives `variations`.
- Leave wikilinks raw (`[[04 Маркеры + Заготовки|#3]]`). The runtime `parseInline` already renders them as alias text. Note that `trains` is not rendered anywhere in the UI today [VERIFIED: grep].

### Pattern 2: Sidecar grammar (concrete)
````markdown
# l0.4
note: 0.4 Бинарный поиск
examples:
- assertEquals(2, binarySearch(intArrayOf(1, 3, 5, 7), 5))
- assertEquals(-1, binarySearch(intArrayOf(1, 3), 0))
- assertEquals(0, binarySearch(intArrayOf(5), 5))
- assertEquals(-1, binarySearch(intArrayOf(), 1))

## theory Когда бинпоиск
signals:
- Массив отсортирован
- Нужно уложиться в O(log n)
- Ищем индекс или границу
body: Каждый шаг выбрасывает половину диапазона, поэтому O(log n).

## theory Каркас
skeleton:
```kotlin
var lo = 0
…
```
body: Инвариант: ответ, если он есть, всегда внутри `[lo, hi]`.

## theory Грабли
pitfalls:
- `lo < hi` вместо `<=` пропустит последний элемент
- `(lo + hi) / 2` может переполниться на больших индексах

## e2
```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = ⟦lo + (hi - lo) / 2 | ~(lo + hi) ushr 1⟧
        …full function…
}
```
- ~`(lo + hi) ushr 1`: работает, но эталон читаемее и не опирается на беззнаковый сдвиг
- `lo < hi`: при `lo == hi` цикл не зайдёт: `[5]`, target `5` вернёт `-1`
- `(lo + hi) / 2`: `lo + hi` переполняет `Int` …
- `hi - lo / 2`: выходит за `[lo, hi]` …
- @1 `(lo + hi) / 2`: `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- @2 `lo < hi`: `mid` станет `Boolean`, и `nums[mid]` не скомпилируется
? Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.
? Середина `mid = lo + (hi - lo) / 2` (защита от переполнения). Три ветки: нашли / ушли вправо / ушли влево.
````
Rules:
- `# <lessonId>` is the lesson id, and must equal the file stem. `note: <heading>` selects `## <heading>` in note 05. Optional overrides on that top section: `title:`, `statement:`, `trains:`, `caption:`, `pitfalls:` (bullets), `variations:` (bullets). Use `pitfalls:` for 0.2/0.3, which have no Грабли in the note.
- `## theory <title>`: card keys `signals:` (bullets), `skeleton:` (fence), `pitfalls:` (bullets), `body:` (one line). Emit keys in the fixed order **title, signals, skeleton, pitfalls, body**, omitting empty ones. That reproduces all three current l0.4 cards [VERIFIED: key order of l0.4.json].
- `## eK` gives exercise id `<lessonId>.eK`. One ```` ```kotlin ```` fence holds the **full** function. `⟦a | b | ~c⟧`: alternatives are separated by `" | "` (space-pipe-space); `~` marks acceptable; the first non-`~` entry is `ok[0]`. ponytail: `" | "` separator; level 0 has no `||` chip text, so revisit if it ever appears.
- Bullets: `` - `T`: why `` is a distractor chip with chip-level `why`. `` - `T` `` (no why) is allowed only if every hole has an `@H` override. `` - @H `T`: why `` is `holes[H-1].wrongWhy[T]`. `` - ~`T`: note `` is the acceptable note for the hole that lists `~T`. `? text` is a hint, in order.
- Bank order (this reproduces l0.4 exactly): `ok[0]` of each hole in hole order (**with multiplicity**, so two `1` holes give two `1` chips), then any other ok/acceptable texts not yet present, then distractors in bullet order.
- JSON key order: lesson `schema,id,level,title,statement,trains,targetTimeSec,theory,exercises,solution`; exercise `id,segments,holes,bank,hints`; hole `ok,acceptable,wrongWhy` (omit empty); chip `text,why`; solution `code,time,space,pitfalls,variations` (`variations: []` is kept even when empty, as in l0.4). Write with `json.dumps(obj, ensure_ascii=False, indent=2) + "\n"`.

### Pattern 3: Drift check (CONT-02 "markup without holes = note reference")
For each exercise: strip `⟦…⟧` → `ok[0]`. That gives `code`. Compare it with the note's first kotlin fence, after normalizing both sides per line with `re.sub(r"\s*//.*$", "", line).rstrip()`. Compare the whole text, not a fragment. All exercises of a lesson must produce the **same** `code`. That becomes `solution.code`, which is what `validate()` requires: segments + ok[0] == solution.code for every exercise.
- Why ignore comments: 0.1 has `var max = nums[0]            // не 0! массив может быть весь отрицательный`, which **gives away the e1 answer**, so the sidecar drops it. ponytail: the `//` stripper assumes no `//` inside string literals, which is true for level 0.

### Pattern 4: Generated reference test (CONT-05)
```kotlin
// GENERATED by tools/gen_content.py from content/authoring/*.md. Do not edit; rerun the generator.
package com.tlenparty.algolingo.lesson

import kotlin.test.Test
import kotlin.test.assertEquals

private object L0_4_v0 { // reference
fun binarySearch(nums: IntArray, target: Int): Int { … }
}
private object L0_4_v1 { // l0.4.e2 hole 2 = (lo + hi) ushr 1 (acceptable)
fun binarySearch(nums: IntArray, target: Int): Int { … }
}

class ReferenceSolutionsTest {
    @Test fun l0_4_v0() { with(L0_4_v0) { assertEquals(2, binarySearch(intArrayOf(1, 3, 5, 7), 5)); … } }
    @Test fun l0_4_v1() { with(L0_4_v1) { … } }
}
```
- Variants: the reference, plus for every exercise, hole and text in `ok[1:] + acceptable` the code with only that hole substituted (other holes at `ok[0]`), **deduped by code text**. Level 0 gives 4 references plus about 4–5 variants: `Int.MIN_VALUE`, `l <= r` ×2 (0.2, 0.3) and `ushr`, deduped across exercises.
- Inside `with(obj)` the member wins, so `reverse(arr)` calls the object's function, not the stdlib extension `CharArray.reverse()`. Use block-bodied `@Test` functions that return Unit (safe on Kotlin/Native).
- Example idioms: `assertEquals(-7 to -2, sumAndMax(intArrayOf(-5, -2)))`; mutating `reverse`: `assertEquals("dcba", charArrayOf('a','b','c','d').also { reverse(it) }.concatToString())`.
- Distractors are **not** compiled. Many are type errors by design. ponytail: the "distractor that actually passes" check (PITFALLS #1) is left to manual tracing and customer review. Add a `!run` flag per distractor if a bad one ever ships.

### Pattern 5: `--check` mode = golden test hook
`gen_content.py --check` renders everything in memory and diffs it against the files on disk (index, lessons, generated test). It exits 1 and lists stale files. `test_gen_content.py` calls it, so "committed output is up to date with the sources" is a test.

### Anti-patterns to avoid
- Reading the vault from the generator. Use the bundled kb copy. Refreshing it is `sync_notes.py`'s job.
- Partial code snippets in sidecar exercises. `validate()` requires that every exercise rebuilds the **whole** `solution.code`.
- A chip-level `why` that only makes sense in one hole (Phase 2 WR-04). If a distractor can land in a hole where its `why` is wrong (type mismatch, a different line), add an `@H` override.
- Putting a correct-but-different answer in the bank as a distractor. Examples: `x >= max` in 0.1, `s.lastIndex` for `s.size - 1`. Either leave such a chip out or make it ok/acceptable.
- Extra JSON keys such as `source`. LessonContentTest decodes **strictly** (`ignoreUnknownKeys = false`).

## Content drafts (CONT-03/04). Counterexamples traced by hand; all need customer review

Ladder for all four lessons: 1 → 2 → 4 holes, the same as l0.4.

**l0.1 Сумма и максимум** (sidecar code without the `// не 0!` comment):
- e1: `var max = ⟦nums[0] | ~Int.MIN_VALUE⟧`. Distractors:
  - `0`: «`[-5, -2]` вернёт max `0`, а такого элемента нет»
  - `Int.MAX_VALUE`: «`x > max` никогда не сработает: `[1, 2]` вернёт max `2147483647`»
  - `nums[1]`: «на `[7]` — выход за границы массива»
  - `~Int.MIN_VALUE` note: «работает, но на пустом массиве молча вернёт `Int.MIN_VALUE` вместо ошибки; `nums[0]` честнее» [ASSUMED wording]
- e2: + `var sum = ⟦0⟧`. **Needs `@2` `0`** («`[-5, -2]` вернёт max `0`»), because `0` is correct in hole 1, so `validate()` will not force a why.
- e3 (4 holes): `⟦0⟧`, `⟦nums[0]⟧`, `sum ⟦+=⟧ x`, `if (x ⟦>⟧ max)`. Distractors:
  - `=`: «`[1, 2]` даст sum `2`»
  - `<`: «найдёт минимум: `[1, 3]` вернёт max `1`»
  - Each needs an `@H` "не скомпилируется" in the value holes.
  - Do **not** offer `>=`, which gives the same results.
- Theory sources: 03 §1.1/1.2 (signals «пройти и накопить», «найти max/min без сортировки → линейный проход»), 00 §4 (O(n)/O(1)), note 0.1 hint (max starts from the first element). Cards: «Когда один проход» (signals), «Каркас» (skeleton `var acc = …\nfor (x in nums) { … }`), «Грабли» (`max = 0` on `[-5, -2]`; empty array, ask the interviewer).

**l0.2 Разворот строки** (no Грабли in the note, so write `pitfalls:` in the sidecar):
- e1: `while (⟦l < r | ~l <= r⟧)`. Distractors:
  - `l > r`: «цикл не выполнится: `abcd` останется `abcd`»
  - `l != r`: «на чётной длине указатели разминутся: `abcd` → выход за границы»; traced: (2,1),(3,0) swap back, then `s[4]`
  - `~l <= r` note, from the note's hint: «работает, но на нечётной длине средний символ меняется сам с собой — лишний шаг»
- e2: + `var r = ⟦s.size - 1⟧`. Distractor `s.size`: «первый же `s[r]` вне массива: `abcd` → `s[4]`». Do not offer `s.lastIndex`, which is correct.
- e3: `while (⟦l < r⟧)`, `s[r] = ⟦t⟧`, `⟦l++⟧; ⟦r--⟧`. Distractors:
  - `s[l]`: «`s[l]` уже перезаписан: `ab` → `bb`»
  - `l--`: «указатели расходятся: `abcd` → `s[-1]`»
  - `r++`: «`abcd` → `s[4]`»
- Theory: 04 §3 (markers «палиндром», «развернуть/симметрия»; skeleton `var l = 0; var r = n - 1\nwhile (l < r) { … }`; the ⚠️ `l < r` warning; 🗣 phrase) and 03 §1.3.

## Common Pitfalls

### P1: Lesson-level `why` explains the wrong line
**What goes wrong:** a chip's `why` is right for its intended hole but wrong in another hole. This happened in Phase 2 WR-04.
**Avoid:** for every distractor, ask "can it land in every hole, and is the why true there?" If not, add `@H`. Pay special attention to Boolean-vs-Int holes, which need "не скомпилируется".

### P2: A correct chip in the wrong hole shows no explanation
**What goes wrong:** `validate()` doesn't require a why for "used" texts, so the result is only «Верно: X».
**Avoid:** add `@H` for the teaching-critical swaps, such as `0` in the max hole in 0.1 and `false`/`true` in 0.3.

### P3: A distractor that is actually correct
**Examples:** `x >= max`, `s.lastIndex`, `l <= r` in reverse.
**Avoid:** leave them out of the bank, or make them `~` acceptable. Trace every counterexample by hand. The generated tests only cover ok/acceptable.

### P4: Emoji VS16 and `>` handling
**Avoid:** `⚠️?`; the unprefix rule from Pattern 1. The golden test pins the parsed fields for all 4 sections.

### P5: Strict decode
LessonContentTest uses `ignoreUnknownKeys = false`, so any extra key fails CI. Generator output must use the schema keys only.

### P6: The `l0.4.json` diff
If regeneration is not byte-identical, the generator's bank order, key order or formatting is wrong. Fix the generator, not the JSON. The existing assertions (holes [1,2,4], two `1` chips) must keep passing.

### P7: Physical phone attached
`adb devices` shows a physical phone (`3B15CV00B1X00000`) next to `emulator-5554` [VERIFIED]. **Every** adb command needs `-s emulator-5554`, and zsh does not word-split variables (Phase 4), so write the literal commands.

### P8: idb not on PATH
Use the full path `/Users/user/.venvs/idb/bin/idb`. Edge swipes don't work, so use on-screen back.

### P9: Network off on the walkthrough host
Do not disable the Mac's network. On Android use airplane mode, then `airplane-mode disable` afterwards.

```python
# Source: derived from the bundled note format (verified bytes) + PITFALLS #5
def unquote(lines):
    out = []
    for ln in lines:
        if ln == ">": out.append("")
        elif ln.startswith("> "): out.append(ln[2:])
        else: break
    return out

def section(note_lines, heading):            # heading e.g. "0.4 Бинарный поиск"
    start = note_lines.index("## " + heading) + 1
    end = next((i for i in range(start, len(note_lines))
                if note_lines[i].startswith(("## ", "# ", "---"))), len(note_lines))
    return note_lines[start:end]
```

### Hole split
```python
HOLE = re.compile(r"⟦(.*?)⟧")
def split_holes(code):
    segs, holes, pos = [], [], 0
    for m in HOLE.finditer(code):
        segs.append(code[pos:m.start()]); pos = m.end()
        alts = [a.strip() for a in m.group(1).split(" | ")]
        holes.append(([a for a in alts if not a.startswith("~")], [a[1:] for a in alts if a.startswith("~")]))
    segs.append(code[pos:])
    return segs, holes   # stripped code = segs interleaved with ok[0]
```
