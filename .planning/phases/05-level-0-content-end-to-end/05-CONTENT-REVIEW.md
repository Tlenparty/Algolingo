# Уровень 0 «Разминка» — ревью контента (CONT-06)

Ниже всё, что войдёт в приложение для уроков 0.1–0.4. Текст собран из сгенерированных JSON. Дырки в коде показаны как ⟦верный ответ⟧. «Принято, но…» — ответ засчитывается, но с пометкой. Для неверных облачков указана причина (why); пометка «(дырка N)» значит, что этот текст показывается, только если облачко поставлено в N-ю дырку.

Как ответить: напиши «approved» или список правок в формате «урок → что → новый текст / добавить / убрать облачко».

## Решения на подтверждение

1. **`l <= r` засчитывается с пометкой в 0.2 и 0.3** (e1 и e2 в 0.2, e1 в 0.3; в e3 принимается только `l < r`). Шпаргалка 04 §3 называет `<=` ошибкой, и карточка теории 0.2 это объясняет. Проверь формулировки:
   - 0.2: «работает, но на нечётной длине средний символ меняется сам с собой: `abc` делает лишний шаг на `b`»
   - 0.3: «работает, но на нечётной длине средний символ сравнится сам с собой: `"aba"` делает лишний шаг на `b`»
   - теория 0.2: «В шпаргалке 04 `<=` назван ошибкой: элемент возьмётся дважды. В развороте это безвредный лишний шаг, поэтому здесь `l <= r` засчитывается с пометкой.»
2. **Пометка к `Int.MIN_VALUE` (0.1, дырка `max`):** «работает, но на пустом массиве молча вернёт max `Int.MIN_VALUE` вместо ошибки; `nums[0]` честнее».
3. **Пометка к `ushr` (0.4 e2, дырка `mid`):** `(lo + hi) ushr 1` засчитывается с текстом «работает, но эталон читаемее и не опирается на беззнаковый сдвиг». Это решение A4 из фазы 2, оно ещё открыто.
4. **Карточки теории 0.1–0.3:** по три карточки на урок («Когда…», «Каркас», «Грабли»), полный текст в разделах уроков ниже.
5. **Тексты 0.4, которые в фазе 2 помечены «нужно проверить человеку»:**
   - WR-04, e3, `0` в `return ⟦⟧`: «вернёт `0` вместо найденного индекса: `[1, 3]`, target `3` даст `0`»
   - WR-04, e3, `-1` в `return ⟦⟧`: «скажет «не найдено», хотя элемент есть: `[5]`, target `5` даст `-1`»
   - WR-04, e3, `0` в `hi = mid - ⟦⟧`: «`hi = mid - 0` не исключает `mid`: `[1, 3]`, target `0` — `hi = 0`, `mid` снова `0`, цикл бесконечный»
   - WR-04, e3, `-1` в `hi = mid - ⟦⟧`: «`hi = mid - -1 = mid + 1` не сужает диапазон: `[1, 3]`, target `0` — `mid = 0`, `hi` снова `1`, цикл бесконечный»
   - IN-01, e3, `1` в `return ⟦⟧`: «вернёт константу `1`, а не индекс: `[5]`, target `5` даст `1` — такого индекса нет»
   - IN-01, e3, `mid` в `lo = mid + ⟦⟧`: «`lo = mid + mid` = 2·`mid`: `[1, 3]`, target `3` — `mid = 0`, `lo` остаётся `0`, цикл бесконечный»
   - IN-01, e3, `mid` в `hi = mid - ⟦⟧`: «`hi = mid - mid` всегда `0`: `[1, 3, 5, 7, 9]`, target `3` — `hi = 0`, вернёт `-1`»
   - IN-02, e1, `lo != hi`: «при `lo == hi` цикл останавливается, не проверив последний кандидат: `[1, 3]`, target `3` вернёт `-1`; а если `hi` уйдёт ниже `lo`, условие останется истинным: `[1, 3]`, target `0` зацикливается»

Также для сведения (подтверждать не нужно, если устраивает):
- **0.2 e3:** дырки сделаны как `l⟦++⟧; r⟦--⟧`, а не `⟦l++⟧; ⟦r--⟧`. Проверка идёт по каждой дырке отдельно, и равносильный ответ `r--; l++` иначе был бы засчитан как ошибка. Неверные варианты здесь — перепутанные `--` / `++`.
- Если облачко, верное в другой дырке, поставить не туда и оно просто не компилируется, приложение покажет только «Верно: X» без объяснения. Это сделано намеренно.
- Поле «Тренирует» в 0.2 содержит ссылку Obsidian `[[04 Маркеры + Заготовки|#3]]`. Сейчас это поле в приложении не показывается.

## 0.1 Сумма и максимум

*Верни сумму всех чисел массива и (отдельно) максимальный элемент.* Тренирует: базовый линейный проход с аккумулятором. Цель: 60 с.

### Теория

**1. Когда один проход**
- сигнал: «Пройти и накопить»: сумма, счётчик
- сигнал: «Найти max/min» без сортировки
Один `for` и одна переменная-аккумулятор: время O(n), память O(1). Никакой структуры данных не нужно.

**2. Каркас**
```kotlin
var acc = start
for (x in nums) {
    // обновить acc по x
}
```
Старт для суммы — `0`, для максимума — первый элемент `nums[0]`.

**3. Грабли**
- грабли: `max = 0` ломается на `[-5, -2]`: вернёт `0`, а такого элемента нет
- грабли: Пустой массив: уточни у интервьюера, что делать (исключение или `null`)

### e1 — дырок: 1

```kotlin
fun sumAndMax(nums: IntArray): Pair<Int, Int> {
    var sum = 0
    var max = ⟦nums[0]⟧
    for (x in nums) {
        sum += x
        if (x > max) max = x
    }
    return sum to max
}
```
- дырка 1: верно `nums[0]`
  - принято, но… `Int.MIN_VALUE` — работает, но на пустом массиве молча вернёт max `Int.MIN_VALUE` вместо ошибки; `nums[0]` честнее

Облачка: `nums[0]`, `Int.MIN_VALUE`, `0`, `Int.MAX_VALUE`, `nums[1]`
- `0` — на отрицательных числах `x > max` не сработает: `[-5, -2]` вернёт max `0`, а такого элемента нет
- `Int.MAX_VALUE` — `x > max` никогда не сработает: `[1, 2]` вернёт max `2147483647`
- `nums[1]` — на массиве из одного элемента выход за границы: `[7]` упадёт на `nums[1]`

Подсказки:
1. Максимум инициализируй **первым элементом**, не нулём: числа могут быть отрицательными.

## 0.2 Разворот строки

*Переверни `CharArray`: `abcd` → `dcba`. Без создания новой строки.* Тренирует: два указателя навстречу (скелет [[04 Маркеры + Заготовки|#3]]). Цель: 120 с.

### Теория

**1. Когда два указателя навстречу**
- сигнал: «Развернуть / симметрия»
- сигнал: «Палиндром»
- сигнал: Отсортированный массив + «пара / сумма»
Указатели стоят по краям и идут навстречу, обрабатывая пару `s[l]`, `s[r]`: время O(n), память O(1).

**2. Каркас**
```kotlin
var l = 0
var r = n - 1
while (l < r) {
    // обработать пару s[l], s[r]
    l++; r--
}
```
В шпаргалке 04 `<=` назван ошибкой: элемент возьмётся дважды. В развороте это безвредный лишний шаг, поэтому здесь `l <= r` засчитывается с пометкой.

**3. Грабли**
- грабли: `r = s.size`: первый же `s[r]` вне массива
- грабли: `l != r` на чётной длине: указатели проскочат друг друга, `abcd` → `s[4]`
- грабли: Обмен без временной переменной: `s[l] = s[r]; s[r] = s[l]` превратит `ab` в `bb`

### e1 — дырок: 1

```kotlin
fun reverse(s: CharArray) {
    var l = 0
    var r = s.size - 1
    while (⟦l < r⟧) {
        val t = s[l]; s[l] = s[r]; s[r] = t
        l++; r--
    }
}
```
- дырка 1: верно `l < r`
  - принято, но… `l <= r` — работает, но на нечётной длине средний символ меняется сам с собой: `abc` делает лишний шаг на `b`

Облачка: `l < r`, `l <= r`, `l > r`, `l != r`
- `l > r` — цикл не выполнится ни разу: `abcd` останется `abcd`
- `l != r` — на чётной длине указатели проскочат друг друга: `abcd` → выход за границы на `s[4]`

Подсказки:
1. `l = 0`, `r = n - 1`, меняем местами, пока `l < r`.
2. Именно `<`: при `<=` средний символ поменяется сам с собой (не страшно, но лишний шаг).

### e3 — дырок: 4


1. Обмен через временную `t`: `s[l]` к этому моменту уже перезаписан.
2. Левый указатель идёт вправо (`l++`), правый — влево (`r--`).

- грабли: `l <= r` работает, но на нечётной длине средний символ меняется сам с собой: лишний шаг
- грабли: `r = s.size` вместо `s.size - 1`: первый же `s[r]` вне массива
- грабли: `l != r`: на чётной длине указатели проскочат друг друга и выйдут за границы
- вариация: проверка палиндрома — тот же скелет, но вместо swap сравниваем `s[l] != s[r] → return false`

## 0.3 Палиндром

*Читается ли строка одинаково с обеих сторон? (считаем, что регистр и пробелы уже неважны)* Тренирует: два указателя навстречу как проверка. Цель: 120 с.

### Теория

**1. Тот же скелет**
- сигнал: «Палиндром / симметрия»
- сигнал: «Читается одинаково с обеих сторон»
Скелет разворота из 0.2, только вместо обмена сравниваем пару: `s[l] != s[r]` — сразу `return false`. Время O(n), память O(1).

**2. Каркас**
```kotlin
var l = 0
var r = n - 1
while (l < r) {
    // пара не сходится -> сразу ответ
    l++; r--
}
// дошли до середины -> ответ
```
Как и в 0.2, `l <= r` засчитывается с пометкой: средний символ лишний раз сравнится сам с собой.

**3. Грабли**
- грабли: `r = s.length`: первый же `s[r]` вне строки
- грабли: `l != r` на чётной длине: указатели проскочат друг друга, `"abba"` → `s[4]`
- грабли: Перепутать ответы: на несовпадении `false`, после цикла `true`

### e1 — дырок: 1

```kotlin
fun isPalindrome(s: String): Boolean {
    var l = 0
    var r = s.length - 1
    while (⟦l < r⟧) {
        if (s[l] != s[r]) return false
        l++; r--
    }
    return true
}
```
- дырка 1: верно `l < r`
  - принято, но… `l <= r` — работает, но на нечётной длине средний символ сравнится сам с собой: `"aba"` делает лишний шаг на `b`

Облачка: `l < r`, `l <= r`, `l > r`, `l != r`
- `l > r` — цикл не выполнится ни разу: `"ab"` вернёт `true`
- `l != r` — на чётной длине указатели проскочат друг друга: `"abba"` → выход за границы на `s[4]`

Подсказки:
1. Указатели с краёв идут навстречу, пока `l < r`.

### e2 — дырок: 2

Подсказки:
1. Нашли несовпадающую пару — дальше смотреть незачем: сразу `return false`.

```kotlin
}
```
- дырка 1: верно `s.length - 1`
- дырка 2: верно `l < r`
- дырка 3: верно `!=`
- дырка 4: верно `true`

Облачка: `s.length - 1`, `l < r`, `!=`, `true`, `s.length`, `false`, `==`
- `s.length` — первый же `s[r]` вне строки: `"aba"` → `s[3]`
- `==` — условие перевёрнуто: `"aba"` вернёт `false`
- `false` (дырка 1) — `r` должен быть индексом `Int`, а не `Boolean`: `l < r` не скомпилируется
- `==` (дырка 1) — `var r = ==` не скомпилируется: здесь нужен индекс последнего символа
- `s.length` (дырка 2) — `while` ждёт `Boolean`, а `s.length` — `Int`: не скомпилируется
- `false` (дырка 2) — `while (false)` не выполнится ни разу: `"ab"` вернёт `true`
- `==` (дырка 2) — `while (==)` не скомпилируется: здесь нужно условие `l < r`
- `true` (дырка 2) — `while (true)` не остановится в середине: `"aba"` → выход за границы на `s[3]`
- `s.length` (дырка 3) — `s[l] s.length s[r]` не скомпилируется: здесь нужен оператор сравнения
- `false` (дырка 3) — `s[l] false s[r]` не скомпилируется: здесь нужен оператор сравнения
- `s.length` (дырка 4) — функция возвращает `Boolean`, а `s.length` — `Int`: не скомпилируется
- `false` (дырка 4) — на палиндроме ответ всё равно «нет»: `"aba"` вернёт `false`
- `==` (дырка 4) — `return ==` не скомпилируется: здесь нужен ответ `Boolean`
- `l < r` (дырка 4) — после цикла `l < r` всегда ложно: `"aba"` вернёт `false`

Подсказки:
1. `r` — индекс последнего символа: `s.length - 1`.
2. Нашли несовпадающую пару — сразу `return false`.
3. Цикл дошёл до середины без расхождений — строка палиндром: `return true`.

### Разбор (O(n) / O(1))

- грабли: `l <= r` работает, но на нечётной длине средний символ сравнивается сам с собой: лишний шаг
- грабли: `r = s.length` вместо `s.length - 1`: первый же `s[r]` вне строки
- грабли: `l != r`: на чётной длине указатели проскочат друг друга и выйдут за границы
- грабли: Перепутать ответы: на несовпадении — `false`, после цикла — `true`

## 0.4 Бинарный поиск

*Найди индекс `target` в **отсортированном** массиве за O(log n), иначе `-1`.* Тренирует: каркас бинпоиска и инвариант «ответ всегда внутри `[lo, hi]`». Цель: 180 с.

### Теория

**1. Когда бинпоиск**
- сигнал: Массив отсортирован
- сигнал: Нужно уложиться в O(log n)
- сигнал: Ищем индекс или границу
Каждый шаг выбрасывает половину диапазона, поэтому O(log n).

**2. Каркас**
```kotlin
var lo = 0
var hi = nums.size - 1
while (lo <= hi) {
    val mid = lo + (hi - lo) / 2
    // нашли / вправо / влево
}
```
Инвариант: ответ, если он есть, всегда внутри `[lo, hi]`.

**3. Грабли**
- грабли: `lo < hi` вместо `<=` пропустит последний элемент
- грабли: `(lo + hi) / 2` может переполниться на больших индексах

### e1 — дырок: 1

```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = lo + (hi - lo) / 2
        when {
            nums[mid] == target -> return mid
            nums[mid] < target  -> lo = mid + 1
            else                -> hi = mid - 1
        }
    }
    return -1
}
```
- дырка 1: верно `lo <= hi`

Облачка: `lo <= hi`, `lo < hi`, `lo != hi`, `lo >= hi`
- `lo < hi` — при `lo == hi` цикл не зайдёт и последний кандидат пропущен: `[5]`, target `5` вернёт `-1`
- `lo != hi` — при `lo == hi` цикл останавливается, не проверив последний кандидат: `[1, 3]`, target `3` вернёт `-1`; а если `hi` уйдёт ниже `lo`, условие останется истинным: `[1, 3]`, target `0` зацикливается
- `lo >= hi` — условие ложно с самого начала: на `[1, 3]`, target `1` цикл не выполнится ни разу

Подсказки:
1. Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.

### e2 — дырок: 2

```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = ⟦lo + (hi - lo) / 2⟧
        when {
            nums[mid] == target -> return mid
            nums[mid] < target  -> lo = mid + 1

        }
    }
    return -1
}
```
- дырка 1: верно `lo <= hi`
- дырка 2: верно `lo + (hi - lo) / 2`
  - принято, но… `(lo + hi) ushr 1` — работает, но эталон читаемее и не опирается на беззнаковый сдвиг

Облачка: `lo <= hi`, `lo + (hi - lo) / 2`, `(lo + hi) ushr 1`, `lo < hi`, `(lo + hi) / 2`, `hi - lo / 2`
- `lo < hi` — при `lo == hi` цикл не зайдёт: `[5]`, target `5` вернёт `-1`
- `(lo + hi) / 2` — `lo + hi` переполняет `Int` на больших индексах: при `lo = hi = 2_000_000_000` сумма уходит в минус
- `hi - lo / 2` — выходит за `[lo, hi]`: при `lo = 5`, `hi = 5` получится `3 < lo`
- `(lo + hi) / 2` (дырка 1) — `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- `hi - lo / 2` (дырка 1) — `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- `lo < hi` (дырка 2) — `mid` станет `Boolean`, и `nums[mid]` не скомпилируется

Подсказки:
1. Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.
2. Середина `mid = lo + (hi - lo) / 2` (защита от переполнения). Три ветки: нашли / ушли вправо / ушли влево.

### e3 — дырок: 4

```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = lo + (hi - lo) / 2
        when {
            nums[mid] == target -> return ⟦mid⟧
            nums[mid] < target  -> lo = mid + ⟦1⟧
            else                -> hi = mid - ⟦1⟧
        }
    }
    return -1
}
```
- дырка 1: верно `lo <= hi`
- дырка 2: верно `mid`
- дырка 3: верно `1`
- дырка 4: верно `1`

Облачка: `lo <= hi`, `mid`, `1`, `1`, `lo < hi`, `0`, `-1`
- `lo < hi` — при `lo == hi` цикл не зайдёт: `[5]`, target `5` вернёт `-1`
- `0` — `lo = mid + 0` зацикливается: на `[1, 3]`, target `3` `lo` остаётся `0` навсегда
- `-1` — `lo = mid + -1` уводит границу назад: на `[1, 3]`, target `3` `lo = -1`, `mid` снова `0`, цикл бесконечный
- `0` (дырка 1) — `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- `-1` (дырка 1) — `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- `0` (дырка 2) — вернёт `0` вместо найденного индекса: `[1, 3]`, target `3` даст `0`
- `-1` (дырка 2) — скажет «не найдено», хотя элемент есть: `[5]`, target `5` даст `-1`
- `lo < hi` (дырка 2) — здесь нужен `Int`, а `lo < hi` — `Boolean`: не скомпилируется
- `1` (дырка 2) — вернёт константу `1`, а не индекс: `[5]`, target `5` даст `1` — такого индекса нет
- `lo < hi` (дырка 3) — здесь нужен `Int`, а `lo < hi` — `Boolean`: не скомпилируется
- `mid` (дырка 3) — `lo = mid + mid` = 2·`mid`: `[1, 3]`, target `3` — `mid = 0`, `lo` остаётся `0`, цикл бесконечный
- `0` (дырка 4) — `hi = mid - 0` не исключает `mid`: `[1, 3]`, target `0` — `hi = 0`, `mid` снова `0`, цикл бесконечный
- `-1` (дырка 4) — `hi = mid - -1 = mid + 1` не сужает диапазон: `[1, 3]`, target `0` — `mid = 0`, `hi` снова `1`, цикл бесконечный
- `lo < hi` (дырка 4) — здесь нужен `Int`, а `lo < hi` — `Boolean`: не скомпилируется
- `mid` (дырка 4) — `hi = mid - mid` всегда `0`: `[1, 3, 5, 7, 9]`, target `3` — `hi = 0`, вернёт `-1`

Подсказки:
1. Середина `mid = lo + (hi - lo) / 2` (защита от переполнения). Три ветки: нашли / ушли вправо / ушли влево.
2. Если нашли, возвращаем `mid`; иначе сдвигаем границу за `mid`: `lo = mid + 1` или `hi = mid - 1`.

### Разбор (O(log n) / O(1))

- грабли: `lo < hi` вместо `<=` пропустит последний элемент
- грабли: `(lo + hi) / 2` может переполниться на больших индексах
