========================================================================
l0.4  Бинарный поиск  (Python)
========================================================================
Условие: Найди индекс `target` в **отсортированном** списке за O(log n), иначе `-1`.
Тренирует: каркас бинпоиска и инвариант «ответ всегда внутри `[lo, hi]`»

Примеры:
  binary_search([1, 3, 5, 7], 5) == 2
  binary_search([1, 3], 0) == -1
  binary_search([5], 5) == 0
  binary_search([], 1) == -1

--- Теория ---

[Когда бинпоиск]
  сигнал: Список отсортирован
  сигнал: Нужно уложиться в O(log n)
  сигнал: Ищем индекс или границу
  Каждый шаг выбрасывает половину диапазона, поэтому O(log n) по времени и O(1) по памяти. Инвариант: ответ, если он есть, всегда внутри `[lo, hi]`; цикл идёт, пока диапазон не пуст.

[Каркас]
  каркас:
    | lo, hi = 0, len(nums) - 1
    | while lo <= hi:
    |     mid = (lo + hi) // 2
    |     # нашли / вправо: lo = mid + 1 / влево: hi = mid - 1
    | return -1
  Середина — только целочисленным делением `//`: `/` в Python всегда даёт `float`, а индекс `nums[1.5]` или даже `nums[0.0]` — это `TypeError`. Переполнения `int` в Python нет: числа растут сколько нужно, поэтому `(lo + hi) // 2` безопасно. Запись `lo + (hi - lo) // 2` — привычка из Kotlin/Java, где `lo + hi` может переполнить `Int`; здесь она тоже верна, но не обязательна.

[Грабли]
  грабли: `lo < hi`: при `lo == hi` цикл не заходит, последний кандидат пропущен: `[5]`, `5` → `-1`
  грабли: `/` вместо `//`: `[1, 3, 5, 7]`, `5` → `mid = 1.5`, `TypeError: list indices must be integers or slices, not float`
  грабли: `lo = mid` или `hi = mid` без `± 1`: `[1, 3]`, `3` → `mid = 0`, `lo` остаётся `0`, цикл бесконечный
  грабли: Отрицательный индекс в Python не ошибка: `nums[-1]` — последний элемент. Если `hi` уйдёт ниже нуля, вместо `IndexError` получите зацикливание или неверный ответ
  грабли: `hi = len(nums)` при `lo <= hi`: на `[]` цикл заходит и читает `nums[0]` — `IndexError`

    | def binary_search(nums: list[int], target: int) -> int:
    |     lo, hi = 0, len(nums) - 1
    |     while lo <= hi:
    |         mid = (lo + hi) // 2
    |         if nums[mid] == target:
    |             return mid
    |         elif nums[mid] < target:
    |             lo = mid + 1
    |         else:
    |             hi = mid - 1
    |     return -1
  Грабли:
    - `lo < hi` вместо `<=` пропустит последний кандидат: `[5]`, `5` → `-1`
    - `/` вместо `//`: в Python `/` всегда даёт `float`, и `nums[1.5]` (и даже `nums[0.0]`) падает с `TypeError`
    - `lo = mid` / `hi = mid` без `± 1`: граница не сдвигается, цикл бесконечный
    - Отрицательный индекс не падает: `nums[-1]` в Python — последний элемент, поэтому ошибка в границах часто даёт не `IndexError`, а зацикливание или неверный ответ
  Вариации:
    - в проде: `bisect.bisect_left(nums, target)` и проверка `i < len(nums) and nums[i] == target` — на собесе покажи цикл
    - первое вхождение при дублях: на совпадении не `return`, а запомнить `mid` и идти влево `hi = mid - 1`
    - граница «первый элемент `>= target`» (lower bound): полуинтервал `[lo, hi)`, `hi = len(nums)`, `while lo < hi`

========================================================================
l1.1  Есть ли дубликат  (Python)
========================================================================
Условие: Верни `True`, если в списке есть хоть один повтор, иначе `False`.
Тренирует: множество `set()` «уже видели» и ранний выход

Примеры:
  has_duplicate([1, 2, 3]) is False
  has_duplicate([1, 2, 1]) is True
  has_duplicate([]) is False
  has_duplicate([7, 7]) is True

--- Теория ---

[Когда множество]
  сигнал: «Есть ли повтор?», «видели ли раньше?»
  сигнал: Важно только наличие элемента, не количество
  сигнал: Нужно уложиться в O(n)
  `set` отвечает на `x in seen` в среднем за O(1), поэтому весь проход — O(n) по времени и O(n) по памяти. Повтор нашли — сразу `return True`, дальше смотреть незачем.

[Каркас]
  каркас:
    | seen = set()
    | for x in nums:
    |     if x in seen:
    |         return True
    |     seen.add(x)
    | return False
  Сначала проверка, потом добавление. В Kotlin `add` сам говорит, был ли элемент, а в Python `seen.add(x)` всегда возвращает `None`, поэтому проверка `x in seen` идёт отдельной строкой. Пустое множество — только `set()`: `{}` — это пустой словарь.

[Грабли]
  грабли: `seen = {}`: это словарь, у него нет `add`: `[1, 2, 3]` → `AttributeError: 'dict' object has no attribute 'add'`
  грабли: `if seen.add(x):` — `add` возвращает `None`, условие всегда ложно: `[1, 2, 1]` → `False`
  грабли: Сначала `seen.add(x)`, потом `x in seen`: проверка всегда истинна, `[1, 2, 3]` → `True`
  грабли: `seen = []` и `seen.append(x)`: ответ верный, но `in` по списку линейный — снова O(n²)
  грабли: Ответ строго `True`/`False`: вернуть `seen` или `None` — не то же самое, даже если в `if` они ведут себя похоже

    [{}]: пустой словарь в `if` — ложь, условие не сработает никогда: `[1, 2, 1]` → `False` вместо `True`
    [[]]: пустой список в `if` — ложь, условие не сработает никогда: `[1, 2, 1]` → `False` вместо `True`
  Почему неверно в дырке _3_:
    [set()]: вернём пустое множество, а не `bool`: `[1, 2, 1]` → `set()` вместо `True`
    [False]: повтор нашли, а вернули «повторов нет»: `[1, 2, 1]` → `False` вместо `True`
    [{}]: вернём пустой словарь, а не `bool`: `[1, 2, 1]` → `{}` вместо `True`
    [[]]: вернём пустой список, а не `bool`: `[1, 2, 1]` → `[]` вместо `True`
    [x not in seen]: сюда попадаем, только когда `x` уже в `seen`, значит это `False`: `[1, 2, 1]` → `False` вместо `True`
    [seen.add(x)]: `add` возвращает `None`: `[1, 2, 1]` → `None` вместо `True`
  Почему неверно в дырке _4_:
    [set()]: вернём пустое множество, а не `bool`: `[1, 2, 3]` → `set()` вместо `False`
    [x in seen]: после цикла последний `x` уже лежит в `seen`: `[1, 2, 3]` → `True` вместо `False`, а на `[]` цикла не было и `x` нет — `UnboundLocalError`
    [True]: дошли до конца без повторов, а вернули «есть повтор»: `[1, 2, 3]` → `True` вместо `False`
    [{}]: вернём пустой словарь, а не `bool`: `[1, 2, 3]` → `{}` вместо `False`
    [[]]: вернём пустой список, а не `bool`: `[1, 2, 3]` → `[]` вместо `False`
    [x not in seen]: на `[]` цикла не было и `x` не существует: `[]` → `UnboundLocalError`; на непустом списке случайно `False`, но только потому, что последний `x` уже в `seen`
    [seen.add(x)]: `add` возвращает `None`, а не `False`: `[1, 2, 3]` → `None` вместо `False`
  Подсказки:
    1. Пустое множество — `set()`: `{}` в Python — словарь.
    2. Повтор — это `x`, который уже лежит в `seen`.
    3. Нашли повтор — сразу `True`; цикл закончился без повторов — `False`.

--- Эталон (время O(n), память O(n)) ---
    | def has_duplicate(nums: list[int]) -> bool:
    |     seen = set()
    |     for x in nums:
    |         if x in seen:
    |             return True
    |         seen.add(x)
    |     return False
  Грабли:
    - Двойной цикл «каждый с каждым» даёт O(n²) вместо O(n)
    - `{}` — пустой словарь, а не множество: `seen.add(x)` падает с `AttributeError`
    - `set.add` в Python возвращает `None`, а не `bool`: проверка `x in seen` идёт отдельной строкой до добавления
    - `in` по списку `[]` ищет линейно: даже если бы список подошёл, вышло бы O(n²)
  Вариации:
    - в проде: `return len(set(nums)) != len(nums)` — одна строка, но всегда строит множество целиком, без раннего выхода; на собесе покажи цикл
    - повтор на расстоянии не больше `k`: словарь «значение → последний индекс» вместо множества
    - список отсортирован: повтор — это равные соседи `nums[i] == nums[i - 1]`, O(1) памяти

========================================================================
l1.2  Первый уникальный символ  (Python)
========================================================================
Условие: Верни первый символ строки, встречающийся ровно один раз, иначе `None`.
Тренирует: словарь частот `dict` + второй проход по строке

Примеры:
  first_unique_char("abacb") == "c"
  first_unique_char("aabb") is None
  first_unique_char("z") == "z"
  first_unique_char("") is None
  first_unique_char("ba") == "b"

--- Теория ---

[Когда словарь частот]
  сигнал: «Сколько раз встречается?»
  сигнал: «Ровно один раз», «чаще всего»
  сигнал: «Первый такой» — важен порядок исходных данных
  Словарь `counts` «символ → сколько раз» считается за один проход O(n); память O(k), где k — число разных символов. Готовый `collections.Counter` делает то же самое, но на собесе покажи словарь руками.

[Каркас: два прохода]
  каркас:
    | counts = {}
    | for ch in s:
    |     counts[ch] = counts.get(ch, 0) + 1
    | for ch in s:
    |     if counts[ch] == 1:
    |         return ch
    | return None
  Первый проход считает, второй идёт снова по строке `s`: она знает, какой символ был первым. `counts.get(ch, 0)` вернёт `0` для символа, которого ещё нет, а `counts[ch]` на нём упадёт с `KeyError`. Обход самого словаря тоже даст верный ответ: с Python 3.7 `dict` помнит порядок вставки, а ключи вставлены в порядке первого появления. Но приём «второй проход по строке» не зависит от этой гарантии и работает в любом языке (в Kotlin `HashMap` порядок не хранит).

[Грабли]
  грабли: `counts[ch] + 1` без `get`: на первом же символе ключа ещё нет, `"abacb"` → `KeyError: 'a'`
  грабли: `counts.get(ch)` без значения по умолчанию вернёт `None`: `"abacb"` → `TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'`
  грабли: Стартовое значение `1` вместо `0`: каждый символ посчитается на раз больше, `"z"` → `None` вместо `"z"`
  грабли: `counts = set()`: у множества нет `get`, `"abacb"` → `AttributeError: 'set' object has no attribute 'get'`
  грабли: Пытаться в один проход: пока строка не дочитана, неизвестно, повторится ли символ

--- Шаг e1 (дырок: 1) ---

  Почему неверно (для облачка в целом):

    [sorted(s)]: после сортировки порядок строки потерян, найдётся наименьший уникальный: `"ba"` → `"a"` вместо `"b"`

    1. Первый проход считает частоты. Второй проход **по исходной строке** (порядок важен!) — первый символ с частотой 1.
