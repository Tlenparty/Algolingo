## Summary

All three hard technical questions have a working, measured answer. (1) The embedded compiler (`org.jetbrains.kotlin:kotlin-compiler-embeddable:2.4.21`, already in the Gradle cache because KGP uses it) works as an `androidHostTest` dependency under AGP 9 KMP: one JVM, `K2JVMCompiler().exec(...)` per snippet, **~70-100 ms per snippet warm, 1.4 s first call; 261 snippets compiled in 18 s inside Gradle**. The same snippets can then be *run* in-process (URLClassLoader), so one JVM test can classify every variant as COMPILE / wrong / crash / hang with no kotlinc binary. (2) Hang detection: do NOT use threads/timeouts (JDK 21 has no `Thread.stop`, Native cannot kill threads). Instead the generator injects `tick()` at the start of every `while` body (`while (...) {` -> `while (...) { tick()`); `tick()` throws `HangError` after 1,000,000 steps. Deterministic, platform-independent, no leaked spinning threads; verified on JVM and iosSimulatorArm64. (3) `Random(seed)` is bit-identical on JVM and Native (verified: `Random(42)` -> `333,440,941,302,341,32,-4,true` on both).

The prototype (all 9 lessons, 248 unique wrong-chip programs, plus reference/ok/acceptable, plus hand-written exhaustive edge checks) already surfaced real content findings, which pre-populate the D-06 checkpoint: 4 "wrong" chips that are actually correct (l0.4 x2, l1.1 x2), a reference that crashes on empty input (l0.1), a chip whose wrongness is JVM-only (l1.2 `cnt.keys` - on Native the answer is correct), 5+ reasons whose counterexample is not in `examples:` (so they only fail with edge/oracle checks), and the l0.4 overflow chip that cannot be proven by any feasible test input.

**Primary recommendation:** One JVM host test (`WrongChipsTest`) compiles+runs every wrong (hole, chip) program in one JVM and compares to the tag; the shared `ReferenceSolutionsTest` (JVM+Native) additionally runs sidecar `checks:` (edge cases + oracle diff, tick-instrumented) for reference/ok/acceptable. Tags are written as `` `T` [kind] `` after the chip in the sidecar bullet.

### Pattern 1: Per-case classification harness (generated, identical text in both outputs)
**What:** every `examples:` line and every `case { }` inside `checks:` is classified independently, never aborting the rest. Kind = `AssertionError` -> wrong, `HangError` -> hang, any other `Throwable` -> crash.
**Why per case:** a hang or crash inside an exhaustive loop would otherwise hide a later mismatch (observed in prototype: l0.4 e3 `mid` showed only H because the loop died on the first hang). Tag check is "tag in observed set", so the loop must keep going.
```kotlin
// generated, top of file (private, common code only)
private class HangError : Error()
private object Probe {
    var steps = 0
    val kinds = mutableSetOf<String>()
    fun reset() { steps = 0; kinds.clear() }
}
private fun tick() { if (++Probe.steps > 1_000_000) throw HangError() }
private fun case(f: () -> Unit) {
    Probe.steps = 0
    try { f() }
    catch (e: AssertionError) { Probe.kinds += "wrong" }
    catch (e: HangError) { Probe.kinds += "hang" }
    catch (e: Throwable) { Probe.kinds += "crash" }
}
// each variant:
private object L0_4_v3 { // label
    fun binarySearch(nums: IntArray, target: Int): Int {
        var lo = 0
        var hi = nums.size - 1
        while (lo <= hi) { tick()          // injected: regex ^(\s*while\s*\(.*\)\s*\{)\s*$ -> \1 tick()
            ...
        }
        return -1
    }
    fun run() {
        case { assertEquals(2, binarySearch(intArrayOf(1, 3, 5, 7), 5)) }   // each examples: line
        checks()
    }
    private fun checks() {
        val rnd = kotlin.random.Random(1234)
        /* sidecar checks: fence verbatim, uses case { } */
    }
}
// reference/ok/acceptable test:  Probe.reset(); L0_4_v3.run(); assertEquals(emptySet(), Probe.kinds)
```
Only `while` needs a tick (all loops in note 05 level 0/1 that can hang are `while`; `for` over finite ranges terminate; spike confirmed all 5 hang variants detected). `do/while` not present - if one appears the generator must raise an error (add a generator test).
Instrumentation regex used in prototype: `^(\s*while\s*\(.*\)\s*\{)\s*$` -> `\1 tick()` (all note-05 `while` lines are of this shape; generator must raise if a `while` line does not match).

### Pattern 3: What goes where (D-10)
Lesson JSON stays byte-identical (tags and checks are NOT emitted) except where findings change content. Generated: `ReferenceSolutionsTest.kt` (extended), `wrong_variants.json` (new, checked by `--check` like every other output). JSON entry: `{id, bullet, lesson, exercise, hole, chip, tags, jvmOnly, source}` where `source` is the complete compilable Kotlin text (object + tick instrumentation + run()), so the JVM test needs no Kotlin-side template logic.

### Anti-Patterns to Avoid
- **Compile-checking inside commonTest:** one bad variant breaks all test compilation. Put every wrong-chip program in the JSON.
- **Placing `[wrong]` variants in common code from tags alone:** generator cannot know whether a hole variant compiles (cross-hole type errors); the tag is per bullet, outcome is per hole. This is why recommendation below puts ALL wrong variants in the JVM test.
- **Thread-based timeouts**, `Thread.stop`.
- **Aborting a lesson check on first failure** (loses secondary kinds).

## Common Pitfalls

### Pitfall 1: Generated test file fails to compile and takes down every test
**What goes wrong:** a mis-tagged variant that does not compile in the common file stops all tests with a Kotlin error.
**How to avoid:** keep ALL wrong programs in the JVM JSON (not in common source); common source only contains reference/ok/acceptable, which compile by construction. Each object carries a `// <label>` comment so a compile error names its source bullet.

### Pitfall 2: `checks:` uses JVM-only or deprecated API
Seen live: `String(CharArray)` is a deprecation ERROR on Native (`Use CharArray.concatToString()`), `Math.pow` is JVM-only. Put a generator test that rejects `Math.`, `java.`, `String(` in `checks:`.

### Pitfall 3: Platform-dependent semantics (HashMap order)
F5. Any chip whose wrongness depends on iteration order is JVM-only. Tag `jvm` or remove. Never assert it in common code.

### Pitfall 4: Wrong test classpath for the embedded compiler
`kotlin.test.Test::class.java` resolves to JUnit's jar; use `Class.forName("kotlin.test.AssertionsKt")`. Symptom: all 261 snippets "compile error".

### Pitfall 5: Oracle bugs blamed on variants
F10. Run the reference first; `kinds` must be empty for reference before wrong variants are judged.

### Pitfall 6: Stack overflow / OOM in a variant
Not catchable reliably on Native. None of the 9 lessons recurse or allocate unbounded in a wrong variant (prototype ran all). If a future lesson does, keep that variant JVM-only.

### Pitfall 7: Hang tick limit vs legit work
Counter resets per `case`; 1,000,000 ticks vs max ~10^3 legit iterations on the small domains. Keep exhaustive domains small (<= ~4000 cases per lesson) so total time stays seconds.

### Pitfall 8: `getOrDefault` on Native
The existing `GET_OR_DEFAULT_SHIM` (private extension, shadowed by the JVM member) must be copied into the generated prelude. JVM compile verdicts are authoritative for wrong variants. On JVM and with the shim, `getOrDefault(c, <non-Int>)` compiles by widening `V` (WR-01) and the failure is at `+ 1`; prototype showed Native compiled all 91 non-compile-error variants with the shim, no divergence found `[VERIFIED: prototype]`. Reverse direction (JVM compile error but Native ok) is irrelevant because those variants never reach Native.

### Soft KB load (GAP-4)
Current code: `App.kt` runs `produceState(false) { repo.load(); value = true }` at root - any `Res.readBytes`/JSON failure inside a `produceState` coroutine is an unhandled exception = app crash, and all ~217 notes are read at startup. `KbEntry` decode of a bad `index.json` throws `SerializationException`.
Recommended shape (mirrors `loadLesson`/`loadCatalog`, no new deps):
```kotlin
class KbRepository(private val read: suspend (String) -> ByteArray = { Res.readBytes(it) }) {
    var notes: List<Note> = emptyList(); private set
    private val mutex = Mutex(); private var loaded = false
    /** Idempotent, lazy. Never throws (except CancellationException). */
    suspend fun load(): Result<List<Note>> = mutex.withLock {
        if (loaded) return Result.success(notes)
        try {
            val index = Json { ignoreUnknownKeys = true }.decodeFromString<List<KbEntry>>(read("files/kb/index.json").decodeToString())
            // a single missing/broken note file is skipped, not fatal; empty result = failure
            notes = index.mapNotNull { runCatching { Note(it.id, it.title, it.section, read("files/kb/${it.file}").decodeToString()) }.getOrNull() }
            if (notes.isEmpty()) return Result.failure(IllegalStateException("kb empty"))
            loaded = true; Result.success(notes)
        } catch (e: CancellationException) { throw e }
        catch (e: Exception) { Result.failure(e) }   // not cached: next open retries
    }
}
```
UI: remove the root `produceState`; in `composable<KbList>` and `composable<NoteRoute>` use `val kb by produceState<Result<List<Note>>?>(null) { value = repo.load() }`; `null` -> "…", failure -> soft message ("Не удалось загрузить базу знаний", lessons/Home unaffected), success -> existing screens. NoteRoute must also trigger load (Activity recreation restores NoteRoute first - existing comment in App.kt). Catch `Exception` rather than only `SerializationException` (missing resource throws `MissingResourceException`/IO errors; the `loadLesson` precedent does the same).
Tests (commonTest, `kotlinx-coroutines-test` already a dep, `runTest`): injected reader that (a) throws for index -> `isFailure`, (b) returns garbage JSON -> `isFailure`, (c) throws for one note -> others load, (d) throws for all notes -> failure, (e) load twice only reads once (lazy/idempotent), (f) failure then success on retry. A compose-level "App with broken KB does not crash" test is optional; the logic test covers the regression. Also keep `KbContentTest` (shipped files valid).
