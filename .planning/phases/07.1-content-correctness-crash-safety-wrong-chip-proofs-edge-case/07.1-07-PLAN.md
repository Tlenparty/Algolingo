<objective>
Add UI end-to-end tests for solving lessons with chips (user request 2026-10-23: «Протестируй решение задач с облачками e2e тестами помимо unit. Чтобы смоук можно сделать было.») and one smoke command that runs them on the Android emulator and the iOS simulator (E2E-01, E2E-02, E2E-03).

Purpose: unit tests and the reducer fuzz prove the logic; this proves the shipped UI wiring (chips, holes, «Проверить», result panel, summary, Home progress, KB) on both platforms. Plan 06 reruns it after the content fixes.
Output: one shared scenario file, two thin platform wrappers, a `chip` test tag, Gradle test deps, `tools/smoke.sh`.

Design (locked here, executor follows):
- The scenarios live once in `commonTest` as plain functions with a `ComposeUiTest` receiver (no `@Test`), and run from `androidDeviceTest` and `iosTest` wrappers. They cannot have `@Test` in commonTest, because commonTest also compiles into `androidHostTest`, where `runComposeUiTest` does not run (CMP docs: common Compose tests cannot run as android local tests). This counts as E2E-01's "equivalent under AGP 9". `:androidApp` has no test source set, and a `:androidApp` androidTest could not share scenario code with iOS. `MainActivity` is only `setContent { App(filesDir) }`, so `setContent { App(freshDir) }` in an instrumented test renders the same app.
- `AppGraph` caches the first `dataDir` per process, so each wrapper has exactly ONE `@Test` and passes a fresh temp dir. That test runs the scenarios in this order: wrong-chip (exits the lesson without saving), then KB, then all lessons. The order keeps progress clean for the all-lessons run.
- The driver keeps a headless `LessonReducer` state in lockstep with the UI. It performs the same actions as LessonFuzzTest's smart player (TapHole(h), then the first unplaced bank chip whose text is `hole.ok[0]`, which handles duplicate chips). The headless state tells the driver which screen comes next and what text to expect, so the test has no hard-coded lesson knowledge.
</objective>
