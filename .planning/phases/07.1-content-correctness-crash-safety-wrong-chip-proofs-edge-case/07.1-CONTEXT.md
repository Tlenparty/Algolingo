# Phase 07.1: Content correctness & crash safety - Context

**Gathered:** 2026-10-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Каждая оценка облачка в 9 уроках (l0.1–l1.5) доказана тестом, а приложение не падает ни на одном уроке и ни при сбое загрузки контента. Закрывает GAP-1..5 из `.planning/v1.0-MILESTONE-AUDIT.md`. Новых пользовательских возможностей нет: только тесты, правки генератора/контента и защитная загрузка.

Заказчик сформулировал приоритет так: «для решения алгоритмических задач главное, чтобы всё было покрыто тестами, чтобы проверять результаты, и чтобы не падало приложение».

</domain>

<decisions>
## Implementation Decisions

### Доказательство «неверно» (GAP-1)
- **D-01:** Каждая причина неверного облачка (`- @H \`T\`: why` в `content/authoring/*.md`) получает обязательную метку типа поломки. Тест проверяет, что вариант ломается **именно так**. Текст причины остаётся на ревью человека; ключевые слова ошибки компилятора не сверяем (хрупко при смене Kotlin).
- **D-02:** Четыре метки: `[compile]` — не компилируется; `[wrong]` — компилируется, но результат неверный хотя бы на одном входе; `[crash]` — бросает исключение; `[hang]` — не завершается за таймаут. Генератор падает, если у неверного облачка нет метки.
- **D-03:** Вариант = шаблон упражнения, где все дырки заполнены `ok[0]`, а одна — неверным облачком (как сейчас `variants()` делает для ok/acceptable). Всего сейчас 182 пары «дырка + неверное облачко».
- **D-04:** Всё гоняется внутри `./gradlew :shared:allTests` — одна команда, ничего не забудешь. `[wrong]`/`[crash]`/`[hang]` — сгенерированные тесты в общем наборе (JVM + Native, как `ReferenceSolutionsTest`). `[compile]`-варианты нельзя класть в общий тестовый исходник (сломают компиляцию всех тестов) — их проверяет JVM host-тест, компилирующий каждый вариант по отдельности встроенным Kotlin-компилятором той же версии (2.4.21). `kotlinc` в системе не установлен — не полагаться на него. Допустимо +1–3 мин к тестам.
- **D-05:** `[hang]` проверяется с таймаутом; тест не должен сам зависнуть (вариант запускать так, чтобы его можно было прервать).

### Ложные оценки и падения эталона — чекпоинт заказчика
- **D-06:** Если «неверное» облачко на деле даёт рабочее решение (проходит все примеры, граничные и случайные входы), или метка не совпала с реальностью, или эталон / ok / acceptable-вариант падает на новом граничном случае — исполнитель **не чинит молча**. Он собирает все находки в один документ (`07.1-CONTENT-FINDINGS.md`) с предложением по каждой: перевести в ok / «принято, но…», добавить пример, на котором облачко ломается, исправить эталон/шаблон (и заметку 05, если ошибка там), или явно сузить условие задачи. Заказчик утверждает одним блокирующим чекпоинтом — как ревью контента в фазах 5–6 (`05-CONTENT-REVIEW.md`, `06-CONTENT-REVIEW.md`).

### Граничные случаи (GAP-2)
- **D-07:** Два механизма вместе: (1) явные граничные примеры в сайдкаре по обязательному чек-листу; (2) дифференциальная проверка — каждый вариант (эталон, ok, acceptable, а также `[wrong]`-облачка) сравнивается с наивным «оракулом» на случайных входах с фиксированным seed (детерминированно на JVM и Native).
- **D-08:** Обязательный чек-лист (где применимо к задаче): **пустой вход / один элемент**; **ответа нет / ответ на краях** (первый, последний элемент); **отрицательные, ноль, Int.MAX_VALUE / переполнение** (например `(lo + hi) / 2`). Дубликаты / «все одинаковые» — НЕ обязательны (заказчик не выбрал), но допустимы, где уже есть.
- **D-09:** Граничные примеры и оракулы для 9 уроков пишет исполнитель. Оракул — заведомо другой алгоритм (перебор / stdlib), не копия эталона. Заказчик видит их в том же чекпоинте D-06.
- **D-10:** Граничные примеры и оракул — тестовая инфраструктура в сайдкаре; в приложении не показываются, в JSON урока не попадают (если планировщик не найдёт причину иначе).

### Claude's Discretion
Заказчик не стал обсуждать — решать по рекомендациям аудита:
- **«Не падает» (GAP-3):** фазз-тест редьюсера/движка в commonTest по всем урокам из каталога — случайные последовательности тапов по облачкам, снятия, «Проверить», подсказок, «Дальше», повторов (фиксированные seed), ни одного исключения, состояние всегда валидно. Плюс `adb monkey` на Android-эмуляторе без FATAL EXCEPTION (прогон делает агент сам). Compose UI-тест — по желанию планировщика, не обязателен. iOS — смоук запуска, если дёшево.
- **Мягкая загрузка KB (GAP-4):** `KbRepository.load()` не должна ронять приложение; при сбое — уроки работают, вкладка «База знаний» показывает мягкую ошибку (по образцу `loadLesson`/`loadCatalog`). KB не грузить целиком на старте — лениво при открытии вкладки (или аналогично). Тест на битый/отсутствующий файл.
- **l1.2 / l1.3 (GAP-5):** применить формулировки из `06-REVIEW.md` WR-01/WR-02 (причины для @1 указывают на `+ 1`; подсказка «одна Map: плюсуем буквы a, минусуем буквы b»), пересобрать `gen_content.py`. Если механизм D-01 сам поймает WR-01 — хорошо, это подтверждение. Финальные тексты попадают в чекпоинт D-06 вместе с остальным.
- Формат меток в сайдкаре, имя/расположение compile-теста, генератор случайных входов и оракула в сайдкаре — на усмотрение исследования/планировщика.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `gen_content.variants(lesson)`: уже собирает reference + ok/acceptable-варианты через `assemble(segments, fills)` — расширить на неверные облачка с метками.
- `render_kt()`: генерирует `private object L0_1_vN { <код>; fun examples() }` + `@Test` — тот же паттерн для `[wrong]/[crash]/[hang]` и для оракульного сравнения.
- `GET_OR_DEFAULT_SHIM`: JVM-only API для Native — compile-проверка на JVM должна учитывать, что на Native шим есть (вариант не должен «не компилироваться» только из-за отсутствия шима).
- `LessonContentTest.everyCatalogLessonIsStrictAndValid` (androidHostTest): обход всех уроков каталога — основа для фазз-теста.
- `ShuffleTest` / seeded shuffle в редьюсере: детерминированный RNG уже есть.

### Established Patterns
- Генератор — единственный источник `content/` JSON и `ReferenceSolutionsTest.kt`; `--check` должен оставаться зелёным и только сравнивать.
- Тесты: `./gradlew :shared:allTests` (testAndroidHostTest + iosSimulatorArm64Test), сейчас 160/150, все зелёные.
- Мягкая ошибка загрузки урока/каталога уже есть — повторить для KB.
- Коммиты от tlenparty без Co-Authored-By; прогоны на устройствах делает агент сам (adb/simctl/idb).

### Integration Points
- Сайдкар → `gen_content.py` → (JSON урока, сгенерированные Kotlin-тесты, входные данные compile-теста).
- `App()` → KB-загрузка → `KbListScreen`/`NoteScreen`.

</code_context>

<specifics>
## Specific Ideas

- Уже известный пример ложной причины: l1.2 e3 — «`cnt.getOrDefault(c, s)` не скомпилируется», а на деле компилируется, ломается `+ 1` (проверено kotlinc 2.4.21 в 06-REVIEW). С метками D-02 это `[compile]` всё равно верно, но текст причины ложный — ловится только ревью; поэтому финальные тексты причин l1.2 идут в чекпоинт.
- Известный кандидат на падение эталона: переполнение `(lo + hi) / 2` в бинпоиске l0.4 на больших индексах — проверить по чек-листу D-08.

</specifics>
