  </read_first>
  <action>
    Create `WrongChipsTest` (androidHostTest, JVM only). `@Serializable` data classes mirror the JSON (Json with `ignoreUnknownKeys = true`). For each entry: write `source` to a fresh temp dir as `V.kt`; compile with `org.jetbrains.kotlin.cli.jvm.K2JVMCompiler().exec(PrintStream(ByteArrayOutputStream()), "-no-stdlib", "-no-reflect", "-nowarn", "-cp", cp, "-d", outDir, srcPath)`; exit code other than `ExitCode.OK` -> observed `{"compile"}`. Classpath cp = location of kotlin stdlib (`Unit::class.java`) + location of `Class.forName("kotlin.test.AssertionsKt")` joined by `File.pathSeparator` (NOT `kotlin.test.Test::class.java`: under JUnit that is the junit annotation jar and every compile fails; Pitfall 4). If compiled: load class `V` through a `URLClassLoader` whose parent is the test class loader, get the Kotlin `INSTANCE`, call `kinds()` and split on comma -> observed set (empty = clean). Never use threads or timeouts (hang is tick-based, D-05). Reuse one JVM for all entries (compiler warm). Evaluation, per D-01/D-02, collected into ONE failure message plus a report file `shared/build/reports/wrong-chips.txt`: (1) any non-pending entry with empty observed set -> "runs clean (false wrong?)"; (2) for each claim with scope "hole": every declared tag must be in the observed set of that entry; for scope "chip" claims group entries by claim bullet and require each declared tag to be in the UNION of observed sets across the group; (3) an entry with `pending: true` is skipped, but if it would have produced no failure it is reported as "stale pending" and fails the test (so the list cannot rot). Report lines carry the entry id, bullet, expected tags, observed kinds. Add a second sanity `@Test`: a hand-built trivial program that does compile and returns clean, and one deliberately broken program that classifies as compile, so classifier regressions (e.g. wrong classpath) cannot turn the whole suite into "compile" silently. Total runtime target under ~60 s.
  </action>
