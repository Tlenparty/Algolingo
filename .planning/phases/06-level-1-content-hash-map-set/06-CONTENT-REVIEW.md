## Решения на подтверждение

1. **1.1 e3, дырка 3 (`return ⟦true⟧` внутри цикла): два функционально верных облачка не засчитываются.** Проверка идёт по каждой дырке отдельно, поэтому здесь принимается только `true`. Для двух облачков объяснение честно говорит «сработает, но…»:
   - `!seen.add(x)`: «сработает: второй `add` того же `x` вернёт `false`, `!false` = `true`; но это лишний вызов `add` с побочным эффектом, здесь просто `true`»
   - `seen.contains(x)`: «сработает: `x` уже в `seen`, `contains` вернёт `true`; но это лишняя проверка, здесь просто `true`»

   Варианты: оставить как есть (ошибка с честным объяснением) или сделать оба «принято, но…».
2. **1.2, облачко `cnt.keys`: контрпример верен только на JVM.** Текст: «`HashMap` не хранит порядок вставки; на JVM ключи идут по корзинам хеша: `"ba"` → `'a'` вместо `'b'`». В Kotlin/Native (iOS) `HashMap` перебирает ключи в порядке вставки, и там `"ba"` действительно вернёт `'b'`. Поэтому в тексте сказано «на JVM». Суть от этого не меняется: порядок контрактом не гарантирован.
3. **1.2: «Тренирует» и «Грабли» разбора заменены в sidecar.** Одно предложение «Грабли» из заметки генератор разрезал по `;` на два странных пункта, а в «Тренирует» был `**`-markdown. Сейчас в приложении:

   - грабли: «Нельзя искать уникальный по самой `Map`: она не гарантирует порядок вставки, иди по строке»

4. **1.4 e3: пара `nums[i]` в дырке 3 и `need` в дырке 4 работает, если поменять обе.** Алгоритм «ищем `nums[i]`, кладём `seen[need] = i`» верный, но проверка по дыркам принимает только канон. Тексты:

## 1.1 Есть ли дубликат

*Верни `true`, если в массиве есть хоть один повтор.* Тренирует: `HashSet` и трюк `add`. Цель: 90 с.

### Теория

**1. Когда HashSet**
- сигнал: «Есть ли повтор?», «видели ли раньше?»
- сигнал: Важно только наличие элемента, не количество
- сигнал: Нужно уложиться в O(n)
`HashSet` отвечает «уже было?» за O(1), поэтому весь проход — O(n) по времени и O(n) по памяти.

**2. Трюк add**
```kotlin
val seen = HashSet<Int>()
for (x in nums) if (!seen.add(x)) return true
```
`add` возвращает `false`, если элемент уже был в множестве: одна строка и проверяет, и запоминает.

**3. Грабли**
- грабли: `seen.add(x)` без `!` срабатывает на первом же новом элементе
- грабли: `contains` без `add` ничего не запоминает: повтор не найдётся
- грабли: У `MutableList` метод `add` всегда возвращает `true`, повтор он не заметит

### e1 — дырок: 1

```kotlin
fun hasDuplicate(nums: IntArray): Boolean {
    val seen = HashSet<Int>()
    for (x in nums) if (⟦!seen.add(x)⟧) return true
    return false
}
```
- дырка 1: верно `!seen.add(x)`

Облачка: `!seen.add(x)`, `seen.add(x)`, `seen.contains(x)`, `!seen.contains(x)`
- `seen.add(x)` — условие перевёрнуто: первый же новый элемент даёт `true`: `[1, 2]` → `true`
- `seen.contains(x)` — в `seen` никто ничего не кладёт, условие всегда ложно: `[1, 1]` → `false`
- `!seen.contains(x)` — множество пустое, условие истинно на первом элементе: `[1]` → `true`

Подсказки:
1. `set.add(x)` возвращает `false`, если элемент уже был. Одна строка внутри цикла.

1. `set.add(x)` возвращает `false`, если элемент уже был. Одна строка внутри цикла.

- грабли: Двойной цикл «каждый с каждым» даёт O(n²) вместо O(n)
- грабли: `contains` без `add` ничего не запоминает и никогда не находит повтор

## 1.2 Первый уникальный символ

*Верни первый символ строки, встречающийся ровно один раз, иначе `null`.* Тренирует: `Map` частот + второй проход по строке. Цель: 180 с.

### Теория

**1. Когда Map частот**
- сигнал: «Сколько раз встречается?»
- сигнал: «Ровно один раз», «чаще всего»
- сигнал: «Первый такой» — важен порядок исходных данных
`HashMap<Char, Int>` считает частоты за один проход O(n); память O(k), где k — размер алфавита.

**2. Каркас: два прохода**
```kotlin
val cnt = HashMap<Char, Int>()
for (c in s) cnt[c] = cnt.getOrDefault(c, 0) + 1
for (c in s) if (cnt[c] == 1) return c
```
Первый проход считает, второй идёт снова по строке `s`: только она знает, какой символ был первым.

**3. Грабли**
- грабли: Искать уникальный по самой `Map`: `HashMap` не хранит порядок вставки, иди по строке
- грабли: Пытаться в один проход: пока строка не дочитана, неизвестно, повторится ли символ
- грабли: Стартовое значение счётчика `1` вместо `0`: каждый символ посчитается дважды

### e1 — дырок: 1

```kotlin
fun firstUniqueChar(s: String): Char? {
    val cnt = HashMap<Char, Int>()
    for (c in s) cnt[c] = cnt.getOrDefault(c, 0) + 1
    for (c in ⟦s⟧) if (cnt[c] == 1) return c
    return null
}
```
- дырка 1: верно `s`

Облачка: `s`, `cnt.keys`, `s.reversed()`
- `cnt.keys` — `HashMap` не хранит порядок вставки; на JVM ключи идут по корзинам хеша: `"ba"` → `'a'` вместо `'b'`
- `s.reversed()` — с конца найдётся последний уникальный, а не первый: `"ab"` → `'b'` вместо `'a'`

Подсказки:
1. Первый проход — считаем частоты. Второй проход **по исходной строке** (порядок важен!) — первый символ с частотой 1.

### e2 — дырок: 2

Подсказки:
1. Первый проход — считаем частоты. Второй проход **по исходной строке** (порядок важен!) — первый символ с частотой 1.
2. Уникального нет — честно верни «ничего».

### Разбор (O(n) / O(k))

- грабли: Нельзя искать уникальный по самой `Map`: она не гарантирует порядок вставки, иди по строке
- грабли: Один проход не работает: пока строка не дочитана, неизвестно, повторится ли символ

## 1.3 Анаграмма

*Даны два слова. Состоят ли они из одинакового набора букв с учётом количества? (`йцукен` / `некуцй` → true, `ффффа` / `фффа` → false)* Тренирует: сравнение частотных словарей. Цель: 180 с.

### Теория

**1. Когда сравнивать частоты**
- сигнал: «Одинаковый набор букв», «перестановка», «анаграмма»
- сигнал: «С учётом количества» — важно, сколько раз, а не только есть ли
- сигнал: Нужно уложиться в O(n)
Одна `HashMap<Char, Int>`: плюсуем буквы `a`, минусуем буквы `b`. O(n) по времени, O(k) по памяти.

**2. Каркас**
```kotlin
if (a.length != b.length) return false
for (c in a) cnt[c] = cnt.getOrDefault(c, 0) + 1
for (c in b) {
    val left = (cnt[c] ?: 0) - 1
    if (left < 0) return false
    cnt[c] = left
}
return true
```
Длины равны и счётчик ни разу не ушёл в минус ⇒ частоты совпали. Однострочник `a.groupingBy { it }.eachCount() == b.groupingBy { it }.eachCount()` тоже верен, но на собесе пиши цикл.

**3. Грабли**
- грабли: «Отсортировать обе строки и сравнить» — O(n log n), а `Map` даёт O(n)
- грабли: Без проверки длины `"ab"` и `"a"` пройдут: лишние буквы `a` никто не заметит
- грабли: Буква, которой нет в `a`, должна дать `-1`: старт `(cnt[c] ?: 0)`, а не `1`

### e1 — дырок: 1

```kotlin

    if (a.length != b.length) return false
    val cnt = HashMap<Char, Int>()
    for (c in a) cnt[c] = cnt.getOrDefault(c, 0) + 1
    for (c in b) {
        val left = (cnt[c] ?: 0) - 1
        if (left ⟦<⟧ 0) return false
        cnt[c] = left

```
- дырка 1: верно `<`

Облачка: `<`, `<=`, `==`, `>`
- `<=` — `0` — это «буква израсходована ровно», а не «лишняя»: `"a"` / `"a"` → `false` вместо `true`
- `==` — `0` — это «буква израсходована ровно», а не «лишняя»: `"a"` / `"a"` → `false` вместо `true`
- `>` — перевёрнуто, минус никогда не ловится: `"ab"` / `"ac"` → `true` вместо `false`

Подсказки:
1. Буква лишняя, если счётчик ушёл в минус.

## 1.4 Two Sum

*Верни индексы двух чисел с суммой `target`.* Тренирует: Map «значение → индекс», поиск дополнения `target - x`. Цель: 180 с.

### Теория

**1. Когда Map значение → индекс**
- сигнал: «Найди пару с суммой `target`»
- сигнал: Массив не отсортирован
- сигнал: Вернуть нужно индексы, а не сами числа
Для каждого `x` ищем дополнение `target - x` среди уже пройденных: `HashMap` «значение → индекс» отвечает за O(1). Если массив отсортирован — это два указателя (уровень 2).

**2. Каркас**
```kotlin
for (i in nums.indices) {
    val need = target - nums[i]
    seen[need]?.let { return it to i }
    seen[nums[i]] = i
}
```
Один проход, не два: сначала ищем дополнение, потом кладём текущее число. O(n) по времени и памяти.

**3. Грабли**
- грабли: Сначала положить `nums[i]`, потом искать: `[3, 2, 4]`, `6` → `3` найдёт сам себя, ответ `0 to 0` вместо `1 to 2`
- грабли: Искать `nums[i]` вместо дополнения `target - nums[i]`: пара не найдётся
- грабли: Два вложенных цикла «каждый с каждым» — O(n²)

### e1 — дырок: 1

```kotlin
fun twoSum(nums: IntArray, target: Int): Pair<Int, Int>? {
    val seen = HashMap<Int, Int>()
    for (i in nums.indices) {
        val need = target - nums[i]
        seen[⟦need⟧]?.let { return it to i }
        seen[nums[i]] = i
    }
    return null
}
```
- дырка 1: верно `need`

Облачка: `need`, `nums[i]`, `target`
- `nums[i]` — ищем само число, а не дополнение: `[2, 7]`, `9` → `null` вместо `0 to 1`
- `target` — ищем `target` целиком, а не недостающую часть: `[2, 7]`, `9` → `null` вместо `0 to 1`

Подсказки:
1. Для текущего `x` нужно `target - x`. Если оно уже в Map — ответ.

## 1.5 Победители соревнования

*Дана статистика шагов по дням: `List<List<StepEntry(userId, steps)>>`. Верни `userId` тех, кто набрал **максимум шагов**, **участвуя во все дни без пропусков**.* Тренирует: две Map одновременно (сумма + счётчик участий) + фильтр. Цель: 420 с.

### Теория

**1. Когда две Map**
- сигнал: По каждому юзеру нужны и сумма, и счётчик
- сигнал: «Во все дни», «без пропусков» — счётчик дней равен числу дней
- сигнал: «Максимум среди тех, кто…» — сначала фильтр, потом максимум
Две `HashMap` за один двойной проход: `totalSteps` копит шаги, `daysActive` — дни участия. O(N) по числу записей, O(U) по числу юзеров.

**2. Каркас**
```kotlin
for (day in statistics) for (e in day) {
    totalSteps[e.userId] = totalSteps.getOrDefault(e.userId, 0) + e.steps
    daysActive[e.userId] = daysActive.getOrDefault(e.userId, 0) + 1
}
val full = daysActive.filterValues { it == totalDays }.keys
val maxSteps = full.maxOfOrNull { totalSteps[it] ?: 0 } ?: 0
val champions = full.filter { totalSteps[it] == maxSteps }
```
Фильтр → максимум → сбор всех с этим максимумом. Сначала отфильтруй тех, кто был все дни, и только среди них ищи максимум.

**3. Грабли**
- грабли: Победителей может быть несколько (равный максимум) → возвращаем список, а не одного
- грабли: Максимум по всем юзерам, а не только по участникам всех дней: юзер с пропуском задаст недостижимый максимум, и победителей не останется
- грабли: Без участников `maxOfOrNull` вернёт `null` — нужен `?: 0`

### e1 — дырок: 1

```kotlin
data class StepEntry(val userId: Int, val steps: Int)
data class ChampionResult(val userIds: List<Int>, val steps: Int)

fun findChampions(statistics: List<List<StepEntry>>): ChampionResult {
    val totalDays = statistics.size
    val totalSteps = HashMap<Int, Int>()
    val daysActive = HashMap<Int, Int>()

    for (day in statistics) for (e in day) {
        totalSteps[e.userId] = totalSteps.getOrDefault(e.userId, 0) + e.steps
        daysActive[e.userId] = daysActive.getOrDefault(e.userId, 0) + 1
    }

    return ChampionResult(champions, maxSteps)
}
```

### e3 — дырок: 4

```kotlin
data class StepEntry(val userId: Int, val steps: Int)
data class ChampionResult(val userIds: List<Int>, val steps: Int)

fun findChampions(statistics: List<List<StepEntry>>): ChampionResult {
    val totalDays = statistics.size
    val totalSteps = HashMap<Int, Int>()
    val daysActive = HashMap<Int, Int>()

    for (day in statistics) for (e in day) {
        totalSteps[e.userId] = totalSteps.getOrDefault(e.userId, 0) + ⟦e.steps⟧
        daysActive[e.userId] = daysActive.getOrDefault(e.userId, 0) + ⟦1⟧
    }

    val full = daysActive.filterValues { it == ⟦totalDays⟧ }.keys
    val maxSteps = ⟦full⟧.maxOfOrNull { totalSteps[it] ?: 0 } ?: 0
    val champions = full.filter { totalSteps[it] == maxSteps }
    return ChampionResult(champions, maxSteps)
}
```
- дырка 1: верно `e.steps`
- дырка 2: верно `1`
- дырка 3: верно `totalDays`
- дырка 4: верно `full`

Облачка: `e.steps`, `1`, `totalDays`, `full`, `totalSteps.keys`, `daysActive.size`, `e.userId`
- `totalSteps.keys` — максимум по всем, а юзер с пропуском задаёт недостижимую планку: дни `[(1, 100), (2, 500)]`, `[(1, 100)]` → `ChampionResult([], 500)` вместо `([1], 200)`
- `daysActive.size` — это число юзеров, а не дней: день `[(1, 100), (2, 50)]` → дней `1`, юзеров `2`, ответ `([], 0)` вместо `([1], 100)`
- `e.userId` — к шагам прибавляется номер юзера: день `[(1, 100), (2, 50)]` → `ChampionResult([2], 2)` вместо `([1], 100)`
- (дырка 1) `1` — `totalSteps` считает записи, а не шаги: день `[(1, 100), (2, 50)]` → ничья `1` и `2` с `steps = 1` вместо `([1], 100)`
- (дырка 1) `totalDays` — за каждую запись прибавляется число дней, а не шаги: день `[(1, 100), (2, 50)]` → ничья `1` и `2` с `steps = 1` вместо `([1], 100)`
- (дырка 1) `full` — `full` объявлен ниже, после цикла: `+ full` не скомпилируется
- (дырка 1) `totalSteps.keys` — к числу не прибавить множество: `+ totalSteps.keys` не скомпилируется
- (дырка 1) `daysActive.size` — к шагам прибавляется текущее число юзеров в `daysActive`: день `[(1, 100), (2, 50)]` → `ChampionResult([2], 1)` вместо `([1], 100)`
- (дырка 2) `e.steps` — `daysActive` копит шаги, а не дни, и не совпадёт с `totalDays`: день `[(1, 100)]` → `daysActive[1] = 100`, ответ `([], 0)` вместо `([1], 100)`
- (дырка 2) `totalDays` — за каждый день прибавляется число дней: дни `[(1, 100)]`, `[(1, 100)]` → `daysActive[1] = 4` вместо `2`, ответ `([], 0)` вместо `([1], 200)`
- (дырка 2) `full` — `full` объявлен ниже, после цикла: `+ full` не скомпилируется
- (дырка 2) `totalSteps.keys` — к числу не прибавить множество: `+ totalSteps.keys` не скомпилируется
- (дырка 2) `daysActive.size` — первая запись юзера прибавляет `0` — пока в `daysActive` никого нет: день `[(1, 100)]` → `daysActive[1] = 0`, ответ `([], 0)` вместо `([1], 100)`
- (дырка 2) `e.userId` — прибавляется номер юзера, а не `1` за день: день `[(2, 100)]` → `daysActive[2] = 2` вместо `1`, ответ `([], 0)` вместо `([2], 100)`
- (дырка 3) `e.steps` — после цикла `e` вне области видимости: `it == e.steps` не скомпилируется
- (дырка 3) `1` — остаются те, кто был ровно один день, а не все дни: дни `[(1, 100)]`, `[(1, 100)]` → `([], 0)` вместо `([1], 200)`
- (дырка 3) `full` — `full` ссылается на саму себя: `val full = daysActive.filterValues { it == full }` не скомпилируется
- (дырка 3) `totalSteps.keys` — число дней не сравнить с множеством: `it == totalSteps.keys` не скомпилируется
- (дырка 3) `e.userId` — после цикла `e` вне области видимости: `it == e.userId` не скомпилируется
- (дырка 4) `e.steps` — после цикла `e` вне области видимости: `e.steps.maxOfOrNull { … }` не скомпилируется
- (дырка 4) `1` — у числа нет `maxOfOrNull`, нужна коллекция юзеров: `1.maxOfOrNull { … }` не скомпилируется
- (дырка 4) `totalDays` — у числа нет `maxOfOrNull`, нужна коллекция юзеров: `totalDays.maxOfOrNull { … }` не скомпилируется
- (дырка 4) `daysActive.size` — у числа нет `maxOfOrNull`, нужна коллекция юзеров: `daysActive.size.maxOfOrNull { … }` не скомпилируется
- (дырка 4) `e.userId` — после цикла `e` вне области видимости: `e.userId.maxOfOrNull { … }` не скомпилируется

Подсказки:
1. Тебе нужны две вещи на каждого юзера: суммарные шаги и в скольких днях он участвовал. Две `Map` за один двойной проход.
2. Шаги копим по `e.steps`, дни — по одному за запись.
3. «Без пропусков» = число дней участия равно `statistics.size`.
4. Сначала отфильтруй таких, потом среди них ищи максимум, потом собери всех с этим максимумом (их может быть несколько!).
