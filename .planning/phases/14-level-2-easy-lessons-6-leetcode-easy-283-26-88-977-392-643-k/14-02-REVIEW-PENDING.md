========================================================================
Условие: В `nums1` первые `m` чисел отсортированы, дальше `n` нулей-заглушек; `nums2` из `n` отсортированных чисел. Слей `nums2` в `nums1` **на месте**, чтобы весь `nums1` стал отсортированным (LeetCode 88).
Тренирует: три указателя с конца: два хвоста и место записи
Цель: 5 мин

Примеры:

  assertContentEquals(intArrayOf(1), intArrayOf(1).also { merge(it, 1, intArrayOf(), 0) })

--- Теория ---

[Когда с конца]
  сигнал: Слить два отсортированных массива **на месте**
  сигнал: Свободное место — в конце первого массива
  сигнал: Нужно O(m+n) по времени и O(1) по памяти
  Если писать с начала, затрёшь ещё не прочитанные числа `nums1`. С конца свободно: самый большой из двух хвостов встаёт на последнюю свободную позицию, и запись никогда не догоняет чтение.

[Каркас]
  каркас:

    | var index1 = m - 1
    | var index2 = n - 1

    |     // больший хвост — в mergeIndex
    |     // сдвигаем его указатель

  грабли: Идти с начала: `[4, 0]` и `[1]` → `4` затрётся раньше, чем его прочитали

  грабли: Без `index1 >= 0` в `if` читаем `nums1[-1]`, когда `nums1` кончился

========================================================================
Условие: В `nums1` первые `m` чисел отсортированы, дальше `n` нулей-заглушек; `nums2` из `n` отсортированных чисел. Слей `nums2` в `nums1` **на месте**, чтобы весь `nums1` стал отсортированным (LeetCode 88). Функция ничего не возвращает.
Тренирует: три указателя с конца: два хвоста и место записи
Цель: 5 мин

Примеры:
  a = [1, 2, 3, 0, 0, 0]; merge(a, 3, [2, 5, 6], 3); assert a == [1, 2, 2, 3, 5, 6]
  a = [1]; merge(a, 1, [], 0); assert a == [1]
  a = [0]; merge(a, 0, [1], 1); assert a == [1]

[Когда с конца]
  сигнал: Слить два отсортированных списка **на месте**
  сигнал: Свободное место — в конце первого списка
  сигнал: Нужно O(m+n) по времени и O(1) по памяти
  Если писать с начала, затрёшь ещё не прочитанные числа `nums1`. С конца свободно: самый большой из двух хвостов встаёт на последнюю свободную позицию, и запись никогда не догоняет чтение.

[Каркас]
  каркас:

    | index1, index2 = m - 1, n - 1
    | merge_index = m + n - 1
    | # пока nums2 не кончился

    |     # больший хвост — в merge_index
    |     # сдвигаем его указатель

  Три указателя идут справа налево. Цикл кончается, когда перенесён весь `nums2`: остаток `nums1` уже стоит на своих местах. Индекс `-1` в Python — последний элемент, поэтому `index1 >= 0` в условии обязателен: без него `nums1[-1]` молча прочитает не то.

[Грабли]
  грабли: Идти с начала: `[4, 0]` и `[1]` → `4` затрётся раньше, чем его прочитали

    |     # последний живой в nums1
    |     index1 = m - 1
    |     # последний в nums2
    |     index2 = n - 1
    |     # куда ставить больший
    |     merge_index = m + n - 1
    |     # пока nums2 не кончился
    |     while index2 >= 0:
    |         # берём больший хвост
    |         if index1 >= 0 and nums1[index1] > nums2[index2]:
    |             nums1[merge_index] = nums1[index1]
    |             index1 -= 1
    |         else:
    |             nums1[merge_index] = nums2[index2]
    |             index2 -= 1
    |         # место записи — влево
    |         merge_index -= 1
  Грабли:
    - Идти с начала — затрёшь ещё не прочитанные числа `nums1`
    - `while index1 >= 0` вместо `index2 >= 0`: если `nums1` кончился первым, хвост `nums2` не перенесён
    - Отрицательный индекс в Python не ошибка: `nums2[-1]` молча читает последний элемент, поэтому промах с границей даёт неверный ответ, а не падение
    - `nums1 = sorted(...)` внутри функции не меняет список снаружи: на месте — это запись по индексу или `nums1[:] = ...`
  Вариации:
    - в проде коротко: `nums1[m:] = nums2` и `nums1.sort()` — верно, но O((m+n) log(m+n))
    - с дополнительной памятью — обычное слияние с начала в новый список, O(m+n) памяти
    - `heapq.merge(a, b)` сливает два отсортированных итерируемых лениво, но это тоже новый список
