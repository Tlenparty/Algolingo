# l1.4
note: 1.4 Two Sum (массив НЕ отсортирован)
title: Two Sum
examples:
- assertEquals(0 to 1, twoSum(intArrayOf(2, 7, 11, 15), 9))
- assertEquals(1 to 2, twoSum(intArrayOf(3, 2, 4), 6))
- assertEquals(0 to 1, twoSum(intArrayOf(3, 3), 6))
- assertNull(twoSum(intArrayOf(1, 2), 7))

## theory Когда Map значение → индекс
signals:
- «Найди пару с суммой `target`»
- Массив не отсортирован
- Вернуть нужно индексы, а не сами числа
body: Для каждого `x` ищем дополнение `target - x` среди уже пройденных: `HashMap` «значение → индекс» отвечает за O(1). Если массив отсортирован — это два указателя (уровень 2).

## theory Каркас
skeleton:
```kotlin
for (i in nums.indices) {
    val need = target - nums[i]
    seen[need]?.let { return it to i }
    seen[nums[i]] = i
}
```
body: Один проход, не два: сначала ищем дополнение, потом кладём текущее число. O(n) по времени и памяти.

## theory Грабли
pitfalls:
- Сначала положить `nums[i]`, потом искать: `[3, 2, 4]`, `6` → `3` найдёт сам себя, ответ `0 to 0` вместо `1 to 2`
- Искать `nums[i]` вместо дополнения `target - nums[i]`: пара не найдётся
- Два вложенных цикла «каждый с каждым» — O(n²)

## e1
```kotlin
fun twoSum(nums: IntArray, target: Int): Pair<Int, Int>? {
    val seen = HashMap<Int, Int>()
    for (i in nums.indices) {
        val need = target - nums[i]
        seen[⟦need⟧]?.let { return it to i }
        seen[nums[i]] = i
    }
    return null
}
```
- `nums[i]` [wrong]: ищем само число, а не дополнение: `[2, 7]`, `9` → `null` вместо `0 to 1`
- `target` [wrong]: ищем `target` целиком, а не недостающую часть: `[2, 7]`, `9` → `null` вместо `0 to 1`
? Для текущего `x` нужно `target - x`. Если оно уже в Map — ответ.

## e2
```kotlin
fun twoSum(nums: IntArray, target: Int): Pair<Int, Int>? {
    val seen = HashMap<Int, Int>()
    for (i in nums.indices) {
        val need = target ⟦-⟧ nums[i]
        seen[⟦need⟧]?.let { return it to i }
        seen[nums[i]] = i
    }
    return null
}
```
- `+` [wrong]: дополнение — это разность, а не сумма: `[2, 7]`, `9` → ищем `11` и `16`, ответ `null` вместо `0 to 1`
- `nums[i]` [wrong]: ищем само число, а не дополнение: `[2, 7]`, `9` → `null` вместо `0 to 1`
- @1 `need` [compile]: между `target` и `nums[i]` нужен оператор, а `need` ещё не объявлен: `target need nums[i]` не скомпилируется
- @1 `nums[i]` [compile]: между `target` и `nums[i]` нужен оператор: `target nums[i] nums[i]` не скомпилируется
- @2 `-` [compile]: в скобках нужен ключ, а не оператор: `seen[-]` не скомпилируется
- @2 `+` [compile]: в скобках нужен ключ, а не оператор: `seen[+]` не скомпилируется
? Для текущего `x` нужно `target - x`. Если оно уже в Map — ответ.

## e3
```kotlin
fun twoSum(nums: IntArray, target: Int): Pair<Int, Int>? {
    val seen = HashMap<Int, Int>()
    for (i in ⟦nums.indices⟧) {
        val need = target ⟦-⟧ nums[i]
        seen[⟦need⟧]?.let { return it to i }
        seen[⟦nums[i]⟧] = i
    }
    return null
}
```
- `0..nums.size` [crash]: `..` включает `nums.size`, последний шаг читает за границей: `[1, 2]`, `7` → падает на `nums[2]` вместо `null`
- `+` [wrong]: дополнение — это разность, а не сумма: `[2, 7]`, `9` → ищем `11` и `16`, ответ `null` вместо `0 to 1`
- `target`
- @1 `-` [compile]: после `in` нужен диапазон, а не оператор: `for (i in -)` не скомпилируется
- @1 `need` [compile]: `need` объявляется только внутри цикла: `for (i in need)` не скомпилируется
- @1 `nums[i]` [compile]: `i` ещё не объявлен, а одно число не перебрать: `for (i in nums[i])` не скомпилируется
- @1 `+` [compile]: после `in` нужен диапазон, а не оператор: `for (i in +)` не скомпилируется
- @1 `target` [compile]: одно число `Int` не перебрать циклом: `for (i in target)` не скомпилируется
- @2 `nums.indices` [compile]: между `target` и `nums[i]` нужен оператор: `target nums.indices nums[i]` не скомпилируется
- @2 `need` [compile]: между `target` и `nums[i]` нужен оператор, а `need` ещё не объявлен: `target need nums[i]` не скомпилируется
- @2 `nums[i]` [compile]: между `target` и `nums[i]` нужен оператор: `target nums[i] nums[i]` не скомпилируется
- @2 `0..nums.size` [compile]: между `target` и `nums[i]` нужен оператор: `target 0..nums.size nums[i]` не скомпилируется
- @2 `target` [compile]: между `target` и `nums[i]` нужен оператор: `target target nums[i]` не скомпилируется
- @3 `nums.indices` [compile]: ключи `seen` — числа `Int`, а не диапазон: `seen[nums.indices]` не скомпилируется
- @3 `-` [compile]: в скобках нужен ключ, а не оператор: `seen[-]` не скомпилируется
- @3 `nums[i]` [wrong]: при `seen[nums[i]] = i` ниже ищем само число, а не дополнение: `[2, 7]`, `9` → `null` вместо `0 to 1`. Сработает, только если и хранить наоборот — `seen[need] = i` («какое число жду → индекс»); но здесь собираем канон: ищем `need`, кладём `nums[i]`
- @3 `0..nums.size` [compile]: ключи `seen` — числа `Int`, а не диапазон: `seen[0..nums.size]` не скомпилируется
- @3 `+` [compile]: в скобках нужен ключ, а не оператор: `seen[+]` не скомпилируется
- @3 `target` [wrong]: ищем `target` целиком, а не недостающую часть: `[2, 7]`, `9` → `null` вместо `0 to 1`
- @4 `nums.indices` [compile]: ключи `seen` — числа `Int`, а не диапазон: `seen[nums.indices] = i` не скомпилируется
- @4 `-` [compile]: в скобках нужен ключ, а не оператор: `seen[-] = i` не скомпилируется
- @4 `need` [wrong]: при `seen[need]` выше кладём дополнение, а ищем дополнение к другому числу: `[2, 7]`, `9` → `null` вместо `0 to 1`. Сработает, только если и искать наоборот — `seen[nums[i]]` («кто ждал это число?»); но здесь собираем канон: ищем `need`, кладём `nums[i]`
- @4 `0..nums.size` [compile]: ключи `seen` — числа `Int`, а не диапазон: `seen[0..nums.size] = i` не скомпилируется
- @4 `+` [compile]: в скобках нужен ключ, а не оператор: `seen[+] = i` не скомпилируется
- @4 `target` [wrong]: под одним ключом `target` хранится только последний индекс, чисел не запоминаем: `[2, 7]`, `9` → `null` вместо `0 to 1`
? Идём по всем индексам массива — `i` нужен для ответа.
? Для текущего `x` нужно `target - x`. Если оно уже в Map — ответ.
? Иначе кладём `x → i`: Map хранит «значение → индекс».
