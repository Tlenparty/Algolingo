# l2.4
note: 2.4 Квадраты отсортированного массива
trains: два указателя навстречу, ответ заполняется с конца
examples:
- assertContentEquals(intArrayOf(0, 1, 9, 16, 100), sortedSquares(intArrayOf(-4, -1, 0, 3, 10)))
- assertContentEquals(intArrayOf(4, 9, 9, 49, 121), sortedSquares(intArrayOf(-7, -3, 2, 3, 11)))
checks:
```kotlin
// оракул: квадраты, потом sorted(); все отсортированные массивы длины 0..5 из {-3..3}
for (n in 0..5) case {
    for (m in 0 until pw(7, n)) {
        val a = IntArray(n) { (m / pw(7, it)) % 7 - 3 }.also { it.sort() }
        val expected = a.map { it * it }.sorted()
        assertEquals(expected, sortedSquares(a.copyOf()).toList(), a.toList().toString())
    }
}
case { assertContentEquals(intArrayOf(), sortedSquares(intArrayOf())) }
case { assertContentEquals(intArrayOf(25), sortedSquares(intArrayOf(-5))) }
case { assertContentEquals(intArrayOf(1, 4, 9), sortedSquares(intArrayOf(-3, -2, -1))) }
case { assertContentEquals(intArrayOf(1, 4, 9), sortedSquares(intArrayOf(1, 2, 3))) }
case { assertContentEquals(intArrayOf(0, 0, 0), sortedSquares(intArrayOf(0, 0, 0))) }
case { assertContentEquals(intArrayOf(10000, 10000), sortedSquares(intArrayOf(-100, 100))) }
// контрпримеры из причин
case { assertContentEquals(intArrayOf(1, 4), sortedSquares(intArrayOf(-1, 2))) }
case { assertContentEquals(intArrayOf(1, 9), sortedSquares(intArrayOf(-3, 1))) }
case { assertContentEquals(intArrayOf(1), sortedSquares(intArrayOf(1))) }
```

## theory Когда навстречу с конца
signals:
- Массив отсортирован, но преобразование ломает порядок (квадрат, модуль)
- Самые большие результаты — **по краям** массива
- Нужно O(n), без сортировки за O(n log n)
body: После возведения в квадрат отсортированный массив похож на долину: большие квадраты по краям, маленькие в середине. Указатели с двух концов каждый раз дают самый большой из оставшихся квадратов, поэтому ответ заполняется **с конца**.

## theory Каркас
skeleton:
```kotlin
// концы массива
var left = 0
var right = nums.size - 1
// пишем с конца
for (writeIndex in nums.size - 1 downTo 0) {
    // больший квадрат — в ячейку
    // сдвигаем его указатель
}
```
body: Каждый шаг забирает один конец, поэтому за `n` шагов указатели сходятся, а все ячейки ответа заполнены.

## theory Грабли
pitfalls:
- Просто возвести в квадрат: `[-4, -1, 0, 3]` → `[16, 1, 0, 9]`, порядок сломан
- Заполнять с начала: у концов самые **большие** квадраты, ответ выйдет убывающим: `[-1, 2]` → `[4, 1]`
- Сравнивать `nums[left]` и `nums[right]` без квадрата: `-3 < 1`, хотя `9 > 1`
- `nums.size downTo 0`: ячейки `nums.size` нет, первая же запись падает

## e1
```kotlin
fun sortedSquares(nums: IntArray): IntArray {
    // ответ той же длины
    val result = IntArray(nums.size)
    // концы массива — кандидаты
    var left = 0
    var right = nums.size - 1
    // заполняем с конца
    for (writeIndex in ⟦nums.size - 1 downTo 0⟧) {
        // квадраты обоих концов
        val leftSquare = nums[left] * nums[left]
        val rightSquare = nums[right] * nums[right]
        // больший — в ячейку
        if (leftSquare > rightSquare) {
            result[writeIndex] = leftSquare
            left++
        } else {
            result[writeIndex] = rightSquare
            right--
        }
    }
    return result
}
```
- `0 until nums.size` [wrong]: у концов самые большие квадраты, с начала ответ выйдет убывающим: `[-1, 2]` → `[4, 1]` вместо `[1, 4]`
- `nums.size downTo 0` [crash]: последняя ячейка — `nums.size - 1`: `[1]` → `result[1]` падает с `ArrayIndexOutOfBoundsException`
? Больший из двух концов — самый большой из оставшихся квадратов. Где ему место в ответе?

## e2
```kotlin
fun sortedSquares(nums: IntArray): IntArray {
    // ответ той же длины
    val result = IntArray(nums.size)
    // концы массива — кандидаты
    var left = 0
    var right = nums.size - 1
    // заполняем с конца
    for (writeIndex in ⟦nums.size - 1 downTo 0⟧) {
        // квадраты обоих концов
        val leftSquare = nums[left] * nums[left]
        val rightSquare = nums[right] * nums[right]
        // больший — в ячейку
        if (leftSquare ⟦> | ~>=⟧ rightSquare) {
            result[writeIndex] = leftSquare
            left++
        } else {
            result[writeIndex] = rightSquare
            right--
        }
    }
    return result
}
```
- ~`>=`: тоже верно: при равных квадратах в ячейку попадёт то же число, какой конец ни возьми
- `0 until nums.size` [wrong]: у концов самые большие квадраты, с начала ответ выйдет убывающим: `[-1, 2]` → `[4, 1]` вместо `[1, 4]`
- `nums.size downTo 0` [crash]: последняя ячейка — `nums.size - 1`: `[1]` → `result[1]` падает с `ArrayIndexOutOfBoundsException`
- `<` [wrong]: в конец уходит меньший квадрат: `[-1, 2]` → `[4, 1]` вместо `[1, 4]`
- @1 `>` [compile]: после `in` нужен диапазон, а не оператор: `for (writeIndex in >)` не скомпилируется
- @1 `>=` [compile]: после `in` нужен диапазон, а не оператор: `for (writeIndex in >=)` не скомпилируется
- @1 `<` [compile]: после `in` нужен диапазон, а не оператор: `for (writeIndex in <)` не скомпилируется
- @2 `nums.size - 1 downTo 0` [compile]: между двумя числами нужен оператор сравнения: `leftSquare nums.size - 1 downTo 0 rightSquare` не скомпилируется
- @2 `0 until nums.size` [compile]: между двумя числами нужен оператор сравнения: `leftSquare 0 until nums.size rightSquare` не скомпилируется
- @2 `nums.size downTo 0` [compile]: между двумя числами нужен оператор сравнения: `leftSquare nums.size downTo 0 rightSquare` не скомпилируется
? Больший из двух концов — самый большой из оставшихся квадратов. Где ему место в ответе?
? В текущую ячейку идёт больший из двух квадратов.
