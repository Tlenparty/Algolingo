# l5.1
note: 5.1 Climb Stairs (разгон в DP)
title: Подъём по лестнице
trains: от рекурсии к DP с O(1) памятью: две переменные вместо массива
pitfalls:
- Наивная рекурсия `f(n - 1) + f(n - 2)` без запоминания — O(2ⁿ): одни и те же ступени считаются заново
- База: до 1-й ступени 1 способ, до 2-й — 2; `n <= 2` отвечаем сразу, без цикла
- Порядок обновления: сначала `next`, потом `prev = current`, потом `current = next`; иначе старое значение потеряется
- Шагов цикла `n - 2`: ступени 1 и 2 уже посчитаны
variations:
- Массив `ways` длины `n + 1`: `ways[i] = ways[i - 1] + ways[i - 2]` — проще объяснить, но O(n) памяти
- Рекурсия с мемо (`HashMap<Int, Int>`) — сверху вниз, тоже O(n)
- Шаги 1, 2 или 3 (трибоначчи): три переменные, `next = a + b + c`
- Min Cost Climbing Stairs (LeetCode 746): тот же каркас, но `minOf` вместо суммы
examples:
- assertEquals(2, climbStairs(2))
- assertEquals(3, climbStairs(3))
- assertEquals(8, climbStairs(5))
- assertEquals(1, climbStairs(1))
checks:
```kotlin
// оракул: список ways[i] = ways[i - 1] + ways[i - 2]; все n от 1 до 45
case {
    val ways = IntArray(46)
    ways[0] = 1
    ways[1] = 1
    for (i in 2..45) ways[i] = ways[i - 1] + ways[i - 2]
    for (n in 1..45) assertEquals(ways[n], climbStairs(n), "n = $n")
}
// оракул 2: перебор шагов рекурсией в лоб; n от 1 до 20
case {
    fun naive(k: Int): Int = if (k < 0) 0 else if (k == 0) 1 else naive(k - 1) + naive(k - 2)
    for (n in 1..20) assertEquals(naive(n), climbStairs(n), "n = $n")
}
case { assertEquals(1836311903, climbStairs(45)) } // максимум LeetCode, ещё влезает в Int
// контрпримеры из причин
case { assertEquals(1, climbStairs(1)) }
case { assertEquals(2, climbStairs(2)) }
case { assertEquals(3, climbStairs(3)) }
case { assertEquals(5, climbStairs(4)) }
case { assertEquals(8, climbStairs(5)) }
```

## theory Когда DP «как Фибоначчи»
signals:
- «Сколько способов» дойти до шага `n`
- Ход — на 1 или на 2 вперёд
- Ответ для `i` собирается из ответов для `i - 1` и `i - 2`
body: На ступень `i` приходят либо с `i - 1`, либо с `i - 2`, поэтому `ways(i) = ways(i - 1) + ways(i - 2)`. Рекурсия в лоб считает одно и то же много раз — O(2ⁿ). Идём снизу вверх и помним только два последних ответа: O(n) времени, O(1) памяти.

## theory Каркас: две переменные
skeleton:
```kotlin
// ответы для i-2 и i-1
var prev = 1
var current = 2
repeat(n - 2) {
    val next = prev + current
    // сдвигаем окно на ступень
    prev = current
    current = next
}
```
body: `prev` и `current` — окно из двух последних ступеней. Каждый шаг сдвигает его на одну ступень вверх.

## theory Грабли
pitfalls:
- `prev = current` после `current = next`: старое `current` уже затёрто, `prev` станет равным `current`
- Шагов `n - 1` вместо `n - 2`: ступени 1 и 2 уже в `prev` и `current`, лишний шаг уводит на ступень выше
- База `n <= 2` → `return n`: для `n = 1` ответ `1`, для `n = 2` — `2`, без цикла
- Рекурсия без мемо — O(2ⁿ): `n = 45` считается секунды

## e1
```kotlin
// Случай 1: n = 2 → 2 (1+1, 2)
// Случай 2: n = 3 → 3 (1+1+1, 1+2, 2+1)
// Случай 3: n = 5 → 8
fun climbStairs(n: Int): Int {
    // 1 ступень — 1 способ, 2 — два
    if (n <= 2) return n
    // способов дойти до i-2 и до i-1
    var prev = 1
    var current = 2
    repeat(n - 2) {
        // на ступень i — с i-1 или с i-2
        val next = ⟦prev + current⟧
        prev = current
        current = next
    }
    return current
}
```
- `prev * current` [wrong]: способы с двух ступеней складываются, а не перемножаются: `n = 3` → `2` вместо `3`
- `current + current` [wrong]: с `i - 2` приходит `prev` способов, а не `current`: `n = 3` → `4` вместо `3`
- `current + 1` [wrong]: со ступени `i - 2` приходит не один способ, а `prev`: `n = 4` → `4` вместо `5`
? На ступень `i` приходят с `i - 1` или с `i - 2`. Как сложить способы?

## e2
```kotlin
// Случай 1: n = 2 → 2 (1+1, 2)

    var prev = ⟦1⟧
    var current = ⟦2⟧

        // на ступень i — с i-1 или с i-2

    }

```
- `current` [compile]: `current` объявлена ниже или в этой же строке, читать её ещё нельзя: `var prev = current` не скомпилируется
- `0`
- `n - 1`
- @1 `1` [wrong]: для двух ступеней способов два (1+1 и 2): `n = 2` → `1` вместо `2`
- @1 `2` [wrong]: на одну ступень есть один способ: `n = 1` → `2` вместо `1`
- @1 `0` [wrong]: ступень есть, значит способ есть: `n = 1` → `0` вместо `1`

## e3
```kotlin
// Случай 1: n = 2 → 2 (1+1, 2)
// Случай 2: n = 3 → 3 (1+1+1, 1+2, 2+1)
// Случай 3: n = 5 → 8
fun climbStairs(n: Int): Int {
    // 1 ступень — 1 способ, 2 — два

    // способов дойти до i-2 и до i-1

    var current = 2
    repeat(⟦n - 2⟧) {
        // на ступень i — с i-1 или с i-2
```

- `prev`
