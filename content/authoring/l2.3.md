# l2.3
note: 2.3 Слияние отсортированных массивов
examples:
- assertContentEquals(intArrayOf(1, 2, 2, 3, 5, 6), intArrayOf(1, 2, 3, 0, 0, 0).also { merge(it, 3, intArrayOf(2, 5, 6), 3) })
- assertContentEquals(intArrayOf(1), intArrayOf(1).also { merge(it, 1, intArrayOf(), 0) })
- assertContentEquals(intArrayOf(1), intArrayOf(0).also { merge(it, 0, intArrayOf(1), 1) })
checks:
```kotlin
// оракул: (a + b).sorted(); все отсортированные a и b длины 0..3 из {1..4}, хвост nums1 — нули-заглушки
for (m in 0..3) for (n in 0..3) case {
    for (x in 0 until pw(4, m)) for (y in 0 until pw(4, n)) {
        val a = IntArray(m) { (x / pw(4, it)) % 4 + 1 }.also { it.sort() }
        val b = IntArray(n) { (y / pw(4, it)) % 4 + 1 }.also { it.sort() }
        val nums1 = a.copyOf(m + n)
        merge(nums1, m, b.copyOf(), n)
        assertEquals((a + b).sorted(), nums1.toList(), "${a.toList()} ${b.toList()}")
    }
}
```

## theory Когда с конца
signals:
- Слить два отсортированных массива **на месте**
- Свободное место — в конце первого массива
- Нужно O(m+n) по времени и O(1) по памяти
body: Если писать с начала, затрёшь ещё не прочитанные числа `nums1`. С конца свободно: самый большой из двух хвостов встаёт на последнюю свободную позицию, и запись никогда не догоняет чтение.

## theory Каркас
skeleton:
```kotlin
// хвосты и место записи
var index1 = m - 1
var index2 = n - 1
var mergeIndex = m + n - 1
// пока nums2 не кончился
while (index2 >= 0) {
    // больший хвост — в mergeIndex
    // сдвигаем его указатель
    mergeIndex--
}
```
body: Три указателя идут справа налево. Цикл кончается, когда перенесён весь `nums2`: остаток `nums1` уже стоит на своих местах.

## theory Грабли
pitfalls:
- Идти с начала: `[4, 0]` и `[1]` → `4` затрётся раньше, чем его прочитали
- `while (index1 >= 0)`: если `nums1` кончился первым, хвост `nums2` не перенесён: `[4, 0]`, `[1]` → `[4, 4]`
- `mergeIndex = m + n`: такой ячейки нет, первая же запись падает
- Без `index1 >= 0` в `if` читаем `nums1[-1]`, когда `nums1` кончился

## e1
```kotlin
fun merge(nums1: IntArray, m: Int, nums2: IntArray, n: Int) {
    // последний живой в nums1
    var index1 = m - 1
    // последний в nums2
    var index2 = n - 1
    // куда ставить больший
    var mergeIndex = m + n - 1
    // пока nums2 не кончился
    while (⟦index2 >= 0⟧) {
        // берём больший хвост
        if (index1 >= 0 && nums1[index1] > nums2[index2]) {
            nums1[mergeIndex] = nums1[index1]
            index1--
        } else {
            nums1[mergeIndex] = nums2[index2]
            index2--
        }
        // место записи — влево
        mergeIndex--
    }
}
```
- `index1 >= 0` [wrong]: если `nums1` кончился первым, хвост `nums2` не перенесён: `[4, 0]`, `m = 1`, `[1]` → `[4, 4]` вместо `[1, 4]`
- `mergeIndex > 0` [wrong]: ячейку `0` не заполним никогда: `[0]`, `m = 0`, `[1]` → `[0]` вместо `[1]`
? Хвост `nums1` уже стоит на месте, а `nums2` надо перенести целиком.

## e3
```kotlin
fun merge(nums1: IntArray, m: Int, nums2: IntArray, n: Int) {
    // последний живой в nums1
    var index1 = m - 1
    // последний в nums2
    var index2 = n - 1
    // куда ставить больший
    var mergeIndex = ⟦m + n - 1⟧
    // пока nums2 не кончился
    while (⟦index2 >= 0⟧) {
        // берём больший хвост
        if (index1 >= 0 && nums1[index1] ⟦> | ~>=⟧ nums2[index2]) {
            nums1[mergeIndex] = nums1[index1]
            index1--
        } else {
            nums1[mergeIndex] = nums2[index2]
            index2--
        }
        // место записи — влево
        mergeIndex--
    }
}
```
- ~`>=`: тоже верно: при равенстве первым уходит число из `nums1`, но равные числа неотличимы, порядок всё равно правильный
- `m + n` [crash]: последняя ячейка — `m + n - 1`: `[1, 0]`, `m = 1`, `[2]` → `nums1[2]` падает с `ArrayIndexOutOfBoundsException`
- `index1 >= 0` [wrong]: если `nums1` кончился первым, хвост `nums2` не перенесён: `[4, 0]`, `m = 1`, `[1]` → `[4, 4]` вместо `[1, 4]`
- `<` [wrong]: в конец уходит меньший, порядок ломается: `[1, 0]`, `m = 1`, `[2]` → `[2, 1]` вместо `[1, 2]`
- @1 `index2 >= 0` [compile]: `mergeIndex` станет `Boolean`, а индекс должен быть числом: `nums1[mergeIndex]` не скомпилируется
- @1 `index1 >= 0` [compile]: `mergeIndex` станет `Boolean`, а индекс должен быть числом: `nums1[mergeIndex]` не скомпилируется
- @1 `>` [compile]: после `=` нужно значение, а не оператор: `var mergeIndex = >` не скомпилируется
- @1 `>=` [compile]: после `=` нужно значение, а не оператор: `var mergeIndex = >=` не скомпилируется
- @1 `<` [compile]: после `=` нужно значение, а не оператор: `var mergeIndex = <` не скомпилируется
- @2 `m + n - 1` [compile]: условию `while` нужен `Boolean`, а не число: `while (m + n - 1)` не скомпилируется
- @2 `m + n` [compile]: условию `while` нужен `Boolean`, а не число: `while (m + n)` не скомпилируется
- @2 `>` [compile]: условию нужно выражение, а не оператор: `while (>)` не скомпилируется
- @2 `>=` [compile]: условию нужно выражение, а не оператор: `while (>=)` не скомпилируется
- @2 `<` [compile]: условию нужно выражение, а не оператор: `while (<)` не скомпилируется
- @3 `m + n - 1` [compile]: между двумя числами нужен оператор сравнения: `nums1[index1] m + n - 1 nums2[index2]` не скомпилируется
- @3 `m + n` [compile]: между двумя числами нужен оператор сравнения: `nums1[index1] m + n nums2[index2]` не скомпилируется
- @3 `index2 >= 0` [compile]: между двумя числами нужен один оператор сравнения: `nums1[index1] index2 >= 0 nums2[index2]` не скомпилируется
- @3 `index1 >= 0` [compile]: между двумя числами нужен один оператор сравнения: `nums1[index1] index1 >= 0 nums2[index2]` не скомпилируется
