# l0.3
note: 0.3 Палиндром ли строка
title: Палиндром
pitfalls:
- `l <= r` работает, но на нечётной длине средний символ сравнивается сам с собой: лишний шаг
- `r = s.length` вместо `s.length - 1`: первый же `s[r]` вне строки
- `l != r`: на чётной длине указатели проскочат друг друга и выйдут за границы
- Перепутать ответы: на несовпадении — `false`, после цикла — `true`
examples:
- assertTrue(isPalindrome("aba"))
- assertTrue(isPalindrome("abba"))
- assertFalse(isPalindrome("ab"))
- assertTrue(isPalindrome(""))
- assertTrue(isPalindrome("a"))

## theory Тот же скелет
signals:
- «Палиндром / симметрия»
- «Читается одинаково с обеих сторон»
body: Скелет разворота из 0.2, только вместо обмена сравниваем пару: `s[l] != s[r]` — сразу `return false`. Время O(n), память O(1).

## theory Каркас
skeleton:
```kotlin
var l = 0
var r = n - 1
while (l < r) {
    // пара не сходится -> сразу ответ
    l++; r--
}
// дошли до середины -> ответ
```
body: Как и в 0.2, `l <= r` засчитывается с пометкой: средний символ лишний раз сравнится сам с собой.

## theory Грабли
pitfalls:
- `r = s.length`: первый же `s[r]` вне строки
- `l != r` на чётной длине: указатели проскочат друг друга, `"abba"` → `s[4]`
- Перепутать ответы: на несовпадении `false`, после цикла `true`

## e1
```kotlin
fun isPalindrome(s: String): Boolean {
    var l = 0
    var r = s.length - 1
    while (⟦l < r | ~l <= r⟧) {
        if (s[l] != s[r]) return false
        l++; r--
    }
    return true
}
```
- ~`l <= r`: работает, но на нечётной длине средний символ сравнится сам с собой: `"aba"` делает лишний шаг на `b`
- `l > r` [wrong]: цикл не выполнится ни разу: `"ab"` вернёт `true`
- `l != r` [crash]: на чётной длине указатели проскочат друг друга: `"abba"` → выход за границы на `s[4]`
? Указатели с краёв идут навстречу, пока `l < r`.

## e2
```kotlin
fun isPalindrome(s: String): Boolean {
    var l = 0
    var r = s.length - 1
    while (l < r) {
        if (s[l] ⟦!=⟧ s[r]) return ⟦false⟧
        l++; r--
    }
    return true
}
```
- `==` [wrong]: условие перевёрнуто: `"ab"` вернёт `true`, а `"aba"` — `false`
- `true` [wrong]: на несовпадении скажет «да»: `"ab"` вернёт `true`
- @1 `true` [compile]: `s[l] true s[r]` не скомпилируется: здесь нужен оператор сравнения
- @2 `==` [compile]: `return ==` не скомпилируется: здесь нужен ответ `Boolean`
? Нашли несовпадающую пару — дальше смотреть незачем: сразу `return false`.

## e3
```kotlin
fun isPalindrome(s: String): Boolean {
    var l = 0
    var r = ⟦s.length - 1⟧
    while (⟦l < r⟧) {
        if (s[l] ⟦!=⟧ s[r]) return false
        l++; r--
    }
    return ⟦true⟧
}
```
- `s.length` [wrong]: первый же `s[r]` вне строки: `"aba"` → `s[3]`
- `false`
- `==` [wrong]: условие перевёрнуто: `"aba"` вернёт `false`
- @2 `s.length` [compile]: `while` ждёт `Boolean`, а `s.length` — `Int`: не скомпилируется
- @3 `s.length` [compile]: `s[l] s.length s[r]` не скомпилируется: здесь нужен оператор сравнения
- @4 `s.length` [compile]: функция возвращает `Boolean`, а `s.length` — `Int`: не скомпилируется
- @1 `false` [compile]: `r` должен быть индексом `Int`, а не `Boolean`: `l < r` не скомпилируется
- @2 `false` [wrong]: `while (false)` не выполнится ни разу: `"ab"` вернёт `true`
- @3 `false` [compile]: `s[l] false s[r]` не скомпилируется: здесь нужен оператор сравнения
- @4 `false` [wrong]: на палиндроме ответ всё равно «нет»: `"aba"` вернёт `false`
- @1 `==` [compile]: `var r = ==` не скомпилируется: здесь нужен индекс последнего символа
- @2 `==` [compile]: `while (==)` не скомпилируется: здесь нужно условие `l < r`
- @4 `==` [compile]: `return ==` не скомпилируется: здесь нужен ответ `Boolean`
- @2 `true` [crash]: `while (true)` не остановится в середине: `"aba"` → выход за границы на `s[3]`
- @4 `l < r` [wrong]: после цикла `l < r` всегда ложно: `"aba"` вернёт `false`
? `r` — индекс последнего символа: `s.length - 1`.
? Нашли несовпадающую пару — сразу `return false`.
? Цикл дошёл до середины без расхождений — строка палиндром: `return true`.
