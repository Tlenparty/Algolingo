# l2.3
note: 2.3 Слияние отсортированных массивов
lang: python
statement: В `nums1` первые `m` чисел отсортированы, дальше `n` нулей-заглушек; `nums2` из `n` отсортированных чисел. Слей `nums2` в `nums1` **на месте**, чтобы весь `nums1` стал отсортированным (LeetCode 88). Функция ничего не возвращает.
pitfalls:
- Идти с начала — затрёшь ещё не прочитанные числа `nums1`
- `while index1 >= 0` вместо `index2 >= 0`: если `nums1` кончился первым, хвост `nums2` не перенесён
- Отрицательный индекс в Python не ошибка: `nums2[-1]` молча читает последний элемент, поэтому промах с границей даёт неверный ответ, а не падение
- `nums1 = sorted(...)` внутри функции не меняет список снаружи: на месте — это запись по индексу или `nums1[:] = ...`
variations:
- в проде коротко: `nums1[m:] = nums2` и `nums1.sort()` — верно, но O((m+n) log(m+n))
- с дополнительной памятью — обычное слияние с начала в новый список, O(m+n) памяти
- `heapq.merge(a, b)` сливает два отсортированных итерируемых лениво, но это тоже новый список
examples:
- a = [1, 2, 3, 0, 0, 0]; merge(a, 3, [2, 5, 6], 3); assert a == [1, 2, 2, 3, 5, 6]
- a = [1]; merge(a, 1, [], 0); assert a == [1]
- a = [0]; merge(a, 0, [1], 1); assert a == [1]
checks:
```python
# оракул: sorted(a + b); все отсортированные a и b длины 0..3 из {1..4}, хвост nums1 — нули-заглушки
for m in range(4):
    for n in range(4):
        with case():
            for x in range(pw(4, m)):
                for y in range(pw(4, n)):
                    a = sorted((x // pw(4, i)) % 4 + 1 for i in range(m))
                    b = sorted((y // pw(4, i)) % 4 + 1 for i in range(n))
                    nums1 = a + [0] * n
                    r = merge(nums1, m, b[:], n)
                    assert r is None and nums1 == sorted(a + b), (a, b, nums1)
with case():
    a = []
    merge(a, 0, [], 0)
    assert a == []
with case():
    a = [-1, 0, 3, 0, 0]
    merge(a, 3, [-5, 0], 2)
    assert a == [-5, -1, 0, 0, 3]
with case():
    a = [4, 5, 6, 0, 0, 0]
    merge(a, 3, [1, 2, 3], 3)
    assert a == [1, 2, 3, 4, 5, 6]
# контрпримеры из причин
with case():
    a = [4, 0]
    merge(a, 1, [1], 1)
    assert a == [1, 4]
with case():
    a = [1, 0]
    merge(a, 1, [2], 1)
    assert a == [1, 2]
```

## theory Когда с конца
signals:
- Слить два отсортированных списка **на месте**
- Свободное место — в конце первого списка
- Нужно O(m+n) по времени и O(1) по памяти
body: Если писать с начала, затрёшь ещё не прочитанные числа `nums1`. С конца свободно: самый большой из двух хвостов встаёт на последнюю свободную позицию, и запись никогда не догоняет чтение.

## theory Каркас
skeleton:
```python
# хвосты и место записи
index1, index2 = m - 1, n - 1
merge_index = m + n - 1
# пока nums2 не кончился
while index2 >= 0:
    # больший хвост — в merge_index
    # сдвигаем его указатель
    merge_index -= 1
```
body: Три указателя идут справа налево. Цикл кончается, когда перенесён весь `nums2`: остаток `nums1` уже стоит на своих местах. Индекс `-1` в Python — последний элемент, поэтому `index1 >= 0` в условии обязателен: без него `nums1[-1]` молча прочитает не то.

## theory Грабли
pitfalls:
- Идти с начала: `[4, 0]` и `[1]` → `4` затрётся раньше, чем его прочитали
- `while index1 >= 0`: если `nums1` кончился первым, хвост `nums2` не перенесён: `[4, 0]`, `[1]` → `[4, 4]`
- `merge_index = m + n`: такой ячейки нет, первая же запись падает с `IndexError`
- Без `index1 >= 0` в `if` при `index1 = -1` читаем `nums1[-1]` — ошибки нет, ответ неверный

## e1
```python
def merge(nums1: list[int], m: int, nums2: list[int], n: int) -> None:
    # последний живой в nums1
    index1 = m - 1
    # последний в nums2
    index2 = n - 1
    # куда ставить больший
    merge_index = m + n - 1
    # пока nums2 не кончился
    while ⟦index2 >= 0⟧:
        # берём больший хвост
        if index1 >= 0 and nums1[index1] > nums2[index2]:
            nums1[merge_index] = nums1[index1]
            index1 -= 1
        else:
            nums1[merge_index] = nums2[index2]
            index2 -= 1
        # место записи — влево
        merge_index -= 1
```
- `index1 >= 0` [wrong]: если `nums1` кончился первым, хвост `nums2` не перенесён: `[4, 0]`, `m = 1`, `[1]` → `[4, 4]` вместо `[1, 4]`
- `merge_index > 0` [wrong]: ячейку `0` не заполним никогда: `[0]`, `m = 0`, `[1]` → `[0]` вместо `[1]`
? Хвост `nums1` уже стоит на месте, а `nums2` надо перенести целиком.

```python
def merge(nums1: list[int], m: int, nums2: list[int], n: int) -> None:
    # последний живой в nums1
    index1 = m - 1
    # последний в nums2
    index2 = n - 1
    # куда ставить больший
    merge_index = ⟦m + n - 1⟧
    # пока nums2 не кончился
    while ⟦index2 >= 0⟧:
        # берём больший хвост
        if index1 >= 0 and nums1[index1] ⟦> | ~>=⟧ nums2[index2]:
            nums1[merge_index] = nums1[index1]
            index1 -= 1
        else:
            nums1[merge_index] = nums2[index2]
            index2 -= 1
        # место записи — влево
        merge_index -= 1
```
- ~`>=`: тоже верно: при равенстве первым уходит число из `nums1`, но равные числа неотличимы, порядок всё равно правильный
- `m + n` [crash]: последняя ячейка — `m + n - 1`: `[1, 0]`, `m = 1`, `[2]` → `nums1[2] = 2` падает с `IndexError`
- `index1 >= 0` [wrong]: если `nums1` кончился первым, хвост `nums2` не перенесён: `[4, 0]`, `m = 1`, `[1]` → `[4, 4]` вместо `[1, 4]`
- `<` [wrong]: в конец уходит меньший, порядок ломается: `[1, 0]`, `m = 1`, `[2]` → `[2, 1]` вместо `[1, 2]`
- @1 `index2 >= 0` [wrong]: `merge_index` станет `True`, а это индекс `1`: `[0, 0, 0]`, `m = 0`, `[1, 2, 3]` → `[2, 3, 1]` вместо `[1, 2, 3]`
