# l2.14
note: 2.14 Two Sum II (массив отсортирован)
lang: python
title: Two Sum II
statement: Список `numbers` отсортирован по неубыванию. Найди два числа с суммой `target` и верни их номера с единицы. Решение ровно одно, дополнительная память O(1) (LeetCode 167).
trains: два указателя навстречу по отсортированному списку
pitfalls:
- `[left, right]` без `+ 1`: номера с нуля, а нужны с единицы
- Перепутать сдвиги: на малой сумме `right -= 1` уводит от ответа
- `right = len(numbers)`: первый же `numbers[right]` вне списка, `IndexError`
- Без сортировки приём не работает: выкинутое число могло пригодиться
variations:
- словарь из 1.4 тоже решит за O(n), но памяти O(n) и сортировку не использует
- в лоб: перебор всех пар — O(n²)
- `bisect` для каждого числа — O(n log n), без лишней памяти
examples:
- assert two_sum_sorted([2, 7, 11, 15], 9) == [1, 2]
- assert two_sum_sorted([2, 3, 4], 6) == [1, 3]
- assert two_sum_sorted([-1, 0], -1) == [1, 2]
checks:
```python
# оракул: перебор пар; все неубывающие списки длины 2..5 из чисел -2..2 и цели, у которых пара ровно одна
for n in range(2, 6):
    with case():
        for m in range(pw(5, n)):
            a = [(m // pw(5, k)) % 5 - 2 for k in range(n)]
            if any(a[k] < a[k - 1] for k in range(1, n)):
                continue
            for t in range(-4, 5):
                pairs = [[i + 1, j + 1] for i in range(n) for j in range(i + 1, n) if a[i] + a[j] == t]
                if len(pairs) != 1:
                    continue
                got = two_sum_sorted(a, t)
                assert got == pairs[0], (a, t, got)
```

## theory Когда навстречу по сумме
signals:
- Список уже отсортирован
- Пара с заданной суммой
- Память O(1): словарь нельзя
body: Сумма крайних мала — левое число не подходит даже к самому большому справа: `left += 1`. Велика — правое не подходит даже к самому маленькому слева: `right -= 1`. Каждый шаг выкидывает одно число, поэтому O(n).

## theory Каркас
skeleton:
```python
left, right = 0, len(numbers) - 1
while left < right:
    total = numbers[left] + numbers[right]
    # нашли -> номера с единицы
    # мало -> left += 1, много -> right -= 1
```
body: Ответ просит номера с единицы, а индексы в Python с нуля: `left + 1`, `right + 1`. Сумму зовём `total`: имя `sum` занято встроенной функцией.

## theory Грабли
pitfalls:
- `[left, right]`: номера с нуля, `[2, 7, 11, 15]`, `9` → `[0, 1]` вместо `[1, 2]`
- Перепутать сдвиги: на малой сумме `right -= 1` уводит от ответа
- `right = len(numbers)`: первый же `numbers[right]` вне списка, `IndexError`
- Без сортировки приём не работает: выкинутое число могло пригодиться

## e1
```python
# Случай 1: [2, 7, 11, 15], target = 9 → [1, 2]
# Случай 2: [2, 3, 4], target = 6 → [1, 3]
# Случай 3: [-1, 0], target = -1 → [1, 2]
def two_sum_sorted(numbers: list[int], target: int) -> list[int]:
    # левый указатель — с начала
    left = 0
    # правый указатель — с конца
    right = len(numbers) - 1
    # идём навстречу
    while left < right:
        total = numbers[left] + numbers[right]
        # нашли пару: номера с единицы
        if total == target:
            return [left + 1, right + 1]
        # мало — левый вправо, много — правый влево
        if total ⟦<⟧ target:
            left += 1
        else:
            right -= 1
    # по условию пара всегда есть
    return []
```
- `>` [wrong]: сдвиги перепутаны: `[2, 7, 11, 15]`, `9` → сумма `17` велика, а `left += 1` делает её ещё больше: `[]` вместо `[1, 2]`
- `==` [wrong]: условие всегда ложно, двигается только `right`: `[2, 7, 11, 15]`, `22` → `[]` вместо `[2, 4]`
? Сумма меньше нужной — левое число слишком маленькое: двигаем `left`.
