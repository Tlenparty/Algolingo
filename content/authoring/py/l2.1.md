# l2.1
note: 2.1 Перемещение нулей
lang: python
statement: Сдвинь все нули в конец списка, сохранив порядок ненулевых, **на месте** (LeetCode 283). Функция ничего не возвращает.
trains: fast/slow в одну сторону на месте
pitfalls:
- `slow += 1` вне `if` двигает `slow` и на нулях: нули остаются на месте
- Условие `nums[fast] > 0` теряет отрицательные: `[-1, 0]` → `[0, 0]`
- Забыть добить хвост нулями: `[0, 5]` → `[5, 5]` вместо `[5, 0]`
- `nums = [...]` внутри функции не меняет список снаружи: на месте — это запись по индексу или `nums[:] = ...`
variations:
- swap за один проход без добивания: `nums[slow], nums[fast] = nums[fast], nums[slow]`
- в проде коротко: `nums[:] = [x for x in nums if x != 0] + [0] * nums.count(0)` — но это новый список, O(n) памяти
- стабильная сортировка по ключу: `nums.sort(key=lambda x: x == 0)` — верно, но O(n log n)
- LeetCode 27 Remove Element: пропускаем не нули, а `val`, и возвращаем `slow`
examples:
- a = [0, 1, 0, 3, 12]; move_zeroes(a); assert a == [1, 3, 12, 0, 0]
- a = [0]; move_zeroes(a); assert a == [0]
checks:
```python
# оракул: ненулевые в прежнем порядке, потом нули; все списки длины 0..5 из {-1, 0, 1, 2}
for n in range(6):
    with case():
        for m in range(pw(4, n)):
            a = [(m // pw(4, k)) % 4 - 1 for k in range(n)]
            got = a[:]
            r = move_zeroes(got)
            assert r is None and got == [x for x in a if x != 0] + [x for x in a if x == 0], (a, got)
with case():
    a = []
    move_zeroes(a)
    assert a == []
with case():
    a = [0, 0, 0]
    move_zeroes(a)
    assert a == [0, 0, 0]
with case():
    a = [4, -2, 7]
    move_zeroes(a)
    assert a == [4, -2, 7]
# контрпримеры из причин
with case():
    a = [0, 1]
    move_zeroes(a)
    assert a == [1, 0]
with case():
    a = [-1, 0]
    move_zeroes(a)
    assert a == [-1, 0]
with case():
    a = [0, 5]
    move_zeroes(a)
    assert a == [5, 0]
with case():
    a = [0, 5, 0]
    move_zeroes(a)
    assert a == [5, 0, 0]
```

## theory Когда fast/slow
signals:
- Переставить или отфильтровать **на месте**, без второго списка
- Порядок оставшихся элементов важен
- Нужно O(n) по времени и O(1) по памяти
body: Два указателя бегут в одну сторону: `fast` читает каждый элемент, `slow` показывает, куда писать следующий «хороший». Всё, что левее `slow`, уже готово. «На месте» значит менять сам список по индексам: `nums = ...` внутри функции создаёт новый список, а вызывающий код его не увидит.

## theory Каркас
skeleton:
```python
# куда писать хороший
slow = 0
# fast бежит по всем
for fast in range(len(nums)):
    # плохие пропускаем
    if good(nums[fast]):
        nums[slow] = nums[fast]
        slow += 1
# хвост: дописать или отрезать
```
body: `slow` двигается только после записи, поэтому он никогда не обгоняет `fast` и не затирает непрочитанное. После цикла `slow` — длина «хорошей» части.

## theory Грабли
pitfalls:
- `slow += 1` вне `if`: `slow` растёт и на нулях, они остаются на месте
- `nums[fast] > 0` вместо `!= 0`: `[-1, 0]` → `[0, 0]`, отрицательные тоже ненулевые
- Без добивания хвоста: `[0, 5]` → `[5, 5]` — старые значения остаются в конце
- `while slow <= len(nums)`: последняя запись идёт за конец списка — `IndexError`

## e1
```python
def move_zeroes(nums: list[int]) -> None:
    # куда писать ненулевой
    slow = 0
    # fast бежит по всем
    for fast in range(len(nums)):
        # нули пропускаем
        if nums[fast] ⟦!=⟧ 0:
            # копируем в slow
            nums[slow] = nums[fast]
            slow += 1
    # хвост добиваем нулями
    while slow < len(nums):
        nums[slow] = 0
        slow += 1
```
- `==` [wrong]: копируем нули вместо ненулевых: `[0, 1]` → `[0, 0]` вместо `[1, 0]`
- `>` [wrong]: отрицательные тоже ненулевые, а `>` их выбрасывает: `[-1, 0]` → `[0, 0]` вместо `[-1, 0]`
? `slow` получает только те числа, которые остаются впереди.

- `1` [wrong]: первая ячейка никогда не перезаписывается: `[0, 5]` → `[0, 5]` вместо `[5, 0]`
- `==` [wrong]: копируем нули вместо ненулевых: `[0, 1]` → `[0, 0]` вместо `[1, 0]`
- `slow <= len(nums)` [crash]: `<=` пускает `slow == len(nums)`, а такой ячейки нет: `[0, 5]` → `nums[2] = 0` падает с `IndexError`
- @1 `!=` [compile]: после `=` нужно значение, а не оператор: `slow = !=` — `SyntaxError`
- @1 `==` [compile]: после `=` нужно значение, а не оператор: `slow = ==` — `SyntaxError`
- @1 `nums[fast]` [crash]: `fast` появится только в цикле ниже: `slow = nums[fast]` → `UnboundLocalError` на первой же строке
- @1 `slow < len(nums)` [crash]: `slow` читается раньше, чем ему что-то присвоили: `slow = slow < len(nums)` → `UnboundLocalError`
- @1 `slow <= len(nums)` [crash]: `slow` читается раньше, чем ему что-то присвоили: `slow = slow <= len(nums)` → `UnboundLocalError`
- @2 `0` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] 0 0` — `SyntaxError`
- @2 `1` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] 1 0` — `SyntaxError`
- @2 `nums[fast]` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] nums[fast] 0` — `SyntaxError`
- @2 `slow < len(nums)` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] slow < len(nums) 0` — `SyntaxError`
- @2 `slow <= len(nums)` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] slow <= len(nums) 0` — `SyntaxError`
- @3 `0` [wrong]: вместо числа пишем ноль, ненулевые пропадают: `[0, 5]` → `[0, 0]` вместо `[5, 0]`
- @3 `1` [wrong]: вместо числа пишем единицу: `[0, 5]` → `[1, 0]` вместо `[5, 0]`
