# l0.4
note: 0.4 Бинарный поиск
lang: python
title: Бинарный поиск
statement: Найди индекс `target` в **отсортированном** списке за O(log n), иначе `-1`.
trains: каркас бинпоиска и инвариант «ответ всегда внутри `[lo, hi]`»
pitfalls:
- `lo < hi` вместо `<=` пропустит последний кандидат: `[5]`, `5` → `-1`
- `/` вместо `//`: в Python `/` всегда даёт `float`, и `nums[1.5]` (и даже `nums[0.0]`) падает с `TypeError`
- `lo = mid` / `hi = mid` без `± 1`: граница не сдвигается, цикл бесконечный
- Отрицательный индекс не падает: `nums[-1]` в Python — последний элемент, поэтому ошибка в границах часто даёт не `IndexError`, а зацикливание или неверный ответ
variations:
- в проде: `bisect.bisect_left(nums, target)` и проверка `i < len(nums) and nums[i] == target` — на собесе покажи цикл
- первое вхождение при дублях: на совпадении не `return`, а запомнить `mid` и идти влево `hi = mid - 1`
- граница «первый элемент `>= target`» (lower bound): полуинтервал `[lo, hi)`, `hi = len(nums)`, `while lo < hi`
examples:
- assert binary_search([1, 3, 5, 7], 5) == 2
- assert binary_search([1, 3], 0) == -1
- assert binary_search([5], 5) == 0
- assert binary_search([], 1) == -1
checks:
```python
# оракул: target in a + «по найденному индексу лежит target» (при дублях индекс не единственный)
# все отсортированные списки длины 0..5 из {0..3}, target -1..4; индекс строго в range(len(a))
for n in range(6):
    with case():
        for m in range(pw(4, n)):
            a = sorted((m // pw(4, k)) % 4 for k in range(n))
            for t in range(-1, 5):
                r = binary_search(a, t)
                if t in a:
                    assert type(r) is int and 0 <= r < len(a) and a[r] == t, (a, t, r)
                else:
                    assert r == -1, (a, t, r)
with case():
    assert binary_search([5], 4) == -1
with case():
    assert binary_search([-7, -3, 0, 4], -7) == 0  # первый
with case():
    assert binary_search([-7, -3, 0, 4], 4) == 3  # последний
with case():
    assert binary_search([-7, -3, 0, 4], -5) == -1
with case():
    assert binary_search([1, 3, 5, 7, 9], 3) == 1
with case():
    big = list(range(0, 2 * 10 ** 6, 2))  # большие индексы: в Python переполнения нет
    assert binary_search(big, 1999998) == 999999
# контрпримеры из причин
with case():
    assert binary_search([1, 3], 3) == 1
with case():
    assert binary_search([1, 3, 5, 7], 1) == 0
with case():
    assert binary_search([1, 3, 5, 7], 8) == -1
with case():
    assert binary_search([5], 6) == -1
```

## theory Когда бинпоиск
signals:
- Список отсортирован
- Нужно уложиться в O(log n)
- Ищем индекс или границу
body: Каждый шаг выбрасывает половину диапазона, поэтому O(log n) по времени и O(1) по памяти. Инвариант: ответ, если он есть, всегда внутри `[lo, hi]`; цикл идёт, пока диапазон не пуст.

## theory Каркас
skeleton:
```python
lo, hi = 0, len(nums) - 1
while lo <= hi:
    mid = (lo + hi) // 2
    # нашли / вправо: lo = mid + 1 / влево: hi = mid - 1
return -1
```
body: Середина — только целочисленным делением `//`: `/` в Python всегда даёт `float`, а индекс `nums[1.5]` или даже `nums[0.0]` — это `TypeError`. Переполнения `int` в Python нет: числа растут сколько нужно, поэтому `(lo + hi) // 2` безопасно. Запись `lo + (hi - lo) // 2` — привычка из Kotlin/Java, где `lo + hi` может переполнить `Int`; здесь она тоже верна, но не обязательна.

## theory Грабли
pitfalls:
- `lo < hi`: при `lo == hi` цикл не заходит, последний кандидат пропущен: `[5]`, `5` → `-1`
- `/` вместо `//`: `[1, 3, 5, 7]`, `5` → `mid = 1.5`, `TypeError: list indices must be integers or slices, not float`
- `lo = mid` или `hi = mid` без `± 1`: `[1, 3]`, `3` → `mid = 0`, `lo` остаётся `0`, цикл бесконечный
- Отрицательный индекс в Python не ошибка: `nums[-1]` — последний элемент. Если `hi` уйдёт ниже нуля, вместо `IndexError` получите зацикливание или неверный ответ
- `hi = len(nums)` при `lo <= hi`: на `[]` цикл заходит и читает `nums[0]` — `IndexError`

## e1
```python
def binary_search(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while ⟦lo <= hi⟧:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```
- `lo < hi` [wrong]: при `lo == hi` цикл не заходит и последний кандидат пропущен: `[5]`, `5` → `-1` вместо `0`
- `lo != hi` [hang]: `hi` может уйти ниже `lo`, а условие останется истинным: `[1, 3]`, `0` → `hi` становится `-1`, потом `-2`; `nums[-1]` в Python читает с конца без ошибки, и цикл бесконечный
- `lo > hi` [wrong]: условие ложно с самого начала, цикл не выполнится ни разу: `[1, 3, 5, 7]`, `5` → `-1` вместо `2`
? Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.

## e2
```python
def binary_search(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while ⟦lo <= hi⟧:
        mid = ⟦(lo + hi) // 2 | ~lo + (hi - lo) // 2⟧
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```
- ~`lo + (hi - lo) // 2`: работает, но в Python переполнения нет — это привычка из Kotlin/Java, где `lo + hi` может не влезть в `Int`
- `lo < hi` [wrong]: при `lo == hi` цикл не заходит и последний кандидат пропущен: `[5]`, `5` → `-1` вместо `0`
- `(lo + hi) / 2` [crash]: `/` в Python всегда даёт `float`: `[1, 3, 5, 7]`, `5` → `mid = 1.5`, `nums[1.5]` падает с `TypeError: list indices must be integers or slices, not float` (и `[5]` тоже: `0 / 2` — это `0.0`)
- `(hi - lo) // 2` [hang]: это половина длины диапазона, а не его середина — забыли прибавить `lo`: `[1, 3, 5, 7]`, `5` → `lo` прыгает `2` → `1` → `2`, цикл бесконечный
- @1 `(lo + hi) // 2` [hang]: `while` принимает и число, истинно всё, кроме `0`: `[1, 3, 5, 7]`, `8` → `lo = 4`, `hi = 3`, а условие `7 // 2 = 3` всё ещё истинно, цикл бесконечный
- @1 `lo + (hi - lo) // 2` [hang]: `while` принимает и число, истинно всё, кроме `0`: `[1, 3, 5, 7]`, `8` → `lo = 4`, `hi = 3`, а условие `4 + (-1) // 2 = 3` всё ещё истинно, цикл бесконечный
- @1 `(lo + hi) / 2` [hang]: `while` принимает и число, истинно всё, кроме `0`: `[1, 3, 5, 7]`, `8` → `lo = 4`, `hi = 3`, а условие `7 / 2 = 3.5` всё ещё истинно, цикл бесконечный
- @1 `(hi - lo) // 2` [wrong]: `while` принимает и число, и `0` — это ложь: `[1, 3, 5, 7]`, `5` → после первого шага `lo = 2`, `hi = 3`, `(3 - 2) // 2 = 0`, цикл кончается раньше времени: `-1` вместо `2`
- @2 `lo <= hi` [hang]: `mid` станет `True`, а `True` в Python — число `1`: `[1, 3, 5, 7]`, `5` → всё время смотрим `nums[1]`, `lo` застревает на `2`, цикл бесконечный
- @2 `lo < hi` [hang]: `mid` станет `True`, а `True` в Python — число `1`: `[1, 3, 5, 7]`, `5` → всё время смотрим `nums[1]`, `lo` застревает на `2`, цикл бесконечный
? Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.
? Середина — целочисленным делением: `mid = (lo + hi) // 2`. Переполнения в Python нет.

## e3
```python
def binary_search(nums: list[int], target: int) -> int:
    lo, hi = 0, ⟦len(nums) - 1⟧
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return ⟦mid⟧
        elif nums[mid] < target:
            lo = mid + ⟦1⟧
        else:
            hi = mid - ⟦1⟧
    return -1
```
- `len(nums)` [crash]: `hi` смотрит за конец списка: `[]`, `1` → `hi = 0`, цикл заходит и читает `nums[0]`: `IndexError: list index out of range`
- `0` [hang]: `lo = mid + 0` не сдвигает границу: `[1, 3]`, `3` → `mid = 0`, `lo` остаётся `0`, цикл бесконечный
- `-1` [hang]: `lo = mid + -1` уводит границу назад: `[1, 3]`, `3` → `lo = -1`, `mid` снова `0`, цикл бесконечный
- @1 `mid` [crash]: `mid` появится только в цикле: `lo, hi = 0, mid` → `UnboundLocalError` на первой же строке
- @1 `1` [wrong]: ищем только среди первых двух: `[1, 3, 5, 7]`, `5` → `-1` вместо `2`
- @1 `0` [wrong]: смотрим только первый элемент: `[1, 3, 5, 7]`, `5` → `-1` вместо `2`
- @1 `-1` [wrong]: диапазон пуст с самого начала, цикл не выполнится ни разу: `[5]`, `5` → `-1` вместо `0`
- @2 `len(nums) - 1` [wrong]: вернём индекс последнего, а не найденного: `[1, 3, 5, 7]`, `5` → `3` вместо `2`
- @2 `1` [wrong]: вернём константу, а не индекс: `[5]`, `5` → `1`, а такого индекса нет
- @2 `len(nums)` [wrong]: вернём длину, это индекс за концом: `[1, 3, 5, 7]`, `5` → `4` вместо `2`
- @2 `0` [wrong]: вернём `0` вместо найденного индекса: `[1, 3, 5, 7]`, `5` → `0` вместо `2`
- @2 `-1` [wrong]: скажем «не найдено», хотя элемент есть: `[5]`, `5` → `-1` вместо `0`
- @3 `len(nums) - 1` [hang]: шаг зависит от длины списка: `[1, 3, 5, 7]`, `5` → `lo` прыгает на `4`, мимо ответа; а на `[5]`, `6` шаг `0`, `lo` стоит на месте — цикл бесконечный
- @3 `mid` [hang]: `lo = mid + mid` — это `2 · mid`: `[1, 3]`, `3` → `mid = 0`, `lo` остаётся `0`, цикл бесконечный
- @3 `len(nums)` [wrong]: `lo` прыгает за конец списка: `[1, 3]`, `3` → `lo = 2`, цикл кончился, `-1` вместо `1`
- @4 `len(nums) - 1` [wrong]: `hi` прыгает ниже нуля: `[1, 3, 5, 7]`, `1` → `hi = 1 - 3 = -2`, `-1` вместо `0`
- @4 `mid` [hang]: `hi = mid - mid` — всегда `0`: `[1, 3]`, `0` → `hi = 0`, `mid` снова `0`, цикл бесконечный
- @4 `len(nums)` [wrong]: `hi` прыгает ниже нуля: `[1, 3, 5, 7]`, `1` → `hi = 1 - 4 = -3`, `-1` вместо `0`
- @4 `0` [hang]: `hi = mid - 0` не исключает `mid`: `[1, 3]`, `0` → `hi = 0`, `mid` снова `0`, цикл бесконечный
- @4 `-1` [hang]: `hi = mid - -1` — это `mid + 1`, диапазон не сужается: `[1, 3]`, `0` → `mid = 0`, `hi` снова `1`, цикл бесконечный
? `hi` — индекс последнего элемента: `len(nums) - 1`.
? Нашли — возвращаем `mid`; иначе сдвигаем границу за `mid`: `lo = mid + 1` или `hi = mid - 1`.
