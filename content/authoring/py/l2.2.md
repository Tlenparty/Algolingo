# l2.2
note: 2.2 Удаление дубликатов из отсортированного массива
lang: python
title: Удаление дубликатов
statement: Список отсортирован по неубыванию. Оставь каждое значение по одному разу **на месте**, в начале списка, и верни их количество `k` (LeetCode 26). Что лежит после первых `k` ячеек, не важно.
trains: fast/slow в одну сторону: `slow` пишет, `fast` читает, ответ — длина
pitfalls:
- Вернуть `slow - 1`: `slow` уже указывает на первую свободную ячейку, это и есть длина
- `slow = 0`: `nums[slow - 1]` — это `nums[-1]`, последний элемент; ошибки не будет, будет неверный ответ
- Сравнивать с `nums[slow]` — это свободная ячейка, а не последнее записанное значение: `[1, 2]` → `1`
- Забыть про пустой список: ответ `0`, а не `1`
variations:
- LeetCode 80 — каждое значение не больше двух раз: сравнивай с `nums[slow - 2]`
- в проде: `nums[:] = sorted(set(nums))` или `list(dict.fromkeys(nums))` — коротко, но это новый список, O(n) памяти
- список не отсортирован: тогда `set` для «уже видели» (уровень 1)
examples:
- a = [1, 1, 2]; assert remove_duplicates(a) == 2 and a[:2] == [1, 2]
- a = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]; assert remove_duplicates(a) == 5 and a[:5] == [0, 1, 2, 3, 4]
checks:
```python
# оракул: уникальные значения по порядку; ответ k и первые k ячеек
# все отсортированные списки длины 0..6 из {0..3}
for n in range(7):
    with case():
        for m in range(pw(4, n)):
            a = sorted((m // pw(4, i)) % 4 for i in range(n))
            expected = sorted(set(a))
            got = a[:]
            k = remove_duplicates(got)
            assert type(k) is int and k == len(expected) and got[:k] == expected, (a, k, got)
with case():
    assert remove_duplicates([]) == 0
with case():
    a = [-3, -3, 0, 7, 7, 7]
    assert remove_duplicates(a) == 3 and a[:3] == [-3, 0, 7]
# контрпримеры из причин
with case():
    a = [1, 2]
    assert remove_duplicates(a) == 2 and a[:2] == [1, 2]
with case():
    a = [1, 1, 2]
    assert remove_duplicates(a) == 2 and a[:2] == [1, 2]
with case():
    assert remove_duplicates([2, 2]) == 1
with case():
    assert remove_duplicates([5, 5]) == 1
with case():
    assert remove_duplicates([1]) == 1
```

## theory Когда fast/slow с длиной
signals:
- Список **отсортирован**: одинаковые стоят рядом
- Убрать повторы **на месте**, без второго списка
- Вернуть надо длину, а не новый список
body: `fast` читает каждый элемент, `slow` — длина готовой части и место для следующего нового значения. Новое оно или нет, видно по последнему записанному `nums[slow - 1]`. Ответ — сам `slow`.

## theory Каркас
skeleton:
```python
# первый всегда остаётся
slow = 1
# fast ищет новые значения
for fast in range(1, len(nums)):
    # новое — пишем в slow
    if is_new(nums[fast]):
        nums[slow] = nums[fast]
        slow += 1
# slow — это и есть длина
return slow
```
body: Что лежит после `slow`, не важно: проверяют только первые `slow` ячеек. Пустой список отсекаем заранее, иначе `slow = 1` соврёт. В Python индекс `-1` не ошибка, а последний элемент, поэтому промах на единицу здесь даёт неверный ответ, а не падение.

## theory Грабли
pitfalls:
- Вернуть `slow - 1`: `slow` уже указывает на первую свободную ячейку, это и есть длина
- `slow = 0`: `nums[slow - 1]` молча читает `nums[-1]` — последний элемент: `[1, 2]` → `0`
- Сравнивать с `nums[slow]` — это свободная ячейка, а не последнее записанное значение: `[1, 2]` → `1`
- `return len(set(nums))` считает верно, но список не изменён: проверяют и первые `k` ячеек

## e1
```python
def remove_duplicates(nums: list[int]) -> int:
    # пустой — уникальных нет
    if not nums:
        return 0
    # nums[0] всегда остаётся
    slow = 1
    # fast ищет новые значения
    for fast in range(1, len(nums)):
        # не равно последнему?
        if nums[fast] != ⟦nums[slow - 1] | ~nums[fast - 1]⟧:
            # пишем на место slow
            nums[slow] = nums[fast]
            slow += 1
    # длина без дубликатов
    return slow
```
- ~`nums[fast - 1]`: тоже верно: это предыдущий прочитанный, запись идёт только левее `fast`, и он не испорчен. Но `nums[slow - 1]` — последний записанный, и этот вариант обобщается: для LeetCode 80 сравнивают с `nums[slow - 2]`
- `nums[slow]` [wrong]: `nums[slow]` — свободная ячейка, а не последнее записанное: `[1, 2]` → `1` вместо `2`
- `nums[fast]` [wrong]: число равно самому себе, новое не найдётся никогда: `[1, 2]` → `1` вместо `2`
? Список отсортирован: новое значение отличается от последнего записанного.
