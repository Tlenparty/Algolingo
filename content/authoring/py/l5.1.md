# l5.1
note: 5.1 Climb Stairs (разгон в DP)
lang: python
title: Подъём по лестнице
statement: Сколько способов подняться на `n` ступеней, шагая на 1 или 2? `n ≥ 1` (LeetCode 70).
trains: от рекурсии к DP с O(1) памятью: две переменные вместо списка
pitfalls:
- Наивная рекурсия `f(n - 1) + f(n - 2)` без запоминания — O(2ⁿ): одни и те же ступени считаются заново
- База: до 1-й ступени 1 способ, до 2-й — 2; `n <= 2` отвечаем сразу, без цикла
- Две строки `prev = current` и `current = prev + current` подряд — уже ошибка: вторая видит новое `prev`; кортеж `prev, current = current, prev + current` считает правую часть по старым значениям
- Шагов цикла `n - 2`: ступени 1 и 2 уже посчитаны
variations:
- список `ways = [0] * (n + 1)`: `ways[i] = ways[i - 1] + ways[i - 2]` — проще объяснить, но O(n) памяти
- `@functools.cache` над рекурсией — сверху вниз за O(n); на собесе покажи и итеративный вариант
- шаги 1, 2 или 3 (трибоначчи): три переменные, `a, b, c = b, c, a + b + c`
- Min Cost Climbing Stairs (LeetCode 746): тот же каркас, но `min` вместо суммы
examples:
- assert climb_stairs(2) == 2
- assert climb_stairs(3) == 3
- assert climb_stairs(5) == 8
- assert climb_stairs(1) == 1
checks:
```python
# оракул: список ways[i] = ways[i - 1] + ways[i - 2]; все n от 1 до 45
with case():
    ways = [1, 1]
    for i in range(2, 46):
        ways.append(ways[i - 1] + ways[i - 2])
    for n in range(1, 46):
        assert climb_stairs(n) == ways[n], n


# оракул 2: перебор шагов рекурсией в лоб; n от 1 до 20
def _naive(k):
    if k < 0:
        return 0
    return 1 if k == 0 else _naive(k - 1) + _naive(k - 2)


with case():
    for n in range(1, 21):
        assert climb_stairs(n) == _naive(n), n
with case():
    assert climb_stairs(45) == 1836311903  # максимум LeetCode
# контрпримеры из причин
with case():
    assert climb_stairs(1) == 1
with case():
    assert climb_stairs(2) == 2
with case():
    assert climb_stairs(3) == 3
with case():
    assert climb_stairs(4) == 5
with case():
    assert climb_stairs(5) == 8
```

## theory Когда DP «как Фибоначчи»
signals:
- «Сколько способов» дойти до шага `n`
- Ход — на 1 или на 2 вперёд
- Ответ для `i` собирается из ответов для `i - 1` и `i - 2`
body: На ступень `i` приходят либо с `i - 1`, либо с `i - 2`, поэтому `ways(i) = ways(i - 1) + ways(i - 2)`. Рекурсия в лоб считает одно и то же много раз — O(2ⁿ). Идём снизу вверх и помним только два последних ответа: O(n) времени, O(1) памяти.

## theory Каркас: две переменные
skeleton:
```python
# ответы для i-2 и i-1
prev, current = 1, 2
for _ in range(n - 2):
    # сдвигаем окно на ступень
    prev, current = current, prev + current
```
body: `prev` и `current` — окно из двух последних ступеней. Кортеж справа считается целиком по старым значениям, и только потом оба имени получают новые.

## theory Грабли
pitfalls:
- `prev = current`, а потом `current = prev + current` отдельной строкой: `prev` уже новая, сумма удвоит `current`
- Шагов `n - 1` вместо `n - 2`: ступени 1 и 2 уже в `prev` и `current`, лишний шаг уводит на ступень выше
- База `n <= 2` → `return n`: для `n = 1` ответ `1`, для `n = 2` — `2`, без цикла
- Рекурсия без кеша — O(2ⁿ): `n = 45` считается минуты

## e1
```python
# Случай 1: n = 2 → 2 (1+1, 2)
# Случай 2: n = 3 → 3 (1+1+1, 1+2, 2+1)
# Случай 3: n = 5 → 8
def climb_stairs(n: int) -> int:
    # 1 ступень — 1 способ, 2 — два
    if n <= 2:
        return n
    # способов дойти до i-2 и до i-1
    prev, current = 1, 2
    for _ in range(n - 2):
        # на ступень i — с i-1 или с i-2
        prev, current = current, ⟦prev + current⟧
    return current
```
- `prev * current` [wrong]: способы с двух ступеней складываются, а не перемножаются: `n = 3` → `2` вместо `3`
- `current + current` [wrong]: с `i - 2` приходит `prev` способов, а не `current`: `n = 3` → `4` вместо `3`
- `current + 1` [wrong]: со ступени `i - 2` приходит не один способ, а `prev`: `n = 4` → `4` вместо `5`
