# l3.2
note: 3.2 Корректность скобок
lang: python
title: Корректность скобок
statement: Строка из `()[]{}` — правильная ли вложенность? Каждая открывающая закрыта своей и в правильном порядке; верни `True`/`False` (LeetCode 20).
trains: стек на `list` + словарь «закрывающая → открывающая»
pitfalls:
- Забыть финальную проверку `not stack`: `"("` ошибочно пройдёт как валидная
- `stack.pop()` без проверки на пустоту: `")"` → `IndexError: pop from empty list`
- `stack.pop(0)` снимает первый элемент — это уже очередь, да ещё O(n): `"([)]"` пройдёт как валидная
- `ch in pairs` проверяет ключи, то есть закрывающие; открывающие — это `pairs.values()`
variations:
- `if ch in "([{"` вместо `ch in pairs.values()` — короче, но второй источник правды о скобках
- `collections.deque` вместо `list` — тоже стек (`append`/`pop`), но `list` здесь хватает
- в лоб: вычёркивать `"()"`, `"[]"`, `"{}"` через `replace`, пока строка меняется, — верно, но O(n²)
examples:
- assert is_valid_brackets("()[]{}") is True
- assert is_valid_brackets("([)]") is False
- assert is_valid_brackets("(") is False
- assert is_valid_brackets("{[()]}") is True
- assert is_valid_brackets("") is True
checks:
```python
# оракул: прочие символы выкидываем, пары (), [], {} вычёркиваем, пока есть; пусто → True
def oracle(t):
    r = "".join(c for c in t if c in "()[]{}")
    for _ in range(len(t)):
        r = r.replace("()", "").replace("[]", "").replace("{}", "")
    return r == ""
# все строки длины 0..6 из ()[]{}
for n in range(7):
    with case():
        for m in range(pw(6, n)):
            s = "".join("()[]{}"[(m // pw(6, k)) % 6] for k in range(n))
            r = is_valid_brackets(s)
            assert r is oracle(s), (s, r)
# посторонние символы пропускаются: все строки длины 0..5 из ( ] x )
for n in range(6):
    with case():
        for m in range(pw(4, n)):
            s = "".join("(]x)"[(m // pw(4, k)) % 4] for k in range(n))
            r = is_valid_brackets(s)
            assert r is oracle(s), (s, r)
with case():
    assert is_valid_brackets("a(b)c") is True
with case():
    assert is_valid_brackets("([]{()})") is True
with case():
    assert is_valid_brackets("((") is False
with case():
    assert is_valid_brackets("))") is False
with case():
    assert is_valid_brackets("(]") is False
with case():
    assert is_valid_brackets("()(") is False
# контрпримеры из причин
with case():
    assert is_valid_brackets("(") is False
with case():
    assert is_valid_brackets("()") is True
with case():
    assert is_valid_brackets("([)]") is False
with case():
    assert is_valid_brackets(")") is False
with case():
    assert is_valid_brackets("") is True
```

## theory Когда стек
signals:
- Скобки, теги, любая вложенность
- «Последний открытый закрывается первым»
- Сверить пару с самым свежим открытым
body: Стек хранит открытые скобки, которые ждут пару. Закрывающая всегда сверяется с самой свежей открытой — это вершина стека. В Python стек — обычный `list`: `append` кладёт на вершину, `pop()` снимает с неё, оба за O(1). Итого O(n) по времени, O(n) по памяти.

## theory Каркас
skeleton:
```python
stack = []
for ch in s:
    # открывающая: в стек
    if ch in opens:
        stack.append(ch)
    # закрывающая: снять и сверить
    elif ch in pairs:
        if not stack or stack.pop() != pairs[ch]:
            return False
# все открытые закрылись
return not stack
```
body: Словарь `pairs` хранит «закрывающая → открывающая»: `ch in pairs` ищет среди ключей — закрывающих, `opens` — это `pairs.values()`, а `pairs[ch]` сразу даёт, кого ждём на вершине. `not stack` — пустой список ложен, так что это «стек пуст».

## theory Грабли
pitfalls:
- Вернуть `True` в конце: `"("` → `True`, хотя скобка не закрыта
- `stack.pop()` на пустом стеке: `")"` → `IndexError: pop from empty list`, поэтому сначала `not stack or`
- `stack.pop(0)` — это очередь: `"([)]"` → `True`
- `stack[-1]` только смотрит на вершину и не снимает её: `"()"` → `False`
- `pairs.values` без скобок — сам метод: `ch in pairs.values` падает с `TypeError`

## e1
```python
# Случай 1: "()[]{}" → True
# Случай 2: "([)]" → False
# Случай 3: "(" → False
def is_valid_brackets(s: str) -> bool:
    # открытые, ждущие пары
    stack = []
    # закрывающая -> открывающая
    pairs = {")": "(", "]": "[", "}": "{"}
    for ch in s:
        # открывающая: в стек
        if ch in pairs.values():
            stack.append(ch)
        # закрывающая: сверяем с вершиной
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    # все открытые закрылись
    return ⟦not stack⟧
```
- `True` [wrong]: незакрытые открывающие так и остались в стеке: `"("` → `True` вместо `False`
- `bool(stack)` [wrong]: условие наоборот, правильная строка оставляет стек пустым: `"()"` → `False` вместо `True`
- `stack` [wrong]: вернём сам список, а не `bool`: `"()"` → `[]` вместо `True`
- `len(stack)` [wrong]: вернём число, а не `bool`, да ещё с обратным смыслом: `"()"` → `0` вместо `True`
? Цикл прошёл без ошибок. Но что, если какая-то открывающая так и не закрылась?

- @1 `pairs` [wrong]: `in pairs` ищет среди ключей — закрывающих: в стек пойдут они, а открывающие пропустим: `"()"` → `False` вместо `True`
- @1 `ch` [wrong]: `ch in ch` всегда истинно, в стек идёт каждый символ: `"()"` → `False` вместо `True`
- @1 `pairs.values` [crash]: без скобок это сам метод, по нему не пройти `in`: `"()"` → `TypeError: argument of type 'builtin_function_or_method' is not iterable`
- @2 `pairs.values()` [wrong]: символ никогда не равен набору значений словаря: `"()"` → `False` вместо `True`
- @2 `pairs` [wrong]: символ никогда не равен словарю: `"()"` → `False` вместо `True`
- @2 `ch` [wrong]: на вершине открывающая, а `ch` — закрывающая, они никогда не равны: `"()"` → `False` вместо `True`
- @2 `pairs.values` [wrong]: символ никогда не равен методу: `"()"` → `False` вместо `True`

## e3

```python
# Случай 1: "()[]{}" → True
# Случай 2: "([)]" → False
# Случай 3: "(" → False
def is_valid_brackets(s: str) -> bool:
    # открытые, ждущие пары
    stack = []
    # закрывающая -> открывающая
    pairs = {")": "(", "]": "[", "}": "{"}
    for ch in s:
        # открывающая: в стек
        if ch in pairs.values():
            stack.append(ch)
        # закрывающая: сверяем с вершиной
        elif ch in pairs:
            if not stack ⟦or⟧ ⟦stack.pop()⟧ != pairs[ch]:
                return False
    # все открытые закрылись
    return ⟦not stack⟧
```
- `and`
- `stack.pop(0)`
- `stack[-1]`
- `True`
- @1 `and` [wrong]: на непустом стеке `and` сразу даёт `False`, вершина не снимается: `"()"` → `False` вместо `True`
- @1 `stack.pop()` [compile]: между двумя условиями нужен оператор: `not stack stack.pop()` — `SyntaxError`
- @1 `not stack` [compile]: между двумя условиями нужен оператор: `not stack not stack` — `SyntaxError`
- @1 `stack.pop(0)` [compile]: между двумя условиями нужен оператор: `not stack stack.pop(0)` — `SyntaxError`
- @1 `stack[-1]` [compile]: между двумя условиями нужен оператор: `not stack stack[-1]` — `SyntaxError`
- @1 `True` [compile]: между двумя условиями нужен оператор: `not stack True` — `SyntaxError`
- @2 `or` [compile]: два оператора подряд: `not stack or or != pairs[ch]` — `SyntaxError`
- @2 `and` [compile]: два оператора подряд: `not stack or and != pairs[ch]` — `SyntaxError`
- @2 `not stack` [wrong]: `not stack != pairs[ch]` читается как `not (stack != pairs[ch])`, это всегда `False`, и вершина не снимается: `"()"` → `False` вместо `True`
- @2 `True` [wrong]: `True != pairs[ch]` всегда истинно, любая закрывающая — ошибка: `"()"` → `False` вместо `True`
- @2 `stack.pop(0)` [wrong]: снимаем самую старую открытую, а не самую свежую — это очередь: `"([)]"` → `True` вместо `False`
- @2 `stack[-1]` [wrong]: `stack[-1]` смотрит на вершину, но не снимает её: `"()"` → `False` вместо `True`
- @3 `or` [compile]: оператор — не значение: `return or` — `SyntaxError`
- @3 `and` [compile]: оператор — не значение: `return and` — `SyntaxError`
- @3 `stack.pop()` [crash]: на пустом стеке снимать нечего: `""` → `IndexError: pop from empty list`
- @3 `stack.pop(0)` [crash]: на пустом стеке снимать нечего: `""` → `IndexError: pop from empty list`
- @3 `stack[-1]` [crash]: у пустого списка нет вершины: `""` → `IndexError: list index out of range`
- @3 `True` [wrong]: незакрытые открывающие так и остались в стеке: `"("` → `True` вместо `False`
? Пустой стек — уже ошибка, вершину тогда не трогаем. Какой оператор не вычислит правую часть, если левая истинна?
? Закрывающая закрывает самую свежую открытую. Её надо снять со стека, а не только посмотреть.
? В конце в стеке не должно остаться открытых.
