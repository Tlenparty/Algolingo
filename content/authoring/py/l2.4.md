# l2.4
note: 2.4 Квадраты отсортированного массива
lang: python
statement: Список `nums` отсортирован по неубыванию, числа бывают отрицательными. Верни новый список квадратов всех чисел, тоже отсортированный по неубыванию (LeetCode 977).
trains: два указателя навстречу, ответ заполняется с конца
pitfalls:
- Просто возвести в квадрат: `[-4, -1, 0, 3]` → `[16, 1, 0, 9]`, порядок сломан
- Заполнять с начала: у концов самые **большие** квадраты, ответ выйдет убывающим
- `range(len(nums) - 1, 0, -1)` не доходит до `0`: стоп в `range` не включается, ячейка `0` останется нулём
- `result = []` и запись по индексу — `IndexError`: список нужной длины — `[0] * len(nums)`
variations:
- в проде коротко: `sorted(x * x for x in nums)` — O(n log n), приём не тренирует
- `reversed(range(len(nums)))` — тот же обход с конца, читается проще
- `append` в порядке убывания, а в конце `result.reverse()` — тоже O(n)
examples:
- assert sorted_squares([-4, -1, 0, 3, 10]) == [0, 1, 9, 16, 100]
- assert sorted_squares([-7, -3, 2, 3, 11]) == [4, 9, 9, 49, 121]
checks:
```python
# оракул: sorted(x * x for x in a); все отсортированные списки длины 0..5 из {-3..3}
for n in range(6):
    with case():

# контрпримеры из причин

    assert sorted_squares([-1, 2]) == [1, 4]
with case():
```

## theory Когда навстречу с конца
signals:
- Список отсортирован, но преобразование ломает порядок (квадрат, модуль)
- Самые большие результаты — **по краям** списка
- Нужно O(n), без сортировки за O(n log n)
body: После возведения в квадрат отсортированный список похож на долину: большие квадраты по краям, маленькие в середине. Указатели с двух концов каждый раз дают самый большой из оставшихся квадратов, поэтому ответ заполняется **с конца**.

## theory Каркас
skeleton:
```python
# концы списка
left, right = 0, len(nums) - 1
# пишем с конца
for write_index in range(len(nums) - 1, -1, -1):
    # больший квадрат — в ячейку
    # сдвигаем его указатель
```
body: Каждый шаг забирает один конец, поэтому за `n` шагов указатели сходятся, а все ячейки ответа заполнены. `range(len(nums) - 1, -1, -1)` идёт от последнего индекса до `0` включительно: стоп `-1` в ответ не входит.

## theory Грабли
pitfalls:
- Просто возвести в квадрат: `[-4, -1, 0, 3]` → `[16, 1, 0, 9]`, порядок сломан
- Заполнять с начала: у концов самые **большие** квадраты, ответ выйдет убывающим: `[-1, 2]` → `[4, 1]`
- Сравнивать `nums[left]` и `nums[right]` без квадрата: `-3 < 1`, хотя `9 > 1`
- `range(len(nums) - 1, 0, -1)`: стоп не включается, ячейка `0` останется нулём: `[-1, 2]` → `[0, 4]`

## e1
```python
def sorted_squares(nums: list[int]) -> list[int]:
    # ответ той же длины
    result = [0] * len(nums)
    # концы списка — кандидаты
    left = 0
    right = len(nums) - 1
    # заполняем с конца
    for write_index in ⟦range(len(nums) - 1, -1, -1)⟧:
        # квадраты обоих концов
        left_square = nums[left] * nums[left]
        right_square = nums[right] * nums[right]
        # больший — в ячейку
        if left_square > right_square:
            result[write_index] = left_square
            left += 1
        else:
            result[write_index] = right_square
            right -= 1
    return result
```
- `range(len(nums))` [wrong]: у концов самые большие квадраты, с начала ответ выйдет убывающим: `[-1, 2]` → `[4, 1]` вместо `[1, 4]`
- `range(len(nums) - 1, 0, -1)` [wrong]: стоп в `range` не включается, ячейка `0` не заполнится: `[-1, 2]` → `[0, 4]` вместо `[1, 4]`

## e2
```python
def sorted_squares(nums: list[int]) -> list[int]:

    # концы списка — кандидаты
```

- `range(len(nums) - 1, 0, -1)` [wrong]: стоп в `range` не включается, ячейка `0` не заполнится: `[-1, 2]` → `[0, 4]` вместо `[1, 4]`
- `<` [wrong]: в конец уходит меньший квадрат: `[-1, 2]` → `[4, 1]` вместо `[1, 4]`
