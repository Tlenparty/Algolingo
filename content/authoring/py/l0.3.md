# l0.3
note: 0.3 Палиндром ли строка
lang: python
title: Палиндром
statement: Читается ли строка одинаково с обеих сторон? Верни `True` или `False` (считаем, что регистр и пробелы уже неважны).
trains: два указателя навстречу как проверка
pitfalls:
- `lo <= hi` работает, но на нечётной длине средний символ сравнивается сам с собой: лишний шаг
- `hi = len(s)` вместо `len(s) - 1`: первый же `s[hi]` вне строки, `IndexError`
- `lo != hi`: на чётной длине указатели проскочат друг друга и выйдут за границы
- Перепутать ответы: на несовпадении — `False`, после цикла — `True`
- Символы сравнивают через `==`/`!=`, а не `is`/`is not`: `is` сравнивает объекты, и на `"шалаш"` ответ будет `False`
variations:
- в проде: `return s == s[::-1]` — коротко, но строит перевёрнутую копию, O(n) памяти; на собесе покажи два указателя
- игнорировать регистр и не-буквы: сдвигать `lo`/`hi`, пока `not s[lo].isalnum()`, и сравнивать `s[lo].lower()`
- «палиндром, если удалить не больше одного символа»: на первом расхождении проверить две подстроки
examples:
- assert is_palindrome("aba") is True
- assert is_palindrome("abba") is True
- assert is_palindrome("ab") is False
- assert is_palindrome("") is True
- assert is_palindrome("a") is True
- assert is_palindrome("шалаш") is True
checks:
```python
# оракул: s == s[::-1]; все строки длины 0..5 из {a, b, c}; ответ строго bool
for n in range(6):
    with case():
        for m in range(pw(3, n)):
            s = "".join("abc"[(m // pw(3, k)) % 3] for k in range(n))
            assert is_palindrome(s) is (s == s[::-1]), s
with case():
    assert is_palindrome("aa") is True
with case():
    assert is_palindrome("abcb") is False  # расходится первая пара
with case():
    assert is_palindrome("abca") is False  # расходится внутренняя пара
with case():
    assert is_palindrome("шалаш") is True
with case():
    assert is_palindrome("шалаша") is False
```

## theory Тот же скелет
signals:
- «Палиндром / симметрия»
- «Читается одинаково с обеих сторон»
body: Скелет разворота из 0.2, только вместо обмена сравниваем пару: `s[lo] != s[hi]` — сразу `return False`. Строку можно читать по индексу напрямую, `list(s)` не нужен: менять её мы не будем. Время O(n), память O(1).

## theory Каркас
skeleton:
```python
lo, hi = 0, len(s) - 1
while lo < hi:
    # пара не сходится -> сразу ответ
    lo += 1
    hi -= 1
# дошли до середины -> ответ
```
body: Как и в 0.2, `lo <= hi` засчитывается с пометкой: средний символ лишний раз сравнится сам с собой. В проде пишут `s == s[::-1]`, но это копия строки и O(n) памяти.

## theory Грабли
pitfalls:
- `hi = len(s)`: первый же `s[hi]` вне строки, `"aba"` → `IndexError: string index out of range`
- `lo != hi` на чётной длине: указатели проскочат друг друга, `"abba"` → `s[4]`, `IndexError`
- Перепутать ответы: на несовпадении `False`, после цикла `True`
- `is not` вместо `!=`: на латинице CPython кэширует односимвольные строки и ответ случайно верный, а на `"шалаш"` — `False`
- `false` с маленькой буквы — это не `False`, а неизвестное имя: `NameError`

## e1
```python
def is_palindrome(s: str) -> bool:
    lo, hi = 0, len(s) - 1
    while ⟦lo < hi | ~lo <= hi⟧:
        if s[lo] != s[hi]:
            return False
        lo += 1
        hi -= 1
    return True
```
- ~`lo <= hi`: работает, но на нечётной длине средний символ сравнится сам с собой: `"aba"` делает лишний шаг на `b`
- `lo > hi` [wrong]: цикл не выполнится ни разу: `"ab"` вернёт `True`
- `lo != hi` [crash]: на чётной длине указатели проскочат друг друга: `"abba"` → `s[4]`, `IndexError: string index out of range`
? Указатели с краёв идут навстречу, пока `lo < hi`.

## e2
```python
def is_palindrome(s: str) -> bool:
    lo, hi = 0, len(s) - 1
    while lo < hi:
        if s[lo] ⟦!=⟧ s[hi]:
            return ⟦False⟧
        lo += 1
        hi -= 1
    return True
```
- `==` [wrong]: условие перевёрнуто: `"ab"` вернёт `True`, а `"aba"` — `False`
- `True` [wrong]: на несовпадении скажет «да»: `"ab"` вернёт `True`
- `false` [crash]: в Python это не `False`, а неизвестное имя: `"ab"` → `NameError: name 'false' is not defined`
- `is not` [wrong]: сравнивает объекты, а не символы: у `"шалаш"` первая и последняя `ш` — разные объекты, ответ `False`
- @1 `False` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] False s[hi]:` — `SyntaxError`
- @1 `True` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] True s[hi]:` — `SyntaxError`
- @1 `false` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] false s[hi]:` — `SyntaxError`
- @2 `!=` [compile]: после `return` нужно значение, а не оператор: `return !=` — `SyntaxError`
- @2 `==` [compile]: после `return` нужно значение, а не оператор: `return ==` — `SyntaxError`
- @2 `is not` [compile]: после `return` нужно значение, а не оператор: `return is not` — `SyntaxError`
? Нашли несовпадающую пару — дальше смотреть незачем: сразу `return False`.
? Символы сравнивают через `!=`, а не `is not`.

## e3
```python
def is_palindrome(s: str) -> bool:
    lo, hi = 0, ⟦len(s) - 1⟧
    while ⟦lo < hi⟧:
        if s[lo] ⟦!=⟧ s[hi]:
            return False
        lo += 1
        hi -= 1
    return ⟦True⟧
```
- `len(s)` [crash]: первый же `s[hi]` вне строки: `"aba"` → `s[3]`, `IndexError: string index out of range`
- `False` [wrong]: на палиндроме ответ всё равно «нет»: `"aba"` вернёт `False`
- `==` [wrong]: условие перевёрнуто: `"aba"` вернёт `False`
- @1 `lo < hi` [crash]: справа `lo` читается раньше, чем присвоится: `"aba"` → `UnboundLocalError` на первой же строке
- @1 `!=` [compile]: после `,` нужно значение, а не оператор: `lo, hi = 0, !=` — `SyntaxError`
- @1 `True` [wrong]: `True` в Python — это число `1`: `"aba"` сравнит `a` с `b` и вернёт `False`
- @1 `False` [wrong]: `False` в Python — это число `0`, цикл не выполнится ни разу: `"ab"` вернёт `True`
- @1 `==` [compile]: после `,` нужно значение, а не оператор: `lo, hi = 0, ==` — `SyntaxError`
- @2 `len(s) - 1` [crash]: `while` принимает и число, ненулевое — истина, и цикл не остановится в середине: `"aba"` → `s[3]`, `IndexError`
- @2 `!=` [compile]: после `while` нужно условие, а не оператор: `while !=:` — `SyntaxError`
- @2 `True` [crash]: `while True` не остановится в середине: `"aba"` → `s[3]`, `IndexError: string index out of range`
- @2 `len(s)` [crash]: `while` принимает и число, ненулевое — истина, и цикл не остановится в середине: `"aba"` → `s[3]`, `IndexError`
- @2 `False` [wrong]: `while False` не выполнится ни разу: `"ab"` вернёт `True`
- @2 `==` [compile]: после `while` нужно условие, а не оператор: `while ==:` — `SyntaxError`
- @3 `len(s) - 1` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] len(s) - 1 s[hi]:` — `SyntaxError`
- @3 `lo < hi` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] lo < hi s[hi]:` — `SyntaxError`
- @3 `True` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] True s[hi]:` — `SyntaxError`
- @3 `len(s)` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] len(s) s[hi]:` — `SyntaxError`
- @3 `False` [compile]: между `s[lo]` и `s[hi]` нужен оператор сравнения: `if s[lo] False s[hi]:` — `SyntaxError`
- @4 `len(s) - 1` [wrong]: вернём число, а не `bool`: `"aba"` → `2` вместо `True`
- @4 `lo < hi` [wrong]: после цикла `lo < hi` всегда ложно: `"aba"` вернёт `False`
- @4 `!=` [compile]: после `return` нужно значение, а не оператор: `return !=` — `SyntaxError`
- @4 `len(s)` [wrong]: вернём длину, а не `bool`: `"aba"` → `3` вместо `True`
- @4 `==` [compile]: после `return` нужно значение, а не оператор: `return ==` — `SyntaxError`
? `hi` — индекс последнего символа: `len(s) - 1`.
? Нашли несовпадающую пару — сразу `return False`.
? Цикл дошёл до середины без расхождений — строка палиндром: `return True`.
