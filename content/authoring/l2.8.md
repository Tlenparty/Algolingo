# l2.8
note: 2.8 Самая длинная подстрока без повторов
title: Подстрока без повторов
trains: скользящее окно переменной длины + `Map` последних позиций
examples:
- assertEquals(3, longestUnique("abcabcbb"))
- assertEquals(1, longestUnique("bbbbb"))
- assertEquals(3, longestUnique("pwwkew"))
- assertEquals(0, longestUnique(""))
checks:
```kotlin
// оракул: перебор всех подстрок, длиннейшая без повторов (toSet); все строки длины 0..6 из {a, b, c, d}
for (n in 0..6) case {
    for (m in 0 until pw(4, n)) {
        val s = CharArray(n) { 'a' + (m / pw(4, it)) % 4 }.concatToString()
        var best = 0
        for (i in 0..n) for (j in i..n) if (s.substring(i, j).toSet().size == j - i) best = maxOf(best, j - i)
        assertEquals(best, longestUnique(s), s)
    }
}
case { assertEquals(1, longestUnique(" ")) }
case { assertEquals(3, longestUnique("dvdf")) }
case { assertEquals(5, longestUnique("tmmzuxt")) }
case { assertEquals(3, longestUnique("шалаш")) }
case { assertEquals(26, longestUnique("abcdefghijklmnopqrstuvwxyz")) }
// контрпримеры из причин
case { assertEquals(1, longestUnique("aa")) }
case { assertEquals(2, longestUnique("abba")) }
case { assertEquals(2, longestUnique("abab")) }
case { assertEquals(2, longestUnique("aab")) }
```

## theory Когда окно переменной длины
signals:
- Подряд идущий отрезок: подстрока или подмассив
- «Самый длинный такой, что…» — условие на всё окно
- Нарушение чинится сдвигом левой границы
body: Правая граница `right` идёт по строке и расширяет окно. Если новый символ уже есть внутри окна, левая граница `left` прыгает сразу за его прошлую позицию. Обе границы двигаются только вперёд, поэтому O(n).

## theory Каркас
skeleton:
```kotlin
// символ -> последний индекс
val lastIndex = HashMap<Char, Int>()
var left = 0
for (right in s.indices) {
    val prev = lastIndex[s[right]]
    // повтор внутри окна: ужимаем
    if (prev != null && prev >= left)
        left = prev + 1
    lastIndex[s[right]] = right
    // окно left..right без повторов
}
```
body: Длина окна `left..right` — это `right - left + 1`: обе границы входят в окно.

## theory Грабли
pitfalls:
- Без `prev >= left` старая позиция за окном тянет `left` назад: `"abba"` → `3` вместо `2`
- `left = prev`: повтор остаётся в окне: `"aa"` → `2` вместо `1`
- Длина `right - left` без `+ 1`: `"a"` → `0` вместо `1`
- `prev > left` вместо `>=`: повтор на самой левой границе не ловится: `"aa"` → `2`

## e1
```kotlin
// Случай 1: "abcabcbb" → 3 ("abc")
// Случай 2: "bbbbb" → 1 ("b")
// Случай 3: "pwwkew" → 3 ("wke")
fun longestUnique(s: String): Int {
    // символ -> последний индекс
    val lastIndex = HashMap<Char, Int>()
    // левая граница окна
    var left = 0
    // лучшая длина пока что
    var best = 0
    // правая граница идёт по строке
    for (right in s.indices) {
        val prev = lastIndex[s[right]]
        // повтор внутри окна: ужимаем
        if (prev != null && ⟦prev >= left⟧) left = prev + 1
        lastIndex[s[right]] = right
        // длина окна left..right
        best = maxOf(best, right - left + 1)
    }
    return best
}
```
- `true` [wrong]: старая позиция символа за окном тянет `left` назад: `"abba"` → `3` вместо `2`: на втором `a` окно снова захватывает `bba`
- `prev > left` [wrong]: повтор на самой левой границе окна не ловится: `"aa"` → `2` вместо `1`
? Символ мог встречаться раньше, но уже **за** левой границей. Тогда окно трогать не надо.

## e2
```kotlin
// Случай 1: "abcabcbb" → 3 ("abc")
// Случай 2: "bbbbb" → 1 ("b")
// Случай 3: "pwwkew" → 3 ("wke")
fun longestUnique(s: String): Int {
    // символ -> последний индекс
    val lastIndex = HashMap<Char, Int>()
    // левая граница окна
    var left = 0
    // лучшая длина пока что
    var best = 0
    // правая граница идёт по строке
    for (right in s.indices) {
        val prev = lastIndex[s[right]]
        // повтор внутри окна: ужимаем
        if (prev != null && prev >= left) left = ⟦prev + 1⟧
        lastIndex[s[right]] = right
        // длина окна left..right
        best = maxOf(best, ⟦right - left + 1⟧)
    }
    return best
}
```
- `prev` [wrong]: `left` встаёт на старый повтор, и он остаётся в окне: `"aa"` → `2` вместо `1`
- `right - left` [wrong]: обе границы входят в окно, без `+ 1` длина меньше на один: `"a"` → `0` вместо `1`
- @1 `right - left + 1` [wrong]: это длина окна, а не новая левая граница: `"aab"` → `1` вместо `2`
- @1 `right - left` [wrong]: это длина окна без `+ 1`, а не новая левая граница: `"aaa"` → `2` вместо `1`
- @2 `prev + 1` [compile]: здесь `prev` — `Int?`, проверка на `null` осталась в `if`: `maxOf(best, prev + 1)` не скомпилируется
- @2 `prev` [compile]: здесь `prev` — `Int?`, а `maxOf` ждёт `Int`: `maxOf(best, prev)` не скомпилируется
? Повтор стоит на позиции `prev`. Где должно начаться окно, чтобы его там уже не было?
? В окне `left..right` обе границы считаются. Сколько это символов?

## e3
```kotlin
// Случай 1: "abcabcbb" → 3 ("abc")
// Случай 2: "bbbbb" → 1 ("b")
// Случай 3: "pwwkew" → 3 ("wke")
fun longestUnique(s: String): Int {
    // символ -> последний индекс
    val lastIndex = HashMap<Char, Int>()
    // левая граница окна
    var left = 0
    // лучшая длина пока что
    var best = 0
    // правая граница идёт по строке
    for (right in ⟦s.indices⟧) {
        val prev = lastIndex[s[right]]
        // повтор внутри окна: ужимаем
        if (prev != null && ⟦prev >= left⟧) left = prev + 1
        lastIndex[s[right]] = ⟦right⟧
        // длина окна left..right
        best = maxOf(best, right - left + 1)
    }
    return best
}
```
- `s` [compile]: по строке `right` станет символом, а индекс строки — число: `s[right]` не скомпилируется
- `1 until s.length` [wrong]: первый символ пропущен: `"a"` → `0` вместо `1`
- `prev > left` [wrong]: повтор на самой левой границе окна не ловится: `"aa"` → `2` вместо `1`
- `left` [wrong]: запоминаем не позицию символа, а границу окна: `"abab"` → `3` вместо `2`
- @1 `prev >= left` [compile]: `prev` объявляется только внутри цикла: `for (right in prev >= left)` не скомпилируется
- @1 `prev > left` [compile]: `prev` объявляется только внутри цикла: `for (right in prev > left)` не скомпилируется
- @1 `right` [compile]: `right` появится только в теле цикла: `for (right in right)` не скомпилируется
- @1 `left` [compile]: по числу не пройти циклом: `for (right in left)` не скомпилируется
- @2 `s.indices` [compile]: после `&&` нужен `Boolean`, а не диапазон: `prev != null && s.indices` не скомпилируется
- @2 `s` [compile]: после `&&` нужен `Boolean`, а не строка: `prev != null && s` не скомпилируется
- @2 `1 until s.length` [compile]: после `&&` нужен `Boolean`, а не диапазон: `prev != null && 1 until s.length` не скомпилируется
- @2 `right` [compile]: после `&&` нужен `Boolean`, а не число: `prev != null && right` не скомпилируется
- @2 `left` [compile]: после `&&` нужен `Boolean`, а не число: `prev != null && left` не скомпилируется
- @3 `s.indices` [compile]: в `Map` лежат `Int`, а не диапазон: `lastIndex[s[right]] = s.indices` не скомпилируется
- @3 `s` [compile]: в `Map` лежат `Int`, а не строка: `lastIndex[s[right]] = s` не скомпилируется
- @3 `1 until s.length` [compile]: в `Map` лежат `Int`, а не диапазон: `lastIndex[s[right]] = 1 until s.length` не скомпилируется
- @3 `prev >= left` [compile]: в `Map` лежат `Int`, а не `Boolean`: `lastIndex[s[right]] = prev >= left` не скомпилируется
- @3 `prev > left` [compile]: в `Map` лежат `Int`, а не `Boolean`: `lastIndex[s[right]] = prev > left` не скомпилируется
? Правая граница проходит по всем индексам строки.
? Символ мог встречаться раньше, но уже **за** левой границей. Тогда окно трогать не надо.
? Для символа запоминаем, где он встретился последним.
