# l0.4
note: 0.4 Бинарный поиск
examples:
- assertEquals(2, binarySearch(intArrayOf(1, 3, 5, 7), 5))
- assertEquals(-1, binarySearch(intArrayOf(1, 3), 0))
- assertEquals(0, binarySearch(intArrayOf(5), 5))
- assertEquals(-1, binarySearch(intArrayOf(), 1))

## theory Когда бинпоиск
signals:
- Массив отсортирован
- Нужно уложиться в O(log n)
- Ищем индекс или границу
body: Каждый шаг выбрасывает половину диапазона, поэтому O(log n).

## theory Каркас
skeleton:
```kotlin
var lo = 0
var hi = nums.size - 1
while (lo <= hi) {
    val mid = lo + (hi - lo) / 2
    // нашли / вправо / влево
}
```
body: Инвариант: ответ, если он есть, всегда внутри `[lo, hi]`.

## theory Грабли
pitfalls:
- `lo < hi` вместо `<=` пропустит последний элемент
- `(lo + hi) / 2` может переполниться на больших индексах

## e1
```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = lo + (hi - lo) / 2
        when {
            nums[mid] == target -> return mid
            nums[mid] < target  -> lo = mid + 1
            else                -> hi = mid - 1
        }
    }
    return -1
}
```
- `lo < hi`: при `lo == hi` цикл не зайдёт и последний кандидат пропущен: `[5]`, target `5` вернёт `-1`
- `lo != hi`: при `lo == hi` цикл останавливается, не проверив последний кандидат: `[1, 3]`, target `3` вернёт `-1`; а если `hi` уйдёт ниже `lo`, условие останется истинным: `[1, 3]`, target `0` зацикливается
- `lo >= hi`: условие ложно с самого начала: на `[1, 3]`, target `1` цикл не выполнится ни разу
? Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.

## e2
```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = ⟦lo + (hi - lo) / 2 | ~(lo + hi) ushr 1⟧
        when {
            nums[mid] == target -> return mid
            nums[mid] < target  -> lo = mid + 1
            else                -> hi = mid - 1
        }
    }
    return -1
}
```
- ~`(lo + hi) ushr 1`: работает, но эталон читаемее и не опирается на беззнаковый сдвиг
- `lo < hi`: при `lo == hi` цикл не зайдёт: `[5]`, target `5` вернёт `-1`
- `(lo + hi) / 2`: `lo + hi` переполняет `Int` на больших индексах: при `lo = hi = 2_000_000_000` сумма уходит в минус
- `hi - lo / 2`: выходит за `[lo, hi]`: при `lo = 5`, `hi = 5` получится `3 < lo`
- @1 `(lo + hi) / 2`: `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- @1 `hi - lo / 2`: `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- @2 `lo < hi`: `mid` станет `Boolean`, и `nums[mid]` не скомпилируется
? Цикл идёт, пока диапазон `[lo, hi]` не пуст, то есть пока `lo <= hi`.
? Середина `mid = lo + (hi - lo) / 2` (защита от переполнения). Три ветки: нашли / ушли вправо / ушли влево.

## e3
```kotlin
fun binarySearch(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (⟦lo <= hi⟧) {
        val mid = lo + (hi - lo) / 2
        when {
            nums[mid] == target -> return ⟦mid⟧
            nums[mid] < target  -> lo = mid + ⟦1⟧
            else                -> hi = mid - ⟦1⟧
        }
    }
    return -1
}
```
- `lo < hi`: при `lo == hi` цикл не зайдёт: `[5]`, target `5` вернёт `-1`
- `0`: `lo = mid + 0` зацикливается: на `[1, 3]`, target `3` `lo` остаётся `0` навсегда
- `-1`: `lo = mid + -1` уводит границу назад: на `[1, 3]`, target `3` `lo = -1`, `mid` снова `0`, цикл бесконечный
- @1 `0`: `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- @1 `-1`: `while` ждёт `Boolean`, а это `Int`: не скомпилируется
- @2 `0`: вернёт `0` вместо найденного индекса: `[1, 3]`, target `3` даст `0`
- @2 `-1`: скажет «не найдено», хотя элемент есть: `[5]`, target `5` даст `-1`
- @2 `lo < hi`: здесь нужен `Int`, а `lo < hi` — `Boolean`: не скомпилируется
- @2 `1`: вернёт константу `1`, а не индекс: `[5]`, target `5` даст `1` — такого индекса нет
- @3 `lo < hi`: здесь нужен `Int`, а `lo < hi` — `Boolean`: не скомпилируется
- @3 `mid`: `lo = mid + mid` = 2·`mid`: `[1, 3]`, target `3` — `mid = 0`, `lo` остаётся `0`, цикл бесконечный
- @4 `0`: `hi = mid - 0` не исключает `mid`: `[1, 3]`, target `0` — `hi = 0`, `mid` снова `0`, цикл бесконечный
- @4 `-1`: `hi = mid - -1 = mid + 1` не сужает диапазон: `[1, 3]`, target `0` — `mid = 0`, `hi` снова `1`, цикл бесконечный
- @4 `lo < hi`: здесь нужен `Int`, а `lo < hi` — `Boolean`: не скомпилируется
- @4 `mid`: `hi = mid - mid` всегда `0`: `[1, 3, 5, 7, 9]`, target `3` — `hi = 0`, вернёт `-1`
? Середина `mid = lo + (hi - lo) / 2` (защита от переполнения). Три ветки: нашли / ушли вправо / ушли влево.
? Если нашли, возвращаем `mid`; иначе сдвигаем границу за `mid`: `lo = mid + 1` или `hi = mid - 1`.
