# l1.1
note: 1.1 Есть ли дубликат
title: Есть ли дубликат
pitfalls:
- Двойной цикл «каждый с каждым» даёт O(n²) вместо O(n)
- `contains` без `add` ничего не запоминает и никогда не находит повтор
examples:
- assertFalse(hasDuplicate(intArrayOf(1, 2, 3)))
- assertTrue(hasDuplicate(intArrayOf(1, 2, 1)))
- assertFalse(hasDuplicate(intArrayOf()))
- assertTrue(hasDuplicate(intArrayOf(7, 7)))
checks:
```kotlin
// оракул: toSet().size != size; все массивы длины 0..5 из {-1, 0, 1, 2}
for (n in 0..5) case {
    for (m in 0 until pw(4, n)) {
        val a = IntArray(n) { (m / pw(4, it)) % 4 - 1 }
        assertEquals(a.toSet().size != a.size, hasDuplicate(a))
    }
}
case { assertFalse(hasDuplicate(intArrayOf(5))) }
case { assertTrue(hasDuplicate(intArrayOf(1, 2, 3, 1))) } // дубль первого и последнего
case { assertTrue(hasDuplicate(intArrayOf(1, 2, 3, 3))) } // дубль в самом конце
case { assertFalse(hasDuplicate(intArrayOf(Int.MAX_VALUE, Int.MIN_VALUE, 0))) }
case { assertTrue(hasDuplicate(intArrayOf(Int.MAX_VALUE, Int.MAX_VALUE))) }
// контрпримеры из причин
case { assertFalse(hasDuplicate(intArrayOf(1, 2))) }
case { assertTrue(hasDuplicate(intArrayOf(1, 1))) }
case { assertFalse(hasDuplicate(intArrayOf(1))) }
```

## theory Когда HashSet
signals:
- «Есть ли повтор?», «видели ли раньше?»
- Важно только наличие элемента, не количество
- Нужно уложиться в O(n)
body: `HashSet` отвечает «уже было?» за O(1), поэтому весь проход — O(n) по времени и O(n) по памяти.

## theory Трюк add
skeleton:
```kotlin
val seen = HashSet<Int>()
for (x in nums) if (!seen.add(x)) return true
```
body: `add` возвращает `false`, если элемент уже был в множестве: одна строка и проверяет, и запоминает.

## theory Грабли
pitfalls:
- `seen.add(x)` без `!` срабатывает на первом же новом элементе
- `contains` без `add` ничего не запоминает: повтор не найдётся
- У `MutableList` метод `add` всегда возвращает `true`, повтор он не заметит

## e1
```kotlin
fun hasDuplicate(nums: IntArray): Boolean {
    val seen = HashSet<Int>()
    for (x in nums) if (⟦!seen.add(x)⟧) return true
    return false
}
```
- `seen.add(x)` [wrong]: условие перевёрнуто: первый же новый элемент даёт `true`: `[1, 2]` → `true`
- `seen.contains(x)` [wrong]: в `seen` никто ничего не кладёт, условие всегда ложно: `[1, 1]` → `false`
- `!seen.contains(x)` [wrong]: множество пустое, условие истинно на первом элементе: `[1]` → `true`
? `set.add(x)` возвращает `false`, если элемент уже был. Одна строка внутри цикла.

## e2
```kotlin
fun hasDuplicate(nums: IntArray): Boolean {
    val seen = ⟦HashSet<Int>()⟧
    for (x in nums) if (⟦!seen.add(x)⟧) return true
    return false
}
```
- `mutableListOf<Int>()` [wrong]: `add` у списка всегда возвращает `true`, повтор не заметит: `[1, 1]` → `false`
- `seen.add(x)` [wrong]: условие перевёрнуто: первый же новый элемент даёт `true`: `[1, 2]` → `true`
- `seen.contains(x)` [wrong]: в `seen` никто ничего не кладёт, условие всегда ложно: `[1, 1]` → `false`
- @1 `!seen.add(x)` [compile]: `val seen = !seen.add(x)` ссылается на саму себя, а `x` ещё не объявлен: не скомпилируется
- @1 `seen.add(x)` [compile]: `val seen = seen.add(x)` ссылается на саму себя, а `x` ещё не объявлен: не скомпилируется
- @1 `seen.contains(x)` [compile]: `val seen = seen.contains(x)` ссылается на саму себя, а `x` ещё не объявлен: не скомпилируется
- @2 `HashSet<Int>()` [compile]: `if` ждёт `Boolean`, а `HashSet<Int>()` — множество: не скомпилируется
- @2 `mutableListOf<Int>()` [compile]: `if` ждёт `Boolean`, а `mutableListOf<Int>()` — список: не скомпилируется
? Нужна коллекция, у которой `add` возвращает `false` на повторе: это `HashSet`.
? `set.add(x)` возвращает `false`, если элемент уже был. Одна строка внутри цикла.

## e3
```kotlin
fun hasDuplicate(nums: IntArray): Boolean {
    val seen = ⟦HashSet<Int>()⟧
    for (x in nums) if (⟦!seen.add(x)⟧) return ⟦true⟧
    return ⟦false⟧
}
```
- `mutableListOf<Int>()` [wrong]: `add` у списка всегда возвращает `true`, повтор не заметит: `[1, 1]` → `false`
- `seen.add(x)` [wrong]: условие перевёрнуто: первый же новый элемент даёт `true`: `[1, 2]` → `true`
- `seen.contains(x)` [wrong]: в `seen` никто ничего не кладёт, условие всегда ложно: `[1, 1]` → `false`
- @1 `!seen.add(x)` [compile]: `val seen = !seen.add(x)` ссылается на саму себя, а `x` ещё не объявлен: не скомпилируется
- @1 `seen.add(x)` [compile]: `val seen = seen.add(x)` ссылается на саму себя, а `x` ещё не объявлен: не скомпилируется
- @1 `seen.contains(x)` [compile]: `val seen = seen.contains(x)` ссылается на саму себя, а `x` ещё не объявлен: не скомпилируется
- @1 `true` [compile]: `val seen = true` — это `Boolean`, у него нет `add`: не скомпилируется
- @1 `false` [compile]: `val seen = false` — это `Boolean`, у него нет `add`: не скомпилируется
- @2 `HashSet<Int>()` [compile]: `if` ждёт `Boolean`, а `HashSet<Int>()` — множество: не скомпилируется
- @2 `mutableListOf<Int>()` [compile]: `if` ждёт `Boolean`, а `mutableListOf<Int>()` — список: не скомпилируется
- @2 `true` [wrong]: `if (true)` выходит на первом же элементе: `[1]` → `true`
- @2 `false` [wrong]: `if (false)` никогда не срабатывает: `[1, 1]` → `false`
- @3 `HashSet<Int>()` [compile]: функция возвращает `Boolean`, а не множество: `return HashSet<Int>()` не скомпилируется
- @3 `mutableListOf<Int>()` [compile]: функция возвращает `Boolean`, а не список: `return mutableListOf<Int>()` не скомпилируется
- @3 `!seen.add(x)` [wrong]: сработает: второй `add` того же `x` вернёт `false`, `!false` = `true`; но это лишний вызов `add` с побочным эффектом, здесь просто `true`
- @3 `seen.add(x)` [wrong]: `x` уже в `seen`, второй `add` вернёт `false`: `[1, 1]` → `false`
- @3 `seen.contains(x)` [wrong]: сработает: `x` уже в `seen`, `contains` вернёт `true`; но это лишняя проверка, здесь просто `true`
- @3 `false` [wrong]: повтор нашли, а вернули «повторов нет»: `[1, 1]` → `false`
- @4 `HashSet<Int>()` [compile]: функция возвращает `Boolean`, а не множество: `return HashSet<Int>()` не скомпилируется
- @4 `mutableListOf<Int>()` [compile]: функция возвращает `Boolean`, а не список: `return mutableListOf<Int>()` не скомпилируется
- @4 `!seen.add(x)` [compile]: после цикла `x` вне области видимости: `return !seen.add(x)` не скомпилируется
- @4 `seen.add(x)` [compile]: после цикла `x` вне области видимости: `return seen.add(x)` не скомпилируется
- @4 `seen.contains(x)` [compile]: после цикла `x` вне области видимости: `return seen.contains(x)` не скомпилируется
- @4 `true` [wrong]: дошли до конца без повторов, а вернули «есть повтор»: `[1, 2]` → `true`
? `set.add(x)` возвращает `false`, если элемент уже был. Одна строка внутри цикла.
? Нашли повтор — сразу `true`; цикл закончился без повторов — `false`.
