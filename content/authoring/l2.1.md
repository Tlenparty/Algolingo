# l2.1
note: 2.1 Перемещение нулей
statement: Сдвинь все нули в конец, сохранив порядок ненулевых, **на месте** (LeetCode 283).
trains: fast/slow в одну сторону на месте
pitfalls:
- `slow++` вне `if` двигает `slow` и на нулях: нули остаются на месте
- Условие `nums[fast] > 0` теряет отрицательные: `[-1, 0]` → `[0, 0]`
- Забыть добить хвост нулями: `[0, 5]` → `[5, 5]` вместо `[5, 0]`
- swap вместо копирования тоже работает, но «slow пишет хорошие, потом нули» проще запомнить
variations:
- swap за один проход без добивания: `nums[slow] = nums[fast].also { nums[fast] = nums[slow] }`
- LeetCode 27 Remove Element: пропускаем не нули, а `val`, и возвращаем `slow`
examples:
- assertContentEquals(intArrayOf(1, 3, 12, 0, 0), intArrayOf(0, 1, 0, 3, 12).also { moveZeroes(it) })
- assertContentEquals(intArrayOf(0), intArrayOf(0).also { moveZeroes(it) })
checks:
```kotlin
// оракул: ненулевые в прежнем порядке, потом нули; все массивы длины 0..5 из {-1, 0, 1, 2}
for (n in 0..5) case {
    for (m in 0 until pw(4, n)) {
        val a = IntArray(n) { (m / pw(4, it)) % 4 - 1 }
        val expected = a.filter { it != 0 } + a.filter { it == 0 }
        val got = a.copyOf()
        moveZeroes(got)
        assertEquals(expected, got.toList(), a.toList().toString())
    }
}
case { assertContentEquals(intArrayOf(), intArrayOf().also { moveZeroes(it) }) }
case { assertContentEquals(intArrayOf(0, 0, 0), intArrayOf(0, 0, 0).also { moveZeroes(it) }) }
case { assertContentEquals(intArrayOf(4, -2, 7), intArrayOf(4, -2, 7).also { moveZeroes(it) }) }
case { assertContentEquals(intArrayOf(Int.MIN_VALUE, Int.MAX_VALUE, 0), intArrayOf(Int.MIN_VALUE, 0, Int.MAX_VALUE).also { moveZeroes(it) }) }
// контрпримеры из причин
case { assertContentEquals(intArrayOf(1, 0), intArrayOf(0, 1).also { moveZeroes(it) }) }
case { assertContentEquals(intArrayOf(-1, 0), intArrayOf(-1, 0).also { moveZeroes(it) }) }
case { assertContentEquals(intArrayOf(5, 0), intArrayOf(0, 5).also { moveZeroes(it) }) }
case { assertContentEquals(intArrayOf(5), intArrayOf(5).also { moveZeroes(it) }) }
```

## theory Когда fast/slow
signals:
- Переставить или отфильтровать **на месте**, без второго массива
- Порядок оставшихся элементов важен
- Нужно O(n) по времени и O(1) по памяти
body: Два указателя бегут в одну сторону: `fast` читает каждый элемент, `slow` показывает, куда писать следующий «хороший». Всё, что левее `slow`, уже готово.

## theory Каркас
skeleton:
```kotlin
// куда писать хороший
var slow = 0
// fast бежит по всем
for (fast in nums.indices) {
    // плохие пропускаем
    if (good(nums[fast])) {
        nums[slow] = nums[fast]
        slow++
    }
}
// хвост: дописать или отрезать
```
body: `slow` двигается только после записи, поэтому он никогда не обгоняет `fast` и не затирает непрочитанное. После цикла `slow` — длина «хорошей» части.

## theory Грабли
pitfalls:
- `slow++` вне `if`: `slow` растёт и на нулях, они остаются на месте
- `nums[fast] > 0` вместо `!= 0`: `[-1, 0]` → `[0, 0]`, отрицательные тоже ненулевые
- Без добивания хвоста: `[0, 5]` → `[5, 5]` — старые значения остаются в конце

## e1
```kotlin
fun moveZeroes(nums: IntArray) {
    // куда писать ненулевой
    var slow = 0
    // fast бежит по всем
    for (fast in nums.indices) {
        // нули пропускаем
        if (nums[fast] ⟦!=⟧ 0) {
            // копируем в slow
            nums[slow] = nums[fast]
            slow++
        }
    }
    // хвост добиваем нулями
    while (slow < nums.size) {
        nums[slow] = 0
        slow++
    }
}
```
- `==` [wrong]: копируем нули вместо ненулевых: `[0, 1]` → `[0, 0]` вместо `[1, 0]`
- `>` [wrong]: отрицательные тоже ненулевые, а `>` их выбрасывает: `[-1, 0]` → `[0, 0]` вместо `[-1, 0]`
? `slow` получает только те числа, которые остаются впереди.

## e2
```kotlin
fun moveZeroes(nums: IntArray) {

    for (fast in nums.indices) {

            // копируем в slow
            nums[slow] = ⟦nums[fast]⟧

        }
    }
    // хвост добиваем нулями

        nums[slow] = 0
        slow++
    }
}
```
- `==` [wrong]: копируем нули вместо ненулевых: `[0, 1]` → `[0, 0]` вместо `[1, 0]`
- `fast` [wrong]: пишем индекс, а не число: `[0, 5]` → `[1, 0]` вместо `[5, 0]`
- `0` [wrong]: вместо числа пишем ноль, ненулевые пропадают: `[0, 5]` → `[0, 0]` вместо `[5, 0]`
- @1 `nums[fast]` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] nums[fast] 0` не скомпилируется
- @1 `fast` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] fast 0` не скомпилируется
- @1 `0` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] 0 0` не скомпилируется
- @2 `!=` [compile]: после `=` нужно значение, а не оператор: `nums[slow] = !=` не скомпилируется
- @2 `==` [compile]: после `=` нужно значение, а не оператор: `nums[slow] = ==` не скомпилируется

? В ячейку `slow` пишем то, что сейчас читает `fast`.

## e3
```kotlin
fun moveZeroes(nums: IntArray) {
    // куда писать ненулевой
    var slow = ⟦0⟧
    // fast бежит по всем
    for (fast in nums.indices) {
        // нули пропускаем
        if (nums[fast] ⟦!=⟧ 0) {
            // копируем в slow
            nums[slow] = ⟦nums[fast]⟧
            slow++
        }
    }
    // хвост добиваем нулями
    while (⟦slow < nums.size⟧) {
        nums[slow] = 0
        slow++
    }
}
```
- `1` [wrong]: первая ячейка никогда не перезаписывается: `[0, 5]` → `[0, 5]` вместо `[5, 0]`
- `==` [wrong]: копируем нули вместо ненулевых: `[0, 1]` → `[0, 0]` вместо `[1, 0]`
- `slow <= nums.size` [crash]: `<=` пускает `slow == nums.size`, а такой ячейки нет: `[0, 5]` → `nums[2] = 0` падает с `ArrayIndexOutOfBoundsException`
- @1 `!=` [compile]: после `=` нужно значение, а не оператор: `var slow = !=` не скомпилируется
- @1 `==` [compile]: после `=` нужно значение, а не оператор: `var slow = ==` не скомпилируется
- @1 `nums[fast]` [compile]: `fast` объявляется только в цикле ниже: `var slow = nums[fast]` не скомпилируется
- @1 `slow < nums.size` [compile]: `slow` ссылается сам на себя при объявлении: `var slow = slow < nums.size` не скомпилируется
- @1 `slow <= nums.size` [compile]: `slow` ссылается сам на себя при объявлении: `var slow = slow <= nums.size` не скомпилируется
- @2 `0` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] 0 0` не скомпилируется
- @2 `1` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] 1 0` не скомпилируется
- @2 `nums[fast]` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] nums[fast] 0` не скомпилируется
- @2 `slow < nums.size` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] slow < nums.size 0` не скомпилируется
- @2 `slow <= nums.size` [compile]: между `nums[fast]` и `0` нужен оператор сравнения: `nums[fast] slow <= nums.size 0` не скомпилируется
- @3 `0` [wrong]: вместо числа пишем ноль, ненулевые пропадают: `[0, 5]` → `[0, 0]` вместо `[5, 0]`
- @3 `1` [wrong]: вместо числа пишем единицу: `[0, 5]` → `[1, 0]` вместо `[5, 0]`
- @3 `!=` [compile]: после `=` нужно значение, а не оператор: `nums[slow] = !=` не скомпилируется
- @3 `==` [compile]: после `=` нужно значение, а не оператор: `nums[slow] = ==` не скомпилируется
- @3 `slow < nums.size` [compile]: в ячейку `Int` нельзя записать `Boolean`: `nums[slow] = slow < nums.size` не скомпилируется
- @3 `slow <= nums.size` [compile]: в ячейку `Int` нельзя записать `Boolean`: `nums[slow] = slow <= nums.size` не скомпилируется
- @4 `0` [compile]: условию `while` нужен `Boolean`, а не число: `while (0)` не скомпилируется
- @4 `1` [compile]: условию `while` нужен `Boolean`, а не число: `while (1)` не скомпилируется
- @4 `!=` [compile]: условию нужно выражение, а не оператор: `while (!=)` не скомпилируется
- @4 `==` [compile]: условию нужно выражение, а не оператор: `while (==)` не скомпилируется
- @4 `nums[fast]` [compile]: условию `while` нужен `Boolean`, а это число, да и `fast` живёт только внутри `for`: `while (nums[fast])` не скомпилируется
