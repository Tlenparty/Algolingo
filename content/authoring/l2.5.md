# l2.5
note: 2.5 Является ли подпоследовательностью
title: Подпоследовательность
examples:
- assertTrue(isSubsequence("abc", "ahbgdc"))
- assertFalse(isSubsequence("axc", "ahbgdc"))
checks:
```kotlin
// оракул: перебор всех подпоследовательностей t по маске; все s и t из {a, b} длины 0..3 и 0..4
for (sLen in 0..3) for (tLen in 0..4) case {
    for (x in 0 until pw(2, sLen)) for (y in 0 until pw(2, tLen)) {
        val s = (0 until sLen).map { "ab"[(x / pw(2, it)) % 2] }.joinToString("")
        val t = (0 until tLen).map { "ab"[(y / pw(2, it)) % 2] }.joinToString("")
        val expected = (0 until pw(2, tLen)).any { mask -> t.filterIndexed { i, _ -> (mask / pw(2, i)) % 2 == 1 } == s }
        assertEquals(expected, isSubsequence(s, t), "$s $t")
    }
}
case { assertTrue(isSubsequence("", "")) }
case { assertTrue(isSubsequence("", "abc")) }
case { assertFalse(isSubsequence("a", "")) }
case { assertTrue(isSubsequence("abc", "abc")) }
case { assertFalse(isSubsequence("aaa", "aa")) }
case { assertFalse(isSubsequence("ab", "ba")) }
// контрпримеры из причин
case { assertTrue(isSubsequence("a", "a")) }
case { assertTrue(isSubsequence("b", "ab")) }
case { assertTrue(isSubsequence("ab", "abc")) }
```

## theory Когда по указателю на строку
signals:
- Две последовательности, и **порядок** элементов важен
- «Получается ли одна из другой вычёркиванием»
- Нужно O(n) и O(1) памяти
body: `tIndex` читает `t` по одному символу, `sIndex` ждёт свой очередной символ из `s`. Совпало — `s` продвинулась на шаг. Брать самое раннее совпадение всегда безопасно: позднее оставило бы для остатка `s` меньше символов `t`.

## theory Каркас
skeleton:
```kotlin
// по указателю на строку
var sIndex = 0
var tIndex = 0
// пока обе не кончились
while (sIndex < s.length && tIndex < t.length) {
    // совпало — двигаем s
    // t двигается всегда
}
// нашли всю s?
```
body: `tIndex` растёт на каждом шаге, поэтому цикл сделает не больше `t.length` шагов. После цикла смотрим на `sIndex`: дошёл до конца `s` — значит, все её символы нашлись по порядку.

## theory Грабли
pitfalls:
- `return tIndex == t.length`: `t` дочитывается до конца и тогда, когда `s` не нашлась: `"axc"`, `"ahbgdc"` → `true`
- Двигать `t` только при совпадении: на первом же несовпадении цикл встаёт навсегда
- `||` вместо `&&`: индекс уходит за конец одной из строк и падает
- Пустая `s` — подпоследовательность любой строки, даже пустой

## e1
```kotlin
fun isSubsequence(s: String, t: String): Boolean {
    // указатель в s
    var sIndex = 0
    // указатель в t
    var tIndex = 0
    // пока обе не кончились
    while (sIndex < s.length && tIndex < t.length) {
        // совпало — двигаем s
        if (s[sIndex] == t[tIndex]) sIndex++
        // t двигается всегда
        tIndex++
    }
    // всю s нашли по порядку?
    return ⟦sIndex == s.length⟧
}
```
- `tIndex == t.length` [wrong]: `t` дочитывается до конца и тогда, когда `s` не нашлась: `"axc"`, `"ahbgdc"` → `true` вместо `false`
- `sIndex < s.length` [wrong]: условие наоборот — «нашли не всё»: `"abc"`, `"ahbgdc"` → `false` вместо `true`
? `t` может кончиться и тогда, когда `s` не нашлась. Какой указатель знает, сколько символов `s` уже найдено?

## e3
```kotlin
fun isSubsequence(s: String, t: String): Boolean {
    // указатель в s
    var sIndex = 0
    // указатель в t
    var tIndex = 0
    // пока обе не кончились
    while (sIndex < s.length ⟦&&⟧ tIndex < t.length) {
        // совпало — двигаем s
        if (s[sIndex] == t[tIndex]) ⟦sIndex++⟧
        // t двигается всегда
        ⟦tIndex++⟧
    }
    // всю s нашли по порядку?
    return ⟦sIndex == s.length⟧
}
```
- `||` [crash]: цикл идёт, пока не кончились **обе** строки, и читает за концом одной: `"ab"`, `"abc"` → `s[2]` падает с `StringIndexOutOfBoundsException`
- `tIndex == t.length` [wrong]: `t` дочитывается до конца и тогда, когда `s` не нашлась: `"axc"`, `"ahbgdc"` → `true` вместо `false`
- @1 `sIndex++` [compile]: между двумя условиями нужен логический оператор: `sIndex < s.length sIndex++ tIndex < t.length` не скомпилируется
- @1 `tIndex++` [compile]: между двумя условиями нужен логический оператор: `sIndex < s.length tIndex++ tIndex < t.length` не скомпилируется
- @1 `sIndex == s.length` [compile]: между двумя условиями нужен логический оператор: `sIndex < s.length sIndex == s.length tIndex < t.length` не скомпилируется
- @1 `tIndex == t.length` [compile]: между двумя условиями нужен логический оператор: `sIndex < s.length tIndex == t.length tIndex < t.length` не скомпилируется
- @2 `&&` [compile]: после `if (...)` нужна команда, а не оператор: `if (s[sIndex] == t[tIndex]) &&` не скомпилируется
- @2 `||` [compile]: после `if (...)` нужна команда, а не оператор: `if (s[sIndex] == t[tIndex]) ||` не скомпилируется
- @2 `tIndex++` [wrong]: при совпадении двигается не тот указатель, `sIndex` стоит на `0`: `"a"`, `"a"` → `false` вместо `true`
- @2 `sIndex == s.length` [wrong]: сравнение ничего не меняет, `sIndex` стоит на `0`: `"a"`, `"a"` → `false` вместо `true`
- @2 `tIndex == t.length` [wrong]: сравнение ничего не меняет, `sIndex` стоит на `0`: `"a"`, `"a"` → `false` вместо `true`
- @3 `&&` [compile]: на строке нужна команда, а не оператор: строка `&&` не скомпилируется
- @3 `||` [compile]: на строке нужна команда, а не оператор: строка `||` не скомпилируется
- @3 `sIndex++` [wrong]: `s` двигается на каждом шаге, а `t` стоит: `"axc"`, `"ahbgdc"` → `true` вместо `false`
- @3 `sIndex == s.length` [hang]: сравнение ничего не двигает, на несовпадении оба указателя стоят: `"b"`, `"ab"` — цикл не кончается
- @3 `tIndex == t.length` [hang]: сравнение ничего не двигает, на несовпадении оба указателя стоят: `"b"`, `"ab"` — цикл не кончается
- @4 `sIndex++` [compile]: функция возвращает `Boolean`, а `sIndex++` — число: `return sIndex++` не скомпилируется
- @4 `tIndex++` [compile]: функция возвращает `Boolean`, а `tIndex++` — число: `return tIndex++` не скомпилируется
- @4 `&&` [compile]: после `return` нужно значение, а не оператор: `return &&` не скомпилируется
- @4 `||` [compile]: после `return` нужно значение, а не оператор: `return ||` не скомпилируется
? Цикл идёт, пока **обе** строки не кончились: за концом строки читать нельзя.

? Указатель в `t` двигается на каждом шаге — иначе цикл может встать.
